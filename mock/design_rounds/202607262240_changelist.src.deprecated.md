# Src changelist: the release-blocker round

**Date:** 2026-07-26
**Phase:** IMPL
**Doc changelist:** `202607262215_changelist.doc.lock.md`
**Status:** living until locked

Two correctness fixes, one regression test for a contract nothing was guarding, the toolchain pin, and the
warning sweep the release should not carry.

## CHANGE: `Requires` and `Satisfied` ADDED to arvo

File: `mock/crates/arvo/src/predicate.rs`

A const-predicate witness: `pub struct Requires<const COND: bool>` and `pub trait Satisfied`, implemented
only for `Requires<true>`, carrying a `#[diagnostic::on_unimplemented]` note. Placed alongside the
existing predicate shims because both name a constraint, though these are const-evaluated where `Pred` is
a runtime callback.

Verification: `grep "pub trait Satisfied" mock/crates/arvo/src/predicate.rs` returns one match, and
`grep "impl Satisfied for Requires<true>"` returns one.

## CHANGE: `Identity` for `UFixed` and `IFixed` GAINS a one-integer-bit bound

Files: `mock/crates/arvo/src/ufixed.rs:81`, `mock/crates/arvo/src/ifixed.rs`

Both impls gain `Requires<{ I.raw() >= 1 }>: Satisfied`, so neither exists at zero integer bits.

Measured before the change, on the pinned nightly:

| Type | `ONE` raw | Should be |
|---|---|---|
| `UFixed<0, 8, Hot>` | 0 | unrepresentable |
| `UFixed<0, 8, Precise>` | 255 | unrepresentable |
| `IFixed<0, 7, Hot>` | -128 | unrepresentable |
| `IFixed<0, 7, Precise>` | 127 | unrepresentable |

The signed case is the worse of the two and was not in the original report. `IFixed<0, 7, Hot>::ONE` is
the most negative value of the type, so multiplying by the identity does not merely annihilate, it flips
sign.

`ZERO` is untouched and stays available at every width. `MINUS_ONE` on `IFixed` is deliberately not
covered by the same bound: a signed purely fractional type has range `[-1, 1)`, so minus one **is**
representable there even though one is not. The asymmetry is real and the bound is not copied across
without checking it.

Verification: `<UFixed<0, 8, Hot> as Identity>::ONE` fails to compile with the note. A test asserts
`<UFixed<1, 7, Hot> as Identity>::ONE` still holds `1 << 7`, so the bound refuses the broken case without
taking the working one with it.

## CHANGE: `i_mul_fixed` HANDLES the container minimum

File: `mock/crates/arvo-strategy/src/arith.rs:541`

The negative branch reaches its result by negating an unsigned magnitude. At the container minimum the
magnitude is `2^127`, which casts to `i128::MIN`, and negating that overflows: verified as a panic from
`<Hot as IArith<128>>::i_mul_fixed::<0>(i128::MIN, 1)`. The minimum is returned directly instead.

`Hot` and `Cold` are the strategies that promise not to panic, and under const evaluation an overflow is
a hard error, so this fails a build rather than a run.

Verification: that call returns `i128::MIN` rather than panicking, asserted as a test.

## CHANGE: out-of-range column regression test ADDED to arvo-bitmask

File: `mock/crates/arvo-bitmask/tests/out_of_range.rs`

Pins the `BitsBitPrim` contract that a bit position at or beyond the word width leaves the word unchanged.
Currently true and currently unguarded.

The case is worth a test because the plausible regression is silent and severe rather than loud. Setting
a bit is a shift by the position, and a native shift by 70 on a 64-bit word masks to `1 << 6` in release
builds. Were that to reach the container, `set_edge(nid(0), nid(70))` would set column **6**: an edge that
was never asked for, in a graph, feeding every algorithm downstream. Every existing test would still pass,
because none of them addresses a column that does not exist.

Verification: the test asserts the row is empty after the out-of-range insert, and specifically that the
aliased position is clear.

## CHANGE: toolchain pin MOVED to the repo root

Files: `rust-toolchain.toml` (added), `mock/rust-toolchain.toml` (deleted)

`mock/rust-toolchain.toml` read `channel = "nightly"`, floating, and shadowed the root for the whole
workspace. There was no root file, so deleting the `mock/` one alone would have left the repo unpinned
entirely. The root gains `nightly-2026-05-28` with the workspace's standard components, and rustup's
upward search gives `mock/` the same pin.

Verification: `rustup show active-toolchain` run in `mock/` names `nightly-2026-05-28` and cites the root
file as the override source.

## CHANGE: warning sweep

Nine `#![feature]` gates declared and unused (`const_ops` in arvo-strategy and arvo-bits,
`const_param_ty_trait` in arvo-strategy, arvo-bits-contracts and arvo-numeric-contracts,
`adt_const_params` in arvo-mask-contracts, `const_cmp` and `try_trait_v2` in arvo), plus an unused
`Transparent` import in arvo-bits-contracts. Removed.

An unvetted gate is not free: the vetting rule treats a gate for a feature the crate does not use as
drift, and a stale gate misrepresents what the crate depends on.

Verification: `cargo build` across the workspace emits no `unused_features` or `unused_imports` warning.

## Deliberately not in this round

**The four private-in-public warnings** (`BitPrim`, `IBitPrim`, `UBitContainer`, `IBitContainer` over
`pub(crate)` sealing traits). These are the sealed-trait pattern working as intended: the supertrait is
private precisely so nobody outside implements it. Silencing them means changing how sealing is expressed
across the contracts crate, which is a design question rather than a release fix.

**The remaining em-dashes in crate sources.** A mechanical sweep across every crate is its own pass and
would bury the correctness changes in this diff.

**The wide divide above 64-bit logical width**, which stays a catalogued red with its tracked task. That
is the correct resting state for an unbuilt case. What changes is that the release text names the limit
rather than describing the arithmetic as complete.
