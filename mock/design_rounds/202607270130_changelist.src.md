# Src changelist: an identity belongs to an operation

**Date:** 2026-07-27
**Phase:** IMPL
**Doc changelist:** `202607270015_changelist.doc.lock.md`
**Source topic:** `202607262330_topic.identity-per-operation.md`
**Status:** living until locked

The `Identity<Op>` redesign and the mechanism carrying it, the two verified correctness fixes, the tests
that would have caught all three, the file splits the now-sighted size limit demands, and the removal of
the build-script bootstrap that put a git dependency in front of every consumer.

## CHANGE: `Identity` GAINS an operation parameter

File: `mock/crates/arvo-strategy/src/identity.rs` (new, split out of `arith.rs`)

```rust
pub struct Additive;
pub struct Multiplicative;

pub const trait Identity<Op>: Sized {
    const IDENTITY: Self;
}
```

The paired `ZERO` / `ONE` associated constants go away. Every primitive gains two impls in place of one,
emitted by the existing `impl_bounded_identity_u!` / `impl_bounded_identity_i!` / `impl_bounded_identity_f!`
macros, which grow a second `Identity` block rather than a second macro.

Verification: `grep "pub const trait Identity<Op>" mock/crates/arvo-strategy/src/identity.rs` returns one
match, and `grep -c "const ZERO: Self" mock/crates/arvo-strategy/src/identity.rs` returns zero.

## CHANGE: `SignedIdentity` DROPS its `Identity` supertrait

File: `mock/crates/arvo-strategy/src/identity.rs`

`pub const trait SignedIdentity: Identity` becomes `pub const trait SignedIdentity: Sized`. The supertrait
named the un-parameterised trait, and there is no single `Identity` to name any more. Nothing about
`NEG_ONE` needed the multiplicative identity to exist, which is the point: on `IFixed<0, F, S>` minus one is
representable and one is not, so a supertrait bound would have made `MINUS_ONE` unreachable on exactly the
types that have it.

Verification: `grep "trait SignedIdentity" mock/crates/arvo-strategy/src/identity.rs` shows `: Sized`.

## CHANGE: `OneRepresentable` and `tag_one_representable` ADDED

File: `mock/crates/arvo-strategy/src/identity.rs`

The sealed tag projection carrying representability, in the shape `container.rs` already uses:

```rust
pub const fn tag_one_representable(int_bits: u16) -> usize {
    if int_bits >= 1 { 0 } else { 1 }
}

pub trait OneRepresentable<const TAG: usize>: crate::sealed::Sealed {}
impl OneRepresentable<0> for Picker {}
```

`Picker` is the existing dispatch site and `crate::sealed::Sealed` the existing seal, so downstream cannot
supply the missing impl. The trait carries a `#[diagnostic::on_unimplemented]` note naming the range the
type spans and saying that a purely fractional type has no one, since that note is the whole error message a
consumer sees.

No impl exists for tag 1. That absence is the refusal.

Verification: `<UFixed<0, 8, Hot> as Identity<Multiplicative>>::IDENTITY` fails to compile with the note.
`<UFixed<1, 7, Hot> as Identity<Multiplicative>>::IDENTITY` compiles and holds `1 << 7`, so the bound
refuses the broken case without taking the working one.

## CHANGE: `UFixed` and `IFixed` SPLIT their identity impls

Files: `mock/crates/arvo/src/ufixed.rs`, `mock/crates/arvo/src/ifixed.rs`

One `impl const Identity` becomes two. The additive impl is unconditional. The multiplicative impl carries
`Picker: OneRepresentable<{ tag_one_representable(I.raw()) }>` and keeps the `ufixed_fixed_one` body, which
is now only ever instantiated at widths where its result fits.

Measured before the change, on the pinned toolchain, and the reason the constraint exists:

| Type | `ONE` held raw | Effect of `x * ONE` |
|---|---|---|
| `UFixed<0, 8, Hot>` | 0 | annihilates |
| `UFixed<0, 8, Precise>` | 255 | shrinks by 1/256 |
| `IFixed<0, 7, Hot>` | -128 | flips sign |
| `IFixed<0, 7, Precise>` | 127 | shrinks by 1/128 |

Verification: the identity-law matrix below, which fails to compile against the current source and passes
after.

## CHANGE: every call site of `ZERO` and `ONE` MOVES to the parameterised form

Files: `arvo-bitmask/src/{mask,ops}.rs`, `arvo-bits-contracts/src/lib.rs`, `arvo-comb/src/{binpack,dp,greedy}.rs`,
`arvo-graph/src/{components,path,spanning,waist}.rs`, `arvo-numeric-contracts/src/predicates.rs`,
`arvo-sparse/src/{block,dm,rcm}.rs`, `arvo-spectral/src/partition.rs`,
`arvo-storage/src/{bits,bridges,lib,meta_bits,platform}.rs`, `arvo-strategy/src/{ieee,lib,widebits,width}.rs`,
`arvo/src/{bitfield,float,lib,strategy}.rs`, plus the test files that name them

`<T as Identity>::ZERO` becomes `<T as Identity<Additive>>::IDENTITY` and `::ONE` becomes
`<T as Identity<Multiplicative>>::IDENTITY`. Bounds naming `[const] Identity` name the operation they
actually use, which is the additive one almost everywhere: a mask's `empty()`, a graph row word, an
accumulator's starting value.

Two call sites need both and say so. The float blanket impls take `Op` as a parameter and forward, so
`FastFloat<F>` and `StrictFloat<F>` carry whatever `F` carries.

Verification: `grep -rn "as Identity>::" mock/crates/` returns nothing.

## CHANGE: `i_mul_fixed` HANDLES the container minimum

File: `mock/crates/arvo-strategy/src/arith.rs:541`

The negative branch reached its result by negating an unsigned magnitude. At the container minimum that
magnitude is `2^127`, which casts to `i128::MIN`, and negating that overflows. Verified as a panic from
`<Hot as IArith<128>>::i_mul_fixed::<0>(i128::MIN, 1)`. `wrapping_neg` is identical for every other input
and yields the minimum itself there, which is the correct two's-complement answer.

`Hot` and `Cold` are the strategies that promise not to panic, and under const evaluation an overflow is a
hard error, so this failed a build rather than a run.

Verification: `never_panic_contract.rs` below, which panics against the current source.

## CHANGE: identity-law matrix ADDED

File: `mock/crates/arvo/tests/identity_laws.rs`

Asserts, for each type, that the additive identity leaves a value unchanged under addition and that the
multiplicative one leaves it unchanged under multiplication, over the **whole** matrix of signedness,
strategy, and integer/fractional split, not a sample of it. The old suite had 401 passing tests and asserted
neither law anywhere.

The matrix is the point. A law asserted only over the widths where it already holds reports green and proves
nothing about the rest, and that is exactly how four wrong constants survived. Rows at zero integer bits
assert the additive law and assert that the multiplicative impl does not exist.

Verification: against the current source the file does not compile, and the error is the finding rather than
an obstacle. `1 << 8` does not fit an 8-bit container, so the expected raw for one **cannot be written
down**. After the fix the row compiles because it no longer names a multiplicative identity for a type that
has none.

## CHANGE: never-panic contract test ADDED

File: `mock/crates/arvo-strategy/tests/never_panic_contract.rs`

Pins that `Hot` and `Cold` return a value for every input rather than panicking, over the container extremes
where a sign-magnitude path has no symmetric answer. Currently unguarded, and the multiply defect lived
exactly there.

Verification: panics on `i128::MIN` before the change, passes after.

## CHANGE: out-of-range column regression test ADDED

File: `mock/crates/arvo-bitmask/tests/out_of_range.rs`

Pins the `BitsBitPrim` contract that a bit position at or beyond the word width leaves the word unchanged.
Currently true and currently unguarded.

Worth a test because the plausible regression is silent rather than loud. Setting a bit is a shift by the
position, and a native shift by 70 on a 64-bit word masks to `1 << 6` in release. Were that to reach the
container, `set_edge(nid(0), nid(70))` would set column 6: an edge nobody asked for, in a graph, feeding
every algorithm downstream. Every existing test would still pass, because none addresses a column that does
not exist.

A compile-time refusal is not available without changing the API, since `set_edge` takes runtime `NodeId`
values.

Verification: the row is empty after the out-of-range insert, and the aliased position specifically is clear.

## CHANGE: `arith.rs` SPLITS into four modules

Files: `mock/crates/arvo-strategy/src/arith.rs` (843 lines, over the 500 limit), becoming `arith.rs`,
`arith_impl.rs`, `euclid.rs`, `identity.rs`

The file carried four unrelated concerns behind one name. `arith.rs` keeps the `UArith` / `IArith` /
`USaturating` / `ISaturating` declarations; `arith_impl.rs` takes the wrapping, saturating and widening
macros with their invocations; `euclid.rs` takes the scalar euclidean contract; `identity.rs` takes
`Bounded`, `Identity<Op>`, `SignedIdentity` and the representability projection.

The split is the reason the limit exists rather than a chore it imposes: the identity work in this round
touches only the last of the four, and every re-read of it until now has meant scrolling past 800 lines of
arithmetic macros.

Verification: every file under `mock/crates/arvo-strategy/src/` is under 500 non-blank, non-comment lines,
and `cargo mock` reports no `file-size` error.

## CHANGE: `traits.rs` SPLITS into a module directory

Files: `mock/crates/arvo/src/traits.rs` (814 lines, over the limit), becoming `traits/` with `mod.rs`,
`total_ord.rs`, `sqrt.rs`, `recip.rs`, `abs.rs`, `from_constant.rs`, `const_sign.rs`, `euclid.rs`

One module per trait family, along the section comments the file already carried. `mod.rs` re-exports so no
consumer path changes.

Verification: as above, plus `grep -rn "arvo::traits::" mock/` shows no path that stopped resolving.

## CHANGE: the mockspace build-script bootstrap is REMOVED

Files: 15 `mock/crates/*/build.rs` deleted, `mock/crates/arvo/build.rs` stripped to its cfg declaration,
16 `mock/crates/*/Cargo.toml` lose `[build-dependencies] mockspace`, `mock/Cargo.toml` loses the
`workspace.dependencies` entry, `mock/mockspace.toml` moves to `mockspace.toml` gaining `mock_dir = "mock"`,
`.cargo/config.toml` deleted

Every crate carried a build script whose only job was `mockspace::bootstrap::bootstrap_from_buildscript()`,
and a matching build-dependency on a git source. That shape predates the `cargo mock` launcher, which is
installed once per machine and resolves its own engine pin from `mockspace.toml`.

It is a release blocker rather than untidiness. The dependency ships in the published manifest, so every
consumer of arvo would fetch the design tooling at their build time for a tool that does nothing there, and
publishing is refused outright, since a registry takes no crate whose dependency resolves to a git source.
Confirmed rather than assumed: `cargo package -p arvo` failed on the mockspace git build-dependency before
the entries came out, and afterwards reaches the ordinary path-dependency-needs-a-version stage.

The four parts land together because they are one change. Attempted separately, the legacy build script
regenerated `.cargo/config.toml` from the in-mock config, and with the config already relocated it wrote an
alias with an empty `--dir`, so `cargo mock` stopped resolving a mock directory at all.

`mock/crates/arvo/build.rs` survives, stripped to the `arvo_fast_math` cfg declaration that stops rustc
warning on `#[cfg(arvo_fast_math)]`. It has nothing to do with the design tooling.

Verification: `grep -rn mockspace mock/crates/*/Cargo.toml mock/Cargo.toml` returns nothing,
`ls mock/crates/*/build.rs` returns one path, and `cargo mock` runs through the launcher with no alias
shadowing it.

## CHANGE: the toolchain pin is REMOVED from the mock workspace

File: `mock/rust-toolchain.toml` deleted

It read `channel = "nightly"`, floating, and shadowed the repo root for the whole Cargo workspace, which is
where every test runs. The root file added earlier in this branch pins `nightly-2026-05-28`, and rustup's
upward search gives `mock/` the same pin once the shadow is gone.

Every claim of verification on the pinned nightly in this repo, before the root file landed, was false.

Verification: `rustup show active-toolchain` run in `mock/` names `nightly-2026-05-28` and cites the root
file as the override source.

## CHANGE: the bench worker FORWARDS the threaded flag

File: `mock/benches/src/main.rs`

`harness::run_worker` gained a `threaded` parameter. The coordinator passes `--threaded` through from the
manifest, and the worker parses it and forwards it, so a threaded bench's spawned workers are not pinned to
a core the coordinating thread alone would hold.

Verification: `cargo check --workspace` is clean.

## CHANGE: warning sweep

Nine `#![feature]` gates declared and unused (`const_ops` in arvo-strategy and arvo-bits,
`const_param_ty_trait` in arvo-strategy, arvo-bits-contracts and arvo-numeric-contracts, `adt_const_params`
in arvo-mask-contracts, `const_cmp` and `try_trait_v2` in arvo), plus an unused `Transparent` import in
arvo-bits-contracts. Removed.

An unvetted gate is not free: the vetting rule treats a gate for a feature the crate does not use as drift,
and a stale gate misrepresents what the crate depends on.

Verification: `cargo build` across the workspace emits no `unused_features` or `unused_imports` warning.

## Deliberately not in this round

**The four private-in-public warnings** (`BitPrim`, `IBitPrim`, `UBitContainer`, `IBitContainer` over
`pub(crate)` sealing traits). The sealed-trait pattern working as intended: the supertrait is private
precisely so nobody outside implements it. Silencing them means changing how sealing is expressed across the
contracts crate, which is a design question rather than a release fix.

**The remaining em-dashes in crate sources.** A mechanical sweep across every crate is its own pass and
would bury the correctness changes in this diff.

**The wide divide above 64-bit logical width**, which stays a catalogued red with its tracked task. That is
the correct resting state for an unbuilt case. What changes is that the release text names the limit rather
than describing the arithmetic as complete.

**The bit-matrix axis naming.** Rows are chosen directly as `Dim<100>` while columns arrive as a consequence
of the row word, and `Capacity` says nothing about which axis it sizes. It changes no shipped behaviour.
