# Addendum to 202609011102's doc changelist

**Date:** 2026-09-01
**Written by:** round 202609011145, which found it.

The locked file is frozen and its bytes are unchanged. This says what one of its
claims turned out to be.

## The claim

Its second `## CHANGE` block says the tool's `description` string is the one
place a `mock/tools/` edit can reach a generated document, that `mock tools`
prints it and the generated tool catalogue snapshots it, and that regeneration
at the close picks the new line up.

## What holds instead

The string moved, from `what reaches each obligation, by tier, with the
preconditions against it` to `what reaches each obligation, by the rung that
reaches it, with the preconditions against it`. That half is right.

**There is no generated tool catalogue in this repository.** A search for the
string finds it in `mock/tools/obligation-coverage/src/lib.rs` and nowhere else,
and nothing under `docs/` or in any `*.md.tmpl` names the tool at all. So the
regeneration at the close had nothing to pick up, the catalogue did not move
because there is no catalogue, and the verification the block names could not
have failed and could not have passed either.

The conclusion the block reached is still the right one, that the round moved no
generated document. The route it reasoned along does not exist.

## Why it matters enough to write down

A changelist naming a check is how a later reader decides what was already
looked at. This one names a check nobody could run, and it reads exactly like
one somebody did. The round that found it carries a replacement block naming the
search that actually settles the question.
