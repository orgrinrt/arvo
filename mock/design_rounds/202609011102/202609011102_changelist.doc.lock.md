# Doc changelist: no template changes

**Date:** 2026-09-01
**Round:** a namespace is not a rung, and a stamp nothing follows is not a stamp
**Scope:** none.

## CHANGE: nothing FROM the templates TO the templates
File: none
Verification: `git diff --name-only origin/dev...HEAD` over this round names no `*.md.tmpl` and no
generated document.

The round changes how one tool decides a tier and what it prints beside each row. `mock/tools/` is not
a template surface and nothing under it renders into `docs/`, so no `*.md.tmpl` moves and no generated
document moves with it.

## CHANGE: nothing about the tool catalogue, and it is checked rather than assumed
File: none
Verification: the generated catalogue's entry for this tool read against the `description()` the round
leaves behind.

The tool's `description` string does move this round, from "what reaches each obligation, by tier, with
the preconditions against it" to one naming the rung, because the old one is the sentence the defect was
hiding behind. `mock tools` prints that string and the generated tool catalogue snapshots it, so this is
the one place a `mock/tools/` edit can reach a generated document, and it is why the check is named here
instead of being waved past with the rest.

Regeneration runs at the close, as it does every round, and the catalogue picks the new line up there.

## CHANGE: nothing in the registry
File: none
Verification: `mock/registry/*.toml` untouched, and `cargo mock` reports 699 rows across 10 namespaces
before and after.

Three things this round found sit in the registry and none of them is fixed here.

**Eighteen of the thirty-one `ratified` rulings carry no `ratified_by`**, which the schema's own field
description calls required on a ratified row. The requirement is conditional and lives in prose, so the
loader cannot hold it and nothing does. That is a lint somebody owes, and writing it is neither a tool
edit nor a doc one.

**`ruling::ingest_is_the_consumers_and_the_c_abi_is_where_it_ends_up` is the row op declined to bless**,
and it stays exactly as it is. It already carries the decline in its own `note`, there is a second row
recording the refusal, `ruling::he_declined_to_bless_the_ingest_row_as_written`, and a question opened
to unblock the promotion. The row is not wrong; the instrument reading it was.

**`proposal::every_operation_arvo_declares_is_a_function_of_the_declared_width` carries
`standing = "one_expert"`** while the ruling that stamps it records promotion on two independent
instances of each of its four propositions. Whether `standing` is meant to move when a stamp lands, or
is meant to stay as the record of what the proposal itself reached, is a canon question rather than a
tool one. The walk does not read `standing` at all, so nothing here turns on the answer.

This changelist exists because the phase machine requires a doc window to close before a src one opens,
not because there is doc work in it.
