# Src changelist: the tier is the rung, and the stamp is followed

**Date:** 2026-09-01
**Round:** a namespace is not a rung, and a stamp nothing follows is not a stamp
**Scope:** `mock/tools/obligation-coverage/src/lib.rs` and its tests.

## CHANGE: the tier FROM the namespace TO the rung of the row that reaches it
File: `mock/tools/obligation-coverage/src/lib.rs`
Verification: arms planting a ruling at each of the four rungs and asserting the tier each lands at,
plus the tool run against the real registry before and after.

`EDGES` mapped a namespace to a tier, `("ruling", Reach::Met)`, and the walk took that tier with no
filter between the iteration and `entry.0 = entry.0.min(tier)`. The word `rung` was in neither the
source nor the tests, against 102 occurrences in `ruling.toml`.

`Reach` becomes seven variants and six of the seven words are the schema's own, for a rung or for a
namespace, so a tier in the report can be grepped for in `mockspace.toml` and found:

    ratified   in_force   stated   proposed   unsettled   route-closed   nothing

`EDGES` keeps the three namespaces and stops carrying a tier beside each, because a `ruling` contributes
its rung and a `proposal` contributes whether a ratified ruling stamped it, and neither is a property of
the namespace. The pairs now carry an `Edge` enum instead, which makes the walk's match exhaustive: a
namespace added there has to be given a reading rather than falling onto a wildcard nobody looked at.
The list stays in the order `an-obligation-edge-comes-from-a-tiered-namespace` holds it in, since the
two lists still cannot check each other and the file already says so.

`met` goes as a tier word. It is a claim about the obligation where every other word is a fact about
the row that reached it, and it is the word that carried the false claim, so retiring it makes a reader
re-read what the tier means. The report says in one line that `ratified` is the only tier that is met.

## CHANGE: a stamped proposal FROM proposed TO the authority of the ruling that stamped it
File: `mock/tools/obligation-coverage/src/lib.rs`
Verification: an arm planting a ratified ruling that ratifies a proposal naming an obligation, and the
control below it.

`stamps()` reads `ruling.ratifies` off every ruling at `rung = "ratified"` and keys the result by the
proposal's slug, which is what `ratifies` holds. A proposal in that map tiers at `ratified` and prints
the ruling that stamped it beside the row; one that is not tiers at `proposed` as before.

**The rung is checked here rather than taken on trust.** `an-unratified-ruling-stamps-a-proposal`
refuses a stamp from below `ratified` at HARD_ERROR, so the hop is guarded at the gate, and a
measurement that assumed the gate had run would report a proposal as canon on exactly the row the gate
exists to catch. The arm for that is the control: a proposal stamped by a `stated` ruling stays
`proposed`.

**The two-hop path prints rather than collapsing.** `ratified` on a proposal-sourced line claims a
ruling's authority, so the line names which ruling. A ruling-sourced line prints its rung the same way,
which is what makes `unsettled` readable: a ruling at `open` and one whose rung could not be read share
a tier and are told apart on the line.

## CHANGE: the unanswered predicate FROM a chain of not-equals TO a match over every tier
File: `mock/tools/obligation-coverage/src/lib.rs`
Verification: an arm asserting the stuck list is empty for an obligation at each answering tier, and
non-empty at each of the other three.

The stuck-with-a-precondition pair filtered on `*tier != Reach::Met && *tier != Reach::Proposed`, which
names the two tiers to exclude. Adding a tier to that enum put it on the unanswered side silently, so
an obligation that had just gained a stronger answer would have been reported as having none. Three
tiers were added this round and the form would have mis-filed all three.

`Reach::answered()` is a match over all seven instead, so the same edit fails to compile until somebody
decides which side a new tier sits on.

## CHANGE: the rungless fixture FROM the only case tested TO one case among five
File: `mock/tools/obligation-coverage/src/tests.rs`
Verification: the arms themselves, and each one's stated failing case.

The old fixture planted a row carrying an `obligation` field and nothing else, so every ruling any arm
ever saw was rungless, and `a_ruling_meets_an_obligation_and_a_proposal_only_proposes_it` asserted `Met`
for it. Setup that helps, exactly: every input was one the implementation handled, so the path that
breaks was never entered and the one property the file asserts about itself in prose had no arm.

The fixture takes a rung per planted ruling. The arms added, each with the value that makes it fail:

**A `stated` ruling does not reach the top tier.** Fails if the walk reads the namespace, which is the
shipped defect and the arm that would have caught it.

**Each of the four rungs lands at its own tier**, over all four in one arm rather than one rung
sampled, so a mapping right for `ratified` and wrong for `in_force` cannot pass.

**A rung the tool does not know does not reach the top tier**, and neither does a missing one. Fails if
an unreadable rung is read optimistically, which is the direction that flatters the count.

**A proposal a ratified ruling stamps reaches the top tier**, and names the stamping ruling on the line.
Fails on the shipped walk, which reads the naming namespace only.

**A proposal stamped by a ruling that is not ratified does not.** The control on the arm above: it fails
if `stamps()` collects the edge without checking the stamper's rung.

**A stamp naming a proposal that does not exist changes nothing**, and does not panic.

**The strongest edge still decides**, now across rungs rather than namespaces: a `stated` ruling and a
ratified one on one obligation is `ratified`, and both are named as having got it there.

**The stuck list is driven at all seven tiers**, so the answered predicate is measured rather than
asserted about.

Two arms already there change their planted rows rather than their meaning:
`the_tally_counts_every_obligation_once_and_at_one_tier` and
`the_report_names_every_tier_and_the_rows_that_got_each_there` now plant a rung, and the tally arm
counts seven tiers.

## CHANGE: the module's account of what it measures FROM the namespace doctrine TO the rung one
File: `mock/tools/obligation-coverage/src/lib.rs`
Verification: read against the schema's `rung`, `ratifies` and `proposal.obligation` descriptions, and
against the two rows named in it.

The old text glossed the top tier as "A ruling names it and op has been in the loop, which is the only
tier that is an answer". He was in the loop on the one row that produced it, and the loop's output was
a refusal, so the sentence was false about the only instance it ever had.

What replaces it says where authority lives, quotes the schema's four rung values, names both live
defects with the rows that carried them, and states the ladder with the one comparison nothing in the
canon makes marked as the file's own reading. `proposed` over `unsettled` is that comparison. Nothing
rests on it: no ruling at `open` carries an obligation edge, so it is one line to move.

The help text moves with it, including the count of lints that refuse a state around this walk, which
goes from three to four now that the stamp check is one of them.

## CHANGE: nothing about the tool being a tool
File: none

The four questions land where they landed. Nothing here adds a state to refuse: an unanswered
obligation is still the state of unfinished work rather than a defect, and gating on a count would
still invent a deadline nobody set. `not_a_lint()` stays `NoFailingCase` and the arm driving every
registry in the file for a blocking outcome stays with it.

## CHANGE: nothing about the preconditions
File: none

`PRECONDITION_SOURCES` is `law` and `proposal`, which is exactly the pair the schema declares
`precondition_for` on, and keeping preconditions out of the tier arithmetic is the call this tool got
right. A stamped proposal's `precondition_for` edges are untouched by the stamp for the same reason: a
precondition is a dependency somebody established either way, and it leaves the obligation further from
met rather than nearer.

## CHANGE: nothing about a new lint
File: none

The stamp hop this now follows is already guarded. `an-unratified-ruling-stamps-a-proposal` refuses the
one state that would make it lie, at HARD_ERROR, and `ratifies` is a typed `proposal[]` so a stamp
naming no row is refused by the schema check over all 699 rows. There is nothing left for a new lint to
hold, and the walk carries the rung check anyway.

## Not this round

The `ratified_by` gap, the ingest row's promotion, and whether `standing` moves when a stamp lands. All
three are registry work and the doc changelist files them.
