## Cycle-avoidance probes (apply-time concerns)

These items need probing during source application; record the resolution inline:

1. `BitsBitPrim<Sign>` sealed bridge trait at arvo-bits-contracts: verify the two-impls-per-Sign approach compiles cleanly on rustc 1.96.0-nightly without hitting `generic_const_exprs` cycle. If cycle: fall back to two distinct impl blocks per consumer trait (one per Sign), each with a single-predicate `where` clause.
2. `notko::Outcome::Ok` / `Outcome::Err` const-callability inside `impl const`: verify enum constructors resolve. Should be fine; record outcome.
3. `Ordering` const-constructibility on rustc 1.96.0-nightly: probe `core::cmp::Ordering::Equal` in const fn body. If yes, use it. If no, ship `ConstOrdering` substrate enum.
4. `f32::from_bits` / `f32::to_bits` const-stability for sqrt_f32/sqrt_f64 lift. If feature-gated, add the gate at arvo's crate root; if unstable, document the boundary and defer the float-const path to a follow-up round (note in BACKLOG).
5. `u*::isqrt` const-stability: if requires `feature(const_int_sqrt)`, add at arvo's crate root.
6. **Layering finding (resolved at apply time):** doc CL placed `ConstEq` / `ConstOrd` / `ConstDefault` in `arvo-strategy` returning `Bool` per the canonical signatures. `Bool` lives in `arvo-storage`, which depends on `arvo-strategy`; placing the bridges in `arvo-strategy` would require either inverting the layer (impossible without restructure) or downgrading the return type to bare `bool` (deviates from doc CL signature). Resolution: **place bridges in `arvo-storage`** (where `Bool` is reachable), alongside the existing `AsBool` trait. The substrate's canonical-const surface (`Bounded`, `Identity`, `SignedIdentity`) stays in `arvo-strategy`. The consumer-facing predicate-bridge family (`ConstEq`, `ConstOrd`, `ConstDefault`) lives one layer below in `arvo-storage`. Layered organisation: strategy holds typed-min/max/zero/one/neg-one (no Bool dependency); storage holds typed-equality/ordering/default (Bool-returning). The doc CL's "Place: arvo-strategy" wording is superseded by this finding; the substrate-bridge concept stands. Doc CL stays locked as audit trail; SRC CL records the resolution.

   Concrete placement update:
   - `arvo-strategy/src/bridges.rs` (NEW): defines only `SignedIdentity` (extends Identity which already lives in arith.rs). Per-signed-primitive impls.
   - `arvo-storage/src/bridges.rs` (NEW): defines `ConstEq`, `ConstOrd`, `ConstDefault`. Per-bare-primitive impls (the implementing-crate-owns-the-impls orphan rule allows arvo-storage to impl substrate-bridge traits on bare primitives since the trait is local). Per-substrate-type impls follow in their owning files.

Each probe outcome is recorded in this CL during apply; this CL is living during SRC phase.
