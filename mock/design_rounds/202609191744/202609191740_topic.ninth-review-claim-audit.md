# ninth-review-claim-audit

The ninth review of the platform-width round found one blocking claim and a catalogue of six more,
against a3b78b02's `no_std` scope having dropped out of the manifest-rename condition in the eighth
review's own audit. This round closes B1, the blocking finding, and the C1-C6 catalogue it filed
alongside it.

## B1: the manifest-rename condition lost its `no_std` scope

The condition "the rename reaches `::core` when the path the edition's prelude import names resolves in
the renamed crate" was true of the four committed fixtures because all four are `#![no_std]`. A `no_std`
crate's own prelude is imported through the name `core`, which the rename has taken over, so the renamed
crate is read for its prelude too. A std dependent has no such need: its own prelude comes through the
name `std`, not `core`, so nothing about the renamed crate's `prelude` module matters to it.

A new fixture, `a_std_dependent_of_the_crate_without_the_glob`, confirms this directly: it depends on
`fakecore_without_the_glob`, the same renamed crate that refuses the `no_std` dependent with "cannot
resolve a prelude import", and it builds, with the same two checks holding. Committed as research
alongside `run.sh`'s new arm and `MANIFEST_RENAME_IS_UNGUARDED.md`'s corrected prose, both already in
this round's TOPIC phase per this repo's discipline on research committed ahead of the doc window.

`DESIGN.md.tmpl`'s manifest-rename paragraph and the lint's own module doc both restate the condition
scoped to `no_std`, state the std case as its own sentence from the new arm, and name `arvo-format` as
`no_std` where the claim is about this crate specifically.

## Catalogue

C1: `user_of_the_crate_with_an_empty_prelude` has no committed control showing its array-length checks
can fail. A `refused` arm, `user_of_the_crate_with_an_empty_prelude_and_a_wrong_width`, is added,
carrying a `fakecore` stand-in whose fake width does not match what the dependent asserts, and the
compiler's `mismatched types` on the array-length trick.

C2: `the_wide_oracle_sweep.rs`'s doc says `wholes()` carries "the steps a span of 200 or 256 turns on",
but no range in the file has such a span. A 200-wide range placed off its own span and a 256-slot range
are added to `ranges()`, and the file's doc is corrected to name exactly what is fed.

C4: `DESIGN.md.tmpl`'s oracle paragraph says the map is applied "each mode's and each policy's meaning
as this crate documents it", which is not so for the `Clamp` reading: the crate documents `Clamp` as
pinning to a declared bound, and the oracle applies it as `Saturate`. The phrase becomes "as the
implementation reads it".

C5: `the_edges.rs`'s dither-below-zero test feeds one denominator, 4. The extreme remainders of the
cross-multiplication at `apply.rs:183`, `1/i64::MAX` and `(i64::MAX-1)/i64::MAX`, are added.

C6: `format/phase.rs:48`'s rustdoc on `Phase::of` narrates history, "which an earlier constructor did".
Removed, and the branch's added lines are grepped for the same class of narration.

C3, C7, C8 and C9 are not actioned: C3 is named harmless by the review itself, C7 is a scratch record
carrying no weight, C8 is carried to op from the eighth review already and this round adds nothing to
it, and C9 is a pre-existing file-size finding this round's edits do not make worse in the direction
that matters (checked at close).
