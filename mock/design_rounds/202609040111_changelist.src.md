## CHANGE: type `Reach` FROM absent TO declared

File: `crates/arvo-format/src/symmetry.rs`
Verification: `grep -c 'pub struct Reach' mock/crates/arvo-format/src/symmetry.rs` returns one, and `awk '/^impl Reach/,/^}/' mock/crates/arvo-format/src/symmetry.rs | grep -c 'pub const fn '` returns fifteen.

The region coordinate. The fields are private and the perimeter is `EVERYTHING`,
the three that build one, `of`, `translated_by` and `without_ties`, and twelve
accessors each returning a `Slot` or a `Bool`.

`lowest_rounded_position` is the one worth reading. The relocation law rounds the
position and the translated position both, so the set the rounding region sees is
the union rather than the positions a caller wrote down. The sketch's first
revision asked the sign question about the positions alone and was unsound in six
cells, and `a_negative_translation_carries_a_non_negative_position_below_zero`
keeps that case as an arm.

File: `crates/arvo-format/src/symmetry.rs`
Verification: `grep -c 'pub const fn behaviour_of' mock/crates/arvo-format/src/symmetry.rs` returns one.

What a mode reads besides the residue and when it reads it, which is what makes

## CHANGE: `a_dither_at_the_edges_still_selects_between_two_neighbours` FROM asserting range membership under a `Floor` signature TO asserting the selection under a `Stochastic` one

File: `crates/arvo-format/src/apply/tests/mod.rs`
Verification: `cargo test -p arvo-format --lib a_dither_at_the_edges` passes, and adapting through `Edge` instead makes it fail on the `assert_ne!` with both answers equal.

Two defects, and the second is the one worth recording. The arm was named for the
stochastic mode's cross-multiplication at the edges of the type and adapted
through `Edge`, which is a `Floor` signature and reads no dither at all, so the
path it names was never entered. And its only assertion was that both answers sat
inside the declared window, which under wrapping is true for every input by
construction: `complete_slot` returns `lo + (slot - lo).rem_euclid(span)`, so
replacing the stochastic branch with a constant left it green.

Neither was visible from the arm. The assertion was real, the name read as a
description of what it covered, and the dithers passed in looked like the thing
being varied. I found the first only because strengthening the second made the
arm fail with both answers equal.

The repair uses a `Stochastic` signature, asserts the two dithers pick different
neighbours, pins each against `wrap_of_wide` and against a value worked out on
paper, and carries two controls: that the products the mode compares do not fit a
slot index, so the wide comparison is reached rather than named, and that the same
two dithers through `Edge` give one answer, which is what the arm used to be
measuring.

## What the tests are worth

The suite goes from 179 passing to 201, with the same three catalogue-red arms
ignored and nothing new left red.

**The load-bearing ones.** `the_map_relocates_exactly_where_the_predicate_says`
runs the predicate against the map over 432 cells, counting a licensed law the
map refuses and a refused law the map honours separately and asserting both at
zero. `the_classification_of_every_mode_agrees_with_what_the_map_reads` derives
what each mode reads by walking the map over domains that differ in one
restriction at a time and asserts the shipped table equals it. Those two are what
stop the module from being the `matches!` over an enumeration this crate deleted
four of.

**The negative controls, which are what say the two above can fail.**
`the_control_a_wrong_classification_would_be_caught` names four wrong
classifications and shows the derivation rejecting each.
`the_control_a_degenerate_reach_licenses_everything_and_says_so` reports what a
vacuous reach looks like, so a yes is read as a claim about the reach it was
handed. `the_control_the_derivation_can_tell_the_four_domains_apart` requires the
four domains to produce four distinct rows.
`the_control_a_slot_outside_the_wide_range_would_be_caught` shows the isolation
assertion can fire. `neither_region_alone_decides_either_law` measures that the
completion region alone does not decide either law, so the conjunction is a rule
rather than a pile.

**And a mutation run, which is evidence rather than an arm.** With
`behaviour_of` temporarily declaring `HalfEven` to read the sign rather than the
parity, two arms fail:
`the_classification::the_classification_of_every_mode_agrees_with_what_the_map_reads`
and `the_cross::the_map_relocates_exactly_where_the_predicate_says`, the second
with `Signed HalfEven Wrap Restriction { negative_positions: false,
negative_translations: false, ties: true }: the predicate says true and the map
says false`. That is the unsound direction, which is the defect the cross exists
to catch. The file was restored from a copy whose checksum matches, and the run
is recorded here because it is not reproducible from the tree.

**One that is honest about being weak.**
`the_control_the_cross_reaches_every_case_a_verdict_could_turn_on` carries a
per-cell floor of 250 triples and its derivation is in the comment, because the
first floor I wrote was 500 on a wrong derivation and the arm caught it: the
smallest cell is 264, on the symmetric range with the translations restricted to
non-negative, and restricting the translations is what makes a cell on a range
reaching negatives smaller than one on a range that does not.

**What is not covered.** Every cell runs at one fixed dither. The stochastic mode
is a function of the position only once its decision is pinned, so the question
has no answer otherwise, and `no_verdict_here_moves_with_the_dither` requires the
verdict to be the same at each of five dithers rather than claiming the mode was
swept. The seeding and keying questions are untouched.

The cross runs at one width per range kind, three bits. That is not a sample of
the widths: the predicates read the range only through whether its lowest slot is
below zero and whether it is the negation of the highest, and
`the_control_every_range_kind_the_predicates_read_is_in_the_cross` asserts the
three kinds are all present. What a wider run would guard against is a
width-dependent defect in `adapt` itself, which is the applied map's own suite's
job and which its edge arms already cover at `i64::MAX` and `i64::MIN`. The
committed sketch runs the same cross at five-bit widths over thirty-eight
residues, which is where the wider number lives.
