# Doc changelist: round 202605111719

Closes the impedance gap that left hilavitkutin's plan-stage shipping `rcm_reorder`, `block_diagonalise`, and `spectral_partition` as passthrough stubs. The substrate already implements the algorithms; this round corrects two design failures in the shipped surface:

1. **CSR-shaped consumers cannot reach the algorithms.** arvo-sparse and arvo-spectral consume `BitMatrix<W, N>` adjacency. hilavitkutin's `DependencyGraph<MAX_UNITS, MAX_EDGES>` is CSR. Resolution: a sealed `SparseAdjacency` trait family that both representations implement.
2. **Algorithms hardcode `BitMatrix<Bits<64, Hot, Unsigned>, N>` in their public signatures.** The chassis is generic over W; the algorithms throw that away in their literals. Resolution: every public algorithm signature in scope becomes generic over `W: BitPrim`, with module-root default-W type aliases preserving the short consumer-call form.

Both topics absorb into this one CL. The structural-decomposition + spectral-bisection bench bundles (Subtopic F) commit before the CL locks. Findings home is `mock/research/findings_graph_spectral_202605111719.md` (created during bench landing).

The CL touches arvo-sparse and arvo-spectral. arvo-graph carries the same smell and is tracked separately: round-202605111741 audit names it as the next round; it does not land here.

### Section: `## Sparse adjacency contract` (NEW, after `## Sparse matrix representations`)

**Add.** New section. Names the sealed trait family.

Content:

- Lead paragraph: both `BitMatrix<W, N>` and `Csr<ROWS, NNZ, W>` describe the same abstract object, a directed graph over `0..N` nodes. Algorithms only ask the same handful of questions: successor set, predecessor set, degree, iteration over set bits, membership test. A sealed `SparseAdjacency<const N: Cap>` trait names that interface; algorithms become generic over `T: SparseAdjacency<N>`. Cost: one trait layer per call. Benefit: any consumer that ships its own adjacency representation implements the trait once and reuses every algorithm.

- Trait declaration block (Rust code fence):

  ```rust
  pub const trait SparseAdjacency<const N: Cap> {
      type Successors<'a>: Iterator<Item = NodeId>
      where
          Self: 'a;
      fn successors<'a>(&'a self, node: NodeId) -> Self::Successors<'a>;
      fn node_count(&self) -> USize;
      fn successor_mask<W: BitPrim>(&self, node: NodeId) -> Mask<W>;
  }

  pub const trait BidirectionalSparseAdjacency<const N: Cap>:
      SparseAdjacency<N>
  {
      type Predecessors<'a>: Iterator<Item = NodeId>
      where
          Self: 'a;
      fn predecessors<'a>(&'a self, node: NodeId) -> Self::Predecessors<'a>;
  }
  ```

- One paragraph: `successor_mask` has a default impl from the `successors` iterator (collect into the mask). Impls override when they can answer the bitmap question more cheaply than walking the iterator (e.g. `BitMatrix` returns the row mask directly).

- One paragraph: const-trait requires `#![feature(const_trait_impl)]` and `#![feature(const_index)]` at crate root. Sketch 01 from round 202605111719 confirmed the shape compiles on HEAD nightly with `-Znext-solver=globally`.

- Concrete-impl table (two columns, three rows):

  | Type | Implements |
  |---|---|
  | `BitMatrix<W, N>` | `SparseAdjacency<N>` |
  | `Csr<ROWS, NNZ, W>` | `SparseAdjacency<ROWS>` |
  | `CsrBidirectional<ROWS, NNZ, W>` | `SparseAdjacency<ROWS>` + `BidirectionalSparseAdjacency<ROWS>` |
