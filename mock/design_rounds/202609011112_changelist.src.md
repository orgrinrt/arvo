# Src changelist: pin the refusal the declared widths are spelled around

**Date:** 2026-09-01
**Round:** the one position the language refuses to repair
**Scope:** `mock/crates/arvo-format/tests/`

## CHANGE: the refusal FROM a hand check that answered once TO a `trybuild` case
File: `mock/crates/arvo-format/tests/ui/an_arvo_type_as_a_const_parameter.rs`, its `.stderr`, and the
new entry in `mock/crates/arvo-format/tests/compile_fail.rs`
Verification: the case fails to build with the diagnostic in the committed `.stderr`, and it is the
diagnostic the toolchain actually emits rather than one written from memory, because `trybuild` compares
against the compiler's output and rejects a mismatch.

`Width` cannot be the type of a const generic parameter. That was established by compiling a four-line
file by hand, which answered and then evaporated, and it is the fact the whole spelling of
`Constant<const EXP: i32>` and `Signed<const BITS: u32>` rests on. The design paragraph this round's doc
side adds says so in prose; this is the same statement in a form that fails when it stops being true.

The case declares a struct with `Width` in that position and nothing else. The `.stderr` carries the
refusal, the note that the position takes an integer, a `bool` or a `char`, and the help naming the
compiler feature, which is the part worth keeping in the tree: the escape exists, it is a gate, and a
crate declaring its own format would have to carry it too.

**The case that must fail is stated and does fail.** A `trybuild` compile-fail entry over a file that
builds is reported as an error by `trybuild` itself, so the arm cannot pass by the refusal quietly going
away; it can only pass by the refusal being exactly what the `.stderr` says. Swapping `Width` for `u32`
in the case makes it build and the test then fails, which is the control and is the reason the file
declares nothing else: there is no second reason it could be refused for.

The neighbouring entry, `a_width_the_slot_range_cannot_carry_is_refused`, is untouched. Two entries in
one `compile_fail.rs` and one `TestCases` each, matching what is there.

## What this changelist does not touch, stated so the omission is a decision

The ten public associated constants across `Format`, `Ambient`, `Quantum`, `Slots` and `Operation` are
typed with a bare integer or a `bool` and are not const generic parameters, so nothing about the position
above excuses them, and `Slots::WIDTH: Width` in the same file shows the type fits there. Changing them
changes what the traits declare, which is a design change and not a test, and the round for it wants the
question of whether this crate may hold a compiler feature settled first. The topic file carries the
finding so it is not lost.
