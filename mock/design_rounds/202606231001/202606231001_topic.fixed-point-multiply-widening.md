# Topic: fixed-point multiply (overflow-safe, widening) + fixed-point ONE

Round: 202606231001
Phase: TOPIC
Scope: arvo-strategy (IArith/UArith), arvo (IFixed/UFixed Mul + Identity)

## Current state

`IFixed<I, F, S>` and `UFixed<I, F, S>` implement `Mul` by routing through `IArith::i_mul` /
`UArith::u_mul`, which are the container's `wrapping_mul` (Hot/Warm/Cold) or `saturating_mul` (Precise): a
RAW container product with NO fixed-point rescale. For `F = 0` (integer fixed-point) this is correct
integer multiply, and it is the only case the arith tests cover (every `*` test uses `FBits::ZERO`). For
`F > 0` it is silently wrong: multiplying two values each scaled by `2^F` yields a product scaled by
`2^{2F}`, stored as raw, so the result is larger than the true product by `2^F`.

Consistently with the raw multiply, `Identity::ONE` for `IFixed`/`UFixed` is the container's `ONE` (raw
`1`), not the fixed-point one (`1.0` = raw `1 << F`). So today the types form an internally consistent
RAW-INTEGER model (`ONE = raw 1`, `*` = raw product). A downstream consumer (the ikiuni cascade) relies on
this raw convention: it builds values from `ONE`-addition and folds with `*`, where `ONE = raw 1` makes
`x * ONE = x` hold under the raw product.

The downstream need that surfaced this: a consumer requires fractional multiply (relevancy weighting, a
weight in `[0, 1]` scaling a value). Under the raw product, a fractional weight (e.g. `0.5` = raw
`1 << (F-1)`) gives `value * weight = value * 2^{F-1}`, not `value/2`. Fractional fixed-point multiply does
not work today.

## Decision (op, 2026-06-23): make bare `*` rescale for `F > 0`, with overflow-safe widening

`Mul` for `IFixed`/`UFixed` becomes the genuine fixed-point multiply for `F > 0` (`F = 0` stays integer
multiply, unchanged). For `x * ONE = x` to hold, `Identity::ONE` for the fixed-point types changes to the
fixed-point one (`1.0` = raw `1 << F`). The two changes are coupled and land together.

The multiply must be OVERFLOW-SAFE, not a non-widening `(a *raw b) >> F` (which overflows the container
before the shift for non-tiny operands). The correct shape: widen both raw operands to a 2x-width
container, multiply there, shift right by `F`, narrow back to the container. This surfaces the
widen-multiply-narrow arithmetic that arvo's arith.rs deferred ("cross-op widen-narrow logic lands with the
Cold widening table in a later round"); op's call is that the first real need surfaces that impl now.

## Approach

- **`Identity::ONE`** for `IFixed<I, F, S>` / `UFixed<I, F, S>`: `from_raw(1 << F.raw())` (the fixed-point
  one). `F = 0` gives raw `1`, unchanged. `ZERO` is unchanged (raw 0).
- **Fixed-point multiply** as a new `IArith`/`UArith` method (`i_mul_fixed(a, b, frac) -> T` /
  `u_mul_fixed`), so the per-container concrete type is in scope for naming the widen target. Body:
  `narrow( widen(a) *strategy widen(b) >> frac )`, using the existing `Widen` / `Narrow` primitives
  (`arvo-bits-contracts` `widen.rs` / `cross_domain.rs`). The strategy's overflow policy applies to the
  WIDE multiply (Precise saturates the wide product, Hot/Warm/Cold wrap the wide product), then the shift
  and narrow bring it back. `frac = 0` reduces to the current `i_mul` (widen, multiply, `>>0`, narrow ==
  raw product for in-range operands).
- **`Mul` for IFixed/UFixed** calls `i_mul_fixed(a, b, F.raw())` / `u_mul_fixed`.

### The widen target (macro restructure, not generic_const_exprs)

`Widen<T>` takes the destination as a generic parameter (no associated `Widened` type to infer), so each
container must name its 2x type. The `IArith`/`UArith` impls are macro-generated, grouped by bit-range to a
container (1..8 to i8, 9..16 to i16, ...). The clean path is to thread the 2x container type through each
macro invocation group (e.g. `impl_i_arith_wrapping!(Hot, [1..8], i8, i16)`), so the new `i_mul_fixed` body
names the wider type directly. This avoids `generic_const_exprs` for `BitsContainerFor<{2*N}>` (which
arvo's comment flags as still blocked).

### Native-widen now; WideBits-widen at its first need

For containers up to i64/u64 (logical width up to 64), the 2x target is i128/u128: NATIVE, implementable
now. This covers the surfacing need (`Quantity = Signed<31, 16, Hot>` has a 48-bit logical width, i64
container, widens to i128). For the i128/u128 container (65..128-bit logical), the 2x target is a 256-bit
`WideBits`, so the widen-multiply needs `WideBits` arithmetic, which is the genuinely-deferred piece. That
case surfaces when a >64-bit-logical fixed-point multiply is first needed; not now. Until then, the
i128/u128-container `i_mul_fixed` either uses a 128-bit-careful path or is documented as not-yet-widened
(integer `F=0` on those widths keeps working through the existing raw product).

## Consumer impact

- **Cascade (ikiuni)** builds values via `ONE`-addition and folds with `*`. After the change `ONE = 1.0`
  and `*` is fixed-point, so `q(n) = n.0` and `q(n) * ONE = n.0` still hold: the cascade tests stay green
  with no migration (the convention auto-adjusts). Relevancy with fractional weights now works correctly.
- **ikiuni-projection-pass** has a test helper `raw(n) = from_raw(n)` + `weight = from_raw(1)` adopted as a
  workaround for the raw convention. After the change it reverts to fixed-point (`from_raw(n << F)`, weight
  `1.0`), unifying ikiuni on ONE fixed-point scale. The Tally (fixed-point) vs Cascade (raw-integer) scale
  seam (ikiuni task #2) CLOSES: everything is fixed-point, `ONE = 1.0`.
- **Other arvo consumers**: any code relying on `IFixed/UFixed *` for `F > 0` was getting wrong results
  (untested); this fixes them. `F = 0` (integer) consumers are unaffected.

## Verification

- Existing arith `*` tests (all `F = 0`) stay green (the change is identity for `F = 0`).
- New tests: `Signed<I, F> (2.5) * (2.0) == 5.0` and similar across strategies; an overflow case proving
  the widening (operands whose raw product exceeds the container but whose true product fits, e.g. large
  i64-container fixed-point values, verifying the i128 widen path gives the correct result rather than a
  wrapped one); `x * ONE == x`; `ONE * ONE == ONE`.
