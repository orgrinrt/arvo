# Src changelist: the shipped comments stop saying who decided

**Date:** 2026-09-02
**Round:** the surfaces a first release lands on, and what four of them say today
**Scope:** doc comments across three crates, one inline comment, and the package version.

## CHANGE: provenance FROM fifteen shipped comments TO the contract they were attached to
File: `arvo-format/src/apply.rs:6,303,323,324,328`, `format.rs:39`, `overflow.rs:9,11`,
`rounding.rs:9,23`, `width.rs:8`, `arvo-placement/src/lib.rs:239`,
`arvo-strategy/src/lib.rs:25,141`, `arvo-strategy/src/tests.rs:10`
Verification: the class grep over `mock/crates/*/src/*.rs` and `mock/crates/*/tests/*.rs`, matching
`op`, `ratified`, `ratification`, `panel`, `blessed`, `mockspace`, `round`, `reviewer` inside `///`
and `//!` lines, returns only the two ordinary-English uses named below.

`documentation-writing.md` puts rustdoc at tier 1 and forbids provenance there in op's own words: a
design says what a thing is and how it works, never how the project came to know it. This is the
larger public surface of the two, because it renders on docs.rs and is where a reader spends longest.

**The substance survives every cut**, which is what makes this mechanical rather than a rewrite. "The
ratified factoring requires" and "the factoring requires" say the same thing to a reader, and the
dropped word carries nothing they can act on. Where a comment cites a registry row by slug the slug
stays, because a slug is an address rather than an attribution; what goes is the sentence around it
saying who blessed it and when.

Two of the sixteen the grep returns are ordinary English and are left alone: `apply.rs:14`, a
position that may "round onto a slot", and `quantum.rs:67`, a multiplication "the wrong way round".

The worst is `apply.rs:323-328`, which names op on a `///` over a public function and closes on
"would go past what was blessed", and `arvo-strategy/src/lib.rs:141`, which names op and a prior
panel. Neither is rustdoc's business and the second is an inline comment rather than a doc one, so it
does not render, but it ships in the package and `documentation-writing.md` reaches it either way.

## CHANGE: the package version FROM `0.1.0` TO `0.0.0`
File: `mock/Cargo.toml:47`
Verification: `git log -S '0.1.0' -- mock/Cargo.toml` names the seed commit and nothing after it, so
nothing is being undone; and every crate inherits through `version.workspace = true`, so one line
moves all three.

It has never moved since the initial scaffold, which is what makes it a default rather than a
decision. `release-cadence.md` fixes `0.0.0` for the whole design phase with the release named by its
tag, `0.0.0-dNN`, and `0.0.1` as the first stable. `0.1.0` skips both, and it contradicts the readme
three paragraphs above it, which says the api has not settled.

Nothing publishes today in any case: `cargo package -p arvo-format` fails because `notko` is a git
dependency with no version requirement, so the version is a claim with nothing behind it. That is a
reason to make it honest rather than a reason to leave it.
