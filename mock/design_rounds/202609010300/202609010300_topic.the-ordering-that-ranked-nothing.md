# Topic: an ordering that ranked nothing still reads as a ranking

**Date:** 2026-09-01
**Phase:** TOPIC
**Scope:** `mock/tools/awaiting-a-ruling`

`mock awaiting-a-ruling` prints every `ruling` row still at `stated`, and its own description says the
rows come "ordered by what depends on them". The sort is by how many other rows cite each one,
descending, then by slug.

## What it actually produces on the corpus

Run against the registry as it stands, 58 rows come back and exactly one of them carries a citation
count above zero, a second carries one, and the remaining 56 carry none. Checked by hand against the
registry rather than through the tool, so the tool is not confirming itself:

```
the_next_unit_is_chosen_bottom_up                        ruling.toml:1
a_predicate_lists_only_what_holds                        ruling.toml:1
precise_is_accurate_across_chains_not_only_per_operation  ruling.toml:1
```

One occurrence each, which is the row's own definition line. Nothing cites them.

That is not a defect in the counting. It is a true fact about the corpus, and it follows from how the
canon is written: a `stated` row is op's raw direction, and the prose written on top of it cites the
`ruling` that came out of it rather than the ack underneath. So the edge the sort measures barely
exists among the rows the sort is applied to.

## Why it is worth changing anyway

The output already carries the sentence "Ordering is by what cites a row, which is a suggestion and not
a ranking", so the tool is honest about the ordering being weak. It is not honest about the ordering
having been empty on this run. A reader who has been told the ordering is a suggestion still reads the
top of a list as carrying more weight than the bottom, and here the list is alphabetical after the
first two rows.

The shape is the one `a-claim-of-totality-names-what-enforces-it` names: a sentence describing a
mechanism that silently degenerated, with nothing in the output saying it did. The fix is one
sentence, conditional on whether any two rows actually differ in that count.

## Out of scope

Whether the sort should measure a different edge. Ranking `stated` rows by which layer they sit under,
bottom-up, would rank them and citations do not, but that is a question about what the tool is for and
it wants its own round.
