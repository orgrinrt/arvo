# Topic: the one position where the stack's own primitive cannot be written, and what pins it

**Date:** 2026-09-01
**Phase:** TOPIC
**Scope:** `mock/crates/arvo-format/tests/`

The obligation that says a bare number has no place at an API position excepts one position, in op's own
words, carried on `obligation::a_primitive_for_every_position_a_bare_number_would_take`:

> We want arvo there. No bare usize other than in const generics for smoother and more ergonomic api,
> and even there, only when truly painful otherwise.

The row states it as the position rather than as a type: "**A const generic parameter is excepted**, and
even there the bare form is used only where the alternative is genuinely painful."

Nothing in this repository says why that position is the excepted one, and the reason is not a matter of
taste. On the nightly `rust-toolchain.toml` pins, `nightly-2026-05-28`, an arvo type cannot be written
there at all.

## The refusal, measured

```
error: `Width` is forbidden as the type of a const generic parameter
  = note: the only supported types are integers, `bool`, and `char`
help: add `#![feature(min_adt_const_params)]` to the crate attributes to enable
      more complex and user defined types
```

`Width` is `arvo-format`'s own, `repr(transparent)` over a bit count, and the compiler refuses it for
what it is rather than for anything about its contents: the position takes an integer, a `bool` or a
`char`, and nothing else. So `pub struct Signed<const BITS: Width>` does not build, and
`pub struct Signed<const BITS: u32>` is what the crate ships.

The escape the diagnostic names is a feature gate, and that route runs into a second obligation.
`obligation::the_unstable_machinery_does_not_reach_a_consumer` says a consumer naming arvo's types needs
no unstable compiler features of its own, whatever arvo uses internally. A crate outside this one
declaring its own format would have to carry `min_adt_const_params` to write the arvo type in that
position, so the repair moves the cost onto exactly the crate the obligation protects.

Two things follow, and only the first is this round's.

## What this round does

**Pin the refusal.** It was established by hand, once, by compiling a four-line file, and a hand check
that answers and then evaporates is the thing the next reader has to redo. `trybuild` is already set up
here, `tests/compile_fail.rs` holds one case and `tests/ui/` holds its source and its expected
diagnostic, so the second case costs one file and one `.stderr`.

What it buys is narrow and worth saying plainly: it does not prove the exception is right, it records
that the alternative is refused, which is the fact the exception's second bound turns on. If a later pin
lifts the restriction, or a later round adopts the gate, the case goes red and somebody reads this file.

`min_adt_const_params` also has no row in the workspace's `unstable-features.md`, whose own rule is that
a gate with no row is unvetted and must not ship. So the route is not merely costly, it is not currently
permitted either, and vetting it would be its own act.

## What this round does not do, and why it is left standing

The wider finding, recorded here so it is not lost: **the crate's door is wider than its design says.**

`DESIGN.md.tmpl` states the bound: "The door is kept narrow on purpose: two types, no arithmetic beyond
what a width derivation needs, and everything else built from a `Format` instead of added here." The
crate is exempt from the bare-primitive lints crate-wide, by `[primitive-introductions]`, and behind that
exemption ten public associated constants are typed with a bare primitive: `PHASE_NUM` and `PHASE_DEN`
on `Format`, `RADIX` and `SIGNED` on `Ambient`, `BASE`, `SLOPE` and `MAGNITUDES` on `Quantum`, `MIN` and
`MAX` on `Slots`, and `ARITY` on `Operation`. `Slots::WIDTH: Width` is the one that uses the type the
crate defines, which is what shows the rest could.

None of those is a const generic parameter, so the exception does not reach them, and an associated
constant takes an arvo type without complaint: `arvo-placement` declares `const BITS: Width` and carries
no bare primitive anywhere. `Ambient::SIGNED: bool` is the sharpest instance, since `Bool` is defined
eleven lines away in the same crate.

**And the exemption does not contain them.** These are public traits, so a crate outside this one
implementing `Format` writes `const PHASE_NUM: i64` in its own source, where the lints are at hard error
and no exemption applies. The exemption is crate-scoped and the obligation is position-scoped, and the
gap between the two is where the trait surface sits.

That is a change to what the traits declare, which is a design change rather than a test, and it rests
on a question nobody has answered: whether arvo may hold `min_adt_const_params` internally, or whether
the associated constants alone move to `Width` and `Bool` and the const generic parameters stay bare
under the exception. The second needs no gate and closes nine of the ten. It is filed rather than taken,
because filing it keeps the option list and taking it inside a test round would be a design decision
wearing a test's clothes.
