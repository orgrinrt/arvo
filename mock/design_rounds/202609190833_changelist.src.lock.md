# Src changelist: the platform-width points, on a 128-bit slot index

**Date:** 2026-09-19
**Round:** platform-width types (branch `feat/platform-width-types-on-a-wider-slot-range`)
**Scope:** executes `202609190825_changelist.doc.lock.md`. The topic it consumed,
`202609190823_topic.platform-width-types-on-a-wider-slot-coordinate.md`, is the only flat topic and
this round's whole subject; nothing in it is left unaddressed below except what the last section names.

## Canon gate, as it stood before any source moved

`ruling::a_platform_width_type_is_a_target_bound_member_of_the_format_family` governs and serves
`obligation::a_platform_sized_unsigned_integer_at_an_api_position`. `USize` and `ISize` are aligned
with it and are built. `Cap` is refused: the same ruling names a capacity type as not one of the points,
and `ruling::the_numeric_door_carries_the_coordinate_set_and_the_two_type_bound_is_not_canon` removes
the two-type bound it rested on. No capacity type is built, and a const-generic capacity keeps `usize`
under `obligation::a_primitive_for_every_position_a_bare_number_would_take`'s own exception.

## CHANGE: `Slot` and `SlotCount` FROM `i64` TO `i128`

File: `crates/arvo-format/src/slots.rs`

`pub struct Slot(i128)`, `pub struct SlotCount(i128)`; `Slot::at`, `Slot::index`, `SlotCount::of` and
`SlotCount::count` take and return `i128`. The unsigned 64-bit range ends at `2^64 - 1`, which no signed
64-bit index holds, and the sketch `research/sketches/202609190830_the-slot-coordinate-at-sixty-four/`
shows both restatements over an `i64` index (a count, an exclusive end) reaching 63 and not 64.

Verification: `grep -n 'pub struct Slot(i128)\|pub struct SlotCount(i128)' crates/arvo-format/src/slots.rs`
returns two lines.

## CHANGE: the slot ladder FROM widths 1 to 62 TO widths 1 to 64

File: `crates/arvo-format/src/slots.rs`, `crates/arvo-format/src/standards.rs`, `crates/arvo-bits/src/lib.rs`

The impl macro writes each end as a shift of the 64-bit host integer by `64 - width`, cast to `i128`, so
a width of 65 fails at the definition site rather than in a sentence. The list runs to 63 and 64.
`ADMITTED` asserts ordered ends, a width of at least one, a width of at most 64, and
`width_addresses_span`, which takes the span with `checked_sub` and reads an overflow as not addressed.
The count condition is gone: with the width bounded at 64 and the span addressed, nothing can fail it.
`is_admissible` mirrors the four. The `on_unimplemented` note says why 64 is where the ladder stops.
`standards.rs` and the private-constant comment in `arvo-bits` say 64 where they said 62.

Verification: `grep -c 'Self::WIDTH.count() <= 64' crates/arvo-format/src/slots.rs` returns 1;
`ADMITTED_WIDTHS.len() == 64` is asserted in `tests/the_inventory.rs`.

## CHANGE: arithmetic over slots FROM "one domain wider than the index" TO checked or saturating per site

Files: `crates/arvo-format/src/addition.rs`, `apply.rs`, `format.rs`, `symmetry.rs`

With the index the widest integer, each site states its headroom, as the design section on the index's
host integer says.

- `addition.rs`: `sum_is_carried` asks `doubled_plus`, a checked `2 * slot + offset`, for both ends.
  `saturated` is replaced by `saturating_sum(a, b, c)`, which adds an opposite-sign pair first so the
  sum saturates once rather than step by step. `sum_position`, `addition_reach` (which asserts
  `operands == 2`) and `completion_at` use it. The duplicate `greatest_common_divisor` is removed and
  the one in `format.rs` is imported.
- `apply.rs`: `Exact::between` adds its carry with `saturating_add`; `round_slot` takes the step up as
  `down.saturating_add(1)`; the wrap in `complete_slot` reduces the position and the lowest slot
  separately before subtracting, so it is exact at every position the index holds.
- `symmetry.rs`: `Reach::EVERYTHING` sits at the `i128` ends; the reflection verdict takes the highest
  slot's negation with `checked_neg` and reads an overflow as not symmetric.
- `format.rs`: see the next two blocks.

Verification: `grep -n 'fn saturating_sum\|fn doubled_plus' crates/arvo-format/src/addition.rs` returns
two; `grep -n 'checked_neg' crates/arvo-format/src/symmetry.rs` returns one; the negative controls below.

## CHANGE: `cancelling_slot` FROM unreduced scaling in the index TO reduced scaling with a checked end

File: `crates/arvo-format/src/format.rs`

Two defects, both hidden while the index was `i64` and the answer had to fit it:

- The last step computed `num % den` and `num / den` plain. Where scaling leaves `num` at `i128::MIN`
  and `den` is `-1` both overflow. Now `checked_rem` and `checked_div`, and an overflow is `Isnt`.
- Scaling toward a shrinking quantum divides the radix's common factor out of the denominator step by
  step, and a factor the radix does not share (nine over three, twelve over six) left a denominator above
  one forever, so the phase answered `Isnt` at every magnitude past zero. The pair is now reduced by
  `greatest_common_divisor` before any step. `greatest_common_divisor` is `pub(crate)` here.

Verification: `grep -n 'checked_rem(den), num.checked_div(den)' crates/arvo-format/src/format.rs`
returns one; the arms named under negative controls fail without each change.

## CHANGE: the magnitude search bound FROM `SCALING_WIDTH` (127) TO `SCALING_STEPS` + 1 (191)

File: `crates/arvo-format/src/format.rs`

`SCALING_WIDTH` is removed. `SCALING_STEPS: Width = PHASE_DENOMINATOR_WIDTH.add(SLOT_INDEX_WIDTH)`, 63 plus
127, and `MAGNITUDE_SEARCH_BOUND = MagnitudeCount::of(SCALING_STEPS.count() + 1)`. With the index at 128
bits a phase of one over `2^62` is first found at magnitude 189, which the old bound never reached. The
derivation is in the constants' docs.

Verification: `grep -n 'const SCALING_STEPS: Width' crates/arvo-format/src/format.rs` returns one.

## CHANGE: `points` FROM four points TO four points and two aliases

File: `crates/arvo-format/src/lib.rs`

`pub type USize = UFixed<{ usize::BITS }, 0>;` and `pub type ISize = Integer<{ usize::BITS }>;`, aliases
with no `cfg`, documented as the doc changelist says. The points module doc names them.

Verification: `grep -n 'pub type USize\|pub type ISize' crates/arvo-format/src/lib.rs` returns two.

## CHANGE: the test suites FROM an `i64` index and 62 widths TO an `i128` index and 64

Every walk over `dispatch::every_width` counts 64 widths; every sweep, window and edge list is written in
`i128` and reaches the index's own ends. Changes that are more than a type or a count:

- `addition/tests/the_operation.rs`: the totality oracle was `i128` over an `i64` index. It is now `Wide`,
  a two-half sum exact past both ends, with its own test, because an oracle computed in the index would
  share the saturation it checks. The fractional-phase totality runs at 64 bits and at `NearTheTop` and
  `NearTheBottom`. New: `a_sum_past_the_index_saturates_once_so_a_third_term_cannot_bring_it_back`.
- `addition/tests/mod.rs`, `the_step.rs`, `the_verdict.rs`: `Window` takes `i128` ends; `NearTheTop` and
  `NearTheBottom` sit at half the index, where the carry condition is tightest; the refusal and step
  tests use them.
- `apply/tests/the_edges.rs` is new, split out of `apply/tests/mod.rs`, which had passed 500 lines. Its
  oracle `wrap_of` works over unsigned distances rather than the crate's subtraction and is checked
  against hand values first. The stochastic arm moved one slot below the top, because at the top the
  step up now saturates and both neighbours are one slot.
  `rounding_past_the_top_of_the_index_saturates_there_and_wrapping_pays_for_it` pins what that costs.
  The shim `complete` in `apply/tests/mod.rs`, which widened `i64` to `i128`, is deleted and its
  callers call `complete_slot`.
- `apply/tests/the_ratio_coordinate.rs`: the catalogued red `a_carry_past_the_top_of_the_coordinate_still_lands_a_slot`
  is answered by the design's saturation and replaced by two green arms, one at `i64`'s ends where the
  carry now lands exactly and one at the index's ends where it saturates.
- `tests/the_inventory.rs`: the outside-range obligation section moved to
  `tests/the_inventory/the_range_obligation.rs` (the parent was 690 lines). New constructions
  `OneSlotPastSixtyFour`, `WiderThanTheLadder`, `AtTheTop`, `AtTheBottom`; `SpanTooWide` is replaced
  by `SpanPastTheIndex`. New test `the_ranges_at_the_host_widths_are_the_host_integers_own`.
- `tests/the_identity.rs` and `the_identity/the_magnitude_range.rs`: expectations move to the `i128`
  answers; new arms `ScaledToTheLeastValue`, `FoundAtTheFarEnd` and
  `a_phase_written_with_a_factor_the_radix_does_not_share_is_found_at_every_magnitude`.
- `symmetry/tests/the_reach.rs`: new `the_reflection_verdict_answers_for_a_range_whose_top_has_no_negation`.
- `tests/the_platform_width.rs` is new: the aliases' ends against `usize` and `isize`, bound in `const`
  items; integral at the pointer width through the contract; membership of both ends and refusal one past
  them; an error word at an API position (4095, and `u32::MAX`) held at 16, 32 and 64 bits exactly where
  the pointer is wide enough; one arm per `target_pointer_width`.
- `arvo-placement/src/tests.rs`: the objective sweep adds 63 and 64; new
  `the_platform_width_points_are_placed_alone_on_the_pointer_width_carrier`, against literal points chosen
  per `target_pointer_width`.
- UI: `width_above_the_bound.rs` declares `Signed<65>`; `word_length_past_the_ladder.rs` declares
  `Fi<65, 32>`; `addition_over_an_uncarried_sum_is_refused.rs` uses an outside range at half the index,
  since `Signed<8>` with the same phase now carries its sum. New
  `a_range_past_the_ladder_is_refused_where_it_is_used.rs`. Stderr regenerated.

Deleted as a tautology: `the_reach_check_is_wider_than_the_widths_currently_need` in `tests/the_inventory.rs`,
which did arithmetic on two constants and asserted the result, running no code under test. The doc on
`reach_is_representable` in `crates/arvo-format/src/quantum.rs` cited it and cited the slot range's count
condition, which is gone too, so it now says only that the check is computed wider on purpose and why.

Verification: `cargo test --workspace` in `mock/`, whose result lines are in the round's gate output.

## Negative controls run

Each guard was broken once with the editing tool, the named test was seen failing, and the source was
restored with the editing tool and then `touch`ed so the object rebuilt.

- `width_addresses_span` with `wrapping_sub`: `the_law_rejects_a_range_that_passes_the_easy_obligations`
  failed on `SpanPastTheIndex`.
- `is_admissible` without `<= 64`: nothing caught it, so `WiderThanTheLadder` was written; the same test
  then failed with "a width past the ladder was admitted because it addresses its span".
- `ADMITTED` without its `<= 64` assertion: nothing caught it at runtime, so the UI arm
  `a_range_past_the_ladder_is_refused_where_it_is_used` was written; it then failed, the file compiling.
- `cancelling_slot` without the reduction: the suite stayed green, because the radix's own factors cancel
  in the scaling and `Unreduced` carries only those. The non-radix-factor arm was written and failed with
  `Isnt` for nine over three at magnitude 1.
- `SCALING_STEPS` at 127: `the_search_bound_reaches_the_longest_scaling_that_answers` failed, "the search
  stopped before the one magnitude whose slot the range holds".
- `cancelling_slot` with a plain `%` and `/`: `a_phase_scaled_to_the_least_index_value_over_minus_one_answers_isnt`
  panicked, "attempt to calculate the remainder with overflow".
- `round_slot` with `down + 1`: five tests panicked on the add, the two top-of-index arms, both addition
  totality walks and `the_map_is_total_over_every_admitted_width_mode_and_policy`.
- `Exact::between` with a plain `+`: the two carry-past-the-index arms panicked.
- `saturating_sum` saturating step by step: the suite stayed green, so the saturate-once arm was written
  and failed, one slot below the top. With a plain `a + b + c`, four addition tests panicked.
- the reflection verdict with a plain negation: the suite stayed green, so the one-slot range at
  `i128::MIN` was written and panicked, "attempt to negate with overflow".

## Cross-target, checked by hand and not yet a test

`cargo check -p arvo-format -p arvo-placement --tests` at `x86_64-unknown-linux-gnu`,
`i686-unknown-linux-gnu` and `wasm32-unknown-unknown` is green, so the 64-bit and 32-bit arms compile.
The libraries check at `thumbv6m-none-eabi`, and `arvo-format` at `msp430-none-elf` with
`-Zbuild-std=core`, so `USize` names an admitted point at a 16-bit pointer. The 16-bit test arms are not
compiled, because a test harness needs `std` and no 16-bit target has one. None of this runs in a gate
yet, and I have not built the tool that would. That is left for the next round that touches the gate.
