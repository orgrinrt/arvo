**Date:** 2026-05-30
**Phase:** SRC
**Round:** 202605301415 capacity-container-migration
**Scope:** migrate every fixed-capacity container and the algorithms that thread the capacity off the `Cap` const generic onto the `C: Capacity` type parameter shipped in #650. Six crates, one connected component: `arvo-tensor` (`Array`, `Matrix`), `arvo-comb` (DP / greedy / bin-pack), `arvo-bitmask` (`BitMatrix`, `propagate_dirty`), `arvo-graph` (topo / rank / waist / components / spanning), `arvo-sparse` (`Csr`, the sparse-adjacency const-trait family, RCM, Dulmage-Mendelsohn, block-diagonal), `arvo-spectral` (`LinearOperator`, `SparseLaplacian`, power iteration, Fiedler, bisection, k-way).

## Intent

The `Cap` const generic puts `cap_size(N)` in type position (`[T; cap_size(N)]`, `where [(); cap_size(N)]:`). That expression overflows `generic_const_exprs` the moment a generic consumer threads its own capacity through (the `cap_size(cap(N))` ICE the hilavitkutin runtime arc hit at #652's frontier). #650 shipped the GCE-free replacement: capacity is a TYPE (`C: Capacity`), the backing storage is the GAT `C::Array<T>`, and `cap_size` survives only as a value-position const-fn over `C::CAP`. This round moves every container and capacity-threading algorithm onto that foundation.

The migration is behavior-preserving by construction. Array sizes are identical (`Dim<N>::Array<T>` is `[T; N]`, the same layout `Array<T, {cap(N)}>` had), algorithm bodies are unchanged, and the only computed values that move are `cap_size(N)` becoming `cap_size(C::CAP)` (the same `usize`). No bench delta is expected; the arvo bench rerun at PR time confirms it.

The migration is atomic. `SparseAdjacency<C>` is implemented for both `BitMatrix` (arvo-bitmask) and `Csr` (arvo-sparse); `LinearOperator<F, C>` is implemented for both `Matrix` (arvo-tensor, dense) and `SparseLaplacian` over `Csr` (arvo-spectral). Those cross-crate trait families tie all six crates into one connected component, and `no-legacy-shims-pre-1.0` forbids a transitional parallel definition, so the round cannot be sliced into independently-green sub-rounds. `matrix_chain_dp` builds a `Matrix`, so once `Matrix` takes `Capacity` the function's own capacity parameter must too (Rust has no value-to-type lifting). The crates compile bottom-up (`arvo-tensor` first, `arvo-spectral` last); the workspace need only be green at lock.

A foundation extension lands first: `Capacity` gains `from_fn<T, F: FnMut(USize) -> T>(f: F) -> Self::Array<T>`, the per-slot constructor #650 deferred ("until a consumer in #651 needs them"). It is the GAT-returning replacement for the `core::array::from_fn` calls every index-built container and algorithm uses; `core::array::from_fn` cannot produce the opaque `C::Array<T>`.

A per-crate bonus: where `cap_size` leaves type position entirely (only value-position const-fn calls remain), the crate no longer needs `#![feature(generic_const_exprs)]`. The gate drops per-crate where a grep confirms no other GCE use survives, which obviates #628 for those crates. The gate is kept only where some other GCE use remains.

Sketch `mock/research/sketches/202605301400_capacity-trait-migration/` (committed, FINDINGS green) proved the trait migration mechanical and sound under the pinned nightly: the const-trait declarations survive the param-kind change, the GAT `AsRef`/`AsMut` bound carries slice access and 2-D composition, and a fully-generic `rcm_reorder_via<C, A: Adjacency<C>>` builds and walks without a GCE gate.

## Out of scope

`BitMatrix`'s per-row bit-width `W` (the 64-column node cap) is a separate widening concern; only the row-count capacity migrates here. The deferred cross-variant bench decisions (#635 RCM bitmask-vs-CSR, #636/#644 spectral dense-vs-sparse fiber) stay separate; the migration preserves both variants. The hilavitkutin `PlanDims` adoption is #652. Formalizing the convention in `no-bare-primitives.md` is #653.
