**Task:** #651 (umbrella #649)
**Scope:** the six crates whose DESIGN.md.tmpl document a `const _: Cap` container or algorithm surface migrate that surface to a `C: Capacity` type parameter, so the design contract names the GCE-free shape this round's src CL ships.

## Intent

#650 shipped the `Capacity` trait and `Dim<const N: usize>` marker into arvo-tensor and documented them, but changed no container. This round migrates every fixed-capacity container and every algorithm parameterised by `const N: Cap` (storing or returning `[T; cap_size(N)]`) onto a `C: Capacity` type parameter storing `C::Array<T>`. The doc phase updates the shipping contract in each crate's DESIGN.md.tmpl to the new shape before the source lands.

The change is uniform across all six crates: `const N: Cap` becomes `C: Capacity` on every declaration; a field or return typed `[T; cap_size(N)]` becomes `C::Array<T>`; the `where [(); cap_size(N)]:` bound is dropped; value-position `cap_size(N)` becomes `cap_size(C::CAP)`; two-dimensional storage becomes the composition `C::Array<C::Array<W>>`. The algorithms are unchanged (bench-neutral by construction). The migration is atomic because the cross-cutting traits `SparseAdjacency` and `LinearOperator` are each implemented for containers in different crates; the topic file records the full reasoning.

All edits are to prose and `rust` fences, which the `design-doc-source-mismatch` lint does not check (it checks backticked type names in markdown tables). Every migrated type keeps its NAME (`Array`, `Matrix`, `Csr`, `BitMatrix`, `SparseAdjacency`, `LinearOperator`, the graph and comb functions); only the generic parameters change, so any existing table rows stay valid against source.

## File: `mock/crates/arvo-tensor/DESIGN.md.tmpl`

### Change 1: `Capacity` gains `from_fn`

The `## Capacity and Dim` section's `rust` fence gains a `from_fn<T, F: FnMut(USize) -> T>(f: F) -> Self::Array<T>` method alongside `filled`, with the `Dim<N>` impl `core::array::from_fn(f)`. The containers expose `from_fn` (used by `Matrix::diagonal` and by algorithms that build by index), so the foundation grows the method. This is consistent with the locked #650 trait shape, not a change to it. The prose notes `from_fn` as the indexed-build companion to `filled`.

### Change 2: container migration

The closing paragraph of the `## Capacity and Dim` section currently states that `Array`, `Matrix`, `Csr`, and `BitMatrix` keep their `Cap`-const-generic shape and migrate in a follow-on round. That paragraph is replaced to state the migration has landed.

The `## Array<T, const N: Cap>` heading and fence migrate to `## Array<T, C: Capacity>`: `pub struct Array<T, C: Capacity>` with `data: C::Array<T>`, no `where` bound; `new(data: C::Array<T>)`, `from_fn`, `get`/`set` unchanged in surface, `len() -> USize` reads `cap_size(C::CAP)`. The `## Matrix<W, const N: Cap>` heading and fence migrate to `## Matrix<W, C: Capacity>`: `data: C::Array<C::Array<W>>` (the composition the foundation anticipated), `diagonal(&self) -> Array<W, C>`.

## GCE feature gate

Each crate's `#![feature(generic_const_exprs)]` gate is reviewed in the src phase: once `cap_size` leaves type position (no `[T; cap_size(N)]`, no `[(); cap_size(N)]:`), a crate with no other GCE use drops the gate. The DESIGN.md.tmpl gate-rationale prose (where present) updates to reflect the drop. Where a crate retains some other GCE use, the gate and its prose stay. This is verified per crate during the src phase, so the doc edits for the gate prose are finalised then; this round's doc CL records the intent.

## Refinements vs the validated sketches

The trait-migration sketch (`mock/research/sketches/202605301400_capacity-trait-migration/`) confirmed the value-position count idiom is `cap_size(C::CAP)` (or `C::CAP.0` for the `USize` directly), not a re-added `const N: usize` on `Capacity`. The #650 decision to drop `const N` from the trait stands; this round honours it. Loop bounds and `node_count` read `cap_size(C::CAP)`; the length as a runtime value reads `as_ref().len()`.

## Not in scope

The `BitMatrix` per-row bit-width `W` (the 64-column node cap) is a separate widening concern. The deferred cross-variant bench decisions (#635) are untouched; both variants are preserved. The hilavitkutin `PlanDims` adoption (#652) is downstream. `cap` and `cap_size` themselves are unchanged (they remain the value-position bridges).
