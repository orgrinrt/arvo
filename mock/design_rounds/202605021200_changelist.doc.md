```markdown
### Const arithmetic surface (round 202605021200)

USize ships inherent constants and a full const-trait arithmetic
surface so consumers can compute on USize values at const time
without falling back to `.0` field-access on the inner `usize`.

```rust
impl USize {
    pub const ZERO: USize = USize(0);
    pub const ONE: USize = USize(1);
    pub const MAX: USize = USize(usize::MAX);
}
```

Const-trait impls cover the full `core::ops::*` surface: `Add`,
`Sub`, `Mul`, `Div`, `Rem`, `Shl<USize>`, `Shr<USize>`, `BitAnd`,
`BitOr`, `BitXor`, `Not`. Comparison via `PartialOrd<USize>` and
`Ord`.

Each impl carries `impl const Trait<USize> for USize`, requiring
two crate-level features: `feature(const_trait_impl)` (already
shipped via arvo-transparent) and `feature(const_ops)` (new this
round, also enabled at consumer crate roots that compute on USize
at const time, since operator desugaring at const-context call
sites routes through the const trait method).

Mixed-arity ops (`USize + bare-usize`) deliberately do not
compile. Consumer call sites that need a literal use
`USize::ONE` / `USize::ZERO` for the common cases or `USize(N)`
for arbitrary literals.

Overflow semantics match `usize`'s primitive contract: panic on
debug-assertion builds, wrap on release. This is documented as
the contract; consumers needing checked arithmetic use
`Maybe<USize>`-returning helpers in a follow-up round.
```

Also add one paragraph at the end of the section explaining the
no-bare-primitives connection: `USize::add` etc. are how consumer
crates avoid `.0` access on USize in const contexts. The lint rule
forbidding `.0` access on arvo primitives outside the implementing
crate is filed as a follow-up round.

**Cap section**. The current DESIGN.md.tmpl mentions `Cap<N>` once (line 228, "Cap<N> wraps it"). Locate the actual Cap section if one exists; if not, add it after USize. Cap section content:

```markdown
## Cap

`pub struct Cap(pub USize)`. Const-generic capacity newtype, used
wherever a const generic sizes an array. The wrapping prevents
mixing capacities with unrelated indices.

Cap mirrors USize's const-arithmetic surface:

```rust
impl Cap {
    pub const ZERO: Cap = Cap(USize::ZERO);
    pub const ONE: Cap = Cap(USize::ONE);
}
```

The const-trait op surface is `Add`, `Sub`, `Mul`, `Div`, `Rem`
on `Cap` operating against `Cap`. Bodies delegate through USize's
const-trait surface (`Cap(self.0.add(rhs.0))`); no raw `usize`
arithmetic in Cap's body. The semantic distinction holds: `Cap +
USize` does not compile.

Cap implements `Transparent` over USize.
```
