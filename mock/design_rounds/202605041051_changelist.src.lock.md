## Apply-time findings (2026-05-04)

The seven test files all compiled and passed at first apply. Each file exercises substrate already exercised by real consumer code. The discipline gain (regressions surface as compile errors) holds.

A handful of small surface deviations from the doc CL / src CL claim text were resolved by reading the actual surface and writing the test against it. The deviations are recorded here so future readers see the gap between the audit-era surface description and the surface that actually shipped.

### Deviation 1: BitPrim method names

The src CL CHANGE block for `bitprim_const_access.rs` listed `set_bit` / `clear_bit` / `has_bit` (matching the audit text). The actual `BitPrim` / `IBitPrim` surface uses `with_bit_set` / `with_bit_cleared` / `get_bit`. The test exercises the actual surface plus the additional const-callable methods that were not named in the audit (`bitor`, `bitand`, `bitxor`, `bitnot`, `mask_low`, `count_ones`, `trailing_zeros`, `leading_zeros`, `is_zero`, `WIDTH`, `ZERO`, `ONE`).

### Deviation 2: Meta-newtype constructor

The src CL CHANGE block for `metacarrier_const_arith.rs` referenced `IBits::from_raw` / `FBits::from_raw` / `Width::from_raw`. The actual macro-emitted `meta_bits_wrapper!` exposes a `pub MetaCarrier` field (no inherent `from_raw` constructor on the wrapper) plus inherent `raw()` and `as_bits()` methods. The test constructs via `IBits(MetaCarrier::from_raw(n))` and exercises `raw()` plus `as_bits()`.

### Deviation 3: UFixed Bounded projection

The src CL CHANGE block for `ufixed_const_arith.rs` enumerated `Bounded::MIN` / `Bounded::MAX` projections on UFixed. UFixed does not impl `Bounded` directly today (the audit's wording was forward-looking); only `Identity` is implemented. The test exercises the available `Identity::ZERO` / `Identity::ONE` projection.

### Deviation 4: FastFloat / StrictFloat type signature

The src CL CHANGE block for `float_const_arith.rs` framed `FastFloat<F>` and `StrictFloat<F>` const-arith. The const-callable surface that ships today is `FastFloat::new` / `StrictFloat::new` / `into_inner` (the inherent constructors). The arithmetic ops are `impl const` gated on `F: [const] core::ops::Op`; bare `f32`/`f64` don't currently satisfy `[const]` for those traits in stable trait position, so the test exercises arithmetic at runtime with const construction. The boundary is documented in the test's module doc comment.

### Deviation 5: Float ops require runtime exercise

Per Deviation 4, `+`/`-`/`*`/`/` on `FastFloat<f32>` / `StrictFloat<f64>` etc. compile and run, but the `impl const` clause does not currently activate for bare-primitive `F`. The test runs them at runtime; the const-context portion exercises construction, `into_inner`, and `to_raw` round-trip. The `Ieee::WIDTH` / `Ieee::ZERO` / `Ieee::ONE` projections named in the doc CL cross-reference list are not const-accessible without further substrate work and are not exercised in this test.

### Deviation 6: Test file sets paths

The doc CL listed these tests under each crate's `tests/` directory; both `arvo-bits-contracts/tests/` and `arvo-strategy/tests/` did not exist before this round. Creating the first integration test under each crate implicitly created those directories. No `Cargo.toml` change was needed; cargo discovers `tests/*.rs` automatically.
