# the-consumer-test-takes-its-paths-when-it-runs

**Date:** 2026-11-13
**Round:** 202611132123-jozr, the sixth of track T3 on `work/arvo-values`. Ticket
`a_test_that_bakes_a_path_with_env_measures_the_main_clone_wh`, the half of it that is this crate's.

## What the round is for

A defect found and fixed, which is why it stands alone as a round. The test `a_consumer_crate` of
`arvo-numeral` builds the consumer crate under `tests/consumer/` with a cargo run of its own. It read
the crate's directory with `env!("CARGO_MANIFEST_DIR")` and its scratch directory with
`env!("CARGO_TARGET_TMPDIR")`, and both are fixed into the test binary when it is built. A seat shares
one build directory between the clone and its worktrees, so a binary built in the clone is run again
from a worktree, where it builds the clone's consumer crate and reports on the clone's tree. Two
reviewers got a red from it on diffs that did not touch the crate.

The fix is to take both paths when the test runs. Cargo sets `CARGO_MANIFEST_DIR` in the environment
of every test it runs, to the crate the run was started for. It sets no scratch directory at run time,
so that one is derived from where the test binary sits, which is the build directory the run is using.

## What the canon says

Nothing, and nothing is asked of it. This is how a test finds its fixture, with no statement about a
value in it. The value definition the crate is built on,
`proposal::a_value_is_the_sole_occupancy_placement_of_a_declared_signature`, stands on a provisional
stamp and is not touched or promoted here.
