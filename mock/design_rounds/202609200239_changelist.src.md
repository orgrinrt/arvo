## Canon

`ruling::half_up_denotes_ties_toward_positive_infinity` governs what the lint refuses.
`ruling::the_rounding_mode_vocabulary` is what `OTHER_NAMES` below is drawn from: the six are
`toward_zero`, `floor`, `ceil`, `half_up`, `half_even` and `stochastic`, so the five that are not this
mode are candidate antecedents for a pronoun standing for a rounding rule. No row changes.

## CHANGE: `antecedent` binds to a name rather than to a backtick
File: `mock/lints/half_up_is_not_a_magnitude_rule/reading.rs`

`antecedent` refused to carry the mode's name past two backticks standing after it. That answers a
question about how the author punctuated rather than about what was named, and it is wrong in both
directions. Measured against a copy of the shipped module:

- `` `half_up` pairs with `q/2`; it sends a tie away from zero. `` is silent. A backticked `q/2` is not
  something a pronoun standing for a mode can mean, and it takes the carry away.
- `` `half_up` is not the HALF_UP of Java. That one goes away from zero. `` fires. That is the sentence
  of the control at `tests.rs:216` with the backticks removed, and the shape of the ruling's own note.
  The review reported this class as empty.

New `OTHER_NAMES`: the five other names of the six-name vocabulary with their `HalfEven`-style
spellings, the external constants this repository contrasts the mode with, `HALF_UP`, `ROUND_HALF_UP`,
`roundTiesToAway`, `roundTiesToEven` and `RoundingMode`, and MATLAB's `Round`, `Fix` and `Convergent`.
Matched with case and bounded as a word, as `SPELLINGS` is. MATLAB's `Nearest` is deliberately not in it,
because `Nearest` is this mode rather than another one, which the parity suite asserts.

`antecedent` now carries the last spelling unless `OTHER_NAMES` names something after it.
Verification: `grep -c "match_indices('\`')" mock/lints/half_up_is_not_a_magnitude_rule/reading.rs`
returns zero, and `grep -c "OTHER_NAMES" mock/lints/half_up_is_not_a_magnitude_rule/reading.rs` returns
at least three.

## CHANGE: a clause naming no rule is about what the clause before it named
File: `mock/lints/half_up_is_not_a_magnitude_rule/reading.rs`, `clause_hit` and `hits`.

`clause_hit` consulted the carried name only where the clause opened with a pronoun, read off the first
word. That is a second proxy for the same question and it loses every continuation that carries the
reading without a leading pronoun: "`half_up`: a tie goes away from zero.", the same at `;` and `?`,
and "`half_up` is a mode. Ties go away from zero under it."

New `names_nothing`, true of a clause holding neither a spelling of the mode nor an entry of
`OTHER_NAMES`. `clause_hit` gains a branch: a clause that names nothing takes the carried name, falling
back to the doc block's item where nothing is carried. A clause opening with a pronoun keeps the rule it
has, taking the carried name and refusing the fallback, because a pronoun points back explicitly and the
item does not fill in for what the clause before it did not name. A clause naming another rule now takes
neither, where it used to fall through to the subject.

`hits` passes the carry through a clause that names nothing, so anaphora reaches across more than one
sentence: "`half_up` is a mode. It is nearest. Its tie goes away from zero." The blank-line reset is
tested first and is unchanged, so a clause ending in a newline still clears it.

Verification: `cargo test --manifest-path mock/target/mockspace-lints/Cargo.toml half_up` passes, and
the corpus arms below hold.

## CHANGE: the clause-boundary arm states the boundary claim that is true
File: `mock/lints/half_up_is_not_a_magnitude_rule/tests.rs`,
`every_clause_boundary_separates_the_two`.

The arm asserted that for each of eight cuts, "`half_up` goes up{cut}and takes ties away from zero."
stays silent. That sentence says the mode takes ties away from zero and it now fires, which is the
finding rather than a regression: a clause boundary is not what separates a name from a reading.

What replaces it is the claim that holds. For each cut, a later clause naming another rule is not paired
with the earlier one, and a blank line starts afresh. The arm is renamed
`a_clause_boundary_separates_the_two_only_where_the_later_clause_names_another_rule`, and the sentence
it used to assert silence for moves into the corpus as a must-fire.

## CHANGE: arms for the new mechanism, each beside the sentence only it holds
File: `mock/lints/half_up_is_not_a_magnitude_rule/tests.rs`

Three arms. `every_other_name_defeats_the_carry` walks `OTHER_NAMES` whole, planting each after the mode
in one clause and requiring the next clause's pronoun to find nothing, with the control that the same
sentence with no other name fires. `a_name_that_is_not_a_rule_does_not_defeat_the_carry` is the `q/2`
case and the same for a backticked expression. `the_carry_reaches_across_a_clause_that_names_nothing` is
the two-sentence anaphora, with a control that a clause naming another rule stops it.

## CHANGE: the note lint's carve-out is asserted over the real tree
File: `mock/lints/half_up_carries_its_note.rs` module doc, and
`mock/lints/half_up_carries_its_note/tests.rs`

The module doc argues that the documents generated from the registry are excused because none of them
tells a reader what the name means. Nothing measured that. A new arm,
`no_generated_document_states_the_denotation_without_the_note`, reads the real `docs/` tree, finds every
document naming the mode, and asserts that each either carries the note's mark or states no denotation.
Its control plants a document body that states the denotation without the mark and requires it to be
reported, so a green arm is not a fact about an empty walk.

`collect` and `is_crate_source` become `pub(crate)` so the new lint reads the same surface rather than
its own copy of it. Where that walk belongs is a real question the generated lint crate's layout does
not answer: every `mock/lints/*.rs` has to be a lint, so a shared definition of the published surface
has no home except inside one of the lints that reads it. It stays where it is rather than moving to an
equally arbitrary place, and the question is recorded rather than answered here.

## CHANGE: a new lint refuses the project's history in published prose
File: `mock/lints/no_project_history_in_published_prose.rs`, new, with
`mock/lints/no_project_history_in_published_prose/tests.rs`

Reads the same published surface the note lint reads, plus the root `README.md`, for a closed list of
phrases that date a rule or name a past state of this project: `used to`, `formerly`, `previously`,
`before the ruling`, `once recorded`, `an earlier draft`, `an earlier version`, `shipped before`,
`stood before`, `no longer`. Reports each with the line it sits on. Severity HARD_ERROR, as its siblings.

Two carve-outs, each naming the sentence it excuses rather than weakening the phrase list:
`arvo-format/DESIGN.md.tmpl`'s "the one that used to be the join", which names a state of the lattice
rather than of this codebase, and `DESIGN.md.tmpl`'s paragraph about the consumers named in earlier
versions, where the history is the statement and dropping it deletes a correction. A carve-out whose
sentence is no longer in the file is itself a finding, so a carve-out cannot silently widen.

Verification: the lint reports nothing over the tree at this round's head, and both carve-outs are
asserted present with a control that removing one makes its site a finding.

## CHANGE: the reader mutants cover the arms this round adds
File: `mock/research/sketches/the-half-up-lint-reader-mutants/`

The sketch's `reading.mutant.rs.txt` and README are of the reader before this round. Four mutants are
added for what it adds: `backtick` (the defeater counts backticks again), `noother` (`OTHER_NAMES` is
empty, so nothing defeats the carry), `pronounonly` (only a leading pronoun consults the carry), and
`nopass` (a clause naming nothing drops the carry rather than passing it on). Each is run and its
failing test names recorded in `out/runs.txt` beside the control.
