## CHANGE: the refusal's expressibility FROM a property of the tool TO a property of the call site
File: `mock/crates/arvo-format/DESIGN.md.tmpl`
Verification: `grep -c "reports a refused program as compiling"
mock/crates/arvo-format/DESIGN.md.tmpl` returns zero, and the paragraph names the const-bound form
and points at `tests/ui/`. The five `trybuild` cases run and pass, and
`tests/ui/a_law_over_no_magnitudes_is_refused.stderr` carries the `E0080` under `cargo check` that
the old sentence says cannot happen.

The design said an obligation's refusal cannot be a `trybuild` case, on the ground that `trybuild`
runs `cargo check` and a const is evaluated at codegen. **The premise is right and the conclusion does
not follow.** A const is evaluated where it is used, and a `const` item is a use that happens at check
time.

So the corrected paragraph states the axis rather than the verdict. A refusal reached only through a
runtime call needs a doctest, because a doctest builds a binary; a refusal reached through a `const`
binding is visible to `cargo check` and a `trybuild` case pins its diagnostic exactly, which a
`compile_fail` doctest does not. Both ship here and neither is redundant.

**The source is already the corrected version**, on `Quantum::ADMITTED`, on `Slots::ADMITTED` and in
the module documentation of `src/tests/obligations.rs`. What this fixes is the one tier that is
supposed to be their oracle disagreeing with all three.
