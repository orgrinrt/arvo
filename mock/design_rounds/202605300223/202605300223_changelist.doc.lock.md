### Change 1: LinearOperator trait code fence

The fence currently shows a stale `fn dim(&self) -> USize;` that was never implemented in source (pre-existing doc-vs-source drift). Rename it to `live_dim` and make it the required live-node-count method so the documented surface matches the source the src CL lands:

```rust
pub trait LinearOperator<F, const N: Cap>
where
    [(); cap_size(N)]:,
{
    fn apply(&self, x: &[F; cap_size(N)], out: &mut [F; cap_size(N)]);

    // Number of nodes the operator spans: cap_size(N) for a fully
    // packed operator (dense Matrix), the live row count for a
    // loose-CSR SparseLaplacian. Required (no default) so every
    // operator declares it; a default cap_size(N) would silently
    // mispartition a loose consumer that forgot to override.
    fn live_dim(&self) -> USize;
}
```

The required-not-default choice refines an architect review that suggested a `cap_size(N)` default. The default is correct for dense operators but silently wrong for a loose-CSR consumer (the hilavitkutin engine) that neglected the override; requiring the method forces the declaration at compile time, per strict-by-design.

### Change 2: one sentence on loose-CSR awareness

In the operator / spectral-methods prose, add a sentence: the iterative methods iterate over `live_dim()` rather than `cap_size(N)`, so a `SparseLaplacian` over a loose CSR (live rows below capacity) excludes its empty slack rows from the Fiedler iteration and the partition budget. Dense operators inherit the full-capacity default.
