## Summary

`LinearOperator` gains a required `live_dim() -> USize` method. The three operator-driven algorithms iterate `[0, live_dim())` instead of `[0, cap_size(N))`; `spectral_bisection` takes an explicit `live_n`. A loose-CSR `SparseLaplacian` reports `csr.node_count()`, excluding its empty slack rows from the Fiedler iteration and the partition budget. Dense `Matrix` reports `cap_size(N)`, so dense behaviour is unchanged.

## Deviation note (architect review)

An architect review recommended a `cap_size(N)` default body for `live_dim`. This CL makes the method required instead: the default is correct for dense operators but silently wrong for a loose-CSR consumer (the hilavitkutin engine) that forgot to override, and strict-by-design favours forcing the declaration at compile time. The doc surface already carried a (never-implemented) required `dim()`; this round renames it to `live_dim` and implements it.
