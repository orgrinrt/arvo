# Doc changelist: state the div-by-zero contract as it will be

**Date:** 2026-07-29
**Phase:** DOC
**Source topic:** `202607290100_topic.the-round-repeated-its-own-defect.md`
**Status:** living until locked

One design document states the strategy contract that the source states wrongly in two places. The source
comments are corrected in the src changelist; this edit puts the contract in the design first, so the doc
comments have something to be checked against rather than being the only statement of it.

## CHANGE: mock/crates/arvo-strategy/DESIGN.md.tmpl

The strategy-marker section describes what each strategy does at an extreme, and says nothing about a zero
divisor. It gains that, because two source comments currently disagree with each other about it and neither
matches the code.

The contract, stated per strategy rather than as one sentence covering all four. `Hot`, `Warm` and `Cold`
return the numerator unchanged: wrapping arithmetic has no defined answer for division by zero, and
propagating the numerator is the cheapest fallback that does not panic. `Precise` clamps to the logical
bound on the side the quotient is heading toward, which is the maximum for a non-negative numerator and the
minimum for a negative one. A saturating strategy's answer at an extreme is the bound, and which bound
depends on the sign.

Stated in the design because it is a consumer-visible contract that differs across the strategy axis, which
is exactly what the strategy documentation is for, and because it is the half of the contract that was
wrong in the source: the crate said "clamps to max" without qualification, which describes only the
non-negative case.

## Not changed

belongs with the strategies that vary it.
