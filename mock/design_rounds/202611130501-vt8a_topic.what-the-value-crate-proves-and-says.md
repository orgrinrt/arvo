# Topic: what the value crate proves, and what its readmes say

**Date:** 2026-11-13
**Round:** a follow-up to round 202611130342 on branch `work/numeral-integers`, from the first review of
that branch.

## What this round is for

Round 202611130342 shipped `arvo-numeral`. A review of the branch found that the suite proves less than
its design says it does, and that every crate's readme still calls the crate a design without source.
This round closes those gaps. It does not touch the value's doors: whether `raw`, `from_raw` and the
public carrier map are inside `ruling::behaviour_is_stated_per_declared_signature_and_the_premise_dissolves`
is a canon read a second, independent expert is making, and the design's two statements about it (its
canon line on the carrier being observable through nothing the value declares, and its section calling
`raw` the one place a machine integer shows) stay as they are until that read returns. One of the two
changes whichever way it falls, in a round of its own.

## The debug assertion is observed, not inferred

The design said one test per plain marker shows through the verdict that the asserting spelling would
assert, without a `#[should_panic]`. That proves the verdict and not the assertion: deleting the
`assert!` in `add`, `adapted` or `from_raw` left every test green. The panic is the specified behaviour
of the plain markers in a debug build, so a `#[should_panic]` test is the honest observation of it. The
assertion it observes is the one `ruling::the_overflow_panic_is_permitted_and_bounded` permits.

One test per site and per plain marker, six in all, each expecting the site's own message, and one twin
per site under the completing markers taking the same input and completing it. A test that the plain
markers stay quiet on what fits keeps what the two verdict tests showed besides the verdict, and the two
verdict tests go: the exhaustive band already checks `fits_add` against `panic_on_overflow` on every
pair, so they assert nothing the suite does not.

The binary is compiled only under `debug_assertions`, since in a release build there is nothing to
observe.

## A consumer is a crate

The passing `trybuild` case called a consumer was a file compiled inside this crate's test harness, with
whatever features the run had on, and it reached four names. A consumer is a crate of its own, outside
this workspace, depending on `arvo-numeral` with no feature line, and it reaches every public item: each
type and trait, each alias, each associated item of `Sole`, `Carried`, `Machine` and `ValuePolicy`, each
door and operation, the identity, the host doors, and the derived traits. It builds and runs, asserting
what it reads.

A test builds and runs it with `cargo`, into the run's scratch directory inside the shared build
directory, because the run executing the test holds the build directory's lock; this is the place
`trybuild` itself uses. The consumer's lockfile is committed and the build is `--locked --offline`, so it
reads nothing from the network.

## A mutant fails the tests as they stand

Under a rung's mutant feature the tests flipped to expect a mismatch, so a mutant run was green and
proved the tests notice the mutant only through a test written to notice it. The flip goes. The tests
assert agreement with the oracle under every build, so a mutant run is red, and the red output of each
of the four is committed beside the round, trimmed to the binaries, the failing tests and their
messages.

## Widths 9 to 12 are exhaustive

The wider rungs were exhaustive only at widths 1 to 8. Widths 9 to 12 are cheap enough to run every pair
of in each rung wide enough to carry them, both families and both policies, against the oracle; measured
on this branch, about five seconds in the dev profile. That covers the below-carrier-width path of the
16-bit rung exhaustively.

It does not cover the at-carrier-width branch of the 16, 32 and 64-bit rungs, the machine's own wrapping
or saturating add. Width 16 alone is four billion pairs per family and policy. Those branches stay
sampled by the edge lattice and the seeded pairs, and the design says so in those words: exhaustive at
widths 1 to 12, the 8-bit carrier's full width among them, and sampled at 13 to 64, every full-width
branch of the wider carriers among them.

## Bool

`proposal::the_old_facade_returns_as_value_aliases_and_no_facade` lists the boolean among the old
facade's names that return as aliases of the value crate over declared signatures. It stays
`arvo_format::Bool`, re-exported, and the design says why. Every predicate and verdict the format
returns is that `Bool`, including the value's own `eq`, `lt` and `fits_add`, so a second boolean over a
one-bit value would be a second type for one concept and would not be what those return. A one-bit
format's sum is its slots' sum under a policy, which is exclusive or under wrapping and or under
saturation, not the operations a boolean is read through. The proposal is one expert's and not a
ruling, and its intent, that a consumer finds the boolean where it finds the numerals, holds through the
re-export.

## The readmes

All five crate readmes end on a status saying the crate is in design and its source is being built. The
source of each ships, and its tests pass. The status says that instead, and that the surface may change
before a first release, since every crate is at 0.0.0.

Each crate's manifest gains `readme = "README.md.tmpl"`. The template is the crate's own readme, about
that crate alone, written as markdown with no template references, and it is the same field
`mockspace`'s own crates carry.

## The generated documents

`docs/DESIGN.md`, `docs/STRUCTURE.md` and its graph were not regenerated when `arvo-numeral` shipped, and
`docs/NUMERAL.md` was never written. They are regenerated and committed with this round.
