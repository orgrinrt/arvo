## Track 1: Precise saturates at the logical bound

The design decision (see the topic file) is settled: Precise saturates at the LOGICAL range
(`i_MIN..i_MAX` for the logical width N), not the container bound. This is arvo-wide: it affects every
Precise op, not just the multiply.

Steps:

1. In `arith.rs`, the `impl_u_arith_saturating` / `impl_i_arith_saturating` macros implement Precise. Add a
   logical-bound clamp helper, parameterised by the macro's `$bits` (the logical width N), that computes the
   logical MIN/MAX in the container type and clamps a container value into that range. Signed:
   `MAX = (1 << (N-1)) - 1`, `MIN = -(1 << (N-1))`. Unsigned: `MAX = (1 << N) - 1`, `MIN = 0`. It must be
   `const fn`-compatible (the impls are const). The sketch FINDINGS records the exact const-friendly shape.
2. Route every Precise op (`add`, `sub`, `mul`, `div`, `u_mul_fixed` / `i_mul_fixed`) through the clamp:
   compute the (exact, for in-range) container result, then clamp to the logical bound. For the fixed-point
   multiply this composes with Track 2 (compute the wide product, shift, then clamp to logical, then narrow).
3. The existing `saturating_max()` (`USaturating` / `ISaturating`) returns the container MAX; the div-by-zero
   path uses it. Decide per the sketch whether that path should also clamp to the logical max (it should, for
   consistency: a Precise div-by-zero clamps to the logical max, not the container max).
4. Make `i_mul_fixed_precise_should_saturate_to_logical_bound` green and remove its `#[ignore]`. Add a couple
   more Precise saturation asserts (a true add overflow, an unsigned case) so the logical-bound behaviour is
   guarded across ops, not just the one multiply.

## Track 2: the >64-bit-logical widening multiply

The fixed-point multiply needs a 2N-bit intermediate. For logical width <= 64 with a Min container, the
native cast to i128 / u128 holds it (already implemented in `impl_*_arith_wrapping_widen`). Above that
(Hot/Cold logical 65..128, and DoubleLogical Warm/Precise logical 33..64), the product can exceed i128 /
u128 and needs a 256-bit intermediate. `WideBits` is byte-sequence storage with no arithmetic, so the
intermediate is computed with a multi-limb (or intrinsic) multiply; the sketch FINDINGS records the proven
approach (hi/lo limb split, sign handling, shift, narrow).

Steps:

1. Add a widening-multiply helper for u128 / i128 operands producing the shifted, narrowed result, per the
   sketch's working shape. Const-fn-compatible, no_std, no alloc.
2. Extend the widen macros (or add new ones) to cover Hot/Cold logical 65..128 and DoubleLogical 33..64,
   routing `u_mul_fixed` / `i_mul_fixed` through the new helper. The 1..64 Min path is unchanged.
3. Make `i_mul_fixed_widen_above_64_bits_catalogue` green and remove its `#[ignore]`. Add an unsigned
   above-64 case and a Cold case so both signs and both Min strategies are guarded.
4. Track 1 and Track 2 meet for Precise/Warm at logical 33..64: the wide product feeds the logical-bound
   clamp. Make sure a DoubleLogical 33..64 Precise multiply both widens correctly AND clamps to the logical
   bound.

### Track 2 widen: working shape

The 256-bit intermediate is one call to `u128::carrying_mul(b, 0)`, which returns the `(low, high)` u128
limbs of the full 128x128 product. No manual limb splitting. This needs the unstable feature
`#![feature(const_unsigned_bigint_helpers)]` (tracking #152015), which has been vetted ALLOWED and recorded
in the workspace `unstable-features.md` (the method is runtime-stable since 1.91, only const use is gated,
no soundness hole, used internally by core; the std-internal carve-out applies). Add the gate to
`arvo-strategy/src/lib.rs` with a vetting comment mirroring the existing feature gates, and a `// SAFETY`-style
justification at the use site per the carve-out discipline.

```rust
const fn umul256(a: u128, b: u128) -> (u128, u128) { a.carrying_mul(b, 0) } // (lo, hi)

const fn shr256_lo(lo: u128, hi: u128, frac: u32) -> u128 {
    if frac == 0 { lo }
    else if frac < 128 { (lo >> frac) | (hi << (128 - frac)) }
    else if frac == 128 { hi }
    else { hi >> (frac - 128) }
}
// unsigned: u_mul_fixed = shr256_lo(umul256(a, b), FRAC) narrowed to $container.
// signed: multiply magnitudes (a.unsigned_abs()), reapply sign, and CORRECT FOR FLOOR (the trap):
//   neg = (a<0) != (b<0); mag = shr256_lo(umul256(|a|,|b|), FRAC);
//   if dropped-bits-nonzero && neg { -(mag as i128) - 1 } else { +-(mag as i128) }
// "dropped" = any shifted-out low bit set; this matches the arithmetic-shift floor-toward-minus-infinity
// policy the 1..64 widen and the catalogue assertions already use.
```

The signed floor correction is the silent-regression trap: a magnitude/sign multiply without it rounds
negatives toward zero, diverging from the existing `>> FRAC` floor. The sketch's `sketch_a.rs` has the full
correct body and negative-case asserts the catalogue test omits; copy that body and ADD a negative
above-64-bit regression test alongside removing the `#[ignore]`.

### Track 1 Precise clamp: working shape

No widening for Precise per se (it is DoubleLogical, container = 2x logical, holds the in-range product);
the fix is to clamp to the logical bound after the rescale, computing the bound from the const width N.

```rust
const fn i_logical_clamp<const N: u16>(v: $container) -> $container {
    let hi: $container = (1 << (N - 1)) - 1;
    let lo: $container = -(1 << (N - 1));      // unsigned: hi = (1<<N)-1, lo = 0
    if v < lo { lo } else if v > hi { hi } else { v }
}
// fixed-point arm: was `a.saturating_mul(b) >> FRAC` (container-bound). Becomes:
//   i_logical_clamp::<N>(a.wrapping_mul(b) >> FRAC)
// and the same clamp tail wraps add/sub/div results too.
```

Structural note the implementer must handle: `impl_*_arith_saturating!` does NOT currently take the
`$container` type parameter that `impl_*_arith_wrapping_widen!` does. Thread `$container` into the saturating
macros (mirror the widen macros) so the bound literals are typed. The fix is arvo-wide: route every Precise
op (add/sub/mul/div + the fixed-point multiply) through the clamp, and add per-op logical-saturation
regression tests (the catalogue only pins the multiply).
