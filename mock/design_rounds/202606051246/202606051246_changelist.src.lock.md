# Src changelist: graph algorithms generic over row-width

**Date:** 2026-06-05
**Phase:** SRC
**Round:** 202606051246 (graph-algos-generic-width, branch `feat/arvo-graph-generic-width`)

Parameterize every BitMatrix-consuming DAG algorithm in arvo-graph over the
adjacency row-word, lifting the hardcoded 64-node ceiling. `BitMatrix<W, C>`
and `Mask<W>` are already generic over the row-word (arvo-bitmask names that
param `W`); only the algorithm signatures pinned `Bits<64, Hot, Unsigned>`.
Each algorithm gains a row-word type parameter named `B` (distinct from the
edge-weight `W` on the weighted algorithms), bounded on the bit-sequence
traits the bodies already use. Bodies are unchanged: they call
`predecessors` / `successors` / `Mask::empty` / `insert` / `contains` /
`union` / `count` / `iter_set_bits`, all defined generically over the word.

The bounds follow arvo-bitmask's own surface: `Mask<W>` requires
`BitSequence + BitAccess + Copy + Default` to exist; its ops add `BitLogic`;
`Mask::empty()` adds `Identity`; `BitMatrix::predecessors` / `successors`
require `BitSequence + BitAccess + BitLogic + Copy + Default`. So a
matrix-walking algorithm bounds `B: BitSequence + BitAccess + BitLogic +
Copy + Default`, plus `Identity` when it constructs an empty mask.

`BitSequence` / `BitAccess` / `BitLogic` live in `arvo-bits-contracts` and
are not re-exported through the `arvo` facade, so arvo-graph gains a direct
dependency on `arvo-bits-contracts`. The crate's architecture already
sanctions that edge (the `forbidden-imports` allowlist names
arvo-bits-contracts among arvo-graph's permitted deps). `Identity` is
reached through the existing `arvo` facade re-export.

## Test (red first)

`tests/generic_width.rs` builds DAGs at row-words wider than 64 and runs them
through the generalized algorithms. A 100-node chain at
`Bits<128, Hot, Unsigned>` (native 128-bit container) and a 200-node chain at
`Bits<256, Hot, Unsigned>` (wide-bucket WideBits container), each over a
matching `Dim<N>` capacity, exercise `components`, `topo_sort`, and
`waist_detect` at bit positions a `Bits<64>` mask cannot represent. The test
fails to compile against the pinned `Bits<64>` signatures (type mismatch on
the `BitMatrix` word), which is the red; it compiles and the correctness
assertions pass once the algorithms are generic, which is the green. The
existing `Bits<64>` test suite (one valid word) keeps passing unchanged.
