# Doc changelist: the door paragraph says what was settled and stops short of the count

**Date:** 2026-09-01
**Round:** the door question closed, and three tests that cannot fail
**Scope:** `mock/crates/arvo-format/DESIGN.md.tmpl`

Two paragraphs about the numeric introduction door. One states a bound the canon does not carry and
which `ruling::the_numeric_door_carries_the_coordinate_set_and_the_two_type_bound_is_not_canon` names
by path as the design correction owed. The other reports the question as open with four options and
declines to choose, which was right until that ruling closed it and answered none of the four.

## CHANGE: the door's bound FROM two types as the crate's own design TO the coordinate set the ruling names
File: `mock/crates/arvo-format/DESIGN.md.tmpl`
Verification: `grep -n "two types, no arithmetic" mock/crates/arvo-format/DESIGN.md.tmpl` returns
nothing, and the paragraph states the bound as the coordinate set of the ratified parameterisation.

The design said the door was meant to be kept narrow at two types. That bound "is a sentence in the
crate's design and appears nowhere in the canon", in the ruling's own words, so it goes rather than
being qualified. What the door carries out is the coordinate set of the ratified parameterisation,
spelled in types the stack owns, which is what both derivations reached.

**The observation the old paragraph carried survives and is now the point rather than the complaint.**
The coordinates do not go through `Width` and `Bool` and were never going to: an outside format
reusing every shipped part still had to write two host integers, and three of the ten constants carry
values a count of bits over `u32` cannot hold at all, which is why the first recorded option was
arithmetically impossible rather than merely costly.

## CHANGE: the open question FROM open with four options TO closed, with the count still open
File: `mock/crates/arvo-format/DESIGN.md.tmpl`
Verification: `grep -n "four options recorded against it"
mock/crates/arvo-format/DESIGN.md.tmpl` returns nothing, and the paragraph names the ruling and says
which part of it is not settled.

The paragraph reported the question as the panel's to decide and declined among the four. It names
what was ratified instead, and **says plainly that how many types that is stays open**, because the
two derivations disagree and two instances establish their intersection rather than their union.

**The design says what the crate holds without claiming the count is the answer.** One per coordinate
is one of the two live readings and it is what ships; saying so is a different act from settling it,
and the implementing round inherits the count as a live question rather than as a free choice. The
one-expert proposal to replace the count with a rule about positions is named as one instance and open
rather than adopted, because a design adopting a one-expert proposal is deciding a canon question in
the tier below where it belongs.

## CHANGE: the law list FROM silent on the tautology class TO naming what a coordinate test has to do
File: `mock/crates/arvo-format/DESIGN.md.tmpl`
Verification: the laws section says that a test over a declaration reaches something the code does
rather than a second declaration.

Two of this crate's tests asserted a constant against the literal its own definition sets, in a file
that condemns the class six lines below where it does it, so the class is worth a sentence in the
laws the crate owes tests for rather than a comment in one of them. A test over a declaration reaches,
through however many hops, a value some function returns or a construction that could have been
declared otherwise; a law relating two declarations to each other constrains neither.
