# Src changelist: say when the ordering ranked nothing

**Date:** 2026-09-01
**Round:** the ordering that ranked nothing
**Scope:** `mock/tools/awaiting-a-ruling/src/lib.rs` and its tests.

## CHANGE: the closing sentence FROM one wording TO one conditional on whether the sort ranked
File: `mock/tools/awaiting-a-ruling/src/lib.rs`
Verification: three test arms, one per case, each asserting the sentence the other two must not carry.

The report closes on "Ordering is by what cites a row, which is a suggestion and not a ranking",
printed identically whether the counts differ or not. On the corpus as it stands they do not differ:
56 of 58 rows carry no citation at all, so the sort falls through to the slug tiebreak and the list is
alphabetical.

Established against the registry rather than through the tool, which cannot be its own control:

```
the_next_unit_is_chosen_bottom_up                         ruling.toml:1
a_predicate_lists_only_what_holds                         ruling.toml:1
precise_is_accurate_across_chains_not_only_per_operation   ruling.toml:1
```

One occurrence apiece, each of them the row's own definition line.

The sort ranks only when at least two rows differ in the count, so that is the condition the sentence
is now written against. Where they differ it reads as before. Where they do not, it says the ordering
produced no ranking on this run and the list is alphabetical, which is the fact a reader otherwise has
to work out by noticing every parenthetical is missing.

**Three cases and three arms, because the middle one is the one that gets missed.** Counts that
differ, counts that are all zero, and counts that are all equal and non-zero. The third ranks nothing
for the same reason the second does, and an implementation testing `all counts are zero` passes the
first two and fails it.

## CHANGE: nothing about what the sort measures
File: none

The sort still counts citations, and whether it should instead rank a `stated` row by the layer it
sits under is filed in the topic as out of scope. This round makes the existing ordering honest about
itself; it does not replace it.
