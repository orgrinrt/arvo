# Src changelist: say how far the ordering actually reached

**Date:** 2026-09-01
**Round:** the ordering that ranked nothing
**Scope:** `mock/tools/awaiting-a-ruling/src/lib.rs` and its tests.

## CHANGE: the closing sentence FROM one wording TO one carrying how far the sort got
File: `mock/tools/awaiting-a-ruling/src/lib.rs`
Verification: six test arms, one per case, each asserting the wording the others must not carry, plus
the tool run against the registry.

The report closes on "Ordering is by what cites a row, which is a suggestion and not a ranking",
printed identically whatever the counts are. The sort is by count and then by slug, so every row sharing
the lowest count sits in a block the ordering said nothing about, and a reader cannot see that block,
because a ranked list and an alphabetical one look the same.

On the registry as it stands the block is nearly the whole list. 58 rows come back, one carries two
citations and one carries one, and the other 56 carry none. Established against the registry rather
than through the tool, which cannot be its own control:

```
the_next_unit_is_chosen_bottom_up                         ruling.toml:1
a_predicate_lists_only_what_holds                         ruling.toml:1
precise_is_accurate_across_chains_not_only_per_operation   ruling.toml:1
```

One occurrence apiece, each of them the row's own definition line.

**The first version of this changelist said the counts do not differ at all, and that was wrong.** Two
of them do, so the corpus is the partial case rather than the degenerate one, and a binary
ranked-or-not flag would have printed the unchanged wording on the exact run that motivated the round.
Caught by running the tool against the registry after the tests were green, which is the only step that
could have caught it: every planted arm passed.

So the report now names the count. Where the ordering separated some rows it says how many of how many,
and how many share the lowest count and stand in slug order. Where no two rows differ it says the
ordering ranked nothing and the list is alphabetical.

**Six arms, because three of them are cases a plausible implementation gets wrong.** Counts that differ
throughout. Counts that are all zero. Counts that are all equal and non-zero, which an implementation
testing `every count is zero` passes the first two and fails. A single row, which is no pair and so was
never ordered. A partial ordering, pinning the reached count. And a partial ordering whose lowest count
is one rather than zero, which an implementation counting `the rows nobody cites` gets wrong while
every other arm still passes.

## CHANGE: nothing about what the sort measures
File: none

The sort still counts citations, and whether it should instead rank a `stated` row by the layer it sits
under is filed in the topic as out of scope. This round makes the existing ordering honest about how far
it reached; it does not replace it.
