# every-function-the-format-ships-is-inline

**Date:** 2026-11-13
**Round:** `202611132043-aun1`, job `arvo-format`, job 3 of track T2 of the arvo triage.
**Ticket:** `arvo_format_mark_the_const_accessors_inline_so_consumers_fol`.

## What is wrong

No function in `arvo-format` carries `#[inline]`: 209 `const fn` and two trait methods outside the test
modules, none marked. A function that is not generic is compiled once, in this crate, and a consumer
built without link-time optimisation calls it out of line, because its body is not offered across the
crate boundary. The first release disassembly of `arvo-numeral`'s `add`
(`mock/research/sketches/202611130342_value-add-disassembly/outputs/asm-release-x86_64-width-read-at-run-time.txt`
on `work/numeral-integers`) carried 24 calls through the global offset table to `Width::count`,
`Bool::get` and their kind across six probes. `arvo-numeral` now reads them inside inline const blocks,
so its own sum folds, and every other consumer reading them on a runtime path pays the call.

`ruling::never_a_runtime_check_and_one_lowered_path` asks that branching be erased by monomorphisation,
const solving "and ultimately the backend", with unused paths cleared when lowered. The backend can only
clear what it can see, and a call it cannot inline is a wall in the consumer's lowered path.

## Which functions

The ticket names the one-line accessors. The same wall stands at every non-generic function, and it is
not only the public ones: a crate-private helper called from a generic public function is instantiated
in the consumer and calls the helper across the boundary just the same. A generic function is
instantiated where it is used and is offered already, and the attribute costs it nothing. So the line
that has no exceptions to argue over is every function with a body in the crate's shipped source, and a
test-only one is left alone because it ships nowhere. The cost is compile time in the consumer, which
`arvo-compile-time-last` puts last.

## A lint, not a sweep

A sweep alone holds until the next function is added. The check is mechanical, so it is a crate lint in
`mock/lints/`: every `fn` with a body in `arvo-format`, outside the test modules and outside an item
under `#[cfg(test)]`, carries `#[inline]` or `#[inline(always)]`, and `#[inline(never)]` is a finding.
The platform-width lint already carries the comment and literal blanking such a lint reads through, so
that function moves to a module of its own both lints read, rather than being copied.

The other four crates carry the same gap (`arvo-numeral` 33 const functions with 11 marked,
`arvo-placement` 7, `arvo-bits` 4, `arvo-strategy` 1, none marked). They are other lanes' crates, so the
lint covers `arvo-format` here and a ticket carries widening it to them.
