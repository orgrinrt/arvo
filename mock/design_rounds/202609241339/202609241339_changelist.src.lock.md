## CHANGE: `symmetry.rs` splits its coordinate out from its predicates
File: `mock/crates/arvo-format/src/symmetry.rs`, new `mock/crates/arvo-format/src/symmetry/reach.rs`.

`symmetry.rs` was 505 lines, over the `file-size` lint's threshold, and read as two things that do not
need each other to be read: the private `Residues` enum, the `Reach` struct with its full impl (every
exact position and translation an operation reaches), and the private `ordered` fn, beside `Reads`,
`When`, `Behaviour`, `behaviour_of` and the six equivariance predicates (`rounding_is_translation_equivariant`
and its five siblings) that consult `Reach` as a coordinate but never reach into its internals.

`Residues`, `Reach`, `ordered` and their imports (`crate::slots::Slot`, `crate::width::Bool`) move
verbatim into the new `symmetry/reach.rs` (251 lines). `symmetry.rs` (274 lines) keeps everything else,
gains `mod reach; pub use reach::Reach;`, and drops `Slot` from its own `use crate::slots::{Slot, Slots}`
since only `Slots` is still used there. `crate::symmetry::Reach` resolves exactly as before; nothing
outside this crate names `symmetry::reach` and nothing has to.

Verification: `cargo build -p arvo-format` and `cargo test -p arvo-format` are clean, no new warnings.
`wc -l mock/crates/arvo-format/src/symmetry.rs mock/crates/arvo-format/src/symmetry/reach.rs` shows both
under 500.

## CHANGE: `the_verdict.rs` splits into a directory module along its own section headers
File: `mock/crates/arvo-format/src/addition/tests/the_verdict.rs`, replaced by
`mock/crates/arvo-format/src/addition/tests/the_verdict/{mod,counts,brute_force,width_walk,negative_controls}.rs`.

`the_verdict.rs` was 515 lines, a test module for `addition::add` carrying four sections already marked
by their own comment headers: the counts the canon records reproduced at every scale, the verdict checked
against brute force over small licensed windows, the verdict walked over the whole admitted width range,
and two negative controls. None reads another's internals; all four use the parent module's shared
`Table`, `Window`, `DITHERS`, `phases`, `signatures`, `boundary_members`, `pair_for_sum` and
`NearTheTop`, and the two type aliases `Sat<F>`/`Wr<F>` the flat file declared once at its top.

`the_verdict/mod.rs` (43 lines) keeps the module doc, the two type aliases, and declares the four
submodules. `the_verdict/counts.rs` (117 lines), `the_verdict/brute_force.rs` (205 lines),
`the_verdict/width_walk.rs` (171 lines) and `the_verdict/negative_controls.rs` (57 lines) each carry one
section verbatim, importing `Sat`/`Wr` via `super::{Sat, Wr}` and the parent test module's shared items
via `super::super::{...}`. `every_window!`, defined in `brute_force.rs`, still invokes the parent test
module's `every_phase!` macro by its textual def-site scope, unaffected by which file the invoking macro
sits in.

Two unused imports the flat file's grouping had hidden came out during the split: `crate::apply::Dither`
in `brute_force.rs` and `Window` in `width_walk.rs`, neither of which that section's code used.

Verification: `cargo test -p arvo-format the_verdict` selects the same 8 tests before and after, all
passing, zero warnings. `find mock/crates/arvo-format/src -name "*.rs" | xargs wc -l | sort -n | tail -5`
shows nothing over 500 lines in the crate after this round.
