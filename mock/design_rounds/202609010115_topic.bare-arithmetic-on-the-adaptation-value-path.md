# Topic: bare arithmetic on the adaptation's value path, and what a public const fn owes

**Date:** 2026-09-01
**Phase:** TOPIC
**Status:** filed deliberately without doing it, because it needs its own doc changelist

Placed out of scope by round `202609010001`, whose locked doc changelist covers the slot contract and
not the adaptation map. Filed rather than named and forgotten.

## The sites

`mock/crates/arvo-format/src/apply.rs` has three bare arithmetic sites on the value path of
`pub const fn` bodies: `exact.slot + 1`, `exact.num * 2`, and `let span = max - min + 1` inside
`complete_slot`. Across the shipped source the only `checked_`, `wrapping_` or `saturating_`
occurrence is one in `apply/tests.rs`.

## Why it matters, measured on the neighbouring surface

The same shape was measured on `slot_count` during round `202609010001`, on a real consumer crate:

```
overflow-checks = true   ->  builds, then panics at runtime: attempt to add with overflow
overflow-checks = false  ->  builds, returns the wrapped value
```

**Both are wrong and in opposite directions.** A runtime panic is a runtime check, which
`ruling::never_a_runtime_check_and_one_lowered_path` forbids outright. The wrapped value is the silent
wrong answer this arc has spent three rounds closing.

That is arm C of the panel's binding-time material at
`mock/research/202608072330_the-numeral-canon-panel/230_probes/p1_binding_time/`: arithmetic inside a
`const fn` body called from a const context is refused only when `overflow-checks` is on.
Reproduced independently in this tree: `const fn add(a: u8, b: u8) -> u8 { a + b }` at `200 + 100`
refuses at `overflow-checks = true` and yields `44` at `false`.

## What the round has to decide, and why it is not a source edit

**`complete_slot` is `pub` and takes `min` and `max` as plain `i64` parameters.** So it is reachable
with values no contract bounded, which is the same question `checked_width` raised two rounds ago:
what a public const fn owes when its arguments are not typed to the thing they describe.

Three shapes are available and choosing between them is a design call:

The parameters stop being raw and carry the contract that already bounds them, so the caller cannot
supply values the obligation has not admitted.

The function stops being public, so the only reachable caller is `adapt`, which reads an admitted
range.

The arithmetic is done in a width the operands cannot overflow, or through an inspected `checked_`
result, which is arm E's shape and refuses in all four cells of the flag matrix.

**The first two are the ones that remove the question rather than answer it**, and they change the
crate's surface, which is why this needs a doc changelist rather than an edit.

## What is not in question

That the reachable path is currently safe. `adapt` only calls `complete_slot` with bounds from an
admitted `Slots`, and after round `202609010001` an admitted range's span fits a count. **The finding
is about the public surface and about the class, not about a live miscomputation**, and saying so is
the difference between this filing and an alarm.

## A dimension row this bears on

`dimension::build_profile`'s grammar names `debug-assertions` and opt level and does not name
`overflow-checks`, which is the flag arm C shows is the one that acts. A predicate written over the
build profile cannot currently say which of the two it holds under. That is a registry finding rather
than a source one and belongs to whoever next touches the axis.
