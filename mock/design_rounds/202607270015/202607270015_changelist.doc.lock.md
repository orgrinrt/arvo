# Doc changelist: an identity belongs to an operation

**Date:** 2026-07-27
**Phase:** DOC
**Source topic:** `202607262330_topic.identity-per-operation.md`
**Status:** living until locked

Rewrites the canonical typed-const surface so that an identity is stated with respect to an operation, and
records why the multiplicative one is absent on purely fractional types rather than present and wrong.

## Comparison to deprecated changelist

Supersedes `202607262215_changelist.doc.deprecated.md`, which documented the same defect and a different
fix.

### CHANGE: mock/crates/arvo/DESIGN.md.tmpl

The deprecated changelist added two sections here, `Identity requires at least one integer bit` and
`Requires and Satisfied`, and both are removed rather than amended.

Its mechanism was a `Requires<const COND: bool>` witness with a `Satisfied` marker, added to arvo as a new
public primitive, carrying the bound `Requires<{ I.raw() >= 1 }>: Satisfied`. That stated a numeric fact
about a type parameter where the property is representability, and it invented a mechanism the crate
already had: `arvo-strategy` carries a sealed projection table whose missing impl is a refusal with a
`#[diagnostic::on_unimplemented]` note, and whose tag comes from a const fn compressing a large const space
into a small enumerated one. `Requires` and `Satisfied` are therefore not documented, not added, and not
mentioned again.

Its trait shape also removed the whole of `Identity` at zero integer bits, which takes `ZERO` down with
`ONE`. Only `ONE` is unrepresentable there; zero is representable at every width, so the additive identity
was correct and was being discarded for the multiplicative one's sake. `Identity<Op>` separates them, and
neither name survives as a constant: both become `IDENTITY` under their own operation.

Its measured table is kept and extended. The four constants it reported are the same four, across `Hot` and
`Precise` on both signednesses, and they are restated with the effect each has on `x * ONE` rather than only
the raw each held.

### CHANGE: mock/crates/arvo-strategy/DESIGN.md.tmpl

The deprecated changelist added two paragraphs here, on `Hot` and `Cold` wrapping at the container width
rather than the logical width, and on the signed multiply returning the container minimum directly. Both are
correct, both describe behaviour this round does not change, and both are left exactly as written. This
round edits a different part of the same document, the canonical typed-const surface, and the two do not
overlap. The deprecated changelist is superseded on the `Identity` question alone.

### Not changed

The deprecated changelist's own not-changed list stands unaltered, and this round adds nothing to it and
removes nothing from it. `mock/crates/arvo/README.md.tmpl`, `mock/DESIGN.md.tmpl`, `mock/PRINCIPLES.md.tmpl`
and the repo-root `README.md` are still out of scope for the same reasons it gave, and the bit-matrix
axis-naming question is still deliberately absent.

## CHANGE: mock/crates/arvo-strategy/DESIGN.md.tmpl

The canonical typed-const section (`Bounded`, `Identity`, `SignedIdentity`) is rewritten around the
operation parameter.

**The declaration.** `Identity<Op>` carries one associated constant, `IDENTITY`, and the operation markers
`Additive` and `Multiplicative` are ZSTs alongside it. The document states why the parameter is the right
axis rather than a pair of constants: an identity is only ever an identity with respect to an operation, so
`ZERO` and `ONE` were two instances of one concept named after their values. The parameterised form
generalises to `Identity<Min>`, `Identity<Max>`, `Identity<BitOr>` by declaration rather than by bolting on
a third and fourth constant, and it lets a type carry one identity and not another, which is exactly the
case that was broken.

**What absence means.** A missing `Identity<Multiplicative>` impl is a statement that the type has no
multiplicative identity, and naming `IDENTITY` for it fails to resolve. This is stated as the trait's
contract, not as a fixed-point quirk, because the general law is that an identity element must be a value
of the type it is an identity for.

**Representability, and where it comes from.** A new subsection records why the condition cannot come from
the operation contracts, since the reasoning is not obvious and a later reader will otherwise re-propose
them. `UFixed<0, F>` genuinely has multiplication: `[0, 1)` is closed under it, so `Mul` is correctly
implemented for exactly the type that must be refused, and any bound of the form "this type can multiply"
admits it. `UArith<N>` and `IArith<N>` do not help either, being implemented on strategies and keyed on
container width: they say a strategy can multiply 14-bit values, and say nothing about whether a value type
contains a one. Multiplication and its identity are independent facts here.

The condition is carried instead by a sealed tag projection in the same shape as `Project` / `Picker`: a
const fn compresses the `(I, F)` space into the two-element space "one is representable" and "one is not",
and the sealed marker is implemented over the first tag only. The section names the seal, so that a reader
knows downstream cannot add the missing impl, and names the diagnostic attribute as where the explanation
lives.

**`SignedIdentity` keeps its own paragraph and gains a sentence.** `NEG_ONE` is not an identity of any
operation, so it does not fold into `Identity<Op>` and stays as it is. The added sentence says the
representability condition is deliberately not copied onto it: a signed purely fractional type spans
`[-1, 1)`, so minus one is representable there, as the container minimum, while one is not. The asymmetry
is real rather than an oversight, and stating it stops the next reader from "fixing" the inconsistency.

## CHANGE: mock/crates/arvo/DESIGN.md.tmpl

Three edits, one of them a correction to a claim that was already wrong.

**The const arithmetic surface is corrected.** The current text shows `UFixed` and `IFixed` carrying
inherent `ZERO`, `ONE` and `MINUS_ONE` constants. Source carries none: they are trait impls, and
`arvo-strategy`'s own document says in as many words that inherent re-definitions of trait constants are
deliberately not maintained. The two documents contradict each other and the source agrees with the other
one. The block is rewritten to show the trait impls that exist. This is a doc-vs-source drift the round
walks into rather than one it creates, and it is corrected here because the round is rewriting this exact
paragraph.

**The two sections the deprecated CL added are replaced.** `### Identity requires at least one integer bit`
and `### Requires and Satisfied` are removed and one section takes their place. It states which impls each
type has: `UFixed<I, F, S>` has `Identity<Additive>` at every width and `Identity<Multiplicative>` only when
one is representable, and the same for `IFixed`. It gives the four measured constants from the topic as the
evidence, because a reader deciding whether to trust the constraint wants the failure it prevents, and it
names the arithmetic that produced them: the raw encoding of one is `1 << F` in a container of `I + F` bits,
so at `I == 0` the encoding does not fit. The wrapping strategies wrapped it to zero and to the container
minimum, the saturating one clamped it just below one, and the saturating case is called out as the worse
of the two, since it returns a plausible number and compounds quietly rather than announcing itself.

**The float surface is updated to match.** `FastFloat<F>` and `StrictFloat<F>` blanket through the inner
`Ieee` type's identity, and the `Ieee` supertrait bound names `Identity`. Both are restated in the
parameterised form. Floats have both identities at every width, so nothing about their behaviour changes;
only the spelling does.

## CHANGE: the five design documents that spell `Identity` in a bound or a call

Files: `mock/crates/arvo-storage/DESIGN.md.tmpl`, `mock/crates/arvo-bitmask/DESIGN.md.tmpl`,
`mock/crates/arvo-mask-contracts/DESIGN.md.tmpl`, `mock/crates/arvo-bits-contracts/DESIGN.md.tmpl`,
`mock/crates/arvo-graph/DESIGN.md.tmpl`

Each names `Identity` in a trait bound, a where clause, or a constant reference, and each is respelled for
the parameterised trait. `USize` and `Cap` carry both identities, so their bounds name both; `Mask<W>`,
the mask contracts and the graph row-word bound need only the additive one, since `empty()` is the additive
identity of the word and nothing in those bodies multiplies.

This is a mechanical respelling and no contract moves. It is listed because leaving five documents spelling
a trait that no longer has that shape is the doc-vs-source drift the round exists to remove, and because
the next reader would reasonably take the old spelling as current.

`mock/crates/arvo-strategy/BACKLOG.md.tmpl` mentions the old spelling in a historical note about work that
has since landed. Backlog entries record what was decided at the time, so it is left as written.

## CHANGE: mock/agent/rules/cargo.md.tmpl

The build-script section is replaced. It instructs every arvo crate to carry a one-line `build.rs` calling
`mockspace::bootstrap::bootstrap_from_buildscript()` and a matching `[build-dependencies] mockspace` entry.
That was the bootstrap shape at the time it was written and it is no longer how the tooling installs: the
`cargo mock` launcher is installed once per machine, reads `mockspace.toml` at the repo root, and resolves
its own engine pin from the `mockspace_branch` there.

The rule now says arvo crates depend on mockspace nowhere and run no build script for it, and gives the
reason, because the reason is a release constraint rather than a preference. A build script pulling the
design tooling in makes every consumer of arvo fetch it at their build time for a tool that does nothing
there, and blocks publishing outright, since a registry refuses a crate whose dependency resolves to a git
source. Confirmed rather than assumed: `cargo package -p arvo` failed on the mockspace git build-dependency
before the entries came out and reaches the ordinary path-dependency-needs-a-version stage after.

The one build script that stays is `mock/crates/arvo/build.rs`, which declares the `arvo_fast_math` cfg that
hilavitkutin-build's FastMath pragma sets so rustc does not warn on `#[cfg(arvo_fast_math)]`. It has nothing
to do with the design tooling, and the rule says so, so the next reader does not delete it as a leftover.

The manifest and build-script edits this describes are source work and land in the src changelist. The rule
template is the design statement and lands here.

## CHANGE: the mockspace config moves to the repo root

`mock/mockspace.toml` becomes `mockspace.toml` at the root, gaining `mock_dir = "mock"` to map it to the
workspace it governs. A repo has exactly one of these and the root is where it belongs, which is where the
launcher looks for a relocated repo and where the workspace repos already on this shape keep it. The engine
reads either location, preferring the in-place one.

The move is part of the migration and lands with it in the src changelist, not on its own. Attempting it
separately showed why: the legacy build script regenerates `.cargo/config.toml` from the in-mock config, and
with the config relocated it wrote an alias with an empty `--dir`, so `cargo mock` stopped resolving a mock
directory at all. The relocation, the alias removal and the build-script removal are one change.
