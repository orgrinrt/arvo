# Topic: rename `arvo-narrow` to `arvo-refit`

**Date:** 2026-04-30
**Phase:** TOPIC
**Scope:** Rename the `arvo-narrow` crate (and its doc references) to
`arvo-refit`, the domain-name covering both narrow and widen.
**Source topics:** Decision D from round 202604300826 topic file.
**Tasks:** #290 (parent).

## Why

Round 202604300826 added `Widen<T>` and the cross-domain primitive↔Bits
direct impls to the bit-width refit family. The crate hosting the
re-export gateway was named `arvo-narrow` because at the time only
`Narrow<T>` lived in the surface. Post-202604300826 the crate carries
both `Narrow<T>` and `Widen<T>` (plus their `Narrowed` / `Widened`
cosmetic aliases) and re-exports the `BitsRefitCtor` ergonomic
constructors implicitly through `arvo-bits` consumers.

The crate name `arvo-narrow` undersells the surface and lies about
what the gateway covers. The right name is `arvo-refit`, the domain
the trait family operates on. Decision D in the prior round
(202604300826) selected this name explicitly: "arvo-narrow gets
renamed to something that contains both widen and narrow,
thematically they are same domain, just rename to that domain, so we
drop the single-export crate and better yet, don't add another of
those, instead we make one that exports the two things instead."

The rename was deferred to a follow-up round during 202604300826
because the prior round was already churning the trait surface, the
src changelist, and the cross-domain impl matrix. Splitting the
rename into its own round keeps each round single-purpose and keeps
the mechanical refactor reviewable on its own.

## Decisions

### A. Crate name: `arvo-refit`

Selected via AskUserQuestion in round 202604300826 conversation. The
verb "refit" reads naturally over both directions:

- `narrow_to::<N>()` is a refit downward (drop high bits to fit a
  narrower carrier).
- `widen_to()` is a refit upward (extend zero or sign to fit a wider
  carrier).

Both are bit-width refits in the same domain. `arvo-refit` names the
domain; `Narrow<T>` and `Widen<T>` are the directions. Consumer code
reads `use arvo_refit::{Narrow, Widen, Narrowed, Widened};`.

The trait verbs (`Narrow` / `narrow_to`, `Widen` / `widen_to`) stay
unchanged. They name the directions. The crate name `arvo-refit`
names the family that owns both.

### B. Scope: crate rename plus doc/config references

The rename is a mechanical refactor. In scope:

- Rename `mock/crates/arvo-narrow/` directory to
  `mock/crates/arvo-refit/`.
- Update `mock/crates/arvo-refit/Cargo.toml`: `name = "arvo-refit"`.
- Update the crate's own `README.md.tmpl` / `DESIGN.md.tmpl` /
  `BACKLOG.md.tmpl` headings + body to use the new name.
- Update the crate's `src/lib.rs` module-level doc-comment to use the
  new name.
- Update workspace `Cargo.toml`: `members = ["crates/arvo-refit", ...]`
  and `[workspace.dependencies] arvo-refit = { path = "crates/arvo-refit" }`.
- Update `mock/mockspace.toml`: `[lints.forbidden-imports]` scope +
  forbidden-list entries that reference `arvo_narrow::*` flip to
  `arvo_refit::*`. Crate-name renames in scope/forbidden/reason
  fields are explicitly permitted by `.claude/rules/mockspace-toml-edits.md`
  and by the lint-severity-reminder hook. No gate-severity changes.
- Update doc templates that name `arvo-narrow` as a live crate:
  - `mock/PRINCIPLES.md.tmpl`
  - `mock/DESIGN.md.tmpl`
  - `mock/agent/MAIN.md.tmpl`
  - `mock/crates/arvo-bits-contracts/DESIGN.md.tmpl`
  - `mock/crates/arvo-bits/DESIGN.md.tmpl`
  - `mock/crates/arvo-storage/DESIGN.md.tmpl`
  - `mock/crates/arvo/DESIGN.md.tmpl`
  - `mock/crates/arvo/BACKLOG.md.tmpl`
- Update doc-comment references in `arvo-bits-contracts/src/lib.rs`
  that name `arvo-narrow` as the cross-primitive impl host.

### C. Historical references kept

Two classes of mention stay as-is:

1. **Round artefacts under `mock/design_rounds/`**: archived rounds
   are immutable history. References to `arvo-narrow` in them remain
   accurate as the name at that round's close.
2. **Historical context in current docs**: passages naming
   `arvo-narrow-contracts` (the L0.5 trait crate that merged into
   `arvo-bits-contracts` in round 202604280034) stay. That crate name
   is genuinely historical, not a current crate. Passages explicitly
   noting "renamed from `arvo-narrow` in round 202604301700" are
   added where it helps a reader correlate the current name with
   prior round artefacts.

### D. No source-symbol renames

The trait names (`Narrow`, `Widen`, `Narrowed`, `Widened`,
`BitsRefitCtor`) and method names (`narrow_to`, `narrow_to_unmasked`,
`widen_to`, `widen_to_unmasked`, `from_narrowed`, `from_widened`)
do not change. Only the crate name flips.

The arvo facade re-export already routes through `arvo-bits`
(`pub use arvo_bits::{Narrow, Narrowed, Widen, Widened, BitsRefitCtor};`).
That continues unchanged. Consumers that import directly from the
gateway crate flip their `use arvo_narrow::...` to
`use arvo_refit::...`.

  202604300826 decision A; not revisited.
