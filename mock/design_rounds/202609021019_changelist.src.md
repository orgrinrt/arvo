# Source changelist: the ratio constructor, its reader's carrier, and the sweep that hid both

**Date:** 2026-09-02
**Round:** the ratio coordinate saturates its magnitude instead of dropping it
**Scope:** `mock/crates/arvo-format/src/apply.rs`, `mock/crates/arvo-format/src/apply/tests.rs`

## CHANGE: `Fraction::of` FROM a denominator of one on two families TO exact normalisation with magnitude saturation

File: `mock/crates/arvo-format/src/apply.rs`
Verification: `grep -c 'trailing_zeros' mock/crates/arvo-format/src/apply.rs` returns one, and `grep -c 'den: 1 }' mock/crates/arvo-format/src/apply.rs` no longer counts the fallthrough branch. `cargo test -p arvo-format` is green with the new arms below.

The design states the two regions and the four properties. The rule that realises them:

```
den > 0                      -> (num, den)
den == 0                     -> ZERO
num != MIN and den != MIN    -> (-num, -den)
num == 0                     -> ZERO
num == MIN and den == MIN    -> (1, 1)
k = trailing_zeros of whichever operand is not MIN
k > 0                        -> (-(num >> k), -(den >> k))
den == MIN                   -> (-num, MAX)
otherwise                    -> (MAX, -den)
```

Every branch is const and folds where the pair is written. The first is unchanged, so nothing that
reaches the constructor with a positive denominator pays for any of this. No refusal, no panic, no
verdict, and one lowered path per const-known pair.

`k` cannot reach 63: the operand it is taken from is neither zero nor `i64::MIN`, both of which the
branches above have already answered, so its magnitude is at most `2^63 - 1` and it carries at most
62 factors of two. The shift is therefore an exact division on both operands, and the negation that
follows has room because the reduced magnitude is at most `2^62`.

The rustdoc goes with it. What it says now is false: it justifies the branch by saying the exact form
is not representable on those pairs, and on the larger part of them it is.

## CHANGE: `Exact::is_tie` FROM an `i64` doubling TO the carrier `round_slot` already uses

File: `mock/crates/arvo-format/src/apply.rs`
Verification: `grep -c 'self.part.num \* 2 == self.part.den' mock/crates/arvo-format/src/apply.rs` returns zero, and the arm named below fails on the old form.

`self.part.num * 2 == self.part.den`, where the stored remainder can be one below the denominator, so
the doubling leaves `i64` on any remainder above `i64::MAX / 2`. In a debug build that is an overflow
panic inside a function whose contract is to return a verdict, in a crate whose design says it stays
total so the panic belongs to the caller. `round_slot` makes the identical comparison four lines away
in `i128`, so this is one carrier disagreeing with its neighbour rather than a question.

The release build reaches the right answer by accident: a wrapped doubling is negative and cannot
equal a positive denominator, and the case where the answer is actually a tie is `2 * num == den`,
which is below `i64::MAX` and never wraps. That is why no arm caught it, and it is not a reason to
leave it.

## CHANGE: `a_fraction_never_carries_a_denominator_that_cannot_divide` FROM a value assertion gated off the failing region TO the four properties over both parities

File: `mock/crates/arvo-format/src/apply/tests.rs`
Verification: the guard `if den < 0 && den != i64::MIN && num != i64::MIN` is gone, and the arm asserts an exact answer against a cross-multiplied oracle on every pair its matrix reaches.

The existing arm sweeps nine denominators against seven numerators and then asserts the value only
under a guard that excludes both `i64::MIN` families. Its own comment gives the reason, which is the
claim under test: those pairs are lossy, so the value is not checked there.

`of(i64::MIN, -8)` is in that sweep. It is exactly `2^60` over one, the constructor answers `i64::MIN`
over one, and the guard is what stops the arm from looking. **The matrix already contained the input
that refutes the rule and the assertion was switched off exactly over it.**

What replaces it asserts, on every pair:

- the denominator is positive;
- the sign of the answer is the sign of the named ratio;
- the answer is exact, cross-multiplied in `i128`, wherever the coordinate admits an exact form;
- where it does not, the relative error is at most `1 / i64::MAX`, also cross-multiplied.

The matrix carries both parities on both axes, because parity is what decides whether an exact form
exists and the old one had a single even negative denominator in it by accident.

## CHANGE: three arms added for what the old behaviour was pinned at

File: `mock/crates/arvo-format/src/apply/tests.rs`
Verification: `cargo test -p arvo-format` names each of them.

`the_two_pairs_the_old_rule_named_now_keep_their_sign` pins `of(3, i64::MIN)` and `of(i64::MIN, -7)`,
which the previous arm pinned at `3/1` and `i64::MIN/1`. Both are in the saturating region and both
now carry the sign of the ratio that was named.

`a_shared_factor_of_two_cancels_rather_than_saturating` pins the pairs the old rule was losing outright:
`of(i64::MIN, -2)`, `of(i64::MIN, -8)`, `of(4, i64::MIN)`, `of(i64::MIN, i64::MIN)`. Each is exact, and
each is a case the old rule sent to a denominator of one.

`the_saturating_region_is_where_the_other_operand_is_odd` is the negative control on the arm above: it
asserts the region is entered, so a rule that cancelled everything and never saturated would fail
rather than pass by never reaching the branch.

## CHANGE: one arm added for the tie comparison at the top of the carrier

File: `mock/crates/arvo-format/src/apply/tests.rs`
Verification: the arm fails to compile or panics against the pre-change `is_tie`.

`a_tie_is_decided_at_a_remainder_that_does_not_survive_doubling` builds an `Exact` whose stored
remainder is above `i64::MAX / 2` and asks `is_tie`. It also asserts the answer agrees with what
`round_slot` decides at the same position, which is the property the two were supposed to share.

## CHANGE: one catalogued red for the slot carry, which this round does not answer

File: `mock/crates/arvo-format/src/apply/tests.rs`
Verification: `cargo test -p arvo-format -- --ignored` names it and it fails.

`Exact::between` adds the euclidean carry to the slot index in `i64` and a carry past the end of the
type has nowhere to go inside the coordinate. `round_slot` widens to `i128` on the way out, so the map
admits a slot one past the type after `Exact` is built and cannot admit one while it is being built.

That is a question about the slot coordinate rather than the ratio, so the arm states the behaviour
the design's totality sentence calls for and is left ignored with the reason on it, in the form the
two existing catalogued reds in this workspace use.

## CHANGE: nothing in the public surface

File: `mock/crates/arvo-format/src/lib.rs`
Verification: `git diff --name-only` over this round does not name `lib.rs`.

`Fraction`'s name, its two accessors, `ZERO`, `HALF` and `is_zero` are all unchanged. What moves is
the answer on two families of input, which is a contract change inside an existing signature.
