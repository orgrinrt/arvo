# SRC changelist: the rustdoc follows the design, and the arms observe what they claim

Three source changes. The first mirrors the locked doc changelist into the rustdoc that
ships to a reader. The other two are the tests that would have caught the defect the doc
changelist corrects, and did not, because the arm that was supposed to observe an override
routed it through a verb that forces nothing.

## CHANGE: `Format::ADMITTED` rustdoc FROM naming `apply` and the identity search TO naming the two functions

File: `mock/crates/arvo-format/src/format.rs:179`

The doc comment carries the same two sentences the design carried, and the design's copy is
now corrected. It says the obligation "fires where it is forced and nowhere else, which is
`apply` and the identity search", and lists an override among the routes that reach a value
without meeting it.

Verification: `grep -c "identity search" mock/crates/arvo-format/src/format.rs` returns 0,
and `grep -c "cancelling_slot" mock/crates/arvo-format/src/format.rs` returns at least 1.

## CHANGE: `an_implementor_writes_over_the_obligation_and_the_default_is_gone` FROM routing through `contains` TO routing through `has_additive_identity`

File: `mock/crates/arvo-format/src/tests/obligations.rs:326`

`contains` forces no obligation, which this file says two arms earlier. So
`contains::<DisarmedObligation>` and `contains::<PhaseNamesNoPosition>` are the same call for
the same reason, and the arm cannot observe whether the override changed anything: it would
pass identically if `ADMITTED` did not exist. The one verb that makes the override observable
is a forcing one, and swapping it in is what turns the arm from setup that helps into a test.

`has_additive_identity::<DisarmedObligation>()` compiles and returns a verdict.
`has_additive_identity::<PhaseNamesNoPosition>()` does not compile, and that pair is the
property.

Verification: `cargo test -p arvo-format obligations` green, and the arm names
`has_additive_identity` rather than `contains`.

## CHANGE: two arms added, one runtime and one compile-fail, pinning which verbs force

File: `mock/crates/arvo-format/src/tests/obligations.rs`, and
`mock/crates/arvo-format/tests/ui/the_identity_search_forces_the_format_obligation.rs`

Three arms pin the routes that do not force. Nothing pinned which verbs do, and that is the
claim that was wrong: the design named `apply`, which forces `Slots::ADMITTED` at
`apply.rs:355` and never `Format::ADMITTED`, and no test contradicted it.

- The compile-fail arm calls `has_additive_identity` on a format whose phase does not denote
  and asserts the refusal, so the positive half of the guarantee is pinned rather than
  described.
- The runtime arm calls `adapt` on a declared signature over that same format and asserts it
  returns, which establishes that `adapt` does not force the format's own obligation. That is
  the sentence the doc changelist deleted, kept as something that runs.

Verification: `cargo test -p arvo-format` green including the `trybuild` arms, and the new
`.stderr` file committed beside the `.rs`.

## What is not changed

The `compile_fail` doctest already on `Format::ADMITTED` stays as written. It pins the same
refusal from the doctest side and a reader lands on it first.

**No route is closed.** Whether the design should close any of them is open, and
`ruling::the_canon_does_not_police_what_shape_a_law_takes` leaves the shape to this tier.
