## Tests ship, so a comment in one is read by whoever reads the crate

Eight comments in this crate's source name the machinery that produced them rather than the property
they sit beside. A design round, a reviewer, a round's own timestamp. **None of those means anything to
somebody reading the crate**, which is the whole of why the documentation rule names shipped tests as a
public surface: they go in the package and sit beside the rendered documents.

```
apply/tests.rs:8            "four tests round `202608311902` shipped"
apply.rs:62                 "the one function a reviewer named"
tests/the_coordinates.rs:8  "a law about a type this round introduced"
tests/the_identity.rs:13    "The predicate this round replaced"
tests/the_identity.rs:26    "The predicate this round replaced, kept so the control can be run"
tests/the_inventory.rs:14   "the shape this round measured against"
tests/the_inventory.rs:63   "what the round measured against"
tests/the_inventory.rs:327  "The reviewer's construction, values verbatim"
```

**Two of them are mine, from the round two before this one**, which is why this is a class rather than
a list: the same reflex produced them across four rounds and nothing in the crate stopped it.

## What is not a leak, said so the sweep does not take the reason with it

**"An earlier version of this stopped at 32" is a statement about the code and it stays.** It carries
the reason a sweep runs its whole range, which is exactly the thing a later reader would otherwise
narrow again, and the design template uses the same construction about itself. What has to go is the
process noun: a round, a reviewer, a changelist, a timestamp naming one of them.

The distinction is whether a stranger can act on the sentence. "This sweep once stopped at 32 and the
unswept half is where the count overflowed" tells them not to shorten it. "This is what round
`202608311902` shipped" tells them nothing they can use.

**Rounding stays rounding.** A grep for the word catches nineteen lines about the rounding coordinate,
which is the crate's own vocabulary and is not what this is about.

## One more, outside this branch and reported rather than fixed

`arvo-strategy/src/tests.rs:10` says "the property the round that wrote it was fixing". That file is
not in this branch's diff, so it is `dev`'s and a different change's to make. Named here so the class
is recorded whole rather than to the edge of what I happen to be touching.

## And a sentence I put in the design overstates one of the two defects it describes

The round before this one added a law to `arvo-format`'s design:

> **A test over a declaration reaches something the code does.** Two arms in this crate once asserted
> a constant against the literal its own definition sets [...]

**That is right about one of them and wrong about the other.**
`the_overflow_inventory_admits_a_member_this_crate_does_not_know_about` asserted a constant against a
literal set four lines above it in the same file, on a type that existed for no other purpose, so
nothing about it was independent. `the_declared_width_is_read_rather_than_recovered` wrote its own
literals against a macro elsewhere in the crate, so a macro writing `$w - 1` would have failed it.

**It failed the gate for a different reason and the sentence should say which.** No range this crate
ships can separate a width that is read from one recovered by counting, because the declaration and
the bounds agree on every one of them, so the arm could not establish the property in its own name
whatever it asserted. That is the redundant-and-unseparating failure rather than the tautological one,
and the two want different repairs: one gets run through the machinery, the other gets a construction
that can tell the two answers apart.

## Changes proposed

Take the process nouns out of the eight comments, keeping every reason they carried. Correct the
design's law so it names both failures rather than one, since a later reader applying it to the wrong
one would improve a test that needed replacing or replace one that needed an assertion.
