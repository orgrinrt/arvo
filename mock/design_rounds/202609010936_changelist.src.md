# Src changelist: MATLAB's five coordinates, in the crate that can carry them

**Date:** 2026-09-01
**Round:** the standards-alias round
**Scope:** `arvo-format`, and the removal of the crate the deprecated changelist created.

## Comparison to deprecated changelist

Same five coordinates, same parity arms, same two gaps. What moved is where they live and it moved
because the source refused to build anywhere else, which the doc changelist records in full. The
deprecated plan also asserted the printed value directly, and that was wrong: MathWorks prints five
significant figures and four of its five examples print a rounding of the value rather than the value.

## CHANGE: the conventions FROM a crate that cannot build TO a module beside `points`
File: `mock/crates/arvo-format/src/standards.rs`, `mock/crates/arvo-format/src/lib.rs`
Verification: `mock/crates/arvo-standards/` does not exist,
`grep -c 'pub mod standards' mock/crates/arvo-format/src/lib.rs` returns one, and
`cargo mock --lint-only --strict` reports no `no-bare-numeric` or `arvo-types-only` finding anywhere.

`points` ships the four parameterisation points as worked instances of the open inventory. A
convention is another instance, so it goes beside them rather than in a crate whose only distinction
was that a growing inventory felt like it wanted its own address.

## CHANGE: the fraction length FROM an expression in a const argument TO a `Quantum` implementor
File: `mock/crates/arvo-format/src/standards.rs`
Verification: the workspace builds with no `#![feature(...)]` attribute anywhere, and
`grep -c generic_const_exprs mock/crates/arvo-format/src/standards.rs` returns zero.

MATLAB's fraction length is the negation of the quantum exponent, so the direct spelling is
`Constant<{-F}>`, an expression in a const generic argument position, which needs a forbidden feature.
**The wall is not real.** What the expression computes is a quantum law, so it becomes one:
`FractionLength<F>` implements `Quantum` with `BASE` set to `-F` in the impl body, where an arbitrary
expression is legal, and `Fi` bounds on the contract rather than on the expression. `SLOPE` is zero
and `MAGNITUDES` is one, which is the constant family, because a fixed-point convention has one step
rather than a ladder of them.

`F` is an `i32`, so a negative fraction length needs no case of its own: it lands on a positive
exponent.

## CHANGE: the rounding map FROM prose TO four renamed re-exports and two `FIXME`s
File: `mock/crates/arvo-format/src/standards.rs`
Verification: `grep -c FIXME mock/crates/arvo-format/src/standards.rs` returns two, and each names the
registry row that closes it.

Ceiling, Floor, Zero and Convergent become `Ceil`, `Floor`, `TowardZero` and `HalfEven` under MATLAB's
names, so the mapping is something the compiler agrees with rather than a sentence.

Nearest and Round are not mapped, because `question::is_the_rounding_vocabulary_complete_at_six` and
`question::which_tie_direction_an_unqualified_nearest_names` are open on what the one shipped
nearest-not-to-even mode means, and mapping either closes an open question inside a design.

## CHANGE: the word length bound FROM unstated TO the slot range's own, carried by the alias
File: `mock/crates/arvo-format/src/standards.rs`, `mock/crates/arvo-format/tests/ui/word_length_past_the_ladder.rs`
Verification: `cargo test -p arvo-format --test compile_fail` passes with the new case, and its
recorded stderr names the slot ladder rather than the alias.

`Fi<W, F>` carries `Signed<W>: Slots` and `Ufi<W, F>` carries `Unsigned<W>: Slots`, so a word length
the ladder does not admit fails to build where the type is named. **No runtime report and no
widening**, per `ruling::never_a_runtime_check_and_one_lowered_path`. MathWorks documents the word
length to 65535 and the ladder stops at 62, so this refuses ordinary declarations, and the
compile-fail case is where that is recorded.

## CHANGE: the parity arms FROM nothing TO MathWorks' own five worked examples
File: `mock/crates/arvo-format/tests/matlab_fi_parity.rs`
Verification: `cargo test -p arvo-format --test matlab_fi_parity` runs thirteen arms, twelve passing
and one catalogued, and every expected number in the file is one MathWorks publishes.

| MATLAB | word | fraction | printed | stored |
|---|---|---|---|---|
| `fi(pi)` | 16 | 13 | 3.1416 | 25736 |
| `fi(pi,0)` | 16 | 14 | 3.1416 | 51472 |
| `fi(pi,1,8)` | 8 | 5 | 3.1562 | 101 |
| `fi(pi,0,8)` | 8 | 6 | 3.1406 | 201 |
| `fi(pi,1,8,3)` | 8 | 3 | 3.1250 | 25 |

Each expected stored integer is the printed value times two to the fraction length, rounded, so an arm
is checkable by hand without running anything. Pi is fed as an exact rational rather than a float, so
the host's own rounding does not sit between MathWorks' number and this crate's.

**The printed value is asserted as a rounding rather than as the value**, which is the correction the
deprecated changelist needed: four of the five are inexact at five significant figures, and an arm
asserting equality fails. The assertion is that the difference is at most half a unit in the last
printed place, in exact integers.

**They run under both nearest modes at once**, which is honest only because none of them reaches a
tie, and a control asserts exactly that. A second control asserts none reaches an overflow policy, and
a third asserts the five declarations genuinely differ, so five arms are not one arm reported five
times. A fourth reports on a position rather than asserting it, so a comparison that could never fail
would be caught.

## CHANGE: the rounding gap FROM prose TO a catalogued red
File: `mock/crates/arvo-format/tests/matlab_fi_parity.rs`
Verification: `cargo test -p arvo-format --test matlab_fi_parity -- --ignored` runs one arm and it
fails with "no shipped mode rounds to nearest with ties toward positive infinity".

An arm asserting what has to become true: that some shipped mode is nearest with ties toward positive
infinity, which is four positions rather than one, since two off-grid ones say the mode is nearest
rather than directed and two ties say which way a midpoint goes. Red on purpose, marked
`#[ignore = "catalogue: ..."]` with the rows that close it, and green when the vocabulary gains a name
rather than when anybody edits it.

A second arm runs by default and pins why each candidate fails, so the gap cannot be closed by
somebody adding a re-export and assuming it lines up.

## What is deliberately not here

**No IEEE 754**, no change to the rounding vocabulary, no widened ladder, and no change to what the
trait contracts are spelled in. The last is what the round found and it is filed as its own topic.

## How this changelist expects to be checked

`cargo test --workspace` in `mock/`, and `cargo mock --lint-only --strict` green with no numeric
finding anywhere. The parity arms checked by hand against the table above.
