# Topic: the platform-width types, and the slot coordinate that has to carry them

**Date:** 2026-09-19
**Phase:** TOPIC
**Scope:** `USize`, `ISize` and `Cap` in `arvo-format`, and the slot coordinate's carrier.
**Source topics:** `question::what_a_platform_width_type_is`, answered.

## What was asked

Build the platform-width types `USize`, `ISize` and `Cap`, and whatever the slot representation must
become to carry them. Whether each of the three should exist, and where, is part of what the canon has to
answer rather than a premise.

## Authority

The governing row is `ruling::a_platform_width_type_is_a_target_bound_member_of_the_format_family`,
`rung = "ratified"`, `ratified_by = "experts"`, which answers `question::what_a_platform_width_type_is`.
It serves `obligation::a_platform_sized_unsigned_integer_at_an_api_position`, whose consumer is
hilavitkutin. The rows it leans on and that this round reads with it:
`ruling::the_format_spine_is_canon` (a format is its ambient domain and its representable set, the
concept is closed and the inventory open),
`ruling::the_numeric_door_carries_the_coordinate_set_and_the_two_type_bound_is_not_canon` (a capacity is
a coordinate the door carries, not a numeral), `obligation::a_primitive_for_every_position_a_bare_number_would_take`
(its excepted clause, op's words, "No bare usize other than in const generics"),
`ruling::never_a_runtime_check_and_one_lowered_path`, `ruling::the_operating_constraints_are_intents_and_rules`,
and `ruling::behaviour_is_stated_per_declared_signature_and_the_premise_dissolves`. The panel files in the
ruling's provenance, `260_kiselyov_what_a_platform_width_type_is.md` and
`265_lattner_what_a_platform_width_type_is.md`, were read whole for their instruments and not as authority.

The design documents and the shipped source are claims to test here. `arvo-format`'s design says the
slot index is a signed 64-bit integer and the ladder stops at 62; that is the claim this round replaces.

## The canon gate, per type

`USize` is what the ruling is about. At one compilation it is an ordinary member of the format inventory,
quantum one, phase zero, one magnitude, slot range `0 ..= 2^W - 1`, with `W` bound to the target's pointer
width rather than written as a literal, and within one compilation it is indistinguishable through the
`Format` contract from a literal declaration of the same width. So it exists, and it exists in the crate
that holds the format inventory, as a point beside the shipped four. Aligned.

`ISize` is the two's complement twin the ruling names in the same sentence, and its region lists
`signedness in {unsigned, signed}`. No consumer row asks for it by name, and
`obligation::a_primitive_for_every_position_a_bare_number_would_take` does: every public position where a
bare platform-sized index would sit, which a signed one is. Aligned, on those two rows together.

`Cap` is refused, and the gate is what refuses it. The ruling says in terms that `Cap` is out of scope
and is not a platform-width type, and
`ruling::the_numeric_door_carries_the_coordinate_set_and_the_two_type_bound_is_not_canon` answers the
position it names as "a coordinate the door carries rather than a numeral". The position is a const
generic parameter, which the primitive obligation excepts in op's own words, and which `arvo-format`'s
design already declines to hand a stack type to, because the only route is `adt_const_params` and that
feature would land on every crate declaring a format of its own. `tests/ui/an_arvo_type_as_a_const_parameter.rs`
pins that refusal for `Width` today, and `265_probes/p5` measured the same refusal for a `Cap` newtype.
So building `Cap` would contradict two ratified rows and a design decision; it is not built, and the
consumer's capacity positions take the host's `usize`, which is what the exception is for.

## What the slot coordinate must become, and whether it must

The ruling says the obligation "stays unmet in the shipped tree until a design round widens `Slots`' host
type or restates the range as a count or an exclusive bound". Those are three options, weighed here with a
committed sketch, `mock/research/sketches/202609190830_the-slot-coordinate-at-sixty-four/`, and two more
argued without building.

**Restating the range as a count, or with an exclusive end, over a signed 64-bit index.** Refused at 64 in
both signednesses, four ways, by the compiler: the count of either 64-bit range is `2^64`, one past
`u64::MAX`; the exclusive end is `2^64` unsigned and `2^63` signed, neither an `i64`; and the inclusive top
of the unsigned range, `2^64 - 1`, is not an `i64` either, so no restatement of the bounds alone carries the
unsigned twin. The controls reach 63. It wins one width and not the one asked for, so the answer to whether
the host type must change is yes: an unsigned 64-bit range has an endpoint no signed 64-bit integer holds.

**Widening the host type to `i128`, with the ladder still the bound.** Builds at every width 1 to 64, at
five targets over two pointer widths, with the count asserted to be `2^width` at every width and both
signednesses, and with the ends at the running target's width equal to `usize::MAX`, `isize::MIN` and
`isize::MAX`. Width 65 refuses at the definition site. Wins at every pointer width Rust has. The cost is a
slot sixteen bytes wide where it was eight, which is a cost only where a slot is a runtime value, and in
this crate a slot is a coordinate the verbs compute over; no carrier is reachable from here.

**An index stored relative to the range's lowest slot.** Reaches 64 in a 64-bit carrier. Loses the absolute
reading of a slot the whole predicate is stated in: slot zero would name a different position in two
ranges, and `cancelling_slot` and the additive identity are stated over absolute positions. Argued, not
built; it wins only on the footprint of a slot, which this crate does not own.

**Derived endpoints,** `260_probes/p05`'s shape, where a range is its width and signedness and the ends are
computed in the caller's domain. It closes the declared-endpoint gap and leaves the value one: `adapt`
returns a slot, and at an unsigned 64-bit range that slot can be `2^64 - 1`, so the index still needs a
carrier wider than an `i64`. It also narrows the open `Slots` contract to two shapes, which the open
inventory refuses. It wins where only the ends are read and nowhere a slot is returned.

**Running the ladder on past 64 in the wider carrier**, to 126 where the count stops fitting. Wins for
declared widths from 65 to 126, which no row asks for. It would answer how wide arvo goes, which the
design leaves unsettled on purpose, and it would admit formats the placement ladder, whose widest carrier
is 64 bits, has no carrier for.

So the representation becomes an `i128` index and an `i128` count, the ladder admits 1 through 64, and the
reason it stops at 64 is the widest pointer width and the widest carrier, not the carrier of the index.

## What widening moves, found by reading every intermediate

Every function that computed over slots "one domain wider" did it in `i128` over `i64` operands. With the
index itself an `i128`, that argument is gone, and each site was read for what replaces it.

Every range this crate ships sits inside `[-2^63, 2^64 - 1]` and is at most `2^64` slots wide, so two members sum
to at most `2^65`, and each intermediate addition computes over members stays exact with more than sixty
bits to spare. An outside implementor can place a range anywhere in the carrier, and near either end of
it a sum of two members leaves the carrier: that is exactly the refusal addition's obligation already
makes, now reachable only by a range placed near the carrier's end rather than by a wide shipped one.
Positions computed for operands that are not members, and the chain of carries `Exact::between` can
build, saturate at the carrier's ends, which is the act `Reach` and the addition step already perform.
Where a check itself could overflow, the obligation on the slot range, the carry obligation, and the
reflection comparison that negates the highest slot, it is computed with checked arithmetic and an
overflow reads as the refusal it would have been.

Three things move because the domain moved rather than because anything was wrong. The cancelling slot
of a phase of `2^63` whole quanta over one is now a slot, where it was a value no index held.
`Reach::EVERYTHING` is the new carrier's ends. And `Exact::between`'s carry past `i64::MAX`, which a
catalogue test left red because the coordinate had nowhere to put it, is now an ordinary position one slot
up, and the residual carry past the new carrier's end saturates.

## What this round does not deliver, and whose call it is

The obligation asks for a value "usable in a public error type". A format is a declared signature and
holds no value, and no crate in the tree holds a value of any format: `arvo-format` has no carrier by
charter, `arvo-placement` derives placement metadata only, and `arvo-bits` holds an exact-width container
that is explicitly not a numeral. So this round delivers the format and the coordinate the obligation's
range needs, and not the value.

What a value of a numeral is, and where it lives, is `question::what_a_datum_stands_for`, open with the
panel as decider, and filling it inside this design would be filling an open question. It is handed back.
The options as they stand are three: the consumer carries the code in `arvo_bits::Bits<{ usize::BITS }>`
today, which covers the range and is a container rather than a numeral; a value type over a declared
signature, one per format, whose denotation is exactly what Q4 has not settled; or a value type for the
integer points only, which answers Q4 for one region and would need its own ruling.

The ruling also records that `dimension.toml` has no axis for the target's pointer width, so no row can
state "holds at 64-bit targets". Declaring one is canon work, `canon_paths` refuses it while the panel is
open, and it is not this round's.
