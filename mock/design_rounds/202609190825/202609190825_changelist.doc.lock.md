## `crates/arvo-format/DESIGN.md.tmpl`

The surface table lists `USize` and `ISize` in `points`.

"The bound" is restated: widths 1 through 64, the slot index and the count carried as signed 128-bit
integers, why 64 is where it stops (the widest pointer width and the widest placement carrier, not the
index's host integer), why a restatement over a signed 64-bit index reaches only 63 (the sketch), and why
the ladder does not run on to 126. The refusal example moves from `Signed<63>` to `Signed<65>`.

"What an outside implementor owes" drops the count condition and the claim that ends sit near zero. The
obligations are three and are checked at a use site: ordered ends, an admitted width, and a width that
addresses the span, where the span is computed checked and an overflow is a width that does not address
it. A count condition becomes one nothing can fail, so it goes rather than staying as a vacuous assertion.

"The set cannot be widened by accident" names the new mechanism: ends written as shifts of the 64-bit host
integers by `64 - width`, so 65 is refused at the definition site, and writing them over the 128-bit
integer would move the bound into a sentence.

New subsection, "The index's host integer, and what every computation over a slot owes it": with the index
itself the widest integer, the "one domain wider" argument is gone, so each site's headroom is stated. Over
shipped ranges every intermediate is more than sixty bits inside. Near the integer's ends an outside range
gets checked arithmetic where a verdict or obligation is computed (span, carry condition, the reflection
comparison), saturation where a position is computed (non-members, chains of carries), and a wrap
completion that reduces position and lowest slot separately, so it is exact everywhere.

New section, "The platform-width points, which are ordinary points at a width the target supplies":
`USize = UFixed<{ usize::BITS }, 0>` and `ISize = Integer<{ usize::BITS }>`, aliases and not structs, no
`cfg`, why `usize::BITS`; the obligation met at 32 and 64 bits and not at 16; the value half not delivered;
no capacity type; and the laws the tests owe (literal point through the contract, the family at 16, 32 and
64 on any host plus the alias compiled at a target of each pointer width, membership in both directions).

`Exact::between` gains a paragraph: its carry lands as an ordinary slot wherever the host integer holds
it and saturates past it, so `between` is total. The addition passages say the position is computed in the
index's own integer, saturates for non-members, and the carry condition is computed checked and is
reached only by an outside range near the integer's end. The standards ladder reads 1 to 64 and `fi` 65.

## `crates/arvo-bits/DESIGN.md.tmpl`

"Why the width bound is not `arvo_format::slots::Slots`" compared its 64 against `Slots`'s 62 and gave the
signed 64-bit index as the reason. Both bounds now read 64 and still answer different questions, so the
section says that instead.

## `PRINCIPLES.md.tmpl`, `WORKFLOW.md.tmpl`, and the agent templates

Each named a `Cap` newtype for type-level capacities, which the ruling refuses. The primitive table row for
`usize` / `isize` now points at the two format points and says a const-generic capacity keeps `usize`; the
container examples write `const N: usize`; WORKFLOW says the same. In `agent/rules/cookbook.md.tmpl`,
`no-heap.md.tmpl`, `type-surface.md.tmpl` and `agent/skills/type-surface-review/SKILL.md.tmpl` the `Cap`
advice goes the same way. Those agent files carry a banner saying the crate tree they describe is gone;
the rest of what they name is left to that banner, and only the advice this ruling falsifies is changed.
