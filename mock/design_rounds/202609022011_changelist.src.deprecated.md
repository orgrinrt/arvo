# Source changelist: pin the transitive case and drop what cannot fail

## CHANGE: module docs on `width.rs` state what the door carries, not how the count was reached
File: `mock/crates/arvo-format/src/width.rs:24`
Verification: `grep -c 'separate derivations' mock/crates/arvo-format/src/width.rs` returns zero.

`//!` rustdoc renders, so it is a tier 1 surface and `documentation-writing.md`
forbids provenance there. "Two separate derivations reached different counts" is
how the project came to know the thing, which a reader of the crate cannot act on.
The sentence before it says the count is not stated and not settled, which is the
whole of what the door owes, and it stays.

## CHANGE: a new arm and a new `tests/ui` case pin the declaration-dependence of a transitive set
File: `mock/crates/arvo-format/src/tests/obligations.rs`, `mock/crates/arvo-format/tests/ui/`
Verification: `cargo test -p arvo-format` passes with the new arm; the new
`compile_fail` case is registered in `tests/compile_fail.rs` and refuses.

The design now says a set counted transitively is a property of the declaration as
well as the verb. Nothing tested that, which is why the sentence it replaced could
be false and stay green: the previous round's four arms pin the format's own set
and none touches how sets relate.

`has_additive_identity` forces the format's and the quantum's obligations directly.
It reaches the slot range's only through `slot_in_range`, inside the loop, and only
on a magnitude where `cancelling_slot` answers `Is`. So over an inadmissible slot
range the same verb is refused for one format and compiles for another, decided by
the phase.

Both halves ship, because either alone is a fact about one declaration:

- the refusal, as a `compile_fail` case binding the call in a `const` item, since an
  obligation forced from a runtime call is evaluated at codegen and `cargo check`
  does not reach it;
- the arm that compiles and answers, over the same inadmissible slot range with a
  phase that never yields a cancelling slot.

## CHANGE: `a_coordinate_is_readable_off_the_impl_without_the_obligation_firing` is deleted
File: `mock/crates/arvo-format/src/tests/obligations.rs:320`
Verification: `grep -c a_coordinate_is_readable_off_the_impl mock/crates/arvo-format/src/tests/obligations.rs` returns zero.

It cannot fail for the reason it exists. Reading one associated const does not
force another in any Rust this crate could be written in, so no change to the crate
can close the route it claims to pin, and the section header says pinning a
closable route is what these arms are for. Its two assertions duplicate the two at
`:192` and `:200` over an identical fixture. `the-test-gate.md` calls a test that
cannot fail worse than an absent one, because it occupies the space where a real
one would be missed.

The section header says "the three arms below" and had four under it. Deleting this
one makes the count right, and the header is reworded anyway, because the arms are
not all the same kind of thing: two are routes that never reach the obligation and
one is a route that reaches it and finds an implementor's override.
