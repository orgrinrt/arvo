# Topic: three agents fixed one lint by three routes, and none of them knew

**Date:** 2026-09-01
**Round:** 202609011206
**Branch:** `feat/the-standards-alias-and-what-it-refutes`

A review of this pull request found five things. The one that matters is the
conflict with the trunk, and it is not a conflict about wording.

## What the two sides each get right and each get wrong

`no-prose-citation-into-nothing` refuses a citation in prose that resolves to no
registry row. An elided citation, one written with a trailing `...` because the
slug is long, has to be resolved before it can be judged, and that resolution is
where the two sides diverge. Each was written without knowledge of the other.

Both carry a defect the other fixes, measured by running each mechanism against
the other's arms:

- **The trunk resolves a cut that landed mid-word.**
  `proposal::a_law_is_inherit...` resolves against
  `..._a_law_is_inherited_where...` because the prefix match has no boundary
  condition. The branch refuses it and ships the arm.
- **The trunk does not read `…` as an elision at all.** It falls through and the
  citation counts against the ceiling. Latent rather than live: the corpus holds
  thirty-two of the character and none of them follows a qualified slug.
- **The branch's boundary rule refuses a live corpus citation.** It builds the
  probe as `format!("{qualified}_")`, so
  `proposal::a_min_plus_fold_needs_an_absorbing_top_...`, which already ends in
  a separator, becomes a double underscore and matches nothing.
- **The branch folds elisions into the ceiling-gated count**, which is the
  failure the trunk's own text documents: the ceiling becomes a function of the
  registry, and a row planted anywhere can push the gate over a number that may
  not be raised.
- **The branch reports only the first line's half of a wrapped citation**, a
  string nobody wrote. The trunk handles wrapping and has the arm for it.

## The resolution

Take the trunk's mechanism whole, and add the branch's two intents to it: the
word boundary, and the single-character spelling of the mark.

The boundary is written to admit both corpus shapes rather than one. A cut
lands between words either because the prose stopped before the separator, so
the row's next byte is `_`, or because it stopped just after one, so the written
part already ends in `_`. Both occur. Stopping inside a word leaves a prefix
nobody can finish without guessing, and that is the near miss the lint exists
for.

**Neither side is taken wholesale and that is the whole point.** Selecting the
trunk loses two real defects the branch found; selecting the branch loses the
ceiling's meaning and a live citation with it.

## Why a round rather than a merge commit

The consolidation is a source change with a design decision inside it: which
mechanism survives, and what the boundary rule is. It also carries the trunk's
own `arvo-format` work into this branch, which the mockspace guard reads as a
source edit in `TOPIC` and refuses, correctly.

So the merge happens inside an open source window rather than around it, and the
reasoning above is on the record where the next reader of either mechanism will
find it.
