# seventh-review-oracle-sweep-and-token-lint

The seventh review of the platform-width round found the same shape a fourth
time over: a fix killed the one mutant a review named, and left the region the
review named unfed. So this round fixes both problem areas as classes rather
than as instances.

## The applied map is checked against an oracle, not at hand-picked points

`the_cross_end_saturation.rs` fed carried positions from one slot past an end
onward, so the step onto `i128::MIN` from just under it, `past == -1` with the
rounding stepping up, was never fed into a range whose own bottom is not
`i128::MIN` under Saturate or Clamp. A mutant sending that step to the range's
highest slot survives the whole suite.

The answer is an independent oracle for `adapt` and `panic_on_overflow`. It
computes the rounded position exactly as an integer wider than the index (two
limbs), from the documented meaning of each rounding mode and each policy, and
never reads `Exact`, `Rounded`, `round_slot` or `complete_slot`. A sweep
compares it against the shipped surface over every mode, every policy, a set of
ranges at both ends of the index, at neither end, and near each end without
touching it, over positions at each end of the index and at each end of the
fed range, at depths up to eight slots either way, every quarter remainder,
and a set of dithers. The same sweep is run against every broken map the suite
keeps, and has to report each one. The hand-picked matrices the sweep
subsumes are removed; hand-reduced single points stay, as evidence arrived at
another way.

## The `core`-shadowing lint reads tokens, not strings

The lint matched keyword pairs with literal text, so `extern  crate`, a newline
between the two words, or a comment between them escaped it, and its `use`
leaf scan fired on `::core` followed by a terminator anywhere rather than only
inside a `use` item, while missing `use a::{core};`, `use a::core::{self};`
and `use a::r#core;`. It becomes a tokenizer over the comment- and
literal-stripped text, a matcher for `mod core` and `extern crate ... as core`
on tokens, and a real use-tree walk that reports every name a `use` item binds.
The design text and the lint's own messages are rewritten so each sentence is
true: the leading `::` resists `mod core` and every `use` binding on its own,
and an `extern crate ... as core` at the crate root, like a manifest rename,
reaches it.

## The probe runs every arm under one command

`run.sh` checks every arm with its expected outcome, the negative control
included, plus a manifest-rename fixture and a macro-expanded `extern crate
self as core` arm, and `run.out` is its output. The false headers in the arms
are corrected.

## Catalogue

The stale test comment in the lint's tests, the two broken-map names carrying
finding ids, the broken map doc comparing two blind spots that are not the
same, and the green assertions that pin a law's blindness are fixed or
removed.
