# Doc changelist: the design says what a non-positive phase denominator means

**Date:** 2026-09-01
**Round:** a negative phase denominator carries a value and a zero one does not
**Scope:** `mock/crates/arvo-format/DESIGN.md.tmpl`

The design states that `Phase`'s constructors cannot produce a zero denominator and stops there. That
is a statement about the invariant the type holds, not about what a caller's non-positive denominator
becomes, so the constructor answered the question on its own and answered it wrongly for every
negative input.

## CHANGE: the phase paragraph FROM naming only the never-zero condition TO naming what each non-positive denominator becomes
File: `mock/crates/arvo-format/DESIGN.md.tmpl`
Verification: `grep -c 'moves its sign to the numerator' mock/crates/arvo-format/DESIGN.md.tmpl`
returns 1, and the paragraph names `i64::MIN` as the bound.

The paragraph gains the reading: a zero denominator names no value and is read as one, a negative one
names a value exactly and normalises by moving the sign to the numerator, and the two pairs `i64::MIN`
puts out of reach stay whole-numbered because the exact form needs a magnitude the type does not
carry.

Stated in the design rather than only in the constructor's doc comment, because it is a property of
what a phase is rather than of how one function happens to be written, and because the source is the
tier that gets nuked.
