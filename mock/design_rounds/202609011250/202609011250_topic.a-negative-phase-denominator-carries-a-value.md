# Topic: a negative phase denominator carries a value and a zero one does not

**Date:** 2026-09-01
**Phase:** TOPIC
**Scope:** `mock/crates/arvo-format/DESIGN.md.tmpl`, `mock/crates/arvo-format/src/format.rs`

## Current state

`Phase::of` reads any non-positive denominator as one:

```rust
if den <= 0 {
    Self { num, den: 1 }
} else {
    Self { num, den }
}
```

Measured on the shipped constructor, `of(3, -7)` answers `3/1`. The exact value the caller named is
`-3/7`, which is representable in the pair the type carries: move the sign to the numerator and
nothing is lost. What the constructor does instead is change the sign and the magnitude at once, and
it does it silently, in a crate whose stated point is that a format is exact.

The guarding test sweeps `-9`, `-1` and `i64::MIN` and asserts only `denominator() > 0`. Every one of
those passes under the lossy constructor, because the assertion never asks what happened to the
value. That is the sampled-law shape: the property that would have caught this was never written.

The design is silent on it. `DESIGN.md.tmpl` says the constructors cannot produce a zero denominator,
which is true and is a different sentence. Nothing there says what a negative one means, so the code
decided, which is an undeclared design change wearing the leaf tier's freedom.

## The two cases are not one case

A zero denominator names no value at all. There is nothing to preserve, so reading it as one is the
only total answer available and it loses nothing that existed.

A negative denominator names a value exactly. `num/den` with `den < 0` equals `-num/-den`, both
representable, so the normalisation is a rewrite rather than a coercion.

Folding the two together is what produced the defect: the zero case's answer was applied to the
negative case, where an answer already existed.

## What `i64::MIN` costs

Two pairs cannot be normalised. `i64::MIN` has no negation in `i64`, so a denominator of `i64::MIN`,
or a numerator of `i64::MIN` under a negative denominator, would need a magnitude one past what the
type carries. Those stay whole-numbered, and the difference from the current state is that they are
the only inputs on which this is lossy rather than every negative one.

Refusing them is not available: `of` is const and total, and the design's own reading is that a
caller computing a coordinate should not have to carry an invariant a constructor can hold.

## Changes proposed

State the reading in the design, then normalise by sign in the constructor, and extend the guarding
sweep to assert the value rather than only the sign of the denominator.
