# Doc changelist

Documents the live-count parameterisation of arvo-sparse `Csr` / `CsrBidirectional`
(topic `202605291942_topic.csr-live-counts.md`, sketch

## FILE: `mock/crates/arvo-sparse/DESIGN.md.tmpl`

- `## CSR` section: extend the `Csr` struct sketch with two runtime fields,
  `live_rows: USize` and `live_nnz: USize`. Add prose: the matrix is packed by
  default (`new()` sets `live_rows = cap_size(ROWS)`, `live_nnz = cap_size(NNZ)`),
  so existing fully-packed consumers are unchanged. A capacity-with-slack
  consumer sets a smaller live count; `row_end` of the last LIVE row returns
  `live_nnz` rather than `cap_size(NNZ)`, so the slack tail
  `col_idx[live_nnz..]` is never read. State the rule that storage stays
  `cap_size(...)`-sized while iteration bounds follow the live counts.

- `## CsrBidirectional` section: note that `with_transpose` reads only the live
  range (`0..live_rows` rows, `0..live_nnz` scatter) and carries the live counts
  through to the result, so the transpose carries no spurious predecessor from
  an unfilled tail.

- `## Sparse adjacency contract` section: clarify that `node_count()` returns
  the live node count (for a packed matrix this equals the cap), and that the
  trait-driven algorithms visit node seeds over `0..node_count()`. `BitMatrix`
  and packed `Csr` keep `node_count() == cap`, so their behaviour is unchanged.

- `## RCM reordering`, `## Block diagonal detection`,
  `## Dulmage-Mendelsohn decomposition`: add one line each that the `_via`
  overloads visit `0..node_count()` and size their output / visited arrays at
  `cap_size(N)`; non-live node slots keep their default and the consumer reads
  the live prefix.

No backticked `pub` item names are added or renamed (the `Csr` /
`CsrBidirectional` / `SparseAdjacency` items already exist), so the
`design-doc-source-mismatch` lint is unaffected; the field names live inside
the struct code blocks, not as standalone backticked item references.
