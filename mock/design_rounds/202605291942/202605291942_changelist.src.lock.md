# Source changelist: live-count CSR

Parameterise the existing `Csr` / `CsrBidirectional` over runtime live
row / nnz counts so a capacity-with-slack consumer (hilavitkutin's
`DependencyGraph`) can drive the sparse algorithms without the packed-CSR
slack tail polluting the transpose. The packed case stays the default:
`new()` sets the live counts to the caps, so `BitMatrix` and every existing
packed `Csr` consumer is unchanged.

The load-bearing correctness claim (the packed transpose pollutes node 0
on slack input; the live-count transpose is clean) is validated by the
committed sketch `mock/research/sketches/202605291942_csr-live-counts/findings.md`
(verdict WORKS, in-degree `[7,1,0,0]` packed vs `[1,1,0,0]` live).

The live counts are stored as written and clamped to the caps at every use
site, matching the defensive accessor style already in `csr.rs` (every query
guards `end > cap_size(NNZ)`). Storage arrays stay `cap_size(...)`-sized;
only the iteration bounds follow the live counts.
