# Src changelist: the review's two defects and the coverage its thesis demanded

**Date:** 2026-07-28
**Phase:** IMPL
**Doc changelist:** `202607280130_changelist.doc.lock.md`
**Source topic:** `202607280100_topic.review-findings-on-the-identity-round.md`
**Status:** living until locked

## CHANGE: `SignedIdentity` GAINS impls for `Bits<N, S, Signed>` and `IFixed<I, F, S>`

Files: `mock/crates/arvo-storage/src/bits.rs`, `mock/crates/arvo/src/ifixed.rs`

Neither type had an impl at any width, while four artifacts said `IFixed` did. `Bits<N, S, Signed>` forwards
to its container's `NEG_ONE`, the all-ones pattern. `IFixed<I, F, S>` holds raw `-(1 << F)`, built by the
same doubling loop `ifixed_fixed_one` uses, started from the container's `NEG_ONE` instead of its one:
doubling minus one `F` times gives `-(2^F)`.

Unconditional at every width, unlike `Identity<Multiplicative>`. `IFixed<I, F, S>` spans `[-2^I, 2^I)`, so
minus one is inside at every `I`, and at `I == 0` it is exactly the container minimum. That is the asymmetry
the previous round argued for and did not implement.

Verification: `<IFixed<{ibits(0)}, {fbits(7)}, Hot> as SignedIdentity>::NEG_ONE` compiles and holds `-128`,
and the law matrix below asserts the raw at every shape rather than at the one that motivated it.

## CHANGE: `Precise::i_div_fixed` SATURATES rather than wrapping

File: `mock/crates/arvo-strategy/src/arith_macros.rs`, the signed and unsigned saturating macros

`wrapping_div` yields the container minimum for `MIN / -1`, and the clamp below reads that as already inside
the logical bound and passes it through. The mathematical answer is `+2^63`, which saturates upward, and the
sibling `i_div` in the same macro reaches it with `saturating_div`. The previous round made `Precise`
consistent with `Hot` instead of with itself, so two functions of one strategy returned opposite signs for
the same input.

Verification: `<Precise as IArith<64>>::i_div_fixed::<0>(i128::MIN, -1)` returns the logical maximum, the
same as `i_div` on that input.

## CHANGE: `never_panic_contract.rs` COVERS every strategy and every arithmetic family

File: `mock/crates/arvo-strategy/tests/never_panic_contract.rs`

The test ran `Hot` and `Cold` at 128 bits only. That width dispatches solely through the 256-bit widening
family, so the plain wrapping and native-widening families were never entered, and four of the six division
edits sat in code the test could not reach. `Precise` was claimed by the changelist and run nowhere, which is
why the sign defect above survived the round that introduced it.

It now walks 8, 16, 32, 64 and 128 logical bits across all four strategies. `Precise` gets its own
assertions rather than a shared no-panic sweep, because its contract is stronger: it must return the clamped
bound, and returning something is not enough.

Verification: the `Precise` sign case fails against the previous source.

## CHANGE: `identity_laws.rs` COVERS the wide band and negative operands

File: `mock/crates/arvo/tests/identity_laws.rs`

The matrix stopped at 64 logical bits so that every strategy carried the same rows. Squareness is not
coverage: 65 to 128 is a different implementation family, the one holding `i_mul_fixed_128` that the previous
round patched, and it reaches only `Hot` and `Cold`. Those rows are added for the two strategies that have
them, and the comment claiming squareness as a virtue goes.

Every probe was also non-negative, so neither law was asserted on a negative operand anywhere. The signed
rows gain negative probes, including the container minimum.

`NEG_ONE` gains its own law over the same matrix, asserting the raw and that `ONE + NEG_ONE == ZERO` where
both exist. Its absence is what let four artifacts describe an impl that was not there.

Verification: the constant assertion tightens from `one.to_raw() >> F == 1`, which accepts any raw in
`[1 << F, 2 << F)`, to `== 1 << F`.

## CHANGE: the compile-fail pin COVERS the signed case and every strategy

Files: `mock/crates/arvo/tests/ui/no_multiplicative_identity.rs` and its `.stderr`, plus a signed sibling

The pin covered `UFixed<0, 8, Hot>` alone, while the topic called the signed case the worst of the four.
Loosening the bound on `ifixed.rs` left the suite green, which the pin's own doc comment says must not be
possible. A signed case is added, and the unsigned one extends across `Warm`, `Cold` and `Precise`.

Verification: removing the `OneRepresentable` bound from either impl turns a compile-fail case red.

## CHANGE: two comments CORRECTED

Files: `mock/crates/arvo-strategy/src/arith_macros.rs`, `mock/crates/arvo/tests/fixed_point_mul.rs`

The division guard's comment reads "Signed MIN / -1 has no representable answer" inside the unsigned macros,
where the case cannot arise; those say the change is for uniformity. And `fixed_point_mul.rs` points at
`identity_laws.rs` for the refusal, which that file explicitly disclaims; it points at `tests/ui/`.

## Deliberately not in this round

Counter increments reading `count + <USize as Identity<Multiplicative>>::IDENTITY` across `arvo-comb`,
`arvo-sparse` and `arvo-graph`. Using the multiplicative identity as the literal one is the conflation this
arc removes, and it couples a counter to a projection unrelated to counting. It is a faithful translation of
what the code said before, and correcting it needs a unit constant that does not exist, which is a design
question rather than a fix. Tracked.

The `notko` git dependency, which still blocks publishing one dependency after the one this arc removed.
Out of scope for a correctness round; the release text is corrected instead.
