# Source changelist: hold the cast refusal, and sweep the cast matrix over values

## `crates/arvo-bits/tests/ui/a_cast_to_zero_bits_is_refused.rs` (new)

A `const` block calling `Bits::<8>::masked(1).cast::<0>()`, which is refused
because `cast` constructs at the target width and that construction forces
`Bits::<0>::ADMITTED`.

## `crates/arvo-bits/tests/ui/a_cast_past_sixty_four_bits_is_refused.rs` (new)

The same at the other end, `cast::<65>()`, forcing `Bits::<65>::ADMITTED`.

## The two `.stderr` files (new)

Generated by `trybuild` and checked before landing rather than accepted. Both
carry `error[E0080]` naming `arvo_bits::Bits::<0>::ADMITTED` and
`arvo_bits::Bits::<65>::ADMITTED` respectively, at the `assert!` inside
`ADMITTED`. That is the ordering the crate wants: the reader sees the sentence
explaining what a width of zero or a width past sixty-four means, rather than
the shift-overflow panic `MASK` would raise first if the obligation were
reached in the other order.

## `crates/arvo-bits/tests/compile_fail.rs` (update)

The two new cases, and four sentences in the module header saying there are two
public doors onto the obligation and that `cast` reaches it by delegation, so
its refusal is one delegation away from disappearing under a refactor nothing
else in the crate would report.

## `crates/arvo-bits/src/tests.rs` (update)

`cast_from::<N>` now sweeps the same eight probes
`construction_drops_exactly_the_bits_above_the_width_everywhere` already
sweeps, rather than the single start value `0x0123_4567_89AB_CDEF`. The doc
comment on `cast_lands_on_the_oracle_for_every_pair_of_widths` says eight
probes rather than implying the pairs were the whole of it, and `cast_from`
carries why: one start value exercises every pair and still puts one bit
pattern through every mask.

CHANGE: the suite could not observe a `cast` that drops a bit the single probe
happens to have clear. Measured on this branch, both directions:

- `cast` mutated to `Bits::<M>::masked(self.raw() & !(1u64 << 4))`, with the
  single probe: `cargo test -p arvo-bits --lib` reports 13 passed, 0 failed.
  The whole suite is blind to it, because `0x0123_4567_89AB_CDEF` has bit four
  clear.
- The same mutation with the eight probes:
  `cast_lands_on_the_oracle_for_every_pair_of_widths` fails at
  `from N = 5 to M = 5, raw = 0xffffffffffffffff`, and it is the only failure,
  so the arm is the one that catches it rather than a neighbour.

The negative control on the other side, so the pair is not one-sided:
`MASK`'s `N == 64` branch mutated to `u64::MAX >> 1` is caught by four
construction sweeps and by neither cast arm, because `cast` takes a value
already masked at `N` and a clipped mask clips the input first. That is a real
bound on what the cast matrix can see, and it is why the two mutations are both
here rather than only the one that argues for the change.

## What this changelist does not touch

`crates/arvo-bits/src/lib.rs`. It was mutated twice to run the controls above
and is byte-identical to its committed state; `git diff` over it is empty.
