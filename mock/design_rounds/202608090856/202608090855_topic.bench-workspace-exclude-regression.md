**Date:** 2026-08-09. **Author:** dispatched expert (thread-axis bench, numeral canon panel file 78).

## What this round is for

A one-line infrastructure fix to `mock/Cargo.toml`, discovered while building a
new bench for the numeral canon panel's thread-axis question (`OPTIONS.md`
Q32). Not a canon or design decision: it restores the bench harness to the
buildable state the crate-tree deletion round said it would keep.

## The regression

Commit `929c46ed` ("chore!: delete the crate sources and empty the
workspace", 2026-08-08 21:59:31 +0300) set `mock/Cargo.toml`'s
`[workspace] members` to `[]` and, in the same edit, dropped the
`"benches"` and every `"benches/variants/*"` entry that had been in the
member list. The commit's own message says plainly that this was not the
intent: "mock/benches stays: its artifacts are committed evidence and the
panel's doability claims cite them."

The consequence: every crate under `mock/benches/` (the shared `-shared`
libraries, every cdylib variant, and any new one) has no `[workspace]` table
of its own, so `cargo` walks up from any of them, finds the nearest ancestor
`Cargo.toml` with a `[workspace]` table (`mock/Cargo.toml`, members empty),
and refuses:

```
error: current package believes it's in a workspace when it's not:
current:   .../mock/benches/variants/<crate>/Cargo.toml
workspace: .../mock/Cargo.toml
```

Verified against a crate that predates the regression
(`bitpack-contend-shared`, last touched by commit `41d2de2e`, which is an
ancestor of `929c46ed`): it fails identically. This is not specific to any
crate this round adds; it broke every bench in the directory, including the
ones the panel had already run and cited (files `26` and `27`), from
2026-08-08 21:59:31 onward. No file after that timestamp in the panel ran a
new bench; `33` and `41` both analyse existing committed csvs rather than
producing new ones, which is consistent with the harness having been broken
for the whole of that stretch.

## The fix

Add `exclude = ["benches"]` to `mock/Cargo.toml`'s `[workspace]` table.
`exclude` is cargo's mechanism for "a package under this path is not part of
my workspace", which stops the upward search from finding this workspace as
governing for anything under `benches/`, without re-listing roughly a hundred
crates as members (which would be the wrong fix: bench crates are not
governed by the canon/design/code chain the empty member list exists to
protect, and the deletion commit's own reasoning already says so).

## Scope

One file, `mock/Cargo.toml`, one line added plus a comment explaining why.
Nothing under `mock/crates/` is touched (there is nothing there to touch).
Nothing about the canon, the strategy set, or any of the panel's open
questions is decided by this round; it restores build tooling to the state
the prior round said it would leave it in.
