#### 2. `Widen<T>` trait + `Widened<T>` alias declarations

Add after the existing Narrow trait declaration (line 553 area):

```rust
/// Widened-result expression alias.
///
/// Cosmetic alias for the result of `widen_to` so consumer signatures
/// read `fn foo() -> Widened<u64>` instead of bare `u64`.
pub type Widened<T> = T;

/// Widen `Self` into a wider bit-width carrier.
///
/// `Self` is a narrower raw value (a bare primitive or a `Bits<M, S, Sign>`).
/// `T` is the target carrier type. The default body uses Rust's `as`
/// cast (zero-extend for unsigned, sign-extend for signed) plus, for
/// `Bits<M, ...>` with sub-carrier-width M, the source-side mask of
/// bits 0..M before the cast.
///
/// Asymmetric with `Narrow<T>`: `Widen<T>` does not carry a const-N
/// parameter. The source bit-width is determined by impl context
/// (carrier `BITS` for primitives, `M` for `Bits<M, ...>`); a const
/// parameter on `widen_to` would be informational at best, never
/// driving impl behaviour. See `DESIGN.md` for the full asymmetry
/// rationale.
pub const trait Widen<T> {
    /// Widen `Self` into `T`. Zero-extends for unsigned source-target,
    /// sign-extends for signed source-target. For sub-carrier-width
    /// `Bits<M, ...>` source the body masks bits 0..M before the
    /// cast.
    fn widen_to(self) -> T
    where
        Self: Sized;

    /// Widen without source-side masking.
    ///
    /// Sound when the caller knows bits above the source's logical
    /// width are already zero (well-formed `Bits<M, ...>`, primitive
    /// source where all bits are valid). Skips the source-side mask
    /// in the body.
    fn widen_to_unmasked(self) -> T
    where
        Self: Sized;
}
```

#### 3. Cross-primitive Widen impls

Add after Widen declaration:

```rust
macro_rules! impl_widen_u {
    ($src:ty => $($dst:ty),+) => {
        $(
            // lint:allow(no-bare-numeric) lint:allow(arvo-types-only) reason: cross-primitive widen impl on bare primitives that the trait was designed to bridge; tracked: #290
            impl const Widen<$dst> for $src {
                #[inline(always)]
                fn widen_to(self) -> $dst {
                    self as $dst
                }

                #[inline(always)]
                fn widen_to_unmasked(self) -> $dst {
                    self as $dst
                }
            }
        )+
    };
}

impl_widen_u!(u8 => u16, u32, u64, u128);
impl_widen_u!(u16 => u32, u64, u128);
impl_widen_u!(u32 => u64, u128);
impl_widen_u!(u64 => u128);

macro_rules! impl_widen_i {
    ($src:ty => $($dst:ty),+) => {
        $(
            // lint:allow(no-bare-numeric) lint:allow(arvo-types-only) reason: cross-primitive signed widen; sign-extending `as` cast; tracked: #290
            impl const Widen<$dst> for $src {
                #[inline(always)]
                fn widen_to(self) -> $dst {
                    self as $dst
                }

                #[inline(always)]
                fn widen_to_unmasked(self) -> $dst {
                    self as $dst
                }
            }
        )+
    };
}

impl_widen_i!(i8 => i16, i32, i64, i128);
impl_widen_i!(i16 => i32, i64, i128);
impl_widen_i!(i32 => i64, i128);
impl_widen_i!(i64 => i128);
```

For unsigned `as`-cast zero-extends; for signed `as`-cast sign-
extends. Both branches use the same body shape; the macro arm
distinction is cosmetic but keeps signed / unsigned readable as
separate lists.

Same-container Widen impls (u8: Widen<u8>, etc.) are unnecessary and
intentionally omitted. Widen is "widen to a strictly wider carrier";
same-width is identity, expressible via `Self` (no Widen impl needed).

#### 4. Cross-Bits Widen impl

Add after the cross-primitive Widen block:

```rust
impl<const M: u16, const N: u16, S: Strategy, Sign: Signedness>
    const Widen<Bits<N, S, Sign>> for Bits<M, S, Sign>
where
    S: BitsContainerFor<M, Sign>,
    S: BitsContainerFor<N, Sign>,
    <S as BitsContainerFor<M, Sign>>::T:
        ~const Widen<<S as BitsContainerFor<N, Sign>>::T>,
{
    #[inline(always)]
    fn widen_to(self) -> Bits<N, S, Sign> {
        let raw = self.to_raw();
        let widened = raw.widen_to();
        Bits::from_raw(widened)
    }

    #[inline(always)]
    fn widen_to_unmasked(self) -> Bits<N, S, Sign> {
        let raw = self.to_raw();
        let widened = raw.widen_to_unmasked();
        Bits::from_raw(widened)
    }
}
```

Parallel to the cross-Bits Narrow forwarder. M < N is not enforced at
the type level; consumers supplying M >= N still get a valid result
(the underlying primitive Widen impl returns identity for same-
container widens, which the same-container Narrow on the cross-Bits
narrow side now covers).

#### 5. Cross-domain primitive↔Bits direct impls

Add after the cross-Bits Widen block. These provide the "skip the
intermediate `Bits::from_raw` wrap" shape underlying the
`from_narrowed` / `from_widened` constructors:

```rust
// --- Cross-domain Pri -> Bits<N, S, Sign> Narrow direct impls ----------
//
// For each primitive Pri the existing Narrow matrix supports, ship
// `Pri: Narrow<Bits<N, S, Sign>>` for every (N, S, Sign) combination
// the strategy table reaches via Pri as carrier. Macro forwards
// through the carrier-side Narrow then wraps with Bits::from_raw.

macro_rules! impl_narrow_pri_to_bits_unsigned {
    ($($pri:ty),+) => {
        $(
            impl<const N: u16, S: Strategy>
                const Narrow<Bits<N, S, Unsigned>> for $pri
            where
                S: BitsContainerFor<N, Unsigned>,
                $pri: ~const Narrow<<S as BitsContainerFor<N, Unsigned>>::T>,
            {
                #[inline(always)]
                fn narrow_to<const W: u16>(self) -> Bits<N, S, Unsigned> {
                    Bits::from_raw(<$pri as Narrow<_>>::narrow_to::<W>(self))
                }

                #[inline(always)]
                fn narrow_to_unmasked<const W: u16>(self) -> Bits<N, S, Unsigned> {
                    Bits::from_raw(<$pri as Narrow<_>>::narrow_to_unmasked::<W>(self))
                }
            }
        )+
    };
}

impl_narrow_pri_to_bits_unsigned!(u8, u16, u32, u64, u128);

macro_rules! impl_narrow_pri_to_bits_signed {
    ($($pri:ty),+) => {
        $(
            impl<const N: u16, S: Strategy>
                const Narrow<Bits<N, S, Signed>> for $pri
            where
                S: BitsContainerFor<N, Signed>,
                $pri: ~const Narrow<<S as BitsContainerFor<N, Signed>>::T>,
            {
                #[inline(always)]
                fn narrow_to<const W: u16>(self) -> Bits<N, S, Signed> {
                    Bits::from_raw(<$pri as Narrow<_>>::narrow_to::<W>(self))
                }

                #[inline(always)]
                fn narrow_to_unmasked<const W: u16>(self) -> Bits<N, S, Signed> {
                    Bits::from_raw(<$pri as Narrow<_>>::narrow_to_unmasked::<W>(self))
                }
            }
        )+
    };
}

impl_narrow_pri_to_bits_signed!(i8, i16, i32, i64, i128);

// --- Cross-domain Bits<M, S, Sign> -> Pri Widen direct impls -----------

macro_rules! impl_widen_bits_to_pri_unsigned {
    ($($pri:ty),+) => {
        $(
            impl<const M: u16, S: Strategy>
                const Widen<$pri> for Bits<M, S, Unsigned>
            where
                S: BitsContainerFor<M, Unsigned>,
                <S as BitsContainerFor<M, Unsigned>>::T: ~const Widen<$pri>,
            {
                #[inline(always)]
                fn widen_to(self) -> $pri {
                    <_ as Widen<$pri>>::widen_to(self.to_raw())

                #[inline(always)]
                fn widen_to_unmasked(self) -> $pri {
                    <_ as Widen<$pri>>::widen_to_unmasked(self.to_raw())

            }
        )+
    };
}

impl_widen_bits_to_pri_unsigned!(u8, u16, u32, u64, u128);

macro_rules! impl_widen_bits_to_pri_signed {
    ($($pri:ty),+) => {
        $(
            impl<const M: u16, S: Strategy>
                const Widen<$pri> for Bits<M, S, Signed>
            where
                S: BitsContainerFor<M, Signed>,
                <S as BitsContainerFor<M, Signed>>::T: ~const Widen<$pri>,
            {
                #[inline(always)]
                fn widen_to(self) -> $pri {
                    <_ as Widen<$pri>>::widen_to(self.to_raw())
                }

                #[inline(always)]
                fn widen_to_unmasked(self) -> $pri {
                    <_ as Widen<$pri>>::widen_to_unmasked(self.to_raw())
                }
            }
        )+
    };
}

impl_widen_bits_to_pri_signed!(i8, i16, i32, i64, i128);
```

Where-clauses constrain the cross-domain impls to (Pri, N, S, Sign)
tuples where the underlying carrier-side trait impl exists; trait
solver rejects unmatched combinations at the call site with a clear
unsatisfied-where-bound error.

## arvo-storage Bits ergonomic constructors

### `mock/crates/arvo-storage/src/bits.rs`

Add to the existing inherent impl block (currently lines 72-85):

```rust
impl<const N: u16, S: Strategy, Sign: Signedness> Bits<N, S, Sign>
where
    S: BitsContainerFor<N, Sign>,
{
    pub const fn from_raw(raw: <S as BitsContainerFor<N, Sign>>::T) -> Self {
        Self(raw)
    }

    pub const fn to_raw(self) -> <S as BitsContainerFor<N, Sign>>::T {
        self.0
    }

    /// Construct from a wider-or-equal-bit-width source via `Narrow`.
    ///
    /// Routes through `Src::narrow_to::<N>(src)` and wraps with
    /// `from_raw`. Source type `Src` is inferred from the value.
    pub const fn from_narrowed<Src>(src: Src) -> Self
    where
        Src: ~const arvo_bits_contracts::Narrow<<S as BitsContainerFor<N, Sign>>::T>,
    {
        Self::from_raw(src.narrow_to::<N>())
    }

    /// Construct from a narrower source via `Widen`.
    ///
    /// Routes through `Src::widen_to(src)` and wraps with `from_raw`.
    /// Source type `Src` is inferred from the value.
    pub const fn from_widened<Src>(src: Src) -> Self
    where
        Src: ~const arvo_bits_contracts::Widen<<S as BitsContainerFor<N, Sign>>::T>,
    {
        Self::from_raw(src.widen_to())
    }
}
```

Imports at the top of the file may need `arvo_bits_contracts::{Narrow,
Widen}` (or the where-clause uses fully-qualified path as shown). The
fully-qualified path keeps the imports tidy and avoids loose
top-level use statements.

If `arvo-storage` does not currently depend on `arvo-bits-contracts`,
update its `Cargo.toml` to add the dep. Per the L0/L0.5 dependency
direction documented in `mock/DESIGN.md.tmpl`, `arvo-storage` is L0
and `arvo-bits-contracts` is L0.5. The constructors taking refit
trait bounds inverts this: L0 reaches into L0.5 for trait
declarations. Two resolution paths:

1. Move `from_narrowed` / `from_widened` to `arvo-bits` (L1) as inherent
   methods on `Bits` reached via blanket impl. Keeps the L0/L0.5
   direction clean. Downside: methods aren't directly on Bits in arvo-
   storage; a separate use site must import `arvo-bits` to find them.

2. Allow arvo-storage to depend on arvo-bits-contracts. Inverts the
   layering. Downside: small layer-cycle introduction.

3. Move the `Narrow` / `Widen` trait declarations from arvo-bits-
   contracts back into arvo-storage. Symmetric with the round
   202604280034 merge of arvo-narrow-contracts into arvo-bits-
   contracts; this would be a similar consolidation move.

Choosing path 1 by default (cleanest layering, no merge churn). The
constructors land as inherent-on-Bits via a blanket-impl in arvo-bits.
Doc placement in `arvo-storage/DESIGN.md.tmpl` updates to point at the
arvo-bits home.

If path 1 turns out to require unergonomic Bits-method shapes that
inherent-method-via-blanket can't produce cleanly, fall back to path
2 with a brief note in the round about the layering inversion.

## arvo-bits re-exports + ergonomic constructor home (path 1)

### `mock/crates/arvo-bits/src/lib.rs`

Update the `pub use` block to include the refit family:

```rust
pub use arvo_bits_contracts::{
    BitAccess, BitLogic, BitPrim, BitSequence, HasBitWidth, IBitContainer, IBitPrim,
    Narrow, Narrowed, Widen, Widened,
    UBitContainer,

pub use arvo_strategy::{Hot, Strategy};
```

Add a blanket impl of `Bits::from_narrowed` and `Bits::from_widened`
as inherent-style ergonomic methods. Since Rust does not allow
inherent impls on foreign types, the methods land via a sealed
extension trait + blanket impl:

```rust
mod refit_constructors {
    use arvo_bits_contracts::{Narrow, Widen};
    use arvo_storage::Bits;
    use arvo_strategy::{BitsContainerFor, Signedness, Strategy};

    /// Sealed extension trait providing `from_narrowed` and
    /// `from_widened` constructors on `Bits`.
    ///
    /// The methods read as inherent-on-Bits at consumer call sites
    /// because the trait is sealed and the blanket impl covers every
    /// `Bits<N, S, Sign>` shape.
    pub trait BitsRefitCtor<const N: u16, S: Strategy, Sign: Signedness>
    where
        S: BitsContainerFor<N, Sign>,
    {
        fn from_narrowed<Src>(src: Src) -> Bits<N, S, Sign>
        where
            Src: ~const Narrow<<S as BitsContainerFor<N, Sign>>::T>;

        fn from_widened<Src>(src: Src) -> Bits<N, S, Sign>
        where
            Src: ~const Widen<<S as BitsContainerFor<N, Sign>>::T>;
    }

    impl<const N: u16, S: Strategy, Sign: Signedness>
        const BitsRefitCtor<N, S, Sign> for Bits<N, S, Sign>
    where
        S: BitsContainerFor<N, Sign>,
    {
        #[inline(always)]
        fn from_narrowed<Src>(src: Src) -> Bits<N, S, Sign>
        where
            Src: ~const Narrow<<S as BitsContainerFor<N, Sign>>::T>,
        {
            Bits::from_raw(src.narrow_to::<N>())
        }

        #[inline(always)]
        fn from_widened<Src>(src: Src) -> Bits<N, S, Sign>
        where
            Src: ~const Widen<<S as BitsContainerFor<N, Sign>>::T>,
        {
            Bits::from_raw(src.widen_to())
        }
    }
}

pub use refit_constructors::BitsRefitCtor;
```

Consumers `use arvo_bits::BitsRefitCtor;` (or pull the trait via the
arvo facade prelude) and call `Bits::<28, Hot>::from_narrowed(src)`
as if it were inherent. The trait is sealed (constructor methods are
visible only through this crate's blanket impl) so consumers cannot
add their own constructors via this trait surface.

If the const-trait + blanket impl approach hits a compiler limitation
(const trait + Self: Sized + auxiliary bounds), fall back to path 2:
move the constructors into `arvo-storage` directly with a layering
inversion noted in the round close commit.
