# SRC changelist: the source says two things the design has given up

Two sentences in shipped source state claims the design no longer makes, one of
them refused by a ratified ruling and one corrected by this round's doc phase.
Both are the same failure: the design moved and the source kept the sentence.

Three tests land with them, because each of the three routes named in the doc
phase is a property established by hand today and evaporating tomorrow if
nobody writes it down.

## CHANGE: `mock/crates/arvo-format/src/width.rs`

### What comes out

`:14` reads `Two types and no more. A count of bits, and a truth value.`, and
`:16` follows with `The coordinates a format is declared with are not a third
and a fourth of these`, which is the same bound stated from the other side.

`ruling::the_numeric_door_carries_the_coordinate_set_and_the_two_type_bound_is_not_canon`
is ratified by two independent experts and says it plainly: the bound the
question inherits, that the door is two types and no more, is a sentence in the
crate's design and appears nowhere in the canon. What the door carries out is
the coordinate set of the ratified parameterisation, spelled in types the stack
owns.

**The design half of this correction has already landed**, checked here rather
than assumed: the phrase is absent from `DESIGN.md.tmpl` and from `docs/FORMAT.md`,
with a control confirming the file is being read. So this is the source catching
up with a design that gave the bound up, and a reader trusting the source over
the design currently holds a bound the canon refuses.

**How many types it is stays unstated**, because the ruling says in its own
words that the count is outside what it ratifies: its two seats disagreed, one
answering a type per coordinate and the other more than two and fewer than ten.
Replacing one wrong count with another would be the same defect.

## CHANGE: `mock/crates/arvo-format/src/format.rs`

`:179` ships the doc phase's false half as rustdoc, which is published: **It
fires at codegen, not at `cargo check`**, so `cargo build` refuses and `cargo
check` does not. A const call site does refuse under `cargo check`, and the
guarantee is over the verbs that force the obligation rather than over the
declaration.

Replaced with what the design now says, in the shorter form rustdoc wants.

## CHANGE: `mock/crates/arvo-format/src/tests/`

Three arms, one per route, each asserting what the design now states rather
than what anybody wishes were true. **They are not catalogue-reds**: every one
of them passes today, and that is the point, since each pins a route the design
has just admitted exists.

- **`contains` answers for a format whose phase does not denote.** Declare one
  with a zero denominator, call `contains`, assert it returns rather than
  refusing. The route is readable without a probe and is the one a consumer
  reaches by accident.
- **An implementor disarms the default.** An impl writing `const ADMITTED: () =
  ();` compiles and the format is then usable at the forcing verbs. Written as
  a law that returns a verdict rather than an assertion, so the disarming impl
  lives on the right side of the suite.
- **A coordinate is readable off the impl without any obligation firing.**
  `<F as Format>::PHASE` reached directly.

**Each carries the negative control that would fail if the route were closed**,
so if a later round closes one, the arm fails loudly rather than passing for a
new reason.

The first two return 0 and returned 1 each before. The third is the control on
them, since two greps returning 0 from a file nobody is reading look exactly
like two greps returning 0 from a file that changed.

**`cargo mock test` reports two of ten trees failing here and that is the same
two `dev` reports**, not a regression this round introduces. The benches are
four manifests with no workspace root, and the lints tree carries the
`LintPack` type mismatch that `#96` exists to fix and that this branch, cut
from `dev` before it merged, still has. The `arvo-format` tree passes with the
three new arms in it.

**The diff is taken against the merge base rather than against `origin/dev`**,
because `dev` moved while this round was open and a diff against it reports
every file the two research merges added as deleted here. It names only the
files above.
