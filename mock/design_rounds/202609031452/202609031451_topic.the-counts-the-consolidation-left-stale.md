# the-counts-the-consolidation-left-stale

A pull request review over the trunk merge found three comments in `arvo-format`
whose numbers no longer match what the code and the design say. None of them
changes behaviour, and each of them is the kind of sentence a later reader
believes instead of counting for themselves, which is why they are being fixed
rather than left.

The first is the one the merge itself introduced. `obligations.rs` carries an arm
whose comment opens "The shortest route of the four". The design names three
routes at `crates/arvo-format/DESIGN.md.tmpl`, two that reach a value without
meeting the obligation and a third that passes a forcing site and defeats it
there. The section lead comment above the arms lists four items, and the fourth
is stated in the same comment as being about a different obligation reached
through a call, which is not a fourth route. So the lead comment is right and the
arm comment counted the lead comment's items rather than the design's routes.

The second is older and the merge made it worse. `tests/compile_fail.rs` opens by
enumerating its cases as one, then three, then two, then a last one, which is
seven against eleven `compile_fail` calls in the file. It was four short on the
trunk and this branch added the eleventh case without touching the paragraph. The
enumeration is worth keeping rather than deleting, because it says what each
group of cases is for and that is not derivable from the file names, so it gets
the four missing groups written in.

The third is a warning rather than a comment. The three fixtures the merge added,
`InvertedSlots`, `NeverCancelsOverAnInvertedRange` and
`NeverCancelsOverAnAdmissibleRange`, are used only in type position, so the test
build emits three `dead_code` warnings. They are typestate markers and the two
const assertions are what exercise them, so deleting them would delete the
evidence. The attribute goes on instead.

## What this round does not do

The review also noted that the previous round's source changelist says the
obligations module runs seventeen arms, where the command it names prints
seventeen and the module holds sixteen: the seventeenth is
`the_law_rejects_a_range_that_passes_the_easy_obligations`, which the substring
filter catches from another module. The changelist is locked and the round it
belongs to is closed, and a locked changelist is the audit trail of what was
claimed at the time rather than a document that gets corrected afterwards. The
correction is recorded here, where a reader of the round's directory will find
it, and the count itself was never load-bearing for anything.
