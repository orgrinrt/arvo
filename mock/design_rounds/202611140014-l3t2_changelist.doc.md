## CREATE: `mock/crates/arvo-digest/DESIGN.md.tmpl`

Sections, in order:

1. What this crate is: a digest is a function of bytes and a width, and nothing else; stable across
   sessions, machines and pointer widths, never cryptographic.
2. The canon it declares: `obligation::a_content_hash`, and the statement that no ruling places the
   crate, with op's answer named as the authority.
3. `Digest<const BITS: u16>`: the widths `Width<BITS>: Carrier` admits (32, 64, 128), each carried as
   the `arvo_numeral::Word` of that width, `raw` giving the word,
   `bits::<N>()` into `arvo_bits::Bits<N>` on the 32 and 64 bit digests, low bits kept, a width wider
   than the digest refused at compile time. Equality and copy, no ordering.
4. Input: `arvo_numeral::Bytes`, the host's byte image entering at `arvo-numeral`'s door, never a host
   integer anywhere in the crate, and why `core::hash::Hash` is neither implemented nor accepted (D7, D8).
5. `Fnv1a<BITS>` at 32 and 64: `of` as `const fn`, the reference constants.
6. `Xxh3<BITS>` at 64 and 128: `of` on xxhash-rust's runtime path with SIMD chosen by
   `cfg(target_feature)`, `of_const` on its `const fn` path, one value for the same bytes.
7. The switched digest, `Digest::<64>::of` and `of_const`: FNV-1a below the crossover, XXH3 from it on,
   one rule on both paths, the crossover part of the digest's definition, taken from the
   `digest-crossover` bench and its findings note, and pinned by tests on both sides.
8. What it does not do: no seed, no streaming state, no 128 bit switch, no consumer edits.
9. Tests: the reference vectors, the planted wrong vector per suite, const against runtime, the switch.
