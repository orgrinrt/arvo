# Src changelist: fixed-point mul review fixes

Round: 202606231218
Phase: IMPL
Scope: arvo (tests/fixed_point_mul.rs)

## CHANGE: replace out-of-range Precise test with in-range correctness

FILE: mock/crates/arvo/tests/fixed_point_mul.rs
WHY: the prior `i_mul_fixed_precise_saturates_on_overflow` passed raw 200 to an 8-bit-logical Precise
type (out of the logical range) and asserted the spuriously-saturated 2047. For in-range Precise operands
the 2x container holds the product so no saturation fires. The test now asserts the correct in-range
rescaled product. Precise container-vs-logical saturation on TRUE overflow is a pre-existing arvo-wide
question (existing Precise add/sub/mul all saturate at the container bound via saturating_max); tracked #3.

## CHANGE: add signed negative-operand guard tests

FILE: mock/crates/arvo/tests/fixed_point_mul.rs
WHY: the multiply had only non-negative coverage. Negative and mixed-sign cases pin the sign behaviour and
the arithmetic-shift (floor) rounding of the rescale.

## CHANGE: add catalogue-red for the deferred >64-bit-logical widen

FILE: mock/crates/arvo/tests/fixed_point_mul.rs
WHY: Hot/Cold 65..128 and Warm/Precise 33..64 (i128/u128 container) need a 256-bit WideBits intermediate
for the FRAC>0 multiply; currently non-widening (correct for FRAC==0, off by 2^F otherwise). An #[ignore]
catalogue test pins the intended behaviour and references task #3, per catalogue-edge-cases-as-tests.md.

## CHANGE: add I=0 (Q0.F) identity confirming test

FILE: mock/crates/arvo/tests/fixed_point_mul.rs
WHY: confirms x*ONE==x holds for a pure-fraction type. ONE=1<<F always fits the container (>= 1+I+F >= F+1
bits), so there is no overflow; the test documents the edge rather than guarding a bug.

## CHANGE: catalogue the arvo-wide Precise container-vs-logical saturation bug

FILE: mock/crates/arvo/tests/fixed_point_mul.rs
FILE: mock/crates/arvo-strategy/src/arith.rs
WHY: per op, the bad Precise behaviour must be loud. A #[ignore] catalogue red
(`i_mul_fixed_precise_should_saturate_to_logical_bound`) asserts the correct logical-bound saturation
(fails today: returns 625, should clamp to logical max 127). A source comment above the saturating macros
in arith.rs documents that every Precise op (add/sub/mul/div + fixed-point mul) clamps at the container
bound, not the logical bound the DESIGN contract promises, with a "fix before further Precise work" note.
