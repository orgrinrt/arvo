## Canon

`ruling::half_up_denotes_ties_toward_positive_infinity` governs what the lint refuses.
`ruling::the_rounding_mode_vocabulary` is what `OTHER_NAMES` below is drawn from: the six are
`toward_zero`, `floor`, `ceil`, `half_up`, `half_even` and `stochastic`, so the five that are not this
mode are candidate antecedents for a pronoun standing for a rounding rule. No row changes.

## CHANGE: `antecedent` binds to a name rather than to a backtick
File: `mock/lints/half_up_is_not_a_magnitude_rule/reading.rs`

`antecedent` refused to carry the mode's name past two backticks standing after it. That answers a
question about how the author punctuated rather than about what was named, and it is wrong in both
directions. Measured against a copy of the shipped module:

- `` `half_up` pairs with `q/2`; it sends a tie away from zero. `` is silent. A backticked `q/2` is not
  something a pronoun standing for a mode can mean, and it takes the carry away.
- `` `half_up` is not the HALF_UP of Java. That one goes away from zero. `` fires. That is the sentence
  of the control at `tests.rs:216` with the backticks removed, and the shape of the ruling's own note.
  The review reported this class as empty.

New `OTHER_NAMES`: the five other names of the six-name vocabulary with their `HalfEven`-style
spellings, the external constants this repository contrasts the mode with, `HALF_UP`, `ROUND_HALF_UP`,
`roundTiesToAway`, `roundTiesToEven` and `RoundingMode`, MATLAB's `Round`, `Fix` and `Convergent`, and
the ties-away alias's own names, `TiesAwayFromZero`, `ties_away`, `ties-away` and `alias`. The last
four are what a clause contrasting the mode against the alias names, and without them the clause at
`symmetry/tests/the_classification.rs:138` reads as the mode taking the reading. Matched with case and
bounded as a word, as `SPELLINGS` is. MATLAB's `Nearest` is deliberately not in it, because `Nearest`
is this mode rather than another one, which the parity suite asserts.

`antecedent` now carries the last spelling unless `OTHER_NAMES` names something after it.
Verification: `grep -c "match_indices('\`')" mock/lints/half_up_is_not_a_magnitude_rule/reading.rs`
returns zero, and `grep -c "OTHER_NAMES" mock/lints/half_up_is_not_a_magnitude_rule/reading.rs`
returns two, the declaration and the one place that reads it.

## CHANGE: a name is matched where a sentence opens on it, and not inside the denotation
File: `mock/lints/half_up_is_not_a_magnitude_rule/reading.rs`, `named_in`.

Two narrowings, each found by running the widened reader over this repository and each stated as a
rule rather than as a patch for the sentence that found it.

`capitalised` adds each name's sentence-initial spelling, because `OTHER_NAMES` is matched with case
and `Toward zero reads the sign of the slot` in `arvo-format/DESIGN.md.tmpl` is the same name opening
a sentence. `without_the_denotation` blanks every spelling of the denotation before the names are
looked for, because `floor` inside `floor(x + q/2)` is this mode's own definition rather than the
floor mode, and a reader taking it as another rule drops the name one clause before the clause that
gives the wrong reading. The blanking preserves byte length, so an offset into the result names the
same place in the original.

Verification: `every_other_name_defeats_the_carry` walks `OTHER_NAMES` whole and the pair added for
the capitalised case kills the `nocap` mutant; the sketch's `out/runs.txt` records both.

## CHANGE: a clause naming no rule is about what the clause before it named
File: `mock/lints/half_up_is_not_a_magnitude_rule/reading.rs`, `clause_hit` and `hits`.

`clause_hit` consulted the carried name only where the clause opened with a pronoun, read off the first
word. That is a second proxy for the same question and it loses every continuation that carries the
reading without a leading pronoun: "`half_up`: a tie goes away from zero.", the same at `;` and `?`,
and "`half_up` is a mode. Ties go away from zero under it."

New `names_nothing`, true of a clause holding neither a spelling of the mode nor an entry of
`OTHER_NAMES`, and not opening on a code span. The code span is what this reader knows about a subject
it has no vocabulary for: "`arvo-format` then asserted a tie at `-2.5` giving `-3`, which is away from
zero" is about a crate, and a reader carrying the mode into it reads a record of what was fixed as a
claim about what is.

`clause_hit` gains a branch: a clause that names nothing takes the carried name, falling back to the
doc block's item where nothing is carried. A clause opening with a pronoun keeps the rule it has,
taking the carried name and refusing the fallback, because a pronoun points back explicitly and the
item does not fill in for what the clause before it did not name. A clause naming another rule now
takes neither, where it used to fall through to the subject.

`hits` passes the carry through a clause that names nothing, so anaphora reaches across more than one
sentence: "`half_up` is a mode. It is nearest. Its tie goes away from zero." The carry is reach
limited rather than unbounded: a clause that names another rule ends it, and a clause that names
nothing and does not open with a pronoun ends it too, so a name reaches the clause after it and no
further unless a pronoun re-points. Without that limit the gloss of the two readings in
`question::which_operation_half_up_denotes` fires four clauses down. The blank-line reset is tested
first and is unchanged, so a clause ending in a newline still clears it.

Verification: `cargo test --manifest-path mock/target/mockspace-lints/Cargo.toml half_up` passes at 81
tests, and the corpus arms below hold.

## CHANGE: a clause stating the denotation before the reading is contrasting, not asserting
File: `mock/lints/half_up_is_not_a_magnitude_rule/reading.rs`, `denotation_before`.

A new escape beside `listed_apart` and `negator_binds`. A clause that states the settled denotation
and then names the other reading is contrasting the two, which is the shape of the ruling's own note
and of `the_oracle.rs:328`. The statement has to come first, because the order is what separates a
contrast from a clause that denies the denotation and then asserts the reading.

`DENOTES` moves here from `half_up_carries_its_note.rs`, which is where it was declared and where the
sibling lint still reads it from. Two copies of one list is the shape this round is correcting
elsewhere, so there is one.

Verification: `a_clause_stating_the_denotation_is_not_also_giving_the_other_reading` walks `DENOTES`
whole with a control that fires and a counter-arm for a denied denotation, and the `nodenote` mutant
is caught.

## CHANGE: the note lint's carve-out is asserted over the rows rather than argued
File: `mock/lints/half_up_carries_its_note.rs` module doc, and
`mock/lints/half_up_carries_its_note/tests.rs`

The module doc argued that the documents generated from the registry are excused because none of them
tells a reader what the name means, and that the rows which do state the denotation cite the ruling
in the same sentence. Nothing measured either half.

`no_registry_row_states_the_denotation_without_citing_the_ruling` reads
`mock/registry/*.toml`, cuts each file into its `[[..]]` rows, and requires every row stating the
denotation to carry the ruling's slug or the note's mark somewhere in it. Three controls: a planted
row with neither, walked over `DENOTES` whole and required to fire, against the same row citing the
ruling and the same row carrying the mark, both required to be silent; a citation in the row before,
required not to reach; and a row naming the mode with no denotation, required to be silent, which is
the other half of the module doc's argument.

It reads the rows rather than the documents they render into, and the reason is not convenience. The
registry-rendered documents under `docs/` are not committed, so an arm walking that directory is green
on a fresh clone because there is nothing there, which is the shape of a test that decides what not to
find out. The rows are tracked, are what a person edits, and every such document is a function of
them.

Run at the sentence granularity the module doc claimed, the arm reports nine sites across
`question.toml` and `ruling.toml`, the ruling's own `says` among them, which states the denotation
with the mark three fields further down. So the sentence was the wrong unit and the row is the right
one: a reader meets a row as one block on the page. The module doc is corrected to say the row, and
to name the arm that holds it.

`collect` and `line_of` become `pub(crate)` so the new lint reads the same surface rather than its own
copy of it. Where that walk belongs is a real question the generated lint crate's layout does not
answer: every `mock/lints/*.rs` has to be a lint, so a shared definition of the published surface has
no home except inside one of the lints that reads it. It stays where it is rather than moving to an
equally arbitrary place, and the question is recorded rather than answered here.

`is_crate_source` narrows to exclude a crate's tests under `src/`, whether spelled `tests.rs` or a
`tests/` directory. Rustdoc prints neither, which is the same argument the function already made for
`crates/*/tests/` and for a lint or a bench, so it is one rule rather than two.

`every_carve_out_still_names_a_sentence_that_is_in_the_file_it_names` reads the real tree, so a

`every_phrase_fires_in_a_document_and_in_rustdoc` walks the phrase list whole, and

## CHANGE: the alias sweep's completion is stated twice
File: `mock/crates/arvo-format/tests/ties_away/completion.rs`, new, and
`mock/crates/arvo-format/tests/the_ties_away_alias.rs`

`complete` was the one part of the oracle nothing double-stated, where the rounding half has
`brute_step` cross-checked against `oracle_step`. It is the other half of every expected value the
sweep forms, so a rearrangement error in it would have moved every cell at once with nothing left to
disagree.

`complete` moves into a new `ties_away/completion.rs` beside `brute`, which states the same completion
from the top of the index rather than the bottom: wrapping counts back from `hi` instead of forward
from `lo`, and saturating forms the position once with a checked add and clamps it instead of
comparing the slot against each end first. Neither is derived from the other. Both assert their
domain, a step of zero or one, which is what the rounding half produces and the only region the two
agree over.

`agrees` returns the cells agreed or the first disagreement rather than asserting, so an arm can
require a wrong spelling to be rejected. Five are planted: clamped before the step, the span one cell
short, wrapped without the step, the overflow taken to the floor, and saturated without the step.
`positions` walks both ends of the `i128`, the band around zero and both ends of each format's index
with three cells of margin, over the four signatures the sweep runs.

The file split is not cosmetic: `the_ties_away_alias.rs` stood at 471 lines against a `file-size` lint
set here at 500, so the second statement had nowhere to go in it.

Verification: `cargo test -p arvo-format --test the_ties_away_alias` passes at 10 arms with nothing
ignored; `the_two_statements_of_the_completion_agree_over_every_range_the_sweep_runs` agrees them and
`the_control_every_planted_completion_is_reported` requires each of the five to be caught.
