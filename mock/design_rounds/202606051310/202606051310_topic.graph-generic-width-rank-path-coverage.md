# Topic: wide-word test coverage for the rank, path, and spanning algorithms

**Date:** 2026-06-05
**Scope:** arvo-graph tests. Post-review coverage extension on the same branch as round 202606051246 (the row-word generalization).
**Source:** round 202606051246 generalized all seven BitMatrix-consuming algorithms over the row-word `B`, but `tests/generic_width.rs` only exercised three (`topo_sort`, `components`, `waist_detect`) at wider words. `upward_rank`, `downward_rank`, `longest_path`, and `spanning_tree` were generalized identically but covered only at `Bits<64>` by the prior suite. The generalization is mechanical (same bodies, same shared `Mask` / `BitMatrix` ops), so the risk that these four specifically break at a wide word is low, but leaving them uncovered at wide widths leaves the cap-lift claim partially unproven.

This round closes that gap: it adds wide-word assertions for the four remaining algorithms on the 129-node bowtie at `Bits<256, Hot, Unsigned>` / `Dim<129>`, the same wide-bucket fixture the existing wide-word tests use. Each assertion touches node indices at and beyond 64 (and beyond 128 for the wide-bucket path), so a row-word narrowed back to 64 would fail it.

## Changes proposed

Add tests to `tests/generic_width.rs` exercising `upward_rank`, `downward_rank`, `longest_path`, and `spanning_tree` at `Bits<256, Hot, Unsigned>` over the 129-node bowtie with unit weights. The expected rank values are small (sources 3, middle 2, sinks 1) and fit the 8-bit weight type the existing rank tests use. No source change; this is test-only.

## Out of scope

The pre-existing em-dash in `src/lib.rs:1` (a module-doc title separator not introduced by round 202606051246) is left for a separate writing-style sweep; this round touches tests only.
