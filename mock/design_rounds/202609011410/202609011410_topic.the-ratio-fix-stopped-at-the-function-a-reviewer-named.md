# Topic: the ratio fix stopped at the function a reviewer named

**Date:** 2026-09-01
**Phase:** TOPIC
**Scope:** `mock/crates/arvo-format/src/apply.rs`, `mock/crates/arvo-format/src/format.rs`, `mock/crates/arvo-format/src/apply/tests.rs`, `mock/crates/arvo-format/src/tests/the_predicate.rs`, `mock/crates/arvo-format/DESIGN.md.tmpl`

## Current state

Round `202609011250` fixed `Phase::of`, which read every non-positive denominator as one and so
discarded the value a negative one names exactly. It fixed that function and nothing else.

`Fraction::of` is the same shape one file over, and it was worse: `if den <= 0 { Self::ZERO }`, so
`Fraction::of(3, -7)` answered `0/1` for a ratio the pair represents exactly. Its own doc states the
same contract `Phase` states, that the denominator is positive and the tighter reading belongs
elsewhere, so nothing about the type made the two cases different.

**Two ratio constructors exist in this crate and both had the defect.** The grep that finds them is
`grep -rn "num: i64, den: i64" mock/crates/`, it returns exactly two lines, and it was not run. That
is the whole of the failure: the fix was applied to the instance a reviewer named rather than to the
property that made the instance wrong.

## The guarding tests could not have caught it, in the same way twice

`a_fraction_never_carries_a_denominator_that_cannot_divide` already existed, already swept negative
denominators, and asserted only `denominator() > 0`. Every input satisfied that while `of` was
answering `ZERO` for all of them. It is the identical shape the `Phase` sweep had before the last
round, written independently, which is what makes it a class rather than a slip.

The two `i64::MIN` pins that round added have the same hole one level down. They assert
`denominator() == 1` and never the numerator, so they do not notice that `Phase::of(3, i64::MIN)`
answers `+3/1` for a tiny negative value and `Phase::of(i64::MIN, -7)` answers negative for a large
positive one. Twelve lines above, the same test says a sign assertion alone never asks about the
value.

## The design says the door is two types and the crate has eleven

`DESIGN.md.tmpl` states that the coordinates are built through the numeric introduction door rather
than widening it, so the crate has no third primitive. Every one of the nine coordinate types wraps a
host primitive directly and hands one back: `Radix(u32)`, `Exponent(i32)`, `Magnitude(u32)`,
`MagnitudeCount(u32)`, `Slot(i64)`, `SlotCount(i64)`, `Arity(u32)`, `Phase{i64,i64}` and
`Fraction{i64,i64}`. Not one is built out of `Width` or `Bool`.

**The sentence is false as written**, and it is the sentence a later round reasons from.

`question::what_the_numeric_introduction_door_may_carry_out` is open on exactly this, with
`decider = "panel"`, and this round does not answer it. Correcting a false statement about what
shipped is not the same act as deciding what should ship, and the second is not a design's to make.

## Changes proposed

Normalise a negative denominator in `Fraction::of` as `Phase::of` now does, assert the value in both
sweeps rather than only the denominator's sign, say in both docs that neither sign nor magnitude
survives the two `i64::MIN` pairs, and correct the design's door sentence to say what is true while
leaving the open question open.
