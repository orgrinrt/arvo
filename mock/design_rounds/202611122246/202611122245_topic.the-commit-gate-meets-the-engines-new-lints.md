# Topic: the commit gate meets the engine's new lints

**Date:** 2026-11-12
**Governing canon:** none of the registry's rows is about the harness; the lints are the workspace's
own, at their declared severity, and nothing here lowers one.
**Where this came from:** arvo's `dev` at `d841c5e1`, under the engine at the head of mockspace `dev`
(`90b5319`), failed its own commit gate, so no commit in this repository could land. Tracked as
`arvo_dev_fails_its_own_commit_gate_21_lint_errors_from_the_e`. The coordinator asked for it cleared
on its own branch, as a defect fix standing alone, before the roadmap's arvo jobs go on.

## What failed, in the order it surfaced

First the custom-lint build. mockspace `17c9ddd` replaced a tool's one required declaration,
`not_a_lint()`, with `purpose()`, whose `Check(NotALint)` keeps the two reasons. The four tools under
`mock/tools/` (`awaiting-a-ruling`, `rounding-vocabulary`, `the-positions`, `unasked-questions`) still
declared the old item, so the cdylib did not build and no lint ran at all. Each keeps the reason it
gave, under `Purpose::Check`: three `NoFailingCase`, `the-positions` `TakesAQuestion`.

With the tools built, 21 errors from two lints the pack added.

`catalogue-ignore`, 19: every `#[ignore]` reason has to read `catalogue: <the gap>; tracked #<id>`,
and the id has to resolve, to a row of the registry by slug or to a row of a ledger file the project
names under `[lints.catalogue-ignore] ledgers`. Eighteen reasons had no `tracked` part, and one,
the `half_up` reader's `catalogue_case!`, wrote `#[ignore = $reason]` in the macro body, which is not a
literal the lint can read. Our tracker's ticket ids are not rows of arvo's registry, which has no
ticket namespace, so they resolve only through a ledger. muisti does the same with
`ledgers = "mock/catalogue.md"`. So:

- one ticket per distinct gap, filed with `ticket --repos arvo`, eleven in all (the line-scanning
  enforcers share three gap classes across four lints, so those are one ticket each, not one per
  test; the `half_up` reader's eighteen entries are one gap, the reader's misattributions, and its
  `promotion` test at `:527` is the same gap as entry 7);
- `mock/catalogue.md`, a ledger listing each id as a row with its gap in a line;
- `[lints.catalogue-ignore] ledgers = "mock/catalogue.md"` in `mockspace.toml`. This names where an id
  resolves. It lowers no severity and exempts nothing;
- each reason gains `; tracked #<id>`. The macro takes the attribute at its call,
  `$(#[$attr:meta])*`, so each entry's own reason stays at the entry and is now a literal.

`no-superseded-citation`, 2. `mock/crates/arvo-strategy/DESIGN.md.tmpl:5` declared both
`ruling::each_preset_names_a_stated_intent` and its successor,
`ruling::the_strategy_intents_are_not_clear_cut`; the superseded one leaves the list, and the
successor stays. `mock/lints/no_prose_citation_into_nothing.rs:1048` used the superseded
`proposal::a_min_plus_fold_needs_an_absorbing_top_and_wrapping_supplies_none` as the registered row
of the fixture for "a cut after the separator resolves"; the fixture now registers the successor,
`proposal::a_min_plus_computation_needs_monotonicity_as_well_as_an_absorbing_top`, and cites it cut
after a separator, which is the same case. The module doc's history of the corpus still names the
old row as the shape it found, which the lint does not read as a citation.

## What this does not do

It closes none of the eleven gaps; it says where each is tracked. It does not touch any lint's
severity, and it changes no crate's behaviour: the one crate source file in it, `arvo-placement`'s
`src/tests.rs`, changes an ignore reason only.
