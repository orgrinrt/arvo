# Topic: the trunk's refusal and this branch's three are one file

**Date:** 2026-09-01
**Phase:** TOPIC
**Scope:** `mock/crates/arvo-format/tests/compile_fail.rs`, `mock/crates/arvo-format/DESIGN.md.tmpl`

## Current state

`compile_fail.rs` gained arms on both sides of a divergence. The trunk added
`an_arvo_type_as_a_const_parameter_is_refused`, which pins that a coordinate type cannot be the type
of a const generic parameter. This branch added three that pin what the coordinate types buy: a host
integer at a coordinate, an index against an extent, and a phase against a fraction.

Neither side knew about the other's, so the file conflicts. The two additions are independent: they
name different refusals, they compile independently, and all five arms pass together.

## Why this is consolidated rather than selected

Taking one side loses real refusals. The trunk's arm is the one the crate's const generic parameters
are spelled around, and this branch's three are the ones that could not have been written before the
contract carried its own types. There is no version of this file that should hold four.

The file's module doc says "the other three", which was true of this branch alone and is not true of
the merge. Off by one in a sentence a reader uses to know whether the file is complete.

## What the design says about the position

`DESIGN.md.tmpl` states that nothing in the coordinate set touches a const generic parameter, that
they are excepted, and that `question::the_width_surface_crossing` is open on that surface. It states
it and nothing holds it: the refusal that makes the sentence true lives only in the trunk's test file,
and the design does not say a refusal pins it.

## Changes proposed

Consolidate the five arms, correct the count in the module doc, and have the design name the refusal
that holds its own const generic parameter sentence up.
