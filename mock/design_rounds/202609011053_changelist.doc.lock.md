# Doc changelist: the contract's coordinates get types the stack owns

**Date:** 2026-09-01
**Round:** the format contract is spelled in host primitives
**Scope:** `mock/crates/arvo-format/DESIGN.md.tmpl`, `mock/crates/arvo-format/README.md.tmpl`

The design states what an implementor supplies, and it states it as `PHASE_NUM` over `PHASE_DEN`,
`BASE`, `SLOPE`, `MAGNITUDES`, `MIN`, `MAX`, `RADIX`, `SIGNED` and `ARITY`, with no word about what
type any of them carries. That silence is what let the source spell every one of them with a host
primitive, and it is why the document has to move before the source does.

## CHANGE: the contracts table FROM naming coordinates TO naming their types
File: `mock/crates/arvo-format/DESIGN.md.tmpl`
Verification: `grep -c 'PHASE_NUM' mock/crates/arvo-format/DESIGN.md.tmpl` returns zero, and the table
row for `Format` names `PHASE` and `Phase`.

Every row of the table gains the type of each coordinate it names. `Format` loses `PHASE_NUM` and
`PHASE_DEN` and gains one `PHASE` of type `Phase`, which is what the ratified parameterisation
carries: a phase, one coordinate.

## CHANGE: a section naming the coordinate types FROM absent TO present
File: `mock/crates/arvo-format/DESIGN.md.tmpl`
Verification: `grep -c 'Radix\|Exponent\|Magnitude\|MagnitudeCount\|Slot\|SlotCount\|Arity\|Fraction\|Phase'`
over the template returns a nonzero count for each name, and `undocumented-type` reports none of them.

The section says what each coordinate is, where its type lives, and why it lives there rather than in
one coordinates module: each sits in the file that declares the trait it is a coordinate of, because
one file is one topic and a coordinate belongs with the contract that reads it.

It also carries the reason the whole round exists, which is that an implementor outside this crate has
to write these types and is refused by the bare-primitive lints for every one of them that is a host
primitive. `proposal::the_concept_is_closed_and_the_inventory_is_open` says admission is a check
rather than a negotiation, and a contract nobody can implement without editing a lint config has made
it a negotiation.

## CHANGE: the two-primitives section FROM claiming the door is two types TO saying what the coordinates are built through
File: `mock/crates/arvo-format/DESIGN.md.tmpl`
Verification: the section still names `Width` and `Bool` as the two primitives and no longer reads as
though nothing else in the crate is a stack-owned type.

`Width` and `Bool` stay the two primitives and the door stays as narrow as the section promises. What
changes is the sentence that reads as though everything else is built from a `Format`, since the
coordinate types are neither primitives nor formats and the document has to account for them.

## CHANGE: the free-function list FROM a bare enumeration TO one that says what they return
File: `mock/crates/arvo-format/DESIGN.md.tmpl`
Verification: the paragraph naming `contains`, `slot_in_range` and their neighbours says the
predicates return `Bool`.

Small, and it matters because the source change moves every predicate's return from `bool` to `Bool`,
and a design that listed the functions without their shape would say nothing about what moved.

## CHANGE: the README's closing paragraph FROM silent on the coordinates TO naming them
File: `mock/crates/arvo-format/README.md.tmpl`
Verification: the file stays inside the three-to-ten-line bound and mentions that the coordinates
carry the stack's own types.

One sentence. A README is short by rule and this is a fact about the crate's surface a reader lands
on, not a design argument.

## What does not move

**No registry row.** The round changes a design and the source under it, and the canon rows it rests
on are already there and already say what they need to: `obligation::a_primitive_for_every_position_a_bare_number_would_take`
for the constraint, `ruling::the_operating_constraints_are_intents_and_rules` for it being in force,
and `proposal::the_concept_is_closed_and_the_inventory_is_open` through
`ruling::the_format_spine_is_canon` for why an unimplementable contract is a defect rather than a
preference. Writing a row here would be recording the panel's own repair as canon, which is not what
the namespace is for.

**No root template.** `mock/DESIGN.md.tmpl` and its siblings describe the workspace and say nothing
about which type a coordinate carries.

**Nothing about the const generic surface.** The design's width bound section stays exactly as it is.
Op excepted const generic parameters by name and `question::the_width_surface_crossing` is open on
that surface with the panel as its decider, so a design edit there would be filling a reserved
question as a side effect of a typing round.
