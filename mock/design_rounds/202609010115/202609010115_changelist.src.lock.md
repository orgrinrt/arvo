# Src changelist: the exact step moves to a carrier that holds it

**Date:** 2026-09-01
**Round:** the value-path round
**Scope:** `arvo-format/src/apply.rs` and its tests.

## CHANGE: the exact step FROM `i64` TO a carrier wide enough to hold it
File: `mock/crates/arvo-format/src/apply.rs`
Verification: a consumer wrapping `i64::MAX` into `[-1, 5]` returns `0` under both settings of
`overflow-checks`, and no `i64` arithmetic remains on the value path.

**Reproduced first, with both controls passing.**

```
complete_slot(Wrap, 3, -1, 5)         -> 3    control, in range
complete_slot(Wrap, 8, -1, 5)         -> 1    control, ordinary out of range
complete_slot(Wrap, i64::MAX, -1, 5)  -> 5    at overflow-checks = off
                                      -> panic at apply.rs:194 at on
```

**The correct answer is 0**, since the span is 7 and `i64::MAX - (-1)` leaves remainder 1. So the
shipped code does not merely overflow: it returns a wrong value **inside the representable range**,
which no consumer can distinguish from a right one. The other cell is a runtime panic, which
`ruling::never_a_runtime_check_and_one_lowered_path` forbids outright.

`proposal::arithmetic_on_a_format_factors_as_an_adaptation_of_an_exact_operation` is ratified and says
arithmetic is an exact operation in an ambient domain composed with a total adaptation onto the
representable set. The code performed the exact step in the set's own carrier. It now performs it in a
carrier that holds it and adapts afterwards, which is the ratified sentence read literally.

**No guard, and that is the point.** With the intermediate wide enough there is no case to catch, so
the function is total on every value of its parameter type rather than on a subset something would have
to check for.

## CHANGE: `round_slot` and `complete_slot` FROM `pub` TO internal
File: `mock/crates/arvo-format/src/apply.rs`
Verification: `grep -c 'pub const fn round_slot\|pub const fn complete_slot'` returns zero, and nothing
outside `apply` referenced either before the change.

`DESIGN.md.tmpl` says the map is one map with two regions and not two mechanisms, and never named
these as surface. **Bringing the code to the design rather than changing the design.**

This is also what removes the finding's first half: a range stops being four loose parameters on the
public surface, because the surface is `adapt`, which takes its range from the declared signature.

## CHANGE: `adapt` FROM reading a range TO forcing its admission
File: `mock/crates/arvo-format/src/apply.rs`
Verification: a rogue `Slots` implementor used through `adapt` does not build.

Finding one says nothing tied `min` and `max` to a range that passed the admission obligation. Reading
an associated const does not force `ADMITTED`, so `adapt` forces it. **That tie was genuinely absent**
and is the half of the finding that the arithmetic change does not address.

## CHANGE: the tests FROM one small range TO the edges of the type
File: `mock/crates/arvo-format/src/apply/tests.rs`
Verification: the file references `i64::MIN` and `i64::MAX`, and a law reports on a construction rather
than only asserting on one.

Thirty references to one small pair and none to the edges of `i64` meant every arm fed a range where
the arithmetic could not leave the type, so the breaking path was never entered. That is setup that
helps, and it is why five passes of review found this rather than the suite.

The new arms take the shape `is_admissible` already uses: `wrap_of` and `saturate_of` return the
answer, tests assert what they return at the edges, and the case that used to be wrong is asserted at
its correct value rather than at whatever the code produces.

## What is deliberately not here

**No change to what the adaptation means**, to the rounding modes, to the overflow policies, or to
which arm packs.

**No new public surface.** Two public functions are removed and none added.

## How this changelist expects to be checked

`cargo test --workspace` in `mock/`, and the same counts under `--release`. `cargo mock check` green at
strict. The consumer reproduction in `mock/research/sketches/value-path/` returning the same answer
under both settings of `overflow-checks`.

## A note on how the new arms avoid agreeing with the code by construction

`wrap_of` in the tests computes the same formula the crate computes. That is deliberate and it is not
circular for the thing it is checking: the two differ in **carrier**, so an arm comparing them catches
a carrier defect, which is precisely the defect this round is about. It would not catch a wrong
formula.

So it is paired with `the_edge_answers_are_the_ones_worked_out_by_hand`, which asserts `-1` and `0` as
constants derived on paper from the span and the remainder rather than from any expression in the
tree. That one catches a wrong formula and the sweep catches a wrong carrier.

**Both were checked by mutation rather than assumed.** Putting the exact step back into the narrow
carrier fails three of the new arms, including the hand-computed one. Every arm that existed before
this round still passed under that mutation, which is what "the breaking path was never entered"
means in practice.
