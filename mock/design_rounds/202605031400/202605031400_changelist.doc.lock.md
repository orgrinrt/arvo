# Doc CL: foundational redesign — doc template changes

This changelist enumerates every `.md.tmpl` template that needs editing during the DOC phase of round #316. It is a mechanical execution plan: per-crate, per-file, what's added, what's removed, what's reshaped. The src CL is written *after* this doc CL locks; source changes are out of scope here.

## Decisions this CL implements (locked in topics)

From original topic + corrective topic, these decisions drive the documentation rewrites:

- D1: Hot strategy = single marker, **align(16) baseline only** (corrective downscope from cfg-driven tier matrix).
- D2: N ≤ 128 → native primitives (u8/u16/u32/u64/u128 or signed); N > 128 → WideBits<bytes_for(N)>.
- D3: Delete `UContainerFor` + `IContainerFor`; unified `BitsContainerFor<const N: Width, Sign: Signedness>` only. No deprecation shims.
- D4: `const N: Width` in every projection trait. Width newtype relocates from arvo-storage to arvo-strategy.
- D5: Single per-Strategy impl via Pattern C (const-tag dispatch through `Project<TAG, Sign, BYTES, S>` helper trait). 22 impls total replacing 2048+ per-N×Sign×Strategy entries.
- D6: `MultiContainer<HiT, LoT>` + `MultiContainerHalf` deleted entirely.
- C1: Byte-ordering convention: bit 0 = LSB of byte 0; `trailing_zeros` walks from byte 0 upward; `leading_zeros` walks from highest-index byte downward. Mirrors MultiContainer's lo-first semantics; preserves observable behaviour.
- C3: 128-bit boundary defended as **rustc primitive ladder**, not hardware-instruction boundary.

### O1. `mock/crates/arvo-storage/DESIGN.md.tmpl`

**Change shape: substantive — new storage primitives introduced.**

This template currently describes Bits, Bool, USize, MetaCarrier (and possibly more storage shapes). The redesign introduces WideBits + AlignedWideBits16 here.

**Remove**:
- Any references to MultiContainer as a storage shape (it lived in arvo-strategy but was sometimes mentioned here as the wide-storage backend).

**Add new sections**:
- **`WideBits<const BYTES: usize>`** (new file in src: `src/widebits.rs`):
  - `repr(C)` with `bytes: [u8; BYTES]` field.
  - Align-1, exact size = BYTES.
  - BitPrim impl with byte-by-byte composition.
  - **Byte-ordering contract** (per C1): bit 0 is the LSB of byte 0; trailing_zeros walks from byte 0 upward (consistent with `u128::trailing_zeros` semantics where bit 0 is the low bit); leading_zeros walks from byte BYTES-1 downward. This mirrors the existing MultiContainer lo-first convention.
  - Size envelope: BYTES = 1 to 8191 (Width=u16 → max 65535 logical bits → max 8192 physical bytes; one byte slack for type-system overhead).

- **`AlignedWideBits16<const BYTES: usize>`** (new file: `src/aligned_widebits.rs`):
  - `repr(C, align(16))` with `bytes: [u8; BYTES]` field.
  - Size = round_up(BYTES, 16); align = 16.
  - Used by Hot strategy for N > 128.
  - Trailing pad bytes are uninitialized; reading the full struct as bytes via transmute or raw-pointer cast is UB. Only `as_bytes() -> &[u8; BYTES]` is safe (per audit L2).
  - Same BitPrim impl as WideBits (only the storage layout differs).

- **Width re-export** (Width newtype now lives in arvo-strategy):
  - `pub use arvo_strategy::Width;` in arvo-storage/src/lib.rs.
  - The doc template notes the relocation rationale (projection traits in arvo-strategy require Width in const-generic position; bridge-home rule applies).

- **`MetaCarrier` (existing, unchanged)**: stays in arvo-storage. ConstParamTy_ carrier; carries Width but doesn't define it.

### B1. `mock/crates/arvo-bits-contracts/DESIGN.md.tmpl`

**Change shape: substantive — MultiContainer BitPrim impl section deleted; WideBits BitPrim impl section added.**

This crate currently houses the canonical `BitPrim` impl on `MultiContainer<HiT, LoT>` (per Round 1 SRC CL line 92). That impl is gone with #316; the new BitPrim impl is on `WideBits<BYTES>`.

**Remove**:
- The entire "BitPrim impl on MultiContainer" section.
- Any references to `MultiContainerHalf`.
- The half-by-half cascade narrative for trailing_zeros / leading_zeros / count_ones / etc.

**Add**:
- New section: "BitPrim impl on WideBits<const BYTES: usize>".
- Methods composed byte-by-byte; per the byte-ordering convention (C1):
  - `count_ones`: sum of `bytes[i].count_ones()`.
  - `count_zeros`: `BYTES * 8 - count_ones()`.
  - `trailing_zeros`: walk from byte 0; if bytes[0] == 0, accumulate 8 and advance; else return accumulated + bytes[i].trailing_zeros().
  - `leading_zeros`: walk from byte BYTES-1 downward symmetrically.
  - `get_bit(idx: USize)`: `(bytes[idx/8] >> (idx % 8)) & 1`.
  - `with_bit_set` / `with_bit_clear` / `with_bit_toggled`: as expected from the bit indexing.
  - `is_zero`: all bytes zero.
  - `clear_lowest_set_bit`: locate byte, apply `b & (b-1)` semantics.
  - `bitand` / `bitor` / `bitxor` / `bitnot`: byte-wise.

- New section: "BitPrim impl on AlignedWideBits16<const BYTES: usize>": same surface; only storage differs. The impls compose through the same byte-indexed access (`as_bytes()` returns `&[u8; BYTES]` regardless of trailing pad).

- Cite sketch 02 for the byte-by-byte ops surface; cite sketch 04 for the SIMD-augmented variants that #320 will land on top.
