## arvo (facade)

The `bitfield!` macro in `mock/crates/arvo/src/bitfield.rs` retains
the inline `1u64 << N` / `u64::MAX` patterns. Routing them through
`<u64 as BitPrim>::mask_low(USize(N))` at the macro-expansion site
adds substrate-call overhead inside macro-generated const-fn bodies
where the existing `1u64 << N` is already optimal. The lint:allow
markers on those sites remain valid per D-7 (tracked: #256). Defer
to a follow-up round (Round 5 #315) if a substrate-wide audit later
finds value in moving the dispatch through the trait method.

## arvo-bitmask MaskOps trait impls

`MaskOps<const W: Width>` lives in `arvo-mask-contracts` (renamed
from `Mask` per Decision D). Concrete impls on
`Mask<Bits<64, Hot, Unsigned>>` and `Mask<Bits<256, Hot, Unsigned>>`
are deferred to Round 5 (#315). The chassis `Mask<W>` already exposes
every method MaskOps would dispatch through (empty/full/insert/remove/
contains/count/union/intersection/difference/complement) as inherent
methods routed via `BitLogic` / `BitSequence` / `BitAccess`. The
trait impl is wrapper-only sugar; landing it does not change runtime
behavior, and consumers calling chassis methods directly already get
the substrate routing. Round 5 lands the trait impls when the wider
ConstHash / ConstFrom bridge family is wired so the const-trait
impl signatures stay consistent across L0.5.
