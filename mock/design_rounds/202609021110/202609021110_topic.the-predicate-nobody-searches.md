# The predicate the suite partitions on is derived, and nothing in the suite searches it

Two properties in `the_ratio_coordinate.rs` split the matrix on
`has_an_exact_form`, a helper that decides whether `n/d` has a form the
coordinate can hold. Property 3 asserts exactness where it says yes, property 4
asserts the saturating bound where it says no. So the helper decides which of
the two laws every pair is tested against, and if it is wrong the suite tests
the wrong law and passes.

It is not wrong. It was derived, and an exhaustive search agreed with it at
every width from three bits to eight. The search lives in
`mock/research/sketches/202609021019_the-fraction-decision/`, which is committed
and citeable, and the helper's own doc comment says so.

What is missing is that the search does not run. A later reader doubting the
partition has to go and rerun a sketch to find out whether it still holds, which
is the thing a suite exists to stop. And the helper reproduces the
implementation's own branch condition, so a change to one that should have moved
the other leaves both agreeing with each other and disagreeing with the
arithmetic. Nothing in the tree would say so.

A brute-force check at a narrow width closes it. The exactness question is about
divisibility and sign, so the shape of it does not depend on the carrier being
64 bits: search every pair at eight bits, compute the exact answer, and assert
the helper agrees with what the search found. That runs in the suite, in
milliseconds, and fails if either side moves without the other.

A second, smaller thing in the same file. The widening arm carries a binding
whose comment was corrected last round to say the case it was reaching for does
not exist. The assertion left under that comment checks that an even numerator
over two is whole, which is true and has nothing to do with the widening it sits
under. The arm's real control is the binding after it, which checks that an
ordinary tie is still detected as one. The leftover reads as though it were part
of the control and is not.
