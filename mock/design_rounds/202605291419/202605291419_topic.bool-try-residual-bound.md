`core::ops::Try::Residual` gained the bound `: Residual<Self::Output>` between nightly-2026-03-28 (where it was the unbounded `type Residual;`) and nightly-2026-05-28. arvo-storage's `Bool: Try` declares `type Residual = core::convert::Infallible`, and bare `Infallible` no longer satisfies the bound: `core::ops::Residual` is implemented only for `Option<Infallible>` / `Result<Infallible, E>` / `ControlFlow<B, Infallible>`, and the orphan rule forbids arvo from implementing `core`'s `Residual` for the foreign `Infallible`. So arvo-storage stops compiling on the pinned nightly. This is an unstable-feature (`try_trait_v2`, WATCH) core evolution, not a soundness regression; the 2-month-stale local nightly hid it until the toolchain pin forced a full-stack build.

`Bool`'s `Try` is infallible: `branch` always returns `Continue`, the residual is the uninhabited case. The fix preserves that exactly, replacing the foreign `Infallible` residual with an owned uninhabited type, the same shape notko applied to `Just` and the same shape `core` itself uses internally (`NeverShortCircuitResidual`). `?` on a `Bool` keeps extracting the inner `bool` with zero runtime cost.

## Decision

Adapt `Bool`'s core `Try` to an owned residual; keep `?` ergonomics.

- Add `pub enum BoolResidual {}` (uninhabited) to `arvo-storage` platform module, re-exported at the crate root alongside `Bool` (the public `Try` impl exposes it, so it must be `pub` and reachable; a private residual on a public `Try` impl is E0446).
- `impl Try for Bool`: `type Residual = BoolResidual` (was `Infallible`); `branch -> ControlFlow<BoolResidual, bool>`; `impl FromResidual<BoolResidual> for Bool`.
- Add the paired `impl Residual<bool> for BoolResidual { type TryType = Bool; }` (the bound's reverse direction).
- Enable the gate: `#![feature(try_trait_v2_residual)]` in `arvo-storage/src/lib.rs` (unconditional, matching the existing `#![feature(try_trait_v2)]`).
- `Bool`'s `notko::ConstTry` / `ConstFromResidual` impls are UNCHANGED: notko's `ConstTry` trait carries the unbounded `type Residual;`, so `Residual = Infallible` stays valid on the const path.

## Consequences

- `arvo-storage/DESIGN.md.tmpl` line 284 ("`Bool` implements `Try` with `Residual = Infallible`") becomes "`Residual = BoolResidual`"; the const-path lines (289 to 291) stay. The doc CL carries this.
- This round bundles two non-gated config changes committed alongside the source: the `rust-toolchain.toml` pin to `nightly-2026-05-28` (the pin cannot build arvo without this Bool fix, so they ship together), and enabling notko's `try_trait_v2` feature in `mock/Cargo.toml` (so notko's `?`-on-`Maybe`/`Outcome`/`Just` impls compile in arvo's build and the previously-dormant pathway is exercised, per the workspace decision to enable it across consumers).
- `BoolResidual` is an uninhabited marker, not a numeric type, so it carries no `S: Strategy`.
