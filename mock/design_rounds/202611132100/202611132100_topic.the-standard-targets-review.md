**Date:** 2026-11-13
**Job:** `arvo-standards`, branch `work/arvo-standards`.

## Current state

Round `202611131910` declared IEEE 754's interchange formats in `standards::ieee754` and gave each
standard a parity suite. The review at `f0eeb2e3` found the parameterisation correct and the verdict
do not merge, for these:

1. The directions are re-exported under the standard's names with `pub use ... as`, which takes over
   the path rustc prints for the shipped modes, so eleven of `arvo-numeral`'s compile-fail cases print
   `RoundTowardZero` where they expect `arvo_format::rounding::TowardZero`.
2. The obligation's `gap` says every binary format is tested under every direction but ties away;
   binary16 and binary64 ran ties to even only.
3. There is no arm for `roundTiesToAway`, which IEEE 754 requires of a decimal format, though the alias
   can be written from the public surface.
4. The decimal oracle is said to read no arvo code and reads its exponent range from the format.
5. `Significand<A, P>` reads the radix and not the sign, so an unsigned ambient and a precision of zero
   both build an admitted format.
6. The root readme still says MATLAB is the only convention named.
7. The fimath sweep runs at one shape, `Fi<8, 0>`, and never at `UfiMath`.

The others: the binary32 test that pins the shipped `Floating` checks declarations against
declarations; summary lines past 80 characters; casts and primitive locals in the new impl bodies; and
the provisional stamp the old topic named without its id, which is ticket
`where_arvo_s_standard_declarations_live`.

## Changes proposed

The directions become type aliases, which rustc does not print in place of the path they name.

The significand states its obligation: an IEEE significand is sign and magnitude, so its ambient is
signed and its precision is at least one, asserted in a const its bounds force, so `adapt` and every
reader of the range refuses the construction where it is used. Two compile-fail cases show it.

The integer digit rule moves into the suites' shared module, written over any radix and over the
standard's five directions in its own words, with each format's precision and exponent range written in
as the standard's numbers. Decimal32 and decimal64 then run under all five directions, ties away through
the alias. Binary16 runs under the four the binary formats carry, against the same rule, beside its
published encodings, and binary64 runs under the four against the host stepped by bits, as binary32
does. One landing composition serves both a declared signature and the ties-away alias, so the search
over magnitudes is written once.

The fimath sweep runs over a matrix of shapes, signed and unsigned, from one bit to sixty-four and at
several fraction lengths, with the rules and both actions computed from the shape, and the planted arms
at every shape.

The `Floating` test sweeps the shipped point through the landing against the host and asserts exactly
one miss, the member `-2^128`.

The readme names both conventions. The `gap` is reworded to what the suites hold.

The casts in the impl bodies stay. The coordinate types are newtypes over host integers with
constructors and readers and no arithmetic, the crate's other impl bodies compute the same way, and a
change there is the overhaul lane's.
