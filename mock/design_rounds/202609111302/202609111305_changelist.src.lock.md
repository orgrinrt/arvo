# Src changelist: the width walk covers the verdict, the phase parts settle at compile time

**Date:** 2026-09-11
**Round:** review fixes on the admitted-addition round (branch `feat/admitted-addition-on-a-declared-signature`)
**Scope:** executes the doc changelist locked as `202609111302_changelist.doc.lock.md`.

## CHANGE: `Addable<F>` FROM no associated const TO `const PHASE_PARTS: PhaseParts`

File: `crates/arvo-format/src/addition.rs`

`phase_parts::<F>(1)` was called fresh inside `remainder_is_held`, `sum_is_carried`, `sum_position` and
`addition_reach` (the last through `addition_is_associative`, which reads `addition_reach` and then
re-derives the same triple a second time). All four calls depend on `F` alone, so the euclidean division
and reduction settle once, at monomorphisation, as `Addable::<F>::PHASE_PARTS`. `addition_reach` keeps the
free function's general form (`phase_parts::<F>(operands - 1)`) reachable in principle but asserts
`operands - 1 == 1` at compile time before reading the cached copy, so the cache and the comment claiming
addition's arity is two cannot drift apart silently.

`phase_parts` returned a bare `(i128, i128, i128)`, which `a-contract-coordinate-is-not-a-host-primitive`
refuses in a `const` declaration's type. Named the triple `PhaseParts { whole, rem, den }`, private to this
file, and every call site now destructures the struct instead of the tuple.

Verification: `grep -n 'phase_parts::<' crates/arvo-format/src/addition.rs` shows one call site left, the
const's own initialiser; every other reader shows `Addable::<F>::PHASE_PARTS` or
`Addable::<S::Format>::PHASE_PARTS`. `cargo test -p arvo-format --lib addition::` green confirms no verdict
moved. `cargo mock check --commit` clears the lint.

## CHANGE: `the_verdict.rs` FROM two width-bound-only checks TO two checks over `dispatch::every_width`

File: `crates/arvo-format/src/addition/tests/the_verdict.rs`

Two tests added, after `a_licensed_cell_never_diverges_and_a_whole_phase_verdict_is_exact_both_ways`:

- `the_verdict_holds_a_witness_or_a_sample_over_every_admitted_width` walks `dispatch::every_width`
  (`Integer<1..=62>` and `UFixed<1..=62,0>`, 124 formats, every mode and shipped policy). For a refused
  whole-phase cell it builds the design-named witness, one past the top or one past the bottom of the
  reach, from `pair_for_sum`, and asserts it diverges through the real `add` function. For a licensed cell
  it asserts `boundary_members`' sample of sixteen triples never diverges.
- `the_verdicts_licensed_half_holds_at_the_widest_ranges_under_a_fractional_phase` covers the same
  licensed-cell claim at `Signed<62>` and `Unsigned<62>` under a third and a half, the same four formats
  `the_operation.rs`'s fractional-phase totality test already carries, since the associativity section's
  claim is not stated as whole-phase-only.

`boundary_members` is used rather than `edges`: the associativity verdict is quantified over stored
operands, and `quantifying_over_the_ambient_domain_refuses_a_format_that_is_associative` (pre-existing)
already pins that a format holding over its stored range can fail once an ambient, out-of-range value
enters. `edges` deliberately reaches past the stored range for the totality claim it was built for;
reusing it here would test a different, stronger claim the design does not make.

Also: `the_count_and_the_verdict_do_not_move_with_the_fraction_width_or_the_radix` asserted every count in
its fractional-phase cross equalled the first without ever pinning what the first was, so a map that
stopped diverging entirely at a fractional phase would pass vacuously. Pinned to `952`, the value the
existing whole-phase cross establishes for the same claim.

Verification: `cargo test -p arvo-format --lib addition::the_verdict::` green;
`grep -n 'assert_eq!(first, 952)' crates/arvo-format/src/addition/tests/the_verdict.rs` shows the pin.

## CHANGE: shared test helpers FROM `edges` local to `the_operation.rs` TO `mod.rs`, plus two new helpers

File: `crates/arvo-format/src/addition/tests/mod.rs`, `crates/arvo-format/src/addition/tests/the_operation.rs`

`edges` moved from `the_operation.rs` (local `fn`) to `mod.rs` (`pub(super) fn`), unchanged, since
`the_verdict.rs`'s new width-walk tests read it for the divergence witness's `pair_for_sum` construction
alongside the totality tests that already used it. Two new shared helpers: `boundary_members` (the four
stored-range extremes a licensed-cell sample draws from) and `pair_for_sum` (the operand pair summing to a
target, used to build the design-named divergence witness).

`pair_for_sum` returns `Maybe<(Slot, Slot)>` rather than `Option`, per `no-bare-option`; `Maybe::Isnt` /
`Maybe::Is` and `Maybe::is_some_and` at the one call site cover the same shape `Option` would have.

Verification: `grep -n 'fn edges' crates/arvo-format/src/addition/tests/*.rs` shows one definition, in
`mod.rs`; `the_operation.rs`'s import list carries `edges` from `super`. `cargo mock check --commit`
clears the lint.

## Negative controls run

Each new or changed assertion was broken once, observed failing, and restored (source edited back with
the editing tool, never moved, so the object rebuilds):

- `saturated`'s common branch mutated from `Slot::at(wide as i64)` to `Slot::at((wide + 1) as i64)`: caught
  9 pre-existing tests (independent-oracle exactness and totality checks in `the_operation.rs` and
  `the_step.rs`, plus the pre-existing whole-phase verdict test in `the_verdict.rs`). Not caught by either
  new test, because both verdict-computation and real-`add`-computation route through the same mutated
  `saturated` and shift together; a uniform-shift bug in the shared arithmetic is invisible to a
  verdict-agrees-with-real-behaviour check by construction, and is exactly what the independent-oracle
  tests that did catch it exist to guard.
- `completion_at`'s `translated_by` mutated from `saturated(min + k)` to `saturated(min - k)`: caught only
  by the pre-existing `a_licensed_cell_never_diverges_and_a_whole_phase_verdict_is_exact_both_ways`, which
  walks nonzero-`k` fractional phases through `every_phase!`. Not caught by the new width-walk test, whose
  formats (`Integer`/`UFixed`) are always `Phase::ZERO`, so `min - k == min + k` trivially there. An
  inherent property of the `dispatch::every_width` walk as literally prescribed, not a defect in the new
  test's construction.
- `completion_at`'s `Reach::of` mutated from `saturated(2 * max + k)` to `saturated(max + k)`: same result
  as above, caught only by the pre-existing test. Root cause: for `Integer<W>` (`W >= 2`) `low_side` is
  independently always false when the cell is genuinely refused, masking any bug purely in `high_side`'s
  term; for `UFixed<W,0>` both `high_side` and `low_side` are always true regardless of position (MIN = 0
  means no negative translation ever exists), so the family is structurally insensitive to this class of
  bug. A genuine, confirmed blind spot of the `Integer`/`UFixed` families under this check, inherent to the
  reviewer's literal prescription of `dispatch::every_width`.
- `addition_is_associative`'s early-return condition mutated from `!reach.reaches_off_the_grid().get()` to
  `reach.reaches_off_the_grid().get()`: caught by
  `the_verdicts_licensed_half_holds_at_the_widest_ranges_under_a_fractional_phase` (a licensed-cell
  divergence at `Signed<62>` under a third, reported with the diverging triple) and by the pre-existing
  whole-phase test. Not caught by the width-walk test: every format it walks has `Phase::ZERO`, so
  `rem = 0`, and the mutated branch's rounding of an already-integral value degenerates algebraically to
  the same `completion_at(whole)` the original branch returns, for every format in that walk. A real,
  confirmed structural property of the `k = 0` walk rather than a defect.
- The fractional-phase count pin (`952`): `assert_eq!(first, 952)` fails on any value the map produces
  that is not `952`, which is the whole of what pinning a previously-unpinned value buys; the number
  itself was read off the passing suite before being written down; the change is being able to see it move.
