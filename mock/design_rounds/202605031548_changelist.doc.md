### `mock/crates/arvo-hash/DESIGN.md.tmpl`

Replace the per-N `hash_const` inherent prose with a `ConstHash<N, S, Sign>` trait section. Update the `Hasher<N>` section to note the bounded-generic impl shape replacing the macro paste. Delete `HasherExt` references.

**ADD section** under existing `## Hash algorithms` heading, named `## ConstHash<N, S, Sign> const trait`:

> The substrate's content-addressing surface for compile-time hash construction. `ConstHash<N, S, Sign>` mirrors the strategy-aware `BitsContainerFor<N, Sign>` cascade and produces a typed `Bits<N, S, Sign>` from a byte slice.
>
> ```rust
> pub const trait ConstHash<const N: u16, S: Strategy, Sign: Signedness>: Sized
> where
>     S: BitsContainerFor<N, Sign>,
>     <S as BitsContainerFor<N, Sign>>::T: [const] NarrowFromU64<N, S, Sign>,
> {
>     fn hash_const(bytes: &[u8]) -> Bits<N, S, Sign>;
> }
> ```
>
> The `[const]` host-effect bound on the supertrait constraint is required for cross-crate const dispatch. Sketch 02 (round 202605031548) validates the chain `ConstHash → NarrowFromU64 → BitsContainerFor → Project` resolves at both compile time and runtime in a downstream crate.
>
> Algorithms implement `ConstHash` once each, generic over `N, S, Sign`. Per-N `hash_const` inherent methods on `Fnv1a<N>` and `XxHash3<N>` are gone; consumers reach for `<Fnv1a<N> as ConstHash<N, Hot, Unsigned>>::hash_const(bytes)` (or import the trait and write `Fnv1a::<N>::hash_const(bytes)` resolved through trait associated-const lookup).

**REWRITE section** `## Hasher<const N: u16> trait`:

> Streaming N-bit hasher. Feed bytes via `update`, finalise to a `Bits<N, S, Sign>`. The trait surface is unchanged from prior rounds; what changes is the impl shape.
>
> Each algorithm now provides a single bounded-generic `impl<const N: u16> Hasher<N> for Fnv1a<N>` (and same for XxHash3) instead of 64 hand-written impl bodies. The width-dispatched narrowing step lifts to `NarrowFromU64<N, S, Sign>` (declared in arvo-bits-contracts). The `impl_fnv1a!` and `impl_xxhash3!` macros are deleted; the bounded-generic impl replaces them.

**DELETE section** `## HasherExt<const N: u16>: Hasher<N>`:

The `HasherExt` blanket extension trait is removed. The cross-crate `.hash()` method dispatch over the const-impl + Pattern C blanket-impl chain failed on rustc nightly (recorded as #316 apply-time finding). With `ConstHash<N, S, Sign>` providing the one-shot `hash_const` form through Pattern C dispatch directly, `HasherExt` is no longer the right shape: it leaves consumers with two parallel APIs where one silently fails cross-crate. Streaming `Hasher<N>` stays for incremental hashing; one-shot ergonomics ride on `ConstHash`.

**UPDATE section** `## Fnv1a<const N: u16>`:

> Streaming FNV-1a-64 hasher with N-bit output. `N` constrained to `1..=64` implicitly by `Hot: BitsContainerFor<N, Unsigned>`. `Fnv1a<N>` impls both `Hasher<N>` (streaming) and `ConstHash<N, S, Sign>` (one-shot, const-callable).
>
> The `Hasher<N>` impl is a single bounded-generic block (not 64 hand-written impls). Internal narrowing dispatches through `<Hot as BitsContainerFor<N, Unsigned>>::T as NarrowFromU64<N, Hot, Unsigned>>::narrow_u64`.

**UPDATE section** `## XxHash3<const N: u16>`: same pattern as Fnv1a — note bounded-generic Hasher impl + ConstHash impl + macro removal.

### `mock/crates/arvo-bits-contracts/DESIGN.md.tmpl`

**ADD section** named `## NarrowFromU64<N, S, Sign>`:

> Bounded-generic narrowing of a `u64` to the dispatched container for `(N, S, Sign)`. Used by `ConstHash` (arvo-hash) to produce typed `Bits<N, S, Sign>` from a u64 algorithm state, and available to any other consumer that needs to project a u64 into a strategy-aware container.
>
> ```rust
> pub const trait NarrowFromU64<const N: u16, S: Strategy, Sign: Signedness>: Sized {
>     fn narrow_u64(raw: u64) -> Self;
> }
> ```
>
> Per-(S, Sign) blanket impls on every native primitive that can be a dispatched container under the matching `BitsContainerFor<N, Sign>` cell:
>
> | Strategy | Sign | Native primitives covered |
> |---|---|---|
> | Hot, Cold | Unsigned | u8, u16, u32, u64, u128 |
> | Hot, Cold | Signed | i8, i16, i32, i64, i128 |
> | Warm, Precise | Unsigned | u16, u32, u64, u128 (no u8; 2x-logical ladder) |
> | Warm, Precise | Signed | i16, i32, i64, i128 |
>
> The `(S, Sign)` partitioning means no two impls overlap on the same `Self` primitive type; sketch 01 (round 202605031548) validates rustc accepts all 36 native blanket impls without E0119 conflicts.
>
> Wide-bucket impl: `impl<const N: u16, S: Strategy, Sign: Signedness, const BYTES: usize, A: Align> const NarrowFromU64<N, S, Sign> for WideBits<BYTES, A>`. The narrowing places the masked u64 in the low 8 bytes of the byte sequence.
>
> Internally uses `mask_low_bits` (declared in arvo-strategy/src/width.rs) to centralise the `if N >= 64 { u64::MAX } else { (1u64 << N) - 1 }` pattern.

### `mock/crates/arvo-strategy/DESIGN.md.tmpl`

**Replace** the existing prose chunk about future `ConstFrom` / `ConstTryFrom` bridges (lines ~219-223) with a current-round entry: these bridges ship in this round.

**ADD section** named `## ConstFrom<T> / ConstTryFrom<T> bridges`:

> Substrate-owned const traits mirroring `core::convert::From` and `core::convert::TryFrom`, callable from `const` context.
>
> ```rust
> pub const trait ConstFrom<T>: Sized {
>     fn const_from(value: T) -> Self;
> }
>
> pub const trait ConstTryFrom<T>: Sized {
>     type Error;
>     fn const_try_from(value: T) -> Outcome<Self, Self::Error>;
> }
> ```
>
> `Outcome<T, E>` is `notko::Outcome`. The trait declarations live in `arvo-strategy` per the bridge-home rule: `notko` (which hosts `Outcome`) is reachable from `arvo-strategy`, and the bridges return `Self` and `Outcome<Self, ...>` respectively. Per-substrate-type impls live in the type-declaring crate via forward composition.

**ADD section** named `## mask_low_bits helper`:

> ```rust
> #[inline(always)]
> pub const fn mask_low_bits(n: u16) -> u64 {
>     if n >= 64 { u64::MAX } else { (1u64 << n) - 1 }
> }
> ```
>
> Centralises the bit-mask pattern used by `NarrowFromU64` (arvo-bits-contracts) and previously inlined in the `impl_fnv1a!` / `impl_xxhash3!` macro pastes. Lives in `arvo-strategy/src/width.rs` next to `bytes_for` and the `tag_*` const fns; saturates at `u64::MAX` for `n >= 64` to avoid the `1u64 << 64` undefined-behaviour shift.

**UPDATE section** `## Pattern C dispatch via Project<TAG, Sign, BYTES, S>` (the existing container.rs prose):

Add subsection on macro deduplication and sealing:

> The 40 native + 8 wide `Project` impls in container.rs collapse to 4 macro invocations via `macro_rules! impl_native_bucket`, one per Strategy. Each invocation emits 8 native impls (4 buckets x 2 sign axes for Hot/Cold; 3 buckets x 2 for Warm/Precise — Warm/Precise have no bucket 4) plus the 1-2 wide impls per Strategy. Total impl count remains 48; the source-line count drops by ~70%.
>
> `Project` is sealed via a sealed-supertrait bound. Downstream consumers cannot add `impl Project<6, ..., Picker>` etc. `Picker` itself stays `pub` because it appears in the public associated-type body of every `BitsContainerFor` impl (`type T = <Picker as Project<...>>::T`). The actual gate against downstream impls is the seal on `Project`, not the visibility of `Picker`. Sketch 02 (round 202605031548) Finding 2 records this constraint.
