# Three comments the first sweep could not see, and why the instrument missed them

## SUBJECT: the class check ran, returned zero, and was wrong twice over

The round before this one cut provenance out of twenty shipped comments and
finished by running a class grep to prove the class was cleared rather than the
list. It returned zero. A reviewer then found three it had not reached.

Both misses are the instrument rather than the pattern, and they fail in
different ways, which is worth separating because only one of them is the
obvious mistake.

**The glob was one directory deep.** `mock/crates/*/src/*.rs` does not reach
`mock/crates/arvo-placement/src/tests/the_open_inventory.rs`, which is two. Two
instances live there.

**The exclusion filter dropped a whole line for one word in it.**
`arvo-strategy/src/lib.rs:118` is inside the glob and matches the pattern on
`panel`. The sweep then piped through an exclusion for `operation` and `option`,
meant to stop `operation` matching a search for `op`, and that exclusion tests
the whole line. Line 118 happens to contain the word "operation" in ordinary use,
so the line was discarded before anything looked at what else was on it.

**The second is the more useful failure**, because the first is visible in the
command and the second is not. A filter that removes lines rather than matches
will silently eat any line where a false positive and a true one share a line, and
nothing about the output says so.

## The repair, and the control it needed from the start

The sweep is recursive over `mock/crates/*/src/` and `mock/crates/*/tests/`, and
it extracts the matched words with `grep -owiE` rather than filtering lines, so a
false positive can no longer take a real hit down with it.

**It carries a positive control.** Planting one line of provenance into a source
file makes it read 4 where the tree reads 0. A sweep that has only ever returned
zero has not been shown to work, and this one had returned zero twice while being
broken.

## Why this is a second round rather than an amendment

The previous round closed, so the phase returned to `TOPIC` and the gate refuses
source. That is the gate working: the fixes below were not in that round's src
changelist, and stretching a closed round to cover them would put changes in the
tree that no changelist names.
