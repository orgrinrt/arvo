# a-fixme-names-its-ticket

**Date:** 2026-11-13
**Round:** a defect round on `work/arvo-lints`: the six `FIXME` markers in `arvo-format` and `arvo-strategy` that name no ticket, and the lint that refuses them.

## What the workspace rule says

`mark-placeholders-fixme.md` makes every placeholder carry a greppable marker, and since 28 October the marker names the ticket opened with it: `FIXME(<ticket id>): <reason>`. A marker with no ticket is non-compliant and a lint is to refuse it. The rule is workspace-wide, so the check is general, and the lint for it has been written and tested in this repository's research directory (`mock/research/202611131930_a-fixme-names-its-ticket/`) without being landed.

## What the tree holds

Twelve markers in `mock/crates/*/src` already name a ticket in the form the rule asks for. Six do not: four in `arvo-strategy/src/lib.rs` (the preset adaptation defaults, each carried as a placeholder) and two in `arvo-format/src/symmetry.rs` (the even-translation parity region, and the reflection predicate that takes no reach). A ticket for each was filed in the arvo lane when the lint was written, so the work left is naming it at the marker.

## Why this is a round and not a loose edit

The gate refuses an edit to a `.rs` file outside a source changelist, and a source changelist needs a locked doc changelist before it. The edit changes no design: the six sentences stay as they are and each gains the id of the ticket that tracks it. The doc changelist therefore carries no template change and says so, which is what lets the round open without touching a design document.

A defect found and fixed stands alone, which is the one exception `a-round-is-a-feature-across-crates.md` allows, and six markers that break a workspace rule are exactly that. The round is not folded into a feature because none of arvo's open rounds touches these two files.

## What lands with it

The lint `a-fixme-names-its-ticket`, at `mock/lints/a_fixme_names_its_ticket.rs`, with `comment_lines` added beside `code_only` in `code_only_source.rs`. It is a crate lint at `HARD_ERROR`, it reads comments from the one parse so a string or a doc line that only mentions a marker is silent, and it checks the shape of the id (snake_case, at least twelve characters, an underscore) because the tracker lives outside the repository. Landing it and the six edits in one change keeps the gate green at every commit.

Its home across repositories is `mockspace-extra-lints`, since the rule binds every repository. That is a ticket against mockspace, filed with this round, and this copy is arvo's own until it moves.

## Open

Whether the lint should also refuse a marker whose id does not resolve in the tracker is a different check and is not part of this round.
