# Doc changelist: the law about a test over a declaration names both failures

**Date:** 2026-09-01
**Round:** the shipped tests narrate the process that wrote them
**Scope:** `mock/crates/arvo-format/DESIGN.md.tmpl`

## CHANGE: the declaration law FROM one failure described as two arms TO the two failures it actually was
File: `mock/crates/arvo-format/DESIGN.md.tmpl`
Verification: the law names both a constant asserted against a literal its own definition set and a
property no shipped construction can separate, and says the repairs differ.

The law as written said two arms once asserted a constant against the literal its own definition sets.
That is accurate about the overflow inventory arm, whose `DeclaredBound` was declared four lines above
it and existed for nothing else, and inaccurate about the declared-width arm, which wrote its own
literals against a macro elsewhere in the crate and would have failed against a macro writing
something else.

**The second one failed for a different reason and the law should carry it**, because a reader with
one description applies the wrong repair. **No construction this crate ships can separate a width that
is read from one recovered by counting**, since the declaration and the bounds agree on every one of
them, so that arm could not establish the property in its own name whatever it asserted. The repair
for the first is to run the declaration through the machinery; the repair for the second is a
construction on which the two answers differ.

## CHANGE: the design FROM silent on what a shipped test comment may say TO stating it
File: `mock/crates/arvo-format/DESIGN.md.tmpl`
Verification: the laws section says a comment in this crate's source names the property rather than
the machinery that produced it.

Eight comments in the crate named a design round, a reviewer, or a round's timestamp. Tests ship, so a
comment in one is read by whoever reads the crate, and a process noun means nothing to them. The
design says so where the laws are stated, because that is what the comments were carrying when they
went wrong: a reason for an arm's shape, told through the machinery that produced the shape rather
than through the property.

**It says what stays as well as what goes.** A sentence about the code's own earlier shape carries the
reason a later reader would otherwise undo, and it is not the same as a sentence about the process.
