### Section: "Sealed marker traits and `pub const trait` discipline"

### Section: "Const-trait substrate bridges (`ConstEq`, `ConstOrd`, `ConstDefault`)"

Add new section. Show canonical signatures:

```rust
pub const trait ConstEq {
    fn const_eq(&self, other: &Self) -> Bool;
    fn const_ne(&self, other: &Self) -> Bool {
        Bool(!self.const_eq(other).0)
    }
}

pub const trait ConstOrd: ConstEq {
    fn const_cmp(&self, other: &Self) -> Ordering;
    fn const_lt(&self, other: &Self) -> Bool;
    fn const_le(&self, other: &Self) -> Bool;
    fn const_gt(&self, other: &Self) -> Bool;
    fn const_ge(&self, other: &Self) -> Bool;
}

pub const trait ConstDefault {
    fn const_default() -> Self;
}
```

Document `Ordering` choice: prefer `core::cmp::Ordering` if const-constructible on rustc 1.96.0-nightly; else ship `pub enum ConstOrdering { Less, Equal, Greater }`. SRC-PLAN time decides.

State coverage: every primitive-wrapper (USize, Cap, Bool, Bits, UFixed, IFixed, FastFloat, StrictFloat, Mask64, Mask256, NodeId, MetaCarrier, IBits, FBits, Width) gains `impl const ConstEq` + `impl const ConstDefault`. `ConstOrd` for the totally-ordered subset (skip Mask, skip floats — NaN-tainted).

State stdlib `Default`/`PartialEq`/`Ord` impls remain alongside (boundary coverage); bridges are additive.

State deferred bridges (BACKLOG cross-refs): `ConstFrom`/`ConstTryFrom` Round 4, `ConstDeref`/`ConstAsRef` Round 4, `ConstTry` Round 5, `ConstHash` Round 5.

### Section: "MultiContainer canonical const surface (BitPrim + Bounded + Identity)"

NEW SECTION. Document the substrate generalisation that unblocks 129..=255-bit Bits.

Show the impl signatures:

```rust
impl<HiT: [const] BitPrim, LoT: [const] BitPrim>
const BitPrim for MultiContainer<HiT, LoT>
{
    const WIDTH: USize = HiT::WIDTH + LoT::WIDTH;
    fn count_ones(self) -> USize {
        self.hi.count_ones() + self.lo.count_ones()
    }
    fn trailing_zeros(self) -> USize {
        if self.lo.is_zero() {
            LoT::WIDTH + self.hi.trailing_zeros()
        } else {
            self.lo.trailing_zeros()
        }
    }
    // leading_zeros / bitor / bitand / bitnot / bitxor / with_bit_set
    // / with_bit_cleared / with_bit_toggled / get_bit / is_zero
    // / clear_lowest_set_bit similarly
}

impl<HiT: [const] Bounded, LoT: [const] Bounded>
const Bounded for MultiContainer<HiT, LoT>
{
    const MIN: Self = MultiContainer { hi: HiT::MIN, lo: LoT::MIN };
    const MAX: Self = MultiContainer { hi: HiT::MAX, lo: LoT::MAX };
}

impl<HiT: [const] Identity, LoT: [const] Identity>
const Identity for MultiContainer<HiT, LoT>
{
    const ZERO: Self = MultiContainer { hi: HiT::ZERO, lo: LoT::ZERO };
    const ONE: Self = MultiContainer { hi: HiT::ZERO, lo: LoT::ONE };
}
```

Document the WIDTH semantics: BitPrim::WIDTH lifts to `USize` in this round (this is part of Decision 5 in the topic; cascades to single-half BitPrim impls too).

State the rename: prior `arvo_strategy::multi_container::BitPrim` (sealing-marker) renames to `MultiContainerHalf` to free the name.
