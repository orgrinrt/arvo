## The five blockers and their resolutions

### A. `UArith<N>` / `IArith<N>` are `pub trait`, not `pub const trait`

Bodies call `wrapping_add`, `saturating_add`, `wrapping_div`, etc. on bare primitives. All const-stable on stable Rust, full-stop. Convert trait declarations and macro impls to const. Single synthetic blocker: arith.rs uses `<<Self as UContainerFor<$bits>>::T as Default>::default()` in the div-by-zero guard. `Default` is not const. Replace with `<<... as UPrimZero<N>>::ZERO`. Define `UPrimZero<N>` in arvo-strategy itself (the layer below arvo-bits-contracts where BitPrim::ZERO already exists), so the dep direction stays correct.

`HasAxes` supertrait does NOT need to be const because UArith does not call any HasAxes method bodies — it is a phantom marker for axis-driven dispatch.

### B. `BitPrim` / `IBitPrim` / `UBitContainer` / `IBitContainer` are `pub trait`

Bodies on u8..u128 / i8..i128 use `count_ones`, `wrapping_sub`, bitwise ops, comparisons, casts. All const-stable. Lift to `pub const trait`, gain `const` on macro impls, gain `[const]` on `where T: BitPrim` bounds at use sites.

### C. Bits blanket impls of L0.5 traits are not `impl const`

This is an existing gap independent of #304. The L0.5 traits (`HasBitWidth`, `BitAccess`, `BitSequence`, `BitLogic`) are already declared `pub const trait` in arvo-bits-contracts. Their blanket impls on `Bits<N, S>` in `bits_impl.rs` are NOT marked `impl const`. Once Blocker B lifts BitPrim to const, the bodies become const-callable. Mark the impls const.

### D. FastFloat / StrictFloat ops bound on `core::ops::$op<Output = F>` (non-const)

`f32 + f32` and `f64 + f64` are const-stable on nightly with `feature(const_ops)` (already enabled in arvo). The macro at `arvo/src/float.rs:102` rewrites to `impl<F: Ieee + [const] core::ops::$op<Output = F>> const core::ops::$op for $wrapper<F>`. The `[const]` on the supertrait bound is the load-bearing piece. Macro change, three lines.

### E. Inherent `pub const ZERO: UFixed<I, F, S>` cannot construct the typed primitive zero

`UFixed::from_raw` is already `pub const fn`. The blocker is the literal `0` not unifying with `<S as BitsContainerFor<N, Sign>>::T` at the const-context. Resolution: add `UPrimZero<N>` / `UPrimOne<N>` / `IPrimNegOne<N>` const traits at arvo-strategy layer (see Blocker A). Then `UFixed::ZERO = UFixed::from_raw(<S as UPrimZero<{ufixed_bits(I, F)}>>::ZERO)` and similar.

For Mask64 / Mask256: `Mask::from_word(QWord::from_raw(0u64))` is the pattern. Already-const Bits::from_raw plus const u64 literal. `from_word` is currently not const-marked; mark it const.

## Sketch validation

The ~200 LOC plan is executable on this nightly.
