# Src changelist: a public trait that changed shape with the build profile

**Date:** 2026-08-31
**Round:** the surfaces round
**Scope:** `mock/crates/arvo-strategy/src/`. No other crate's source changes.

## CHANGE: `StatedIntent` FROM a `#[cfg(debug_assertions)]` public trait TO rustdoc on each preset
Files: `mock/crates/arvo-strategy/src/lib.rs`, `mock/crates/arvo-strategy/src/tests.rs`
Verification: `grep -c StatedIntent mock/crates/arvo-strategy/src/*.rs` returns zero, and
`cargo test -p arvo-strategy` and `cargo test -p arvo-strategy --release` report the same count.

**The measured defect.** A public trait behind `#[cfg(debug_assertions)]` is a public API that changes
shape with the build. A path-dep consumer builds in debug and fails in release with `E0432`, and
`cargo test -p arvo-strategy` gives 10 against `--release` giving 8, both reporting `0 ignored`, so two
tests stop existing and the runner says nothing. Op's condition for the merge is that downstream pin
`dev`, so this reaches the first consumer that builds release.

**Neither remedy the lint names is available to this crate.** `#[cfg(debug_assertions)]` is the
construction that produces the defect. `hilavitkutin_str::Str::const!()` is the other, and
**hilavitkutin depends on arvo**, so reaching for it inverts the stack.

**The third answer is the trait's own documentation.** It described the intents as "something a reader
can read and nothing a compiler can gate on", and a `const` in a trait is exactly something a compiler
gates on: two of the tests asserted against it. The doc comment and the construction contradicted each
other, and the doc comment is the half matching `ruling::the_strategy_intents_are_not_clear_cut`, which
says the per-strategy statements are not to be written down as clear cut and settled. A per-preset
compile-time item keyed on the preset is nearer that row's forbidden behaviour table than prose is.

So the trait goes and the intents become rustdoc on each preset struct. No cfg gate, no `const INTENT`
for the lint to fire on, the doc comment becomes true, and the intents stay exactly as readable.

## CHANGE: two tests FROM shipped TO deleted
File: `mock/crates/arvo-strategy/src/tests.rs`
Verification: `every_preset_states_an_intent` and `the_intents_are_four_distinct_statements` appear
nowhere in the tree.

They went with the trait, and **neither was a law.** The first asserted that a string literal is
non-empty and longer than eighty characters. The second asserted that four string literals differ from
each other. Both are the class this arc deleted a round ago: a declaration checked against itself,
reaching nothing the code does.

**So the release build was not losing two laws.** It was losing two tests that tested nothing, and the
real defect was that a public trait vanished with them. Saying that plainly matters, because "release
runs fewer tests" reads as lost coverage and the coverage was not there.

## CHANGE: `no_preset_carries_a_behaviour_keyed_on_its_own_name` FROM asserting nothing TO asserting uniform access
File: `mock/crates/arvo-strategy/src/tests.rs`
Verification: the test body contains `assert_eq!` rather than `let _ =`.

**The reviewer's claim was checked here and is right, and the defect is worse than filed.** The claim
was that adding `const NAME: &str` to `Strategy` leaves `both_items` compiling. It does. Going
further: adding the const to all five impls as well makes the crate build with exactly the
construction the comment says would break the file, and **the test passes**, ten of ten. A test
existing to forbid a per-strategy behaviour reported green while one was present.

**The property is real and the compiler already enforces it.** Adding an item to `Strategy` breaks
every impl with `E0046`, four errors before any test runs. The test contributed nothing to that and
its comment claimed the credit.

**What it asserts instead is a property it can actually hold**: that both items are reachable for every
preset through one generic path, and that the values returned are the ones each preset declares. That
is uniform access, a consumer depends on it, and it fails if any preset ever gets a privileged route.
The comment stops claiming the structural property and names the compiler as what enforces that.
