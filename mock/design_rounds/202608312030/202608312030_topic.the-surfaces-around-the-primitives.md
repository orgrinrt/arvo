## Finding one: the trait should not exist

The lint offers two remedies and **arvo can use neither**.

`#[cfg(debug_assertions)]` is the one in place and it is what produces the breakage: a public trait
that exists in one profile and not the other is a public API that changes shape with the build, and a
consumer pinning `dev` gets `E0432` the first time it builds release.

`hilavitkutin_str::Str::const!()` is the other, and **hilavitkutin depends on arvo**. Reaching for it
here would invert the stack. It is unavailable by layering, not by preference.

So neither stated remedy is open, which looked at first like an unsatisfiable lint of the kind this
arc has already found twice. It is not, because there is a third answer the lint does not name and the
trait's own documentation already gives:

> something a reader can read and nothing a compiler can gate on

**A `const` in a trait is exactly something a compiler gates on.** It can be dispatched on, asserted
against, and read in a const expression, and two of the tests did assert against it. The doc comment
and the construction contradict each other, and the doc comment is the half that matches the canon:
`ruling::the_strategy_intents_are_not_clear_cut` says the per-strategy statements are not to be written
down as clear cut and settled, and a per-preset compile-time item keyed on the preset is closer to the
behaviour table that row forbids than to prose.

**So `StatedIntent` goes, and the intents become rustdoc on each preset.** That removes the profile
gate, removes every `const INTENT` the lint fires on, makes the doc comment true, and leaves the
intents exactly as readable as they were, because rustdoc is what a reader reads.

**Two tests go with it and neither was a law.** `every_preset_states_an_intent` asserted that a string
literal is non-empty and longer than eighty characters. `the_intents_are_four_distinct_statements`
asserted that four string literals differ from each other. Both are the class this arc deleted a
round ago: a declaration checked against itself, reaching nothing the code does. **The release build
was not losing two laws. It was losing two tests that were not testing anything**, and the real defect
was that a public trait vanished with them.

## Finding three: what replaces it

The property the test names, that no preset carries a behaviour keyed on its own name, is real and is
already enforced, **by the compiler rather than by that test**. Adding an item to `Strategy` breaks
every impl with `E0046`, which is four errors before any test runs. The test contributes nothing to
that and its comment claims the credit.

What the test can honestly assert is a different and real property: that both items are reachable for
every preset through one generic path, and that the values that come back are the ones each preset
declares. That is uniform access, it is what a consumer depends on, and it fails if a preset ever gets
a privileged route. So the test gets an assertion instead of `let _ =`, and its comment stops claiming
a property it never had.

## Finding two: what the documents say and what ships

Four templates describe a seventeen-crate tree deleted on 2026-08-08, including a layer table naming
`arvo-strategy` as `BitsContainerFor` and `Project<TAG, Sign, BYTES, S>`. The source shipping beside
that table names the same crate as a binding from a name to a placement objective.

`mock/agent/rules/implementation.md.tmpl` is the one that matters most, because it is what every agent
loads at session start. It already carries a banner saying the crate names below name a tree that no
longer exists, **which is a disclaimer over a description rather than a description.** Replacing the
content is the fix; the banner is what you write when you are not doing that.

The rendered `docs/` are generated and are not edited directly. They follow from the templates.

## The bench manifests, which I am not touching and why

`fnv1a`, `xxhash3`, `spectral-bisection` and `structural-decomposition` inherit workspace dependencies
that no longer exist. All four fail at `cargo metadata` with a manifest parse error; a variant without
an arvo dependency resolves normally, which is the control.

**They have been broken since the tree was deleted and neither fixing nor deleting them belongs to
this round.** Making them build means writing new bench arms against `arvo-format`, `arvo-placement`
and `arvo-strategy`, which is bench work that needs real competitors and a measurement to be worth
anything, and inventing arms to make a manifest parse is the opposite of what a bench is for. Deleting
them destroys an artifact trail this repository's own workspace manifest says the panel cites.

So they are named here with their exact state and left alone. **Keeping them is the result**, and the
finding is that four of roughly ninety bench variants cannot be built and nothing in the tree says so.

## What lands

The four templates rewritten to describe what ships. `StatedIntent` deleted and the intents moved into
rustdoc. The uniform-access test given an assertion. Finding four confirmed already fixed and recorded
rather than re-fixed.
