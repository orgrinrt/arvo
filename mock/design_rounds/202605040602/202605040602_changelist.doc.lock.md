## arvo-storage

### `DESIGN.md.tmpl`

Add a new section "## NUSize: niche-packed Maybe-of-USize" after the existing USize section. Section content describes:

- `NUSize(Slot<NonZeroUSize>)`, `#[repr(transparent)]`, layout identical to `usize` (8 bytes on 64-bit) via niche optimisation through `core::num::NonZero<usize>`.
- API surface: `NUSize::NONE`, `NUSize::some(USize) -> Self` (shifts +1 internally), `NUSize::as_maybe(&self) -> Maybe<USize>` (unwraps and shifts -1), `NUSize::unwrap_or(self, USize) -> USize`, `NUSize::is_some(&self) -> Bool`, `NUSize::is_none(&self) -> Bool`.
- Use case framing: "an absent-or-present USize without paying a discriminant byte". Replaces the `USize(0)` overloaded sentinel idiom (anti-pattern from F14 audit).
- Relation to `Slot<T: NonZeroable>` from notko: NUSize is a USize-shaped specialisation that adds the +1/-1 shift so consumers see logical 0-indexed semantics.

Update the existing "## Bool" section to add a sentence: "Bool implements `notko::ConstTry` and `notko::ConstFromResidual<core::convert::Infallible>` so the existing non-const `core::ops::Try` / `FromResidual` impls have const-callable counterparts (substrate-internal const-branch surface; not `?` syntax)."

### `README.md.tmpl`

Add `NUSize` to the crate's exported types list.

### `BACKLOG.md.tmpl`

Add an unbackticked entry: "NU8 / NU16 / NU32 / NU64 niche-packed Maybe-of-primitive family. Same shape as NUSize over the corresponding NonZero primitive; ship per-width when a consumer demands it. Naming convention established with NUSize in round 202605040602."
