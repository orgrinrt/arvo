# Topic: `arvo-storage` decomposes, and refit comes home to the container

**Date:** 2026-07-29
**Phase:** TOPIC
**Status:** op's call on the principle; the per-item placement derived from it, with one item flagged
rather than guessed.

## D27. Each family goes to its obvious home; the remnant keeps the crate and is renamed

**Decision (op, 2026-07-29).** `arvo-storage` accumulated three unrelated families under a name that
describes only one of them. Rather than argue the split, each family goes where it obviously belongs,
whatever has no other home stays, and the crate is renamed to fit what is left.

Contents today, verified from source rather than from the documents:

| Item | Where | Destination |
|---|---|---|
| `Bits<N, S, Sign>` | `bits.rs` | stays, and is the remnant |
| `ConstPartialEq`, `ConstEq`, `ConstOrd`, `ConstOrdering` | `bridges.rs` | `arvo-numeric-contracts` |
| `ConstBitEq` | `bridges.rs` | `arvo-bits-contracts` |
| `ConstDefault` | `bridges.rs` | **not obvious, see below** |
| `USize`, `Bool`, `BoolResidual`, `AsBool`, `NUSize` | `platform.rs` | `arvo-platform`, new |
| `Cap` | `platform.rs` | `arvo-capacity`, already settled by D2 |
| `MetaCarrier` | `meta_bits.rs` | `arvo-strategy` |

**The comparison bridges go to `arvo-numeric-contracts` because the axis is already there.** That
crate declares `TotalOrd`; `ConstPartialEq`, `ConstEq`, `ConstOrd` and `ConstOrdering` are the same
question asked const-callably, and splitting one ordering family across two crates is what created
this situation.

**`ConstBitEq` goes to `arvo-bits-contracts`** because bit-pattern equality is a statement about bits
rather than about numeric ordering, and that crate is where bit access is declared.

**The platform wrappers earn their own crate.** `USize` over `usize`, `Bool` over `bool`, `NUSize`
over `NonZeroUsize`: these exist because a platform primitive has to be named once and wrapped, and
that is a different job from holding a bit container. `arvo-platform` says what it is.

**`MetaCarrier` goes to `arvo-strategy`**, which already hosts `Width`. It is the carrier for the
meta-bit newtypes that describe widths, and width dispatch is what `arvo-strategy` does.

## D28. Refit is container work and comes home with the container

**Decision (op, 2026-07-29).** `Narrow`, `Widen`, `Narrowed`, `Widened` and `NarrowFromU64` are
strictly container things: masking to the low N bits, zero-extending, sign-extending, moving a value
into a carrier of a different width. Not bit access, and not mathematics.

They leave `arvo-bits-contracts` and join the container crate, which is where the thing whose width
they change lives. **`arvo-refit` is deleted**, which also removes the `no-empty-crate` finding by
removing its cause rather than silencing it. Pre-1.0, so no shim is owed.

This is the answer to why the crate was empty: it was a gateway to a family filed in the wrong place,
and a gateway is the shape a misplacement takes when nobody wants to move the thing itself.

## The remnant, and its name

What stays is `Bits<N, S, Sign>` plus the operations that change a container's width. That is a
crate about **containers**, so it becomes **`arvo-container`**.

The name is the derived part of this decision rather than op's word: op said "not necessarily
container, but whatever fits the remnants". Once the remnant is a bit carrier plus width conversion,
`arvo-container` fits, and it is the word already used throughout the round to describe exactly this
("the container projection", "which container holds N bits"). Overturn it on sight if a better one
lands.

## The one item not placed

**`ConstDefault` is not obviously anywhere.** It is neither comparison nor bits: it is a construction
contract, the const-callable form of `Default`. It could sit with the comparison bridges purely
because they arrived together, which is not a reason. It could go to the container crate, since
`Bits` is its main implementor, which is a consumer argument rather than a subject-matter one.

Left open rather than guessed, because filing it by proximity is exactly how `arvo-storage` became
what this decision is undoing.
