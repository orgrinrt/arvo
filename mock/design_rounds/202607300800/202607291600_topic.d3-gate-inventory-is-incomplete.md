# Topic: D3's gate inventory misses the ergonomic aliases

**Date:** 2026-07-29
**Phase:** TOPIC
**Status:** a correction to a locked-in decision's factual basis. The decision stands; its inventory
does not.

## What D3 says

`202607282100`, D3:

> The `arvo` facade's only live GCE constructs are two static asserts of the form
> `[(); 1 / is_fractional(F)]:`, at `ufixed.rs:274` and `ifixed.rs:308`. A stable
> `const { assert!(...) }` block is the candidate replacement and needs no feature.

## What is also there

`mock/crates/arvo/src/aliases.rs` declares four type aliases, every one of them the same forbidden
shape:

```rust
pub type Fixed<const I: u16, const F: u16, S = Warm> = UFixed<{ ibits(I) }, { fbits(F) }, S>;
pub type Signed<const I: u16, const F: u16, S = Warm> = IFixed<{ ibits(I) }, { fbits(F) }, S>;
pub type Uint<const N: u16, S = Warm>                 = UFixed<{ ibits(N) }, { fbits(0u16) }, S>;
pub type Int<const N: u16, S = Warm>                  = IFixed<{ ibits(N - 1) }, { fbits(0u16) }, S>;
```

A const-fn call applied to a generic const parameter, in const-generic argument position. Verified in
`mock/research/sketches/202607291400_const-args-under-min-gca/`: the shape is refused without a gate
and rustc names `generic_const_exprs`; `min_generic_const_args` refuses it and asks for a `const`
block; the `const` block then asks for `generic_const_args`. Both successors are outside the allowed
set.

So the facade's gate is load-bearing for six constructs, not two, and a migration plan that budgets
for the asserts alone stops at the first build.

## What this does not change

**D2 and D3 stand exactly as written.** The cure is the one already decided: the same move `Capacity`
made, which is why `arvo-tensor` carries no GCE gate today. The aliases are one more site for it, not
a new problem, and the same sketch confirms two gate-free expressions of the shape (an impl table
projecting the answer as an associated type, or the parameter ceasing to be a const at all).

## The one question the aliases raise on their own

They are close to unused. `Fixed` and `Signed` appear only inside two test *comments*; `Uint` and
`Int` have one use between them outside their own file. Their whole purpose is letting a consumer
write bare `u16` where the underlying types take the `IBits` and `FBits` newtypes.

So migrating them is optional in a way the projection and the asserts are not: deleting them removes
the work instead of doing it, and pre-1.0 there is no shim to owe anyone. Whether they are migrated or
deleted is not settled here.
