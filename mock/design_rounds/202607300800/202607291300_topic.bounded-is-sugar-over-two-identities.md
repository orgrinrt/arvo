# Topic: `Bounded` is sugar over two identities

**Date:** 2026-07-29
**Phase:** TOPIC
**Status:** one op call, refining D24 of `202607291200`.

## D26. `Bounded` is not a bespoke trait; it is two `Identity` impls with a name

**Decision (op, 2026-07-29).** D24 moved `Bounded` to the algebra crates and left "does it dissolve
entirely" as a follow-up. op closed that: it is a convenience over the two identities, so it should say
so in its own declaration rather than duplicate their constants.

```rust
pub const trait Bounded: [const] Identity<Max> + [const] Identity<Min> { .. }
```

**The mapping inverts, and that is the part to get right.** It reads backwards on first sight and is
the reason to write it down:

- `MIN` is the identity of **max**, because `max(x, MIN) == x`. So `MIN` is `Identity<Max>::IDENTITY`.
- `MAX` is the identity of **min**, because `min(x, MAX) == x`. So `MAX` is `Identity<Min>::IDENTITY`.

A reader who pattern-matches `MIN` to `Identity<Min>` gets both wrong. Whatever ships, this pairing is
stated at the declaration.

**What it buys beyond tidiness.** The absence property, which is the whole reason `Identity<Op>` is
shaped the way it is. A type with no least element has no `Identity<Max>` impl, so naming its `MIN`
fails to resolve rather than returning something plausible. Today `Bounded` forces a type to have both
constants or neither, which is the exact complaint `202607281547` records against the `ZERO`/`ONE`
shape that `Identity<Op>` replaced.

**Ergonomics are kept.** `T::MIN` and `T::MAX` stay available as provided methods or associated consts
on `Bounded` that read through to the two identities, so no call site changes. `Bounded` becomes the
sugar it always was instead of a second source of the same values.

## The question this leaves, which is not settled here

`Bounded` has a second reader that is not algebraic: **saturating arithmetic clamps to the
representational limits of the container**, and that is a fact about the storage rather than about a
lattice. For every arvo numeric type the two coincide, which is why the conflation survived unnoticed.

If the saturating path reads `Identity<Max>` and `Identity<Min>`, it is naming a lattice to ask a
question about a container, and it will read wrongly the first time a type's representable range and
its lattice bounds differ. Whether a separate representational-limits contract is owed, and where it
would live, is open.
