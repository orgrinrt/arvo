# One url spelling per git dependency

**Date:** 2026-11-13
**Phase:** TOPIC
**Scope:** `mock/Cargo.toml` and `mock/benches/Cargo.toml`, and the two lockfiles beside them.
**Source:** the roadmap step AR0, arvo's half, from the job `arvo-bench-harness-alive`.

## The question

Cargo keys a git source by the url as it is written, so the same repository named once by `ssh` and once
by `https` is two sources. A resolve that reaches `notko` through arvo (spelled `ssh://git@github.com/orgrinrt/notko.git`)
and through kaski (spelled `https://github.com/orgrinrt/notko.git`) holds two `notko` crates, and every type
either defines is a distinct type from the other's. The stack's graph is meant to hold one.

arvo names notko in `mock/Cargo.toml` and names the mockspace bench crates in `mock/benches/Cargo.toml`, both
by `ssh`. kaski names notko by `https`, and hilavitkutin by `ssh`.

## What the registry and the rules say

The workspace rule on a private repository over `https` (a hang rather than an error) applies to private
repositories only. `notko` and `mockspace` are both public, so the `https` spelling does not hang and is the
one the other repositories of the stack can share. No canon row governs the spelling of a git url.

## Decision

Spell `notko` in `mock/Cargo.toml` as `git = "https://github.com/orgrinrt/notko.git"`, keeping the branch, the
version and the features as they are. Spell the two `mockspace` lines in `mock/benches/Cargo.toml` by
`https://github.com/hiisi-digital/mockspace`, keeping the branch and the features. Regenerate the two
lockfiles so that only the changed sources move, and say in the commit which notko commit the lock now names,
since it moves from `a30683d7`.

## What this does not touch

No crate source, no design template and no canon row. The resolution of the three arvo crates is unchanged;
only where cargo says the notko source comes from changes.
