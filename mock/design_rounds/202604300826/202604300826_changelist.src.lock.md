## arvo-bits-contracts trait + impl additions

### `mock/crates/arvo-bits-contracts/src/lib.rs`

Two structural additions and one matrix extension:

1. **Same-container Narrow impls.** Extend the existing `impl_narrow_u!`
   and `impl_narrow_i!` invocation lists to include same-container
   pairs (`u8 => u8` through `u128 => u128`, signed counterparts).
   The existing macro body's `>= BITS` short-circuit makes the
   same-width case a no-op identity. Closes the gap that broke any
   cross-Bits Narrow within one container range (e.g. `Bits<32, Hot>`
   → `Bits<28, Hot>` both u32-backed).

2. **Module declarations** for the new `widen` and `cross_domain`
   modules (see below). Add `pub use widen::{Widen, Widened};` to
   the crate-level surface.

3. **Imports.** Extend `use arvo_strategy::{...}` to include
   `Signed, Unsigned` (consumed by the cross-domain impls).

### `mock/crates/arvo-bits-contracts/src/widen.rs` (new)

Hosts the Widen trait family. Sections in order:

- `Widened<T> = T` cosmetic alias.
- `pub const trait Widen<T>` with `widen_to(self) -> T` and
  `widen_to_unmasked(self) -> T`. NO const-N parameter; asymmetric
  with Narrow per topic decision A. Source bit-width derives from
  per-impl context.
- Cross-primitive Widen impls via `impl_widen_u!` / `impl_widen_i!`
  macros (parallel to the cross-primitive Narrow macros). Coverage:
  `u8 → {u16, u32, u64, u128}`, `u16 → {u32, u64, u128}`, `u32 → {u64,
  u128}`, `u64 → u128`; signed counterparts.
- Cross-Bits Widen forwarder: `Bits<M, S, Sign>: Widen<Bits<N, S, Sign>>`
  forwarding through `<S as BitsContainerFor<M, Sign>>::T: Widen<<S
  as BitsContainerFor<N, Sign>>::T>`.

### `mock/crates/arvo-bits-contracts/src/cross_domain.rs` (new)

Hosts the cross-domain primitive ↔ Bits direct refit impls.
Sections:

- `impl_narrow_pri_to_bits_unsigned!(u8, u16, u32, u64, u128)` and
  signed counterpart: each primitive Pri gets `Pri: Narrow<Bits<N,
  S, Sign>>` for every (N, S, Sign) where the carrier-side `Pri:
  Narrow<Container>` exists.
- `impl_widen_bits_to_pri_unsigned!(...)` and signed counterpart:
  reverse direction. Each `Bits<M, S, Sign>: Widen<Pri>` where the
  carrier-side `Container: Widen<Pri>` exists.

These underlie the `Bits::from_narrowed<Src>` / `Bits::from_widened
<Src>` ergonomic constructors hosted in `arvo-bits` (see below).
The trait solver's where-clauses constrain the impls to (Pri, N, S,
Sign) tuples where the underlying carrier-side trait impl exists;
unmatched combinations get a clear unsatisfied-where-bound error at
the call site.

### Module-split rationale

The trait + cross-primitive + cross-Bits + cross-domain code totals
~290 lines. Adding it inline to `lib.rs` pushed the file past the
500-line `file-size` lint limit. Splitting into `widen.rs` and
`cross_domain.rs` keeps `lib.rs` focused on the contract-trait
declarations + same-container Narrow impl invocations + cross-Bits
Narrow forwarder, and gives each new code surface its own narrative
file.

## arvo-bits — `BitsRefitCtor` extension trait

### `mock/crates/arvo-bits/src/lib.rs`

1. **Re-export expansion.** Add `Narrow, Narrowed, Widen, Widened`
   to the `pub use arvo_bits_contracts::{...}` block. Consumers
   reach the refit family through `arvo_bits::*` already; this just
   names the symbols explicitly.

2. **Feature gate.** Add `#![feature(const_trait_impl)]` to enable
   the const trait declaration below.

3. **`BitsRefitCtor` sealed extension trait.** New private module
   `refit_constructors` with the trait + blanket impl:

   ```rust
   pub const trait BitsRefitCtor<const N: u16, S: Strategy, Sign: Signedness>
   where S: BitsContainerFor<N, Sign>,
   {
       fn from_narrowed<Src>(src: Src) -> Bits<N, S, Sign>
       where Src: ~const Narrow<<S as BitsContainerFor<N, Sign>>::T>;

       fn from_widened<Src>(src: Src) -> Bits<N, S, Sign>
       where Src: ~const Widen<<S as BitsContainerFor<N, Sign>>::T>;
   }

   impl<const N: u16, S: Strategy, Sign: Signedness>
       const BitsRefitCtor<N, S, Sign> for Bits<N, S, Sign>
   where S: BitsContainerFor<N, Sign>,
   {
       fn from_narrowed<Src>(src: Src) -> Bits<N, S, Sign>
       where Src: ~const Narrow<...>,
       { Bits::from_raw(src.narrow_to::<N>()) }

       fn from_widened<Src>(src: Src) -> Bits<N, S, Sign>
       where Src: ~const Widen<...>,
       { Bits::from_raw(src.widen_to()) }
   }
   ```

   The trait is sealed via the `mod refit_constructors` boundary;
   only this crate's blanket impl implements it. Methods read as
   inherent-on-Bits at consumer call sites because the blanket
   covers every shape.

4. **Re-export `BitsRefitCtor`** at the crate root.

The constructors live in `arvo-bits` rather than `arvo-storage` to
preserve the `arvo-storage` (L0) → `arvo-bits-contracts` (L0.5)
direction. `arvo-bits` (L1) is the natural home for inherent-style
ergonomic methods on `Bits` that route through the L0.5 contracts.
