# Doc changelist: the merge, and the doc half that turned out to need no consolidation

The merge commit lands in this window. It carries `dev` into the branch across
five conflicted files. The doc half is settled here; the source half goes at the
branch parent's bytes and is consolidated in the src changelist, which is where
somebody authors it.

## CHANGE: mock/crates/arvo-format/DESIGN.md.tmpl

### CLAIM: the branch already carries every sentence `dev` added, so the resolution authors nothing

The topic file planned a fold: `dev`'s clause saying the open question is this
tier's to settle was to be kept, on the reading that the branch had dropped it.
Reading both sides against the merge base refutes that. The branch dropped it on
purpose, in `09d770d6`, together with the emphasis on the same paragraphs, and
`documentation-writing.md` is why: naming which tier owns a question is internal
process, and this template renders into `docs/FORMAT.md`, which a stranger reads.
The same commit dropped `dev`'s other two carry-overs, the confession that saying
`contains` forces nothing "was wrong" and the bold on paragraphs this round
rewrote.

What is left after those three is `since the canon does not choose the shape a
law takes`, which the branch carries verbatim. So `dev` holds nothing here the
branch lacks, and each of the three conflicted hunks resolves to the branch side
whole:

- The `contains` paragraph. The branch says the verb carries no force site of its
  own and reaches two obligations through its two calls; `dev` says it forces
  them. The distinction between a force site and a transitive reach is what the
  branch's round established, so the branch's wording is the later one.
- The paragraph on where each obligation fires. `dev` says the sets are disjoint
  from the slot range's; the branch refutes disjointness two paragraphs down, so
  keeping `dev`'s sentence would put the refuted claim back beside its refutation.
- The forcing-set paragraph, which the branch adds and `dev` deletes without
  replacing.

Verification: `git diff HEAD -- mock/crates/arvo-format/DESIGN.md.tmpl` is empty
against the branch parent, and mockspace excuses a merged file byte-identical to
one parent because nobody authored it.

## CHANGE: docs/FORMAT.md

### CLAIM: the generated document is regenerated rather than resolved, and regenerating changes nothing

`cargo mock` over the resolved template produces the file the branch parent
already carries, which follows from the template being at parent bytes. The
conflict was `dev`'s generated copy differing from the branch's, and a generated
copy is not a side to take.

## CHANGE: mock/tools/*/Cargo.lock

### CLAIM: five tool lockfiles follow the engine pin `dev` moved to

`the-tool-locks-pin-one-mockspace` refuses the merge until every tool lockfile
and the generated lint crate name one revision of `mockspace-lint-rules`. The
five tools sat at `82e80e4` against the engine's `1ff158c`, so they lag and they
move.

`cargo update -p mockspace-lint-rules`, which is what the lint's own message
prescribes, does not converge them: the dependency is spelled `branch = "dev"`,
so the update takes the branch head, which was `cf0fb06` and is not what the
launcher resolved the engine to. The lint then refuses the other way round, with
the tools standing together against the generated crate. `--precise
1ff158ca21b735e6819bfc3a5f508dedb3bcd8fe` is what actually pins them to the
engine.

The prescribed fix being wrong for the case the message itself names, where the
generated crate stands alone, is a defect in that lint's message rather than in
this round, and it is filed rather than fixed here.

Verification: `cargo mock` reports no lint errors.

## What this changelist does not do

It does not touch `src/width.rs`, `src/tests/obligations.rs` or
`tests/compile_fail.rs`. All three go into the merge at the branch parent's bytes
and none of them is finished there: the first two carry a sentence and three arms
that need both sides, and that is the src changelist's work.

It makes no new claim about the design. Every sentence in the resolved template
was already written by one side or the other and locked by the round that wrote
it.
