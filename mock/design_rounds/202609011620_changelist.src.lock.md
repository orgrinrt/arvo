# Source changelist: the identity turns on a whole multiple

Source topic: `202609011620_topic.the-identity-turns-on-a-whole-multiple-phase.md`.
Doc changelist: `202609011620_changelist.doc.lock.md`.

## CHANGE: `has_additive_identity` FROM testing `PHASE_NUM == 0` TO testing a whole multiple

File: `mock/crates/arvo-format/src/format.rs`

The phase is `PHASE_NUM / PHASE_DEN` in units of the quantum, so zero is on the
grid exactly when some integer slot satisfies `slot * quantum = -phase`, which is
solvable exactly when the phase is an integer multiple of the quantum. The slot
that lands on it is `-(PHASE_NUM / PHASE_DEN)`, and the range check moves to that
slot rather than staying at zero.

A zero denominator is guarded rather than divided by. The trait documents it as
never zero and no function reads it today, so nothing enforces that: the guard is
what makes the doc true rather than aspirational, and it answers no identity,
which is the honest answer for a phase that names no position.

Verification: `grep -n "PHASE_NUM % F::PHASE_DEN" mock/crates/arvo-format/src/format.rs`
returns one match, and the arms below fail if the old expression is restored.

## CHANGE: three rustdoc comments FROM the retired claim TO the corrected one

Files: `mock/crates/arvo-format/src/format.rs`, `mock/crates/arvo-format/src/lib.rs`

`Format::PHASE_NUM`, the free function, and the `Biased` point each state that a
nonzero phase removes the identity. The function's comment additionally says such
a phase takes the value one off the grid with zero, which `237_probes/p2` measured
false at a half-step grid whose quantum is above one, so that clause goes rather
than being narrowed.

## CHANGE: the phase law FROM one direction sampled TO both directions, with the gap catalogued

File: `mock/crates/arvo-format/src/tests.rs`

`a_nonzero_phase_takes_the_additive_identity_off_the_grid` uses phase numerators
1, 1 and 3 against a denominator the type fixes at 2, so every phase it tries is
fractional and none reaches the region where the function was wrong. It is renamed
for what it now establishes and gains the whole-multiple arms, `Biased<4, 0, 2>`
among them, which is the case both probes ran.

Verification: reverting `has_additive_identity` to `PHASE_NUM == 0` fails the new
arms and passes every old one, which is the control saying the arms reach the
region the old suite could not.

## What this does not change

`Biased` keeps `PHASE_DEN = 2`, so the half-step geometry is still what the point
exercises and the whole-step case is reached by an even numerator rather than by a
new type. Nothing about the format concept, the affine predicate or the adaptation
slot moves.
