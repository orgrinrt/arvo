# Topic: the arm that could not fail, and two words the schema does not have

**Date:** 2026-09-01
**Round:** 202609011145
**Follows:** 202609011102, whose src changelist is locked and whose work this repairs.

A review of the pull request carrying 202609011102 found seven things. Two of
them block, and both are the same shape underneath: a claim the file makes
about itself that nothing checks.

## The arm named for the strongest edge does not catch the last edge

`src/tests.rs:294` is `the_strongest_edge_decides_the_tier_across_rungs`, and
its own comment says what it is for: an implementation that took the last edge
it walked would pass every other arm, because each of those plants one edge.

It does not catch that implementation. Measured rather than argued: mutate
`src/lib.rs:329` from `entry.0 = entry.0.min(tier)` to `entry.0 = tier` and all
34 arms pass.

The reason is the fixture rather than the assertion. `rows_in` yields in slug
order, the arm names the ratified row `he_said_so` and the weak one `an_ack`,
and `an_ack` sorts first, so the strongest edge is the last one walked anyway.
The arm asserts the right answer over the one arrangement in which the wrong
implementation also produces it.

The walk has two orderings and neither is under the arm's control today. Within
one namespace the order is the slug's. Across namespaces it is `EDGES`, fixed
at `ruling`, `proposal`, `retirement`, so a pair drawn from two namespaces is
walked in one order whatever the slugs are called.

So the repair is a table rather than a rename: every pair of tiers a single
edge can produce, planted in both slug orders, with the stronger asserted in
both. The pairs where the walk's order is fixed still assert the right answer;
they just cannot be the ones that kill the mutant, and the file should say so
rather than let a reader assume every row is load-bearing.

## Two of the seven tier words cannot be grepped for, and the file says they can

`src/lib.rs:198-201` says every word `Reach::word` returns is either a `rung`
value or a namespace's own word, spelled as the schema spells it, so a tier in
a report can be grepped for in `mockspace.toml` and found.

Three of the seven fail that. `unsettled` and `route-closed` appear nowhere in
`mockspace.toml`: the rung is spelled `open` and the namespace is spelled
`retirement`. `nothing` appears seventeen times and never as a schema word, all
seventeen being ordinary prose.

Renaming the three is the other repair and it is the wrong one. `route-closed`
is the panel corpus's own word for the tier, used across
`202608072330_the-numeral-canon-panel` in the files this tool was built to
mechanise, and a report that stops using it stops being greppable against the
research that named it. The words stay and the claim gets narrowed to what is
true, with the schema spelling named beside each word that is this file's own.

## And a third own call the file presents as the schema's

`in_force` over `stated` is given as following the schema's ordering of the four
values. The schema lists them in that order and declares no ranking, and
`mock/lints/no_ruling_supersedes_one_that_outranks_it.rs:58` ranks them the
other way round, with a reason: `in_force` is a process call nobody stamped.

Two shipped things in this repository order the same two rungs oppositely. That
is a real question and it is not this round's to settle, because settling it is
a canon reading and takes two independent agreements. What this round owes is
that the file stops claiming the schema decided it, names the lint that
disagrees, and says the ladder is unsettled between them.

## The rest, and what is not here

Two more the review raised and this round takes: nothing pins the report's
order, and the walk never reads `kind`, so a `refusal` or a `deferral` at
`ratified` reads as met with no fixture anywhere planting one. Both are arms.

The `kind` question is a catalogue entry rather than a behaviour change. Eight
of the ninety-four rulings are `refusal` or `deferral` and none of them carries
an obligation edge today, so nothing is misreported now. Whether a refusal that
named an obligation should tier as met is a canon reading, and the arm that
plants one records the answer this walk currently gives rather than asserting
the answer it should give.

The seventh finding is about 202609011102's own locked changelist, which claims
a regeneration that did not move the catalogue. A locked changelist is frozen,
so that is an addendum beside it and not an edit to it.
