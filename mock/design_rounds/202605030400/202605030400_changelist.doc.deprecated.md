### New section: "Meta-bit newtypes (`Width`, `IBits`, `FBits`, `MetaCarrier`)"

Add a new section after the existing strategy-marker family documentation. Document the four meta-bit newtypes that relocate from `arvo-storage`:

- `MetaCarrier`: `repr(transparent)` over `u16`. Layout-stable companion type used as the meta-newtype payload. Carries `Bounded` and `Identity` const-trait impls. Used by `Width`, `IBits`, `FBits` as their underlying carrier through the `meta_bits_wrapper!` macro.
- `Width`: bit-width meta value (1 to 256 inclusive). Used as const-generic param type at trait surfaces such as `arvo-hash::Hasher<const N: Width>`. Reachable from arvo-strategy unblocks Round 3's `Bits<const N: Width>` lift and Deliverable A's `Ieee::WIDTH: Width` typing.
- `IBits`: integer-bit count for fixed-point types. Used at `UFixed<const I: IBits, ...>` and `IFixed<const I: IBits, ...>` const-generic positions.
- `FBits`: fractional-bit count for fixed-point types. Sibling of `IBits`; the type-distinct shape prevents accidental swap at construction sites.

State the relocation rationale: the meta-bit newtypes carry bit-counts at type-parameter positions that live throughout the stack. Their previous home in `arvo-storage` left every layer above L0 reaching back through the strategy-storage boundary for what is in spirit a strategy-axis typed value. Co-locating with `Hot` / `Warm` / `Cold` / `Precise` and the `BitsContainerFor<N, Sign>` projection keeps the type vocabulary that drives container dispatch in one layer.

State the surface that ships from this layer:

- `pub struct MetaCarrier(pub u16)` plus inherent `from_raw` / `to_raw`. `Bounded` and `Identity` const-trait impls. `Transparent` impl with `Inner = u16`.
- `pub struct Width(pub MetaCarrier)`, `pub struct IBits(pub MetaCarrier)`, `pub struct FBits(pub MetaCarrier)` via the `meta_bits_wrapper!` macro. Each carries `Bounded`, `Identity`, `Transparent`, `Deref<Target = u16>`, `AsRef<u16>`, `From<u8>`, `From<u16>`, `From<$W> for u8`, `From<$W> for u16`. Inherent `ZERO` / `ONE` constants. Inherent `raw(self) -> u16` accessor.
- `pub const fn ibits(n: u16) -> IBits`, `pub const fn fbits(n: u16) -> FBits`, `pub const fn width(n: u16) -> Width` const-fn helpers for const-generic-position literal construction.
- `Width::W64` inherent constant.
- `Width::const_add(self, other: Self) -> Self` const-trait `Add` op routed through the inner `u16` arithmetic. Minimum surface to compose `LOGICAL_WIDTH` bodies in Deliverable B.

State the `as_bits()` accessor's relocation: the inherent method that projects each meta-newtype to `Bits<9, Hot, Unsigned>` does not ship from this layer (Bits lives in arvo-storage; arvo-strategy cannot reach it). The accessor lifts to a `BitsView` trait in arvo-storage with per-type impls. arvo-storage carries the consumer-facing `as_bits()` surface.

State the `ConstPartialEq` / `ConstEq` / `ConstBitEq` / `ConstOrd` / `ConstDefault` const-trait impls: these traits live in arvo-storage (per the bridge-home rule, since they return `Bool` and Bool lives in arvo-storage). The impls on MetaCarrier / Width / IBits / FBits ship from arvo-storage, alongside `BitsView`. arvo-strategy carries only the Bounded / Identity surfaces that traits in arvo-strategy can target.

### New section: "Ieee trait (relocated from arvo facade)"

Add a section documenting `Ieee` after the `BitsContainerFor` / `MultiContainer` projection section.

- Show the canonical signature:

  ```rust
  pub const trait Ieee:
      sealed::Sealed + Copy + Default + PartialEq + PartialOrd
      + [const] Identity + [const] Bounded + 'static
  {
      const WIDTH: u16;
  }

  impl const Ieee for f32 { const WIDTH: u16 = 32; }
  impl const Ieee for f64 { const WIDTH: u16 = 64; }
  ```

- State the seal commitment: `Ieee` admits `f32` and `f64` today. Future widenings (`f16` / `bf16` / `f128`) require seal expansion in this file alongside the `impl_bounded_identity_f!` extension. The seal lives in a private `sealed` module.

- State the relocation rationale (matching the `Ieee` doc comment): supertrait commitment to `Identity + Bounded` means the trait sits where its supertraits sit. Co-location resolves the layer-inversion smell where the trait declaration sat at the facade with its supertraits one layer below.

- State that `WIDTH: u16` stays bare-primitive-typed for this round. Round 3 lifts it to `Width` once the bare-`u16` to typed-`Width` substrate sweep cascades through the bridge family.

- State the arvo facade re-exports `Ieee` from arvo-strategy so consumer code keeping `arvo::Ieee` import paths compiles unchanged.

### New section: "Bits projection accessor (`BitsView`)"

Add a section after the `Bits<N, S, Sign>` documentation.

- Show the canonical signature:

  ```rust
  pub const trait BitsView {
      fn as_bits(self) -> Bits<9, Hot, Unsigned>;
  }

  impl const BitsView for MetaCarrier { /* layout-equivalent transmute */ }
  impl const BitsView for Width  { /* via .0.as_bits() */ }
  impl const BitsView for IBits  { /* via .0.as_bits() */ }
  impl const BitsView for FBits  { /* via .0.as_bits() */ }
  ```

- State the rationale: the meta-newtypes (relocated to arvo-strategy this round) cannot carry inherent methods that project to `Bits<9, Hot, Unsigned>` because Bits lives in arvo-storage. The `BitsView` trait at arvo-storage provides the projection at zero cost (the underlying transmute is sound by repr(transparent) layout-equivalence between MetaCarrier and Bits<9, Hot, Unsigned>).

- State the safety-of-transmute commitment: `MetaCarrier` is `repr(transparent)` over `u16`; `Bits<9, Hot, Unsigned>` lowers via `<Hot as BitsContainerFor<9, Unsigned>>::T = u16`. Both types are layout-byte-identical to u16 by Rust spec.
