# Topic: nuking the tree so the canon can be written

**Date:** 2026-08-08.

Op, 2026-08-08:

> Let's nuke the entire mock/crates and make the Cargo.toml in mock/ be an empty workspace. This is
> what we should've done initially when we started working on the canon. Let's now do it for real

## Why this is the mutation order rather than housekeeping

`the-canon-design-code-chain.md` fixes the order in which the tiers may change: to change a design,
the code beneath it is nuked first, and to change canon, every design that declares it goes, and the
code beneath those with it. Nuking is not vandalism; it is the removal of the evidence for a position
that has been abandoned.

And the mechanism that licenses canon work at all: "declaring the lower tiers dead is what unfreezes
it. So an agent that helpfully consults the current designs or the shipped source during canon work is
not being diligent. It is reattaching the tier that had to be detached for the work to be permitted."

The canon panel opened on 2026-08-07 and has run to thirty-five files with the old tree sitting
underneath it the whole time. This should have happened at the start.

## What goes and what stays

**Goes:** every crate under `mock/crates`, and `mock/Cargo.lock`, which pinned the deleted members.
The workspace member list empties.

**Stays:** `mock/benches`, because its artifacts are committed evidence and several of the panel's
doability claims cite them. The bench crates stop being workspace members along with everything else,
so they will not build until something is built for them to measure. That is the correct state: there
is nothing to measure yet.

**Stays:** `mock/research`, `mock/design_rounds`, `mock/agent`, `mock/lints`, and the root templates.
None of them is code.

## Why nothing is lost

Git history holds every byte. `origin/dev` still carries the full tree, so consumers pinned to it are
unaffected, and that is exactly why the working tree could be cleared. The branch is
`feat/arvo-shape-topic`, not a trunk.

## One upstream defect this surfaces

mockspace panics rather than erroring when `mock/crates` does not exist: `can't read crates dir:
NotFound` at `src/parse.rs:12`. The workaround is to keep `mock/crates` as an empty directory, which
is what the sibling repo that did this first also does. **Git cannot track an empty directory**, so a
fresh clone of either repo reproduces the panic. An empty workspace is a legitimate state, and it is
the state this chain requires, so the tool should handle it.
