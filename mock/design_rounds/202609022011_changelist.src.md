## CHANGE: module docs on `width.rs` state what the door carries, not how the count was reached
File: `mock/crates/arvo-format/src/width.rs:24`
Verification: `grep -c 'separate derivations' mock/crates/arvo-format/src/width.rs` returns zero.

`//!` rustdoc renders, so it is a tier 1 surface and `documentation-writing.md`
forbids provenance there. "Two separate derivations reached different counts" is
how the project came to know the thing, which a reader of the crate cannot act on.
The sentence before it says the count is not stated and not settled, which is the
whole of what the door owes, and it stays.

## CHANGE: two const items and a `tests/ui` case pin where a transitive reach is decided
File: `mock/crates/arvo-format/src/tests/obligations.rs`, `mock/crates/arvo-format/tests/ui/`
Verification: `cargo test -p arvo-format` passes; the new `compile_fail` case is
registered in `tests/compile_fail.rs` and refuses.

The plan was an ordinary runtime arm asserting that `has_additive_identity` over an
inadmissible slot range compiles when the phase cancels at no magnitude. It does
not compile, and finding that out is what this entry is now about.

`has_additive_identity` reaches `slot_in_range` inside its loop, on a magnitude
where `cancelling_slot` answers `Is`. In a const evaluation the branch is taken or
not taken, so the slot range's obligation is forced for a format whose phase
cancels and not for one whose phase does not. At a runtime call none of that
applies: monomorphising the verb instantiates `slot_in_range::<F::Slots>` whichever
branch would have run, so the obligation is forced at codegen for every
declaration.

So the arm is a `const` item rather than an `assert_eq!`, and that is the assertion:
it binds the verb over `InvertedSlots`, which admits nothing, and it builds. A
control beside it binds the same phase over an admissible range so the const is
about the phase rather than about the verb. The refusal half is a build failure and
lives in `tests/ui/`.

The design sentence this refuted has been corrected in the same round rather than
carried, which is why the doc changelist was reopened a second time.

## CHANGE: `a_coordinate_is_readable_off_the_impl_without_the_obligation_firing` is deleted
File: `mock/crates/arvo-format/src/tests/obligations.rs`
Verification: `grep -c a_coordinate_is_readable_off_the_impl mock/crates/arvo-format/src/tests/obligations.rs` returns zero.

It could not fail for the reason it existed. Reading one associated const does not
force another in any Rust this crate could be written in, so no change to the crate
could close the route it claimed to pin, and the section header says pinning a
closable route is what these arms are for. Its two assertions duplicated two others
over an identical fixture. `the-test-gate.md` calls a test that cannot fail worse
than an absent one, because it occupies the space where a real one would be missed.

The section header said "the three arms below" and had four under it. The header is
rewritten rather than recounted, because the arms are not all the same kind of
thing.
