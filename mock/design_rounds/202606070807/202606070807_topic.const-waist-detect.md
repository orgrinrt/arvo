## What this round adds

A const-callable waist detector in arvo-graph: `waist_detect_const`, the const
analog of the existing `waist_detect`. Same algorithm, expressed as a `const fn`
over the `ConstCapacity` contract and the const `BitAccess` bit contract, so a
const consumer computes waist boundaries at compile time. The runtime
`waist_detect` is left untouched (op directive: an additional const version, not
a rewrite).

Compile-time DAG analysis is what the GATE-2 const grouping (downstream
hilavitkutin) needs: the canonical phase axis is waist-bounded, so the engine
must compute waists at const time from the WU access graph. Rather than re-roll
the algorithm in the engine, the const version lives in arvo where every
consumer needing compile-time DAG analysis benefits.

## Why the runtime version is not const

`waist_detect<C: Capacity, B>` cannot be a const fn as written:

1. It builds working arrays with `Capacity::filled` and indexes them through
   `AsRef`/`AsMut`, none const.
2. It materialises predecessors as a `Mask<B>` (`BitMatrix::predecessors`) and
   iterates the set bits with `Mask::iter_set_bits`, an iterator, not const.

`waist_detect_const` sidesteps both. Working arrays go through `ConstCapacity`
(const `filled` / `get` / `set` from R1a). The predecessor scan is inlined: for
each candidate `i`, test `succ_rows[i].bit(node)` via the already-const
`BitAccess::bit` contract, so neither `Mask` nor the iterator appears. The const
version is in fact simpler than the runtime one.

## Shape

```rust
pub const fn waist_detect_const<C, W>(
    succ_rows: &C::Array<W>,        // succ_rows[i] = successor word of node i (bit j set = edge i -> j)
    topo_order: &C::Array<NodeId>,
) -> C::Array<Bool>                 // slot k = topo position k sits at a waist depth
where
    C: [const] ConstCapacity,
    W: [const] BitAccess;
```

The input is the raw successor words (the `BitMatrix.rows[i].word` analog), not a
`BitMatrix`, so no non-const `BitMatrix`/`Mask` method is touched. The output is
a `C::Array<Bool>` flag per topo position, the const-contract analog of the
runtime `Mask<B>` (bit k set means the same as flag k true), so the two agree
position-for-position. The algorithm is identical: topo-order forward depth pass,
level widths, occupied depths, strict local minima among occupied depths, then
flags at the topo positions of waist-depth nodes.

## Toolchain

Requires `#![feature(const_trait_impl)]` in arvo-graph's lib.rs (WATCH-tier
ALLOWED; same gate R1a added to arvo-tensor). No `generic_const_exprs` over the
const surface: the working arrays are `ConstCapacity::Array` (min-const-generics
`[T; N]`), never `cap_size(N)` in type position.
