# Topic: scope generic_const_exprs gates to crates that use them

**Date:** 2026-05-29
**Phase:** TOPIC
**Scope:** all 12 arvo crate roots that gate `generic_const_exprs`
**Source:** unstable-feature soundness sweep (task #626), workspace rule `unstable-features.md`

## Context

The workspace soundness sweep classifies `generic_const_exprs` (GCE, rustc
tracking #76560) as a WATCH-tier feature: kept where genuinely used, removed
where dead, with a justification recorded above each retained gate. The
2026-05-29 design talk settled the disposition. GCE is sound for the way the
stack uses it. Its one known unsoundness (#97156, const `TypeId` resolved into
types with higher-ranked-trait-bound subtyping) is unreachable here because the
stack bans `TypeId` outright. The remaining rough edges are incomplete-
implementation gaps, not design unsoundness, which is exactly the WATCH band.
The crate-root gate stays where the construct is written; it should not sit on
crates that gate it without using it, where it reads as a dependency the crate
does not actually have.

Twelve arvo crate roots currently carry `#![feature(generic_const_exprs)]`.
Whether each one needs it is not answerable by grep: GCE has a propagation
property where a crate can require the gate because it calls an API whose
signature carries a const-expression bound, not because it writes one locally.
The authoritative test is remove-and-check. Each gate was removed in isolation
(dependencies kept their gates intact during each probe) and the crate was
compiled with `cargo +nightly-2026-05-28 check -p <crate> --all-targets`, plus
`cargo test --doc` for the candidates that compiled clean, because
`--all-targets` does not build doctests.

## Empirical result

Four crates compile clean without the gate, including doctests: `arvo-bits`,
`arvo-bits-contracts`, `arvo-hash`, `arvo-storage`. Their gates are dead and get
removed. The `arvo-bits-contracts` DESIGN doc already states its predicate-per-
impl-block shape avoids the GCE cycle, so removing the unused gate aligns the
source with the documented intent.

Eight crates fail without the gate, every failure being `generic parameters may
not be used in const operations`, the signature of a genuine GCE construct:
`arvo`, `arvo-bitmask`, `arvo-comb`, `arvo-graph`, `arvo-spectral`,
`arvo-sparse`, `arvo-strategy`, `arvo-tensor`. These keep the gate and gain a
justification comment above it.

The construct varies by crate. Most use `[(); cap_size(N)]:` array-length bounds
that call the single `cap_size` const fn in `arvo-tensor/src/cap.rs`. `arvo`
uses `[(); 1 / is_fractional(F)]:` compile-time assertions in `ufixed.rs` and
`ifixed.rs`. `arvo-strategy` uses Strategy-tag const-expression bounds. A single
uniform justification phrasing covers all three patterns accurately.

## Use-site documentation granularity

The sweep resolution calls for a justification above each gate and at use sites.
There is one GCE use-site kind in the cap_size family: the `cap_size` definition
itself. The 300-plus `[(); cap_size(N)]:` occurrences are calls to that one
already-documented const fn, not independent GCE constructs. Documenting the
definition and each gate is the proportionate, high-signal reading. Repeating an
identical comment across 300 call sites would bury the signal it is meant to
carry, which the writing-style discipline rejects.

## Changes proposed

1. Remove `#![feature(generic_const_exprs)]` from the four dead crate roots
   (`arvo-bits`, `arvo-bits-contracts`, `arvo-hash`, `arvo-storage`).
2. Add a uniform soundness-justification comment above the retained gate in the
   eight crates that use GCE.
3. Augment the existing comment at the `cap_size` definition
   (`arvo-tensor/src/cap.rs`) with the WATCH-soundness note, since that is the
   canonical GCE use-site for the array-length family.
4. While editing `arvo-storage/src/lib.rs` to drop its dead GCE gate, add the
   clarifying comment above its retained `const_convert` gate recorded by the
   #624 reclassification (const_convert is not stale: the feature is still named
   on the pinned nightly and points at the live const-From umbrella #143773).

No `.md.tmpl` documentation changes. Migration off GCE to `generic_const_args`
stays tracked as task #628.
