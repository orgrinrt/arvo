## B1: the shadowing hole moved from `usize` to `core`

The fourth review's fix respelled the platform-width aliases over
`core::primitive::usize::BITS` and declared the shadowing hole closed. The
fifth review's spike shows `core` itself is bindable inside `points`, by
`mod core { ... }`, by `use ... as core`, and hijackable crate-wide by
`extern crate self as core`. Only `::core::primitive::usize::BITS`, with the
leading `::`, resists all three. The spike also confirms `::core::...`
resists both aliasing forms, so the fix is real rather than another
respelling of the same hole.

Chosen fix: (b), spell the leading-`::` absolute path and add lint arms
refusing `mod core`, `use ... as core` and `extern crate ... as core` in
`arvo-format`, each with a firing test and a silent control. Narrow every
sentence claiming more than the leading-`::` path now closes: the doc CL
below names each site.

## B2: cross-end coverage for the Saturate/Clamp arm

`146d` asked for "every carried position into every range", cross-end. The
carry-past-the-index suite covers `past == -1 && up`. The Saturate/Clamp
direction at `apply.rs` ~237 has no coverage on the far side: the review's
mutants M1 and M2 both pass the whole suite while changing that arm's
behaviour at a position one past the top going into a range at the bottom of
the index (and the mirror at the bottom going into a range at the top).

Fix: add M1 and M2 to `the_broken_maps.rs` as broken maps, and write the
cross-end matrix `146d` asked for as a law reporting both, following the
shape `the_translation_law.rs`'s `new_law` already uses for the other broken
maps.
