# Topic: the note travels with the name, and what the closed round claimed that is not true

**Date:** 2026-09-20
**Governing canon:** `ruling::half_up_denotes_ties_toward_positive_infinity`, whose `note` says the note
travels with the name "as the floor note travels with the retired word".
**Where this came from:** the third blocking finding of the review of pull request #150 and its
non-blocking findings five to ten.

## The note does not travel by anybody remembering

The crate's own README template got the note in the closed round. The repository's root `README.md`, which
is the page a stranger lands on, names `half_up` among the six and carries only the retired word's note
beside it. It is not generated from anything: no template renders it, and `git log` shows it hand-edited,
so the round that added the note everywhere else could not have carried it here without somebody thinking
of it.

Three rustdoc pages are in the same state. The `HalfUp` marker type, the `rounding_method` module in
`standards`, and `behaviour_of` in `symmetry` each state what `half_up` denotes and each is a page a
reader reaches directly, and none of them names what the name is not.

[between fixing the six sites and making the class checkable] Both. The sites are fixed and a lint,
`half-up-carries-its-note`, refuses a published surface that names the mode without the note, because the
class is exactly the kind that comes back: the next document naming the mode will be written by somebody
who has the ruling in mind and the note nowhere near their hands.

What the lint reads: the repository's root `README.md`, every `.md.tmpl` under the mock directory outside
`research/`, `design_rounds/`, `target/` and hidden directories, and every doc comment in a `.rs` file
under the same exclusions. A markdown document naming any spelling of the mode carries the note somewhere
in it. A doc passage carries the note where it states the denotation, which is where it names the mode and
says what happens at a tie; a passage naming the mode in passing does not, because the note belongs where
the meaning is given rather than on every mention.

What it does not read: the registry, whose rows are the canon and carry their own note where the ruling
sits; the generated documents under `docs/`, which follow from the templates and would otherwise put the
canon's own rendered rows under this rule; and plain comments, which are not published.

The note is present when the passage names `HALF_UP`, the constant this name is confused with. That is
mechanical and it is what the confusion actually is. A passage that names it and gets the relation the
wrong way round is what the sibling lint refuses, so the two of them together are the check.

## What the closed round claimed that the source does not say

Every verification line in `202609192220_changelist.src.lock.md` was re-run against the tree at this
round's base, and the sketches' claims with them. Two are wrong, and both were found by the review:

- "Each of 29 arms broken in turn fails the suite", in the src changelist and in
  `mock/research/sketches/the-half-up-lint-mutants/README.md`. The README lists 28 mutants, fourteen of
  the passage reader and fourteen of the Rust file reader, and `out/runs.txt` holds 28 runs beside the
  `none` control. The sketch's README is corrected in this round; the locked changelist is frozen and the
  correction is recorded here instead.
- "`grep -c neighbour` in `rounded` returns zero". It returns one, from the comment at
  `the_oracle.rs:170` explaining which neighbour a floor lands on. The claim was about the function
  choosing between neighbours, which it does not; the grep as written does not say that.

Everything else holds: the tie arm reads no sign, the classification is four and two, the sweeps carry
fourteen maps each, the planted tie rules are the five named, the parity file passes with nothing ignored,
and the lint's suite is the forty tests the changelist says.

## The rest of the review's non-blocking findings

[on where a published document may say when something shipped] `DESIGN.md.tmpl` at 690 and its rendered
copy say a planted rule is "the rule this crate shipped before the canon settled what `half_up` denotes".
A published document says what a planted rule is, not when the tree stopped carrying it. The same sentence
in a test's rustdoc is internal and stays.

[on a test asserting a paraphrase] `the_rulings_own_note_and_the_crates_own_docs_read_clean` asserts over
sentences nobody wrote. The ruling's `note` is quoted verbatim instead, and the arm is named for that. The
lint skips a ratified ruling, so what the arm establishes is that the skip hides nothing.

[on the verdict table] `the_verdict.rs` pins the `half up` row as literal counts equal to the `ceil` row's
and explains in a comment that they must be. The relation is asserted, and the four modes that read
nothing besides the residue are asserted to have no associative refusal as a group rather than as four
copied rows of zeros.

[on the parity file] Two arms there do no work. `the_bound_is_attained_and_not_merely_respected` computes
arithmetic over its own literals and claims in its rustdoc that turning the macro's `<=` into `<` fails
here and nowhere else, which is backwards: it fails in the arm the macro generates and never here. It is
deleted, and what it was for, that the bound is reached and the comparison may not become strict, is
asserted inside the macro's own arm where the comparison lives. The equality of two constants in
`no_shipped_mode_is_matlab_round` is deleted for the same reason: it relates two declarations to each
other and nothing else.

[on the rustfmt churn] It is not churn somebody wrote, and it cannot be reverted. Sixty lines of
`mock/tools/rounding-vocabulary/src/lib.rs` changed against `dev`, and fifty-two of them are what the
pinned nightly's own rustfmt produces from the `dev` version under this repository's `rustfmt.toml`,
measured by running it over that version in a scratch copy. The pre-commit autofixer runs the same
formatter over every staged file, so reverting those lines puts them straight back on the next commit
that stages the file. The eight lines left are the round's own doc change.

The class under it is larger and is not this round's. Around seventy tracked `.rs` files outside
`research/` and `benches/` are in the same state, lints, tools and three crate files among them, so any
round touching one of them carries a reformatting diff it did not ask for. Formatting them is a chore of
its own, and doing it inside a correctness round is how a review stops being able to see the
correctness.
