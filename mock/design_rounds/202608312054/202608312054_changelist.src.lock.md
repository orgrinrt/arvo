# Src changelist: a width that derived zero bits, and a key that selected nothing

**Date:** 2026-08-31
**Round:** the width-bound round
**Scope:** `arvo-format/src/slots.rs`, `arvo-placement/src/lib.rs`, both crates' tests, and a marker on
two bench manifests.

## CHANGE: `Slots` FROM two coordinates TO three, carrying the declared width
File: `mock/crates/arvo-format/src/slots.rs`
Verification: `grep -c 'const WIDTH' mock/crates/arvo-format/src/slots.rs` returns one, and
`declared_width` contains no loop.

**Reproduced first.** Transcribing the shipped definitions: width 62 gives count 4611686018427387904
and derives 62 bits; **width 63 gives count -9223372036854775808 and derives 0 bits**. The count wraps
negative, the loop's `1 < count` is false against a negative, and the function returns zero. Width 64
fails const evaluation with `error[E0080]: attempt to negate i64::MIN`.

**The count was never needed.** `declared_width` formed the count of slots and recovered the width by
taking its base-two logarithm in a loop, which reconstructs the number the declaration already stated.
`Signed<13>` knows it is thirteen bits. The count is the only quantity in the chain that leaves the
range it is carried in, and nothing reads it.

So `Slots` carries `WIDTH` and `declared_width` reads it. No count is formed, no loop runs, and the
zero-bits class is gone rather than guarded.

## CHANGE: `MIN` and `MAX` FROM a raw overflow TO a named compile-time refusal
File: `mock/crates/arvo-format/src/slots.rs`
Verification: the compile-fail test in `arvo-format/src/slots/refusal.rs` records the diagnostic.

Above 62 bits a slot index does not fit a signed 64-bit integer. The design refuses there, at const
evaluation, with a message naming the width and the bound, because
`ruling::never_a_runtime_check_and_one_lowered_path` is ratified: invalids are caught at compile time.
A refusal arriving as `attempt to negate i64::MIN` is one a reader cannot act on.

**This is a design call and the canon licenses it being one.**
`question::arbitrary_width_demands_in_the_canon` asks whether the canon should speak of arbitrary
const-width demands, and its second option is "leaving width families to design". Under either answer
the width family is the design's, so choosing 62 is not a parked question. **How wide arvo should
ultimately go stays open and this round does not answer it.**

## CHANGE: `Objective` FROM a runtime argument TO a const parameter that selects
File: `mock/crates/arvo-placement/src/lib.rs`
Verification: `derive_sole` and `derive_shared` take `const O: Objective`, and
`two_objectives_derive_two_placements_at_shared_occupancy` compares them.

**Reproduced first.** Both arms of the match were the same expression and nothing else in either
function read the parameter, so every derivation came back identical whatever was passed.

What the objective selects is derived from ratified rows.
`ruling::cold_is_for_cold_paths_and_cold_storage` says the storage-minimising objective aggressively
minimises and bitpacks; `ruling::the_derivation_is_a_placement_and_the_operation_set_is_an_admission_rule`
gives three outputs at shared occupancy, which is what the two objectives have to differ in.

**At shared occupancy `Footprint` packs**: stride is the declared width and the access reaches wider
because an element can straddle a carrier boundary. **`Access` does not pack**: stride and access are
both the carrier, one element per carrier, padding rather than straddling.

**At sole occupancy they coincide and that is asserted as a result**, because the value owns its
allocation and there is nothing to trade.

The parameter is const rather than an argument because the typestate holds it as a compile-time fact
and I15 wants the branch erased by monomorphisation. `adt_const_params` is on the allowed feature list.

## CHANGE: the width sweeps FROM 1..32 and 2..32 TO the range the design admits
File: `mock/crates/arvo-format/src/tests.rs`
Verification: the macros are invoked over 1 through 62, and the file's claim matches what it runs.

The sweeps stopped at 32 while the ladder reached 64 and the file said they ran every width the slot
ranges admit. They now run every width the design admits, which is 1 through 62, and the sentence is
true rather than aspirational.

## CHANGE: `the_objective_is_a_coordinate_of_the_derivation` FROM asserting neither TO comparing both
File: `mock/crates/arvo-placement/src/tests.rs`
Verification: the test body contains an `assert_ne!` between two derivations.

It asserted that both occupancies were `Sole` and that two enum variants differ, and never compared
the two derivations it had taken. The comparison the test is named for is now the one it makes, at
shared occupancy where the two differ, with the sole-occupancy equality asserted beside it.

## CHANGE: two bench manifests FROM silently unbuildable TO marked
Files: `mock/benches/variants/fnv1a/Cargo.toml`, `mock/benches/variants/xxhash3/Cargo.toml`
Verification: both carry a `FIXME` naming the dead dependency and the reason they are kept.

They inherit workspace dependencies that no longer exist and fail at `cargo metadata`. Keeping them is
still the result, because fixing means inventing bench arms and deleting destroys an artifact trail.
**What was missing was that nothing said so**, which is what a marker is for.

`spectral-bisection` and `structural-decomposition` get the same marker for the same reason.

## What is deliberately not here

**How wide arvo should go.** Open, and named as open in both the design and this file.

**Any change to rounding, overflow or the adaptation**, untouched by this round.

## How this changelist expects to be checked

`cargo mock check` green at strict.

`cargo test --workspace` in `mock/`, with the width sweeps covering 1 through 62 and the objective
tests comparing two derivations rather than one.

The compile-fail record in `arvo-format/src/slots/refusal.rs` naming the diagnostic a width above the
bound produces.
