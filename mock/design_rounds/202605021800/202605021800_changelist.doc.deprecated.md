### Section: "Const-trait substrate bridges (`ConstEq`, `ConstOrd`, `ConstDefault`)"

**Action:** Add new section after "Sealed marker traits". This is the canonical reference for the bridge family.

**Content:** Explain why bridges exist: `core::cmp::PartialEq`, `core::cmp::Ord`, `core::default::Default` are not const-stable in stdlib. Several substrate surfaces require their semantics in `const fn` bodies (UArith division-by-zero check, Predicate family, sorts). Bridge traits provide const-callable equivalents at the substrate boundary while leaving the stdlib traits in place for boundary coverage.

Show the canonical signatures:

```rust
pub const trait ConstEq {
    fn const_eq(&self, other: &Self) -> Bool;
    fn const_ne(&self, other: &Self) -> Bool {
        Bool(!self.const_eq(other).0)
    }
}

pub const trait ConstOrd: ConstEq {
    fn const_cmp(&self, other: &Self) -> Ordering;
    fn const_lt(&self, other: &Self) -> Bool;
    fn const_le(&self, other: &Self) -> Bool;
    fn const_gt(&self, other: &Self) -> Bool;
    fn const_ge(&self, other: &Self) -> Bool;
}

pub const trait ConstDefault {
    fn const_default() -> Self;
}
```

Document the `Ordering` choice: prefer `core::cmp::Ordering` if const-constructible on rustc 1.96.0-nightly; otherwise ship `pub enum ConstOrdering { Less, Equal, Greater }` substrate-owned. SRC-PLAN time decides; the decision lands here at lock time.

State the impl coverage rule: every substrate primitive wrapper (USize, Cap, Bool, Bits, UFixed, IFixed, FastFloat, StrictFloat, Mask64, Mask256, NodeId, MetaCarrier, IBits, FBits, Width) gains an `impl const ConstEq` and an `impl const ConstDefault` in this round. `ConstOrd` impls land for the totally-ordered subset (USize, Cap, Bits, UFixed, IFixed, NodeId, MetaCarrier, IBits, FBits, Width; not Mask, not floats — Mask has lattice ordering via subset, floats have NaN).

State that the stdlib `Default`, `PartialEq`, `Eq`, `PartialOrd`, `Ord` impls remain alongside for boundary compatibility — the bridges are additive, not replacements.

State the deferred bridges (cross-reference rounds 5 and 6):
- `ConstFrom<T>` / `ConstTryFrom<T, E>` — Round 5 / #314
- `ConstDeref` / `ConstAsRef<T>` — Round 5 / #314 (placed in `arvo-transparent`)
- `ConstTry` / `ConstControlFlow<R, O>` — Round 6 / #315 (placed in `notko` or `arvo-storage`)
- `ConstHash` / `ConstHasher` — Round 6 / #315 (placed in `arvo-hash`)

### Section: "USize and Cap canonical surfaces"

**Action:** Update existing USize / Cap documentation. Add a "Canonical const traits" sub-section.

**Content:** Document that `USize` and `Cap` impl const `Bounded` + const `Identity`. The inherent `USize::MAX` / `USize::ZERO` / `USize::ONE` constants stay as ergonomic shorthand but route through the trait projection:

```rust
impl USize {
    pub const MAX: Self = <Self as Bounded>::MAX;
    pub const ZERO: Self = <Self as Identity>::ZERO;
    pub const ONE: Self = <Self as Identity>::ONE;
}
```

Same shape for `Cap`. State explicitly: hardcoded `usize::MAX` literal at the definition layer (in the `impl const Bounded for USize` body) is the substrate's bottom-out point and the only place where the bare primitive literal appears. Consumer code reaches for `USize::MAX` (ergonomic) or `<USize as Bounded>::MAX` (generic).

State that `Cap` gains a `MAX` constant (previously absent — asymmetric with USize); body is `Cap(USize::MAX)`.
