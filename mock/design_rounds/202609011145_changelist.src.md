## CHANGE: the strongest-edge arm becomes a table over both orders
File: `mock/tools/obligation-coverage/src/tests.rs`
Verification: mutate `lib.rs` from `entry.0 = entry.0.min(tier)` to `entry.0 = tier` and the suite
fails; restore it and the suite passes. Measured both ways round, not argued.

The arm as it stands plants `ruling::an_ack` at `stated` and `ruling::he_said_so` at `ratified` and
asserts `Ratified`. `rows_in` yields in slug order, `an_ack` sorts first, so the ratified row is the
last edge walked and an implementation taking the last edge produces the same answer. All 34 arms pass
under that mutation today.

It becomes a table of every tier one edge can produce, with the row that produces it, and every pair of
distinct tiers planted twice: once with the stronger row's slug sorting first and once sorting last.
Fifteen pairs, thirty views, and the stronger tier asserted in all thirty along with both rows appearing
in the second half of the entry.

**Not every pair can kill the mutant and the arm says which.** The walk has two orderings and only one
is the slugs'. Across namespaces the order is `EDGES`, fixed at `ruling`, `proposal`, `retirement`, so a
pair drawn from two namespaces is walked in one order however its rows are named. Those rows still
assert the right answer and a comment says they are not the load-bearing ones, because a reader who
assumes every row in a table is doing work will not look for the ones that are.

## CHANGE: the tier words stop claiming a greppability three of them do not have
File: `mock/tools/obligation-coverage/src/lib.rs`
Verification: `grep -c` in `mockspace.toml` for each of the seven words: `ratified` 8, `in_force` 2,
`stated` 24, `proposed` 3, `unsettled` 0, `route-closed` 0, `nothing` 17 and every one of those
seventeen ordinary prose.

`Reach::word`'s doc says every word it returns is either a `rung` value or a namespace's own word,
spelled as the schema spells it, so a tier in a report can be grepped for and found. Four of the seven
are. `unsettled` stands over the rung the schema spells `open`, `route-closed` over the namespace the
schema spells `retirement`, and `nothing` is this file's own word for absence with no schema word behind
it at all.

The words stay. `route-closed` is the panel corpus's word for that tier, carried through
`mock/research/202608072330_the-numeral-canon-panel/` in the files this tool mechanises, and a report
that stops using it stops being greppable against the research that named it. What changes is the claim:
each of the three names the schema spelling it stands over, so a reader holding a report can still reach
`mockspace.toml` in one hop.

## CHANGE: `in_force` over `stated` is marked as this file's own call, and the lint that disagrees is named
File: `mock/tools/obligation-coverage/src/lib.rs`
Verification: `mock/lints/no_ruling_supersedes_one_that_outranks_it.rs:58` reads
`const TIERS: [&str; 4] = ["open", "in_force", "stated", "ratified"]`, weakest first, which ranks
`stated` above `in_force`. This file ranks them the other way.

The ladder section gives `in_force` over `stated` as following the schema's ordering of the four values.
The schema does list them in that order and declares no ranking over them, and a shipped lint in this
repository ranks the same two rungs oppositely, with a reason: `in_force` is a process call nobody
stamped.

So it is a third own call and the file already marks its other two. **Nothing about the tier changes.**
Settling which order is right is a canon reading and takes two independent agreements, which is not this
round; what this round owes is that the file stops attributing the call to the schema, names the lint by
path, and says the two disagree.

## CHANGE: arms for the report's order and for a `kind` the walk never reads
File: `mock/tools/obligation-coverage/src/tests.rs`
Verification: both arms fail against a mutated implementation, and the `kind` arm's assertion is the
answer the walk gives today rather than the answer it should give.

Nothing pins the order the report prints in, so a change from tier-major to slug-major would move every
line of the output and no arm would fire. One arm plants three obligations at three tiers and pins the
order.

The walk reads `rung` and never `kind`, so a `ruling` at `ratified` whose `kind` is `refusal` or
`deferral` tiers as met. Eight of the ninety-four rulings carry one of those kinds and none of them
names an obligation, so nothing is misreported on the committed registry and no fixture anywhere plants
the case. The arm plants it and records what happens, marked in as many words as the current behaviour
rather than the intended one, because whether a refusal that named an obligation has met it is a canon
question this round does not answer.
