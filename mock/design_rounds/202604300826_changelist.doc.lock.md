## arvo-bits-contracts/DESIGN.md.tmpl

### Add `## Widen` section after the existing `## Narrow` section

Mirror the structure of `## Narrow`. Sections:

1. Trait declaration block:

   ```rust
   pub const trait Widen<T> {
       fn widen_to(self) -> T where Self: Sized;
       fn widen_to_unmasked(self) -> T where Self: Sized;
   }
   ```

   Plus the `Widened<T>` alias pointer (mirrors `Narrowed<const N, T>`).

2. Asymmetry note. Explain why Widen does not carry the const-N
   parameter that Narrow does. Same prose as topic decision A:
   Narrow's const-N is the destination logical width (load-bearing
   for the mask); Widen's source bit-width derives from per-impl
   context (carrier `BITS` for primitives, `M` for `Bits<M, S, Sign>`).
   A const param on `widen_to` would be informational at best.

3. Cross-primitive Widen impls block. Pattern: `impl const Widen<T_dst>
   for T_src`, body delegates to `self as T_dst`. Sign-extension
   via Rust's `as` (signed source to wider signed dest sign-extends;
   unsigned source to wider unsigned dest zero-extends). Same orphan-
   rule reasoning as Narrow: impls live in `arvo-bits-contracts`
   because both trait and primitive types are foreign to `arvo-refit`.

4. Cross-Bits Widen impl block. Pattern matches the cross-Bits
   Narrow forwarder: `Bits<M, S, Sign>: Widen<Bits<N, S, Sign>>` for
   M < N, forwarding through `<S as BitsContainerFor<M>>::T:
   Widen<<S as BitsContainerFor<N>>::T>`. Compile-time guard M < N
   not enforced at the type level (parallel to Narrow's M > N
   non-enforcement); consumers supplying M >= N still get a valid
   widen result that's semantically a same-or-narrower-fit (no-op
   for same width, identity for malformed cases).

### Add same-container Narrow impls coverage note

In the existing `## Narrow` section, after the cross-primitive impls
block, add a paragraph:

> The cross-primitive impl matrix is closed under same-container
> narrowing: `u8: Narrow<u8>`, `u16: Narrow<u16>`, ..., `i128:
> Narrow<i128>`. The macro body's `>= BITS` short-circuit handles
> the same-width case as a no-op. Same-container Narrow unblocks
> cross-Bits narrowing within one container range (`Bits<32, Hot>`
> → `Bits<28, Hot>` both u32-backed; `Bits<28, Hot>` → `Bits<24,
> Hot>` both u32-backed).

### Add cross-domain primitive↔Bits direct impls section

After the existing cross-Bits Narrow forwarder block, add `## Cross-
domain primitive↔Bits direct impls`:

> Symmetric `Pri: Narrow<Bits<N, S, Sign>>` and `Bits<N, S, Sign>:
> Widen<Pri>` impls let consumers narrow a primitive directly into a
> typed Bits, or widen a typed Bits directly into a primitive carrier,
> without an intermediate `Bits::from_raw` wrap. Macro-generated over
> the strategy-and-sign matrix the existing tables cover. The cross-
> domain impls underlie the `Bits::from_narrowed<Src>` and
> `Bits::from_widened<Src>` ergonomic constructors (see
> `arvo-storage/DESIGN.md.tmpl`).

### Add Bits ergonomic constructors section

After the existing description of `Bits::from_raw` / `Bits::to_raw`,
add `## Ergonomic constructors`:

> The inherent `Bits<N, S, Sign>` impl ships two refit-aware
> constructors: `from_narrowed<Src>(src: Src) -> Self` (when the
> source type implements `Narrow<<S as BitsContainerFor<N, Sign>>::T>`)
> and `from_widened<Src>(src: Src) -> Self` (when `Src: Widen<<S as
> BitsContainerFor<N, Sign>>::T>`). The source type `Src` is inferred
> from the value at the call site; no turbofish needed.
>
> ```rust
> let bits28 = Bits::<28, Hot>::from_narrowed(wide_u64);   // narrow_to::<28>() inside
> let bits64 = Bits::<64, Hot>::from_widened(bits28);       // widen_to() inside
> let raw28 = Bits::<28, Hot>::from_raw(carrier_u32);       // existing constructor
> ```
>
> The constructor names match the trait names. `from_raw` remains
> the unchecked entry point; `from_narrowed` and `from_widened` route
> through the refit traits and are the recommended path when the
> source type does not exactly match the carrier projection.
