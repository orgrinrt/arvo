# SRC changelist: the forcing sets are per obligation

## CHANGE: mock/crates/arvo-format/src/format.rs

The rustdoc on the format's obligation says `contains` forces nothing. Narrow it
the same way the design was narrowed: name the two obligations `contains` does
force and the two it does not.

## CHANGE: mock/crates/arvo-format/src/tests/obligations.rs

Two comments. The one on `contains_answers_for_a_format_whose_phase_does_not_denote`
says `contains` forces no obligation, so an inadmissible declaration reaches an
answer through it. True only of a declaration inadmissible in its phase, which is
what the fixture is, so the arm passes without ever entering the path that would
expose the generalisation. The comment gets the narrow claim and says which
inadmissibility it is about.

The one on `an_implementor_writes_over_the_obligation_and_the_forcing_verb_finds_nothing`
repeats the same sweeping claim as its reason for routing through a forcing verb.
The reason stands and the claim behind it does not.

## CHANGE: mock/crates/arvo-format/tests/ui/cancelling_slot_forces_the_format_obligation.rs

New. `Format::ADMITTED` is forced at `cancelling_slot` and `has_additive_identity`,
and only the second is pinned. Deleting `let () = <F as Format>::ADMITTED;` from
`cancelling_slot` today leaves the whole suite green, so the other half of the
claim is unheld. Same shape as the existing arm: bind the call in a const item so
the refusal is reachable at check time rather than only at codegen.

## CHANGE: mock/crates/arvo-format/tests/compile_fail.rs

Register the new arm. A trybuild file nothing registers does not run.
