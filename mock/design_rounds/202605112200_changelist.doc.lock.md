## File 1: `mock/crates/arvo-storage/DESIGN.md.tmpl`

### Section: `## From bridges` (NEW)

**Add.** New section. Names the `Cap` ↔ `USize` const-From impls and the lifted `Bool` ↔ `bool` const-From impls.

Content:

- Lead paragraph: arvo primitives expose ergonomic `.into()` projections between paired newtype layers. Each `From` impl is `impl const From`, so call sites resolve at const time when both operands are const-known. The bridges are typed projections; raw integer access still routes through `Deref`/`Transparent::raw`/`cap_size` per the existing `.0`-field-access-is-a-smell discipline.

- Bridge table (three columns, four rows):

  | From | To | const | Use |
  |---|---|---|---|
  | `Cap` | `USize` | yes | Project a const-generic capacity to a typed count (returns, where-clauses, function arguments) |
  | `USize` | `Cap` | yes | Construct a capacity from a typed count (rare; symmetric companion to the above) |
  | `bool` | `Bool` | yes | Lift a raw `bool` to the typed `Bool` at FFI boundaries |
  | `Bool` | `bool` | yes | Extract a raw `bool` from `Bool` at boundary call sites (parallel to `as_bool()`) |

- One paragraph: the const-ness matters for compile-time eval paths (const-generic computations, `const _: USize = Cap::ONE.into()` type-level checks). Per `arvo-always-optimal-internals`, the impls compile to a copy under repr-transparent layout; zero runtime cost.
