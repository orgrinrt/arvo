# Doc changelist: an exact-width bit container

Topic: `202609040608_topic.an-exact-width-bit-container.md`.

## `mock/crates/arvo-bits/README.md.tmpl` (create)

Shortest tier, three to ten lines. States: what `Bits<const N: u32>` is, that it is exact-width and
opaque (no arithmetic, no signedness), that it is zero-workspace-dependency, `no_std`, no alloc.

## `mock/crates/arvo-bits/DESIGN.md.tmpl` (create)

Middle tier. Sections: overview (the container and why it exists, pointing at the obligation and the
ruling it sits under), the type (const bound, masking construction, `cast`, the unwrap door), why the
bound is not `arvo_format::slots::Slots` (the two different overflow reasons), why the crate has no
workspace dependency (transitive-footprint principle, no type erasure anywhere to make a `WIDTH`
accessor earn its keep), what the ruling constrains and how the design stays compliant under every
reading of the open question, what is explicitly out of scope (no `arvo-hash`, no `ContentHash` alias,
no hashing traits).

## `mock/DESIGN.md.tmpl` (update)

- Crate topology table: add a fourth row, `arvo-bits`, "An exact-width bit container: `Bits<const N:
  u32>`, masked construction and cast, no arithmetic. Introduces the numeric category a second time, so
  `Bits` is defined here.", depends on nothing.
- "The set is open at both ends" paragraph: no change needed, it already speaks in terms open to a
  fourth crate joining beside the three.
- "Contracts and their instances" section: `Bits` is named as a concrete with no contract behind it
  (there is no outside implementor of an exact-width container; it is one type, not an open concept),
  which is itself worth one sentence since every other entry in that section is a contract-plus-instances
  pair and this one is not.
- "Dependency direction" section: state that `arvo-bits` sits parallel to `arvo-format`, not beneath or
  above it, with zero workspace dependency of its own, and that this is a deliberate choice against an
  earlier draft that depended on `arvo-format` for `Width` (recorded in the topic file, not repeated in
  the design doc, which states the result rather than the deliberation).
- "Consumers" section: the existing disclaimer about hilavitkutin/vehki using removed crates stays
  verbatim; append one sentence that `arvo-bits` is new source, not a restoration, and answers one piece
  of what those removed crates used to answer (the exact-width container) and not the rest (hashing,
  string identity).

## `mock/PRINCIPLES.md.tmpl` (update)

- "Topology" section (top of file): "Three crates" becomes "Four crates", with `arvo-bits` folded into
  the same paragraph shape the existing three already use, one sentence, no workspace dependency.
- "Primitive vocabulary (the stack's own)" table: add a row, `` `u8..u128` at an exact declared width ``
  | `` `Bits<const N: u32>` `` | `arvo-bits`. This is additive to the existing `u8..u128` row (which maps
  to `Boundable`/`NonZeroable` in `notko` for the general bounded/nonzero case); the new row is the
  narrower exact-width-container case the obligation asks for, not a replacement for the general row.
- "Contracts before concretes" list: append one line, `` `arvo-bits` ships one concrete with no contract

  three-bullet shape the section already uses.

## What is not touched in DOC phase

`Cargo.toml` (workspace member list, workspace dependency) is ungated per `design-round/SKILL.md`'s own
statement that manifests are wiring, not source; it is edited whenever convenient rather than being
covered by this changelist. `mockspace.toml`'s `[primitive-introductions]` table and
`mock/lints/a_contract_coordinate_is_not_a_host_primitive.rs` are treated as source-equivalent (a
registry write path and a `.rs` lint file respectively) and wait for the source changelist, along with
every file under `mock/crates/arvo-bits/src/` and `mock/crates/arvo-bits/tests/`.
