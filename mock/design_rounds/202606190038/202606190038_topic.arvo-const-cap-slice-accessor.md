# Topic: const slice accessor on ConstCapacity

**Date:** 2026-06-19
**Crate:** arvo-tensor
**Tracked:** hilavitkutin completion-arc P0.1a

## Problem

`ConstCapacity` exposes const `filled` / `get` / `set` (by-value, `Copy`)
but no way to view its backing array as a `&[T]` / `&mut [T]` slice in const
context. `Capacity`'s `AsRef` / `AsMut` are not const-callable. A const fn
that builds a `ConstCapacity::Array<T>` scratch and then hands it to a
slice-taking `[const]` helper (the shape hilavitkutin's const-grouping walk
uses: `masks_of` filling `&mut [USize]` masks/ranks scratch) has no const
bridge from the GAT array to a slice.

## Decision

Add two const methods to `ConstCapacity`:

```
fn slice<T: Copy>(a: &Self::Array<T>) -> &[T];
fn slice_mut<T: Copy>(a: &mut Self::Array<T>) -> &mut [T];
```

For `Dim<N>` each body is the built-in unsized coercion (`a` where
`a: &[T; N]` coerces to `&[T]`). Folded directly into `ConstCapacity` (not a
sibling trait): `Dim<N>` is the sole impl, the GAT already lives there, and a
const consumer that needs both `filled`/`get`/`set` and slice access binds one
trait. Pre-1.0 churn permits adding the methods with no default.
