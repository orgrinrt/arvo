# Topic: the gate over `mock/crates/` is still untested, re-filed after a sweep

**Date:** 2026-08-31
**Phase:** TOPIC
**Scope:** `mock/lints/`, and the `undocumented-type` and `no-std` lints in mockspace itself
**Status:** re-filed, unchanged in substance, owned elsewhere

This is the second re-filing of the same subject and the reason is mechanical rather than new.

`202608311948_topic.the-source-gate-is-untested-and-two-of-it-is-broken.md` was flat when round
`202608311957` opened. That round's doc changelist named it, said it needed nothing from the round, and
said it would stay flat so whoever owns it inherits it the same way. **Then `cargo mock close` swept it
into `mock/design_rounds/202608311957/` along with the round's own files**, because close takes every
loose flat file in the directory regardless of which round it belonged to.

So the changelist's statement became false about the tree the moment the round closed. **The content is
not lost**, it is readable at
`mock/design_rounds/202608311957/202608311948_topic.the-source-gate-is-untested-and-two-of-it-is-broken.md`,
and this file exists so the next round inherits the subject rather than having to find it inside a
closed archive nothing points at.

## What it says, in one paragraph, so this file is not a bare pointer

Five lints gate every line of source under `mock/crates/` and none has a test:
`no_std_enforcer`, `no_alloc_enforcer`, `no_dynamic_dispatch`, `no_runtime_grow`,
`arvo_bits_traits_only`. Two have measured holes: `no_std_enforcer` misses every qualified path
expression, so `std::process::exit(0)` passes it, and `no_alloc_enforcer` matches against the untrimmed
line so `String::from` at column zero passes while the same expression indented is caught. The
other three have not been examined, which is a different statement from saying they are sound. Two
further defects sit in mockspace's own lints: `undocumented-type` is unsatisfiable for any type name
with no lowercase letter, and `no-std` reads only the first thirty lines of a crate root.

The archived file carries the measurements, the probe that established them, and the reasoning.

## Ownership, stated so this is not picked up twice

**The two measured holes are with the agent working on the lint suites**, per the dispatch that opened
round `202608311957`. **The two mockspace lint defects belong to that repository.** Nothing here is
this arc's to fix.

**What is this arc's is that the subject stays visible.** A topic that only exists inside a closed
round's archive is inherited by nobody, and the sweep has now buried it twice.

## The sweep itself is worth a fix and this file is not it

`close` conflating loose flat files from other rounds into the closing round's archive is known
behaviour and the workspace rules name it. The practical consequence, seen twice in two rounds, is that
**a filing left deliberately in the way is removed from the way by the next round that closes**,
whatever that round said about it.

Two workarounds exist and neither is free: close a round while no unrelated flat topic is present,
which serialises rounds against filings they have nothing to do with, or re-file after every close,
which is what happened here and which loses the original timestamp. **Naming it rather than solving it,
because the fix belongs to mockspace and not to arvo.**
