# Topic: the catalogue asserts the owed reading, and the pack tests find their tree

**Date:** 2026-11-12
**Scope:** `mock/lints/half_up_is_not_a_magnitude_rule/sentences/catalogue.rs`, `mock/lints/canon_lint_testkit.rs`.
**Source:** the coordinator's review of `work/dev-gate-green` at `faa66db6`, two findings to fix before it lands.

## What the review found

The eighteen `catalogue_case!` tests asserted that each entry's known-wrong side stays wrong. They
passed while the gap was open and would go red the moment one was fixed, which is the opposite of what
a catalogue ignore is for: it is red on purpose while the gap is open, and the module's own doc says a
fix landing on one entry should change only that entry's test. So each case asserts the reading the
reader owes, keeps its ignore and its reason, and is red under `--ignored` until the reader learns it.

The previous round recorded `half_up_is_not_a_magnitude_rule::reaches_the_gate::no_severity_override_pins_it_to_the_pack_default`
failing and put it down to the working directory. That is a red with an explanation, not a green. The
cause is `canon_lint_testkit::repo_root`, which walks up from the working directory only. Cargo runs a
test from its package's directory, and the pack's package sits in the engine's cache, so under
`cargo test` on the pack nothing above the working directory is a mockspace repository.

## What fixes it

`repo_root` keeps the working-directory walk first, then falls back to walking up from the testkit's
own path, `file!()`, which is absolute in the generated pack and names the tree whose lint sources the
binary compiled. That is the repository whose lints are under test, so the answer is right in both
runs, and it carries none of the shared-target risk the doc names for `env!`: the path is the source
that was compiled, not the directory that compiled it.

With the root found, three testkit tests went red that had been hidden behind the same failure:
`lint_sources` maps every registered repo lint to a file under `mock/lints/` or `mock/tools/`, and
`mockspace_extra_lints::collect` registers `catalogue-ignore` into the same list with no file in this
tree. The testkit asks the shared pack which repo lints it registers and leaves those out of the
lints whose source it reads, rather than naming `catalogue-ignore` by hand, so a lint added upstream is
left out the same way.

## Evidence

Run on the branch, which has `origin/dev` as an ancestor, after `cargo mock --lint-only` in the tree
pointed the shared pack cache at it: the pack's whole suite, 826 passed, 0 failed, 35 ignored; the
catalogue's 19 ignored cases under `--ignored`, 19 failed.
