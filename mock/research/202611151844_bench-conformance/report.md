# Bench Conformance

This note records how arvo's bench tree under `mock/benches/` was brought onto the current mockspace bench harness, so that `cargo mock bench run` with no names builds and runs every bench to its end on any machine class. The overnight runs are op's to launch; what follows is the state the tree was left in for them, what changed to reach it, and what is still owed.

Before the port every bench was a per-size `[[bench.X.sizes]]` table in the root `bench.toml` naming `../target/release/<stem>` paths, built from a flat `variants/` directory the legacy way, so `cargo mock bench list` named no arms for any of the 49 benches. Four arms had not built since 2026-08-08, ten more built only on aarch64, two benches declared a point the byte dispatch could not serve, and one support crate timed a loop with `Instant::now` inside a test.

After the port there is no root bench section and no `variants/` directory. Every bench is a member directory with its arms under `<bench>/arms/<arm>/` and its fields at the top level of its own `bench.toml`, `cargo mock bench list` names the arms of all 46 cells, and a smoke run with no names built all 77 arms and ran every cell to its end on this x86_64 host.

## The benches as they now stand

Benches that shared their arms were one question asked over several regimes, so each such family became one bench with one sweep per former bench. That also builds each arm once rather than once per bench that listed it, which matters on a full run. The keys follow the form the harness's own tests use for this tree, `results/warm-container/width-l1_n80003`.

Eight benches kept their names and have no sweeps: `bitpack-carrier-width`, `bitpack-wide`, `bitpack-decoder-shape`, `bitpack-kernel-amortisation`, `bitpack-sequential-sum`, `bitpack-random-sum`, `quantiser-vs-fadd-subnormal-sweep` and `decimal-quantiser-radix-sweep`.

Every arm directory keeps its former variant name, and every arm's `#[bench_variant]` name string is unchanged, so the variant column of runs before and after the port names the same arm. Each arm keeps a hand-written `Cargo.toml` naming only the support crates it uses, with its `[lib]` name set to the arm directory's name as the harness resolves it; a generated manifest would have linked all thirteen support crates into each of the 77 arms. The comments of the old file (the key encodings, the thread counts, why `bitpack-write-unsound` is dropped at the threaded `race` rows) moved beside the points and sweeps they describe, and `race` keeps its per-point arm lists as point tables. Every bench states `may_differ = false` and `required = true`, as the harness skill asks unless stated otherwise, except `decimal-quantiser-radix-sweep`: its two arms are decimal32 and binary32 rounding to different precisions, which its support crate states, so their outputs differ by design and it carries `may_differ = true`. The first smoke run refused it on exactly that cross-check.

The harness keys a routine by bench and point, not by sweep, so the table in `mock/benches/src/lib.rs` holds one row per bench over the points of all its sweeps. The root `bench.toml` carries only `[dispatch]` and `[timing]`. No bench is byte shaped any more; `[dispatch] points = [64]` stays only because an empty list would make the generated byte dispatch monomorphise every point of every bench, up to 335544324 bytes.

The committed runs of the grouped benches were moved unchanged from `results/<former bench>/<former bench>_n<point>/` to `results/<bench>/<sweep>_n<point>/`, so the history the harness reads for a cell continues across the port. No `meta.json` names its bench, so nothing inside a run changed. `results/INDEX.md` was regenerated with `cargo mock bench report` over the moved runs, 455 run links, none dangling.

The framework pin in every arm and support lockfile moved from mockspace `90b5319` to `09bc088`, the `dev` tip the generated driver resolves. A driver lock left over from an earlier run held the old revision, which predates the run layout (mockspace `bd89291`), and a run on it wrote its cells flat under `results/<bench>/` and `history/`, outside the layout the lint `bench-results-live-in-the-harness-layout` requires.

## Arms deleted, and arms fixed

`fnv1a`, `xxhash3`, `spectral-bisection` and `structural-decomposition` were deleted with their three benches, `fnv1a-vs-xxhash3`, `spectral-bisection` and `structural-decomposition`. Op, 14 November, on ticket `delete_the_four_arvo_bench_variants_that_depend_on_the_delet`: "if they are no longer relevant, why not delete as per no deprecated bloat pre release 1?" and "Yes" to doing it. They depended on the `arvo` crates the canon work deleted, so they measured nothing; their committed runs stay under `results/` as the record. That also removes the `n = 16` point the two graph benches declared outside `[dispatch] points` and the bare `FIXME` the four manifests opened with.

Ten arms called NEON kernels that existed only on aarch64, so a run with no names stopped at the first of them on x86_64: `bitpack-carrier-packed-simd`, `bitpack-plan-simd`, `bitpack-mac-simd`, `bitpack-contend-packed-simd`, `bitpack-contend-pipe2`, `bitpack-contend-pipe4`, `bitpack-contend-d16-padal`, `bitpack-contend-d32-padal`, `bitpack-wide-d16-padal` and `bitpack-wide-pipe4`. Each kernel underneath them (`sum_simd`, `mac_simd`, `sum_simd_padal`, `sum_padal_pipe2`, `sum_padal_pipe4`, `sum_d16_padal`, `sum_d32_padal`) now has a body off aarch64 that runs the scalar code its arm is measured against, the stand-in `bench-satfold-shared`'s `Neon` and `Neon8` already took, and the kernel wrappers above them are no longer gated. On aarch64 nothing changed. Off it those arms are second noise floors and say nothing about a vector decode; each fallback carries a `FIXME` naming the ticket for real x86_64 kernels.

## Timers removed

`diag_sat_lanes_actually_runs` in `support/warm-container-shared` timed the lane-parallel saturating fold with `Instant::now` to show that its loop ran. It is replaced by `the_lane_parallel_fold_reads_the_whole_column`, an output assertion with no timer: at inputs that never clamp, the lane fold equals the serial fold and the plain sum, and moving one element by one, at the first element, in a middle chunk and in the remainder past the last whole chunk, moves the fold by exactly one. A fold that skipped any part of the column, or whose loop was dead, fails it.

No other timer remains in the bench tree, the crates, the tools or the lints. The panel probes that time with `Instant::now` (`20_probes/p1`, `p2`, `p3`, `p4` and `139_probes/p7` under `mock/research/202608072330_the-numeral-canon-panel/`) are committed history and stay. Each one describes itself as an ad-hoc spike deciding whether a committed number measured the work at all (a dead store, an absorbing fixpoint, the aarch64 counter's `nomem`, a test's buffer size), not which arm is faster, so no design decision rests on their timings and none needed a superseding harness bench.

## A test that was red before the port

`every_kernel_agrees_with_the_oracle_at_every_length` in `support/satfold-shared` aborted in a debug build on a misaligned pointer dereference: it read the `Vec<u8>` from `build_bytes` in place as `&Buf`, whose alignment is 64. It now copies the bytes into a `Buf`-aligned allocation, the shape the harness hands an arm. `the_offset_column_is_actually_offset` asserted that the `Vec` itself was 64-byte aligned, which no allocator promises; it now asserts that the offset column starts one byte past a 64-byte boundary inside the `Buf` the arm reads.

## Gates and tests

Before, on `dev` at `8ed016a7`, `cargo mock --lint-only --commit` passed and `cargo mock bench test` failed `support/satfold-shared` as above. After, on this branch, `cargo mock --lint-only --commit` passes with no lint error, and `cargo mock bench test` passes every crate of the tree, 90 crates with 13 carrying tests, 118 passed and none failed, against 107 passed and one crate aborted before. The commit went through the repository's own hooks with no bypass.

## Smoke runs

Every bench was run through the harness at the first point of each sweep with `passes = 1`, `runs_per_pass = 5`, `batch_size = 5`, two validation seeds and one determinism seed, set by hand for the run and put back afterwards. Run `20261115T185501Z` on `linux-x86_64-c4-container-intel`, a release build with fat LTO and one codegen unit as the harness pins it: 77 arms built, 46 cells planned, 45 validated, passed their determinism check and were timed, among them all ten aarch64-only arms on their stand-ins. `decimal-quantiser-radix-sweep` at `n = 0` was refused by the cross-check, set to `may_differ = true` as above, and its rerun validated and timed both arms. The timings are smoke readings with no statistical weight, so none of those run directories was committed; the layout does not require them.
