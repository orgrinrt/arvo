| `probe_1_parse_is_the_quantiser.rs` | Is parsing a digit string the quantiser applied once to the exact rational, and is staged parsing licensed? | **WORKS, three results.** Model: radix 2, p = 8, m in [128, 255], e in [-4, 4], 1152 values. Over all 318,126 four-decimal-place strings in [0.0625, 31.8750]: (a) the scaled-integer single-rounding kernel (remainder-comparison RNE, the quantiser's own shape) agrees with brute-force nearest-representable-ties-to-even on every string, zero disagreements; (b) staging through a p = 12 intermediate with RNE at both steps disagrees with the direct parse on **10,053 strings (3.2%)**, first witness `0.0642` (direct m=131 e=-4, staged m=132 e=-4), so naive two-step parsing is a real defect class, not a theoretical one; (c) the identical staging with round-to-odd at the intermediate (p_mid = 12 >= p + 2) agrees with the direct parse on **all** 318,126 strings. Compile 0.33s, run 1.5s. |
| `probe_2_shortest_print_roundtrip.rs` | Does every datum of the model round-trip through a shortest correctly-rounded decimal print, inside the H bound? | **WORKS, exhaustive.** All 1152 data round-trip (`parse(print(x)) == x`); digit-count distribution k = 1..6: [24, 216, 819, 93, 0, 0]; measured max k = 4 with witness m=206 e=-4, and H = ceil(log10(2^8)) + 1 = 4, so the Matula bound holds and is **tight** at this model (93 data need all four digits). The whole matrix, not a sample. Print is computed from `(m, e)` and integer arithmetic alone: no table, no float, no allocation. Compile 0.23s, run 0.3s. |
| `probe_3_text_capacity_is_a_type.rs` | Is the print buffer's length expressible gate-free? | **WORKS, and the declaration-site check fired once for real.** The capacity is an associated type (`type ShortCap: TextCap`) per the spine rule; a `const _: () = assert!(LEN >= short_budget(RADIX, PRECISION))` at each impl checks coverage at declaration time. The first compile deliberately kept a too-small `C8` for the p = 4 numeral and the assertion refused it with E0080 (`short_budget(2, 4) = 9 > 8`) at the impl, not at any use site; corrected to `C16`, compiles clean, `#![no_std]`, zero gates. Generic `print_short<N: Numeral>() -> <N::ShortCap as TextCap>::Arr` has no const expression in type position. Compile 0.04s. |
| `probe_3b_array_length_is_gce_shaped.rs` | Is the buffer-length question a genuine spine-rule firing site? | **EXPECTED FAIL, confirmed.** `fn print_short<N: Numeral>() -> [u8; short_budget(N::RADIX, N::PRECISION)]` refuses: two counts of `error: generic parameters may not be used in const operations` with rustc's own `help: add #![feature(generic_const_exprs)]`, plus `constant expression depends on a generic parameter`. The const route to a numeral-sized text buffer requires the forbidden feature; the type route (probe 3) does not. |
| `probe_4_digest_keys_on_a_layer.rs` | Does a digest that does not factor through its equality's layer break the consistency law? | **WORKS, both violations compiled.** (a) Padding: two u16 carriers agreeing on all 13 datum bits, differing in the 3 padding bits: `datum_eq` true, FNV-1a over carrier bytes differs (`0x094fe607b5ddcd33` vs `0x094fc607b5dd96d3`), FNV-1a over the masked projection agrees. (b) Datum classes: two NaN-payload data of the one NaN value: value-equal, datum digests differ, value digest through the class-collapsing projection agrees. Both directions of the consistency law (`k1 == k2` implies `h(k1) == h(k2)`) demonstrated broken by the unprojected digest and restored by the projected one. Compile 0.14s, run instant. |
| `probe_5_kernels_are_const.rs` | Are the parse and print kernels const-callable as written? | **WORKS.** The quantiser and the sig-digit rounding re-declared `const fn`, evaluated in const context, `#![no_std]`, zero gates: `quantise_rne(1, 10)` yields `(205, -4)` at const time (0.1 rounds to 205/2048 under RNE), `round_to_sig_digits(205, -4, 3)` yields `(100, -3)`, and reparsing `100/1000` closes the round trip back to `(205, -4)`, all as `const _: () = assert!(...)` items. Compile under 0.1s. |
