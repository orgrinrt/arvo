-----------------------------------------------------------------------------
THE WALL, AND IT IS THE ONE THE WORKSPACE REFLEX NAMES
-----------------------------------------------------------------------------
`Cons<{ A + B }, ...>` puts arithmetic in TYPE position, which is exactly what
`generic_const_exprs` is for and exactly what is forbidden.  I reached for the
type-level list because a refused bound wants a trait, and then put the
arithmetic back into a const argument, which is the same mistake one level
down.

The fix is to stop making the coefficient a const argument.  A coefficient
becomes a TYPE carrying an associated const, so `A + B` is computed in an
impl body where arbitrary const expressions are legal, and nothing arithmetic
ever appears in type position.  That is the shape `109` P5 already used for
`RSum`, applied to a vector instead of a scalar.

Repaired in `p8b`.  This failed version is kept because the wall is worth more
than the fix: the reflex is easy to half-apply, and half-applying it lands you
on the forbidden feature with a clean conscience.
