# arvo-refit. Design

The bit-width refit re-export crate. Hosts the public surface for the
two-direction refit family: `Narrow<T>` for shrinking a value into a
narrower bit-width (with high-bit masking), and `Widen<T>` for promoting
a value into a wider bit-width (zero-extending for unsigned, sign-
extending for signed). Trait declarations and concrete impls live in
`arvo-bits-contracts`; this crate is a re-export gateway. `#![no_std]`,
no alloc.

Depends on `arvo-bits-contracts`. Re-exported by the `arvo` facade and
`arvo-bits` for ergonomic top-level access.

## Re-export surface

```rust
pub use arvo_bits_contracts::{Narrow, Narrowed, Widen, Widened};
```

`Narrow<T>` and `Widen<T>` are const traits. `Narrowed<const N: u16, T>`
and `Widened<T>` are cosmetic aliases for return positions in consumer
signatures. The trait declarations and the cross-primitive + cross-Bits
impl tables live in `arvo-bits-contracts` (orphan-rule constraint:
trait + foreign-primitive impls must share a crate).

## Why a re-export crate exists at all

Generic-over-refit consumers (the `bitfield!` macro, the algorithm
crates) bind to the `Narrow` / `Widen` trait surface without pulling in
mask concretes. The `arvo` facade pulls this crate to expose
`Narrow`, `Widen`, `Narrowed`, `Widened` at the top level so consumers
that do not need the algorithm machinery still get the refit family
without an extra crate dep.

The single-purpose `arvo-narrow` predecessor
shipped before `Widen` existed. Currently, merged the trait
declaration into `arvo-bits-contracts` and reduced the crate to a one-
line re-export. Currently, added `Widen<T>` to the bits-
contracts crate. Currently, renamed the gateway to
`arvo-refit` to name the domain (bit-width refit) rather than one of
the two directions.
