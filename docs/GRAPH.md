# arvo-graph. Design

DAG and graph algorithms on fixed-capacity structures.
`#![no_std]`, no alloc. All algorithms operate on the
`BitMatrix<W, C: Capacity>` and `Mask<W>` chassis from
arvo-bitmask, generic over the row-bearing word. `Bits<64, Hot, Unsigned>`
is one instantiation (single-word, up to 64 nodes); the consumer picks
the word width its node count needs, and the algorithms span whatever
widths the substrate's container projection offers. Node indices use
`NodeId` from arvo-bitmask.

The crate depends on
`arvo-storage`, `arvo-bits-contracts`, `arvo-numeric-contracts`,
`arvo-tensor`, `arvo-bitmask`. Trait surface is reached through the
contract crates; concrete types come from `arvo-bitmask` and
`arvo-tensor`. The prior `arvo-bits` direct dep is replaced by
`arvo-bits-contracts`.

## Capacity

Algorithms are generic over the adjacency row-word, a type parameter
named `B` (distinct from the edge-weight `W` on the weighted algorithms),
bounded on the bit-sequence traits the bodies use (`BitSequence +
BitAccess + BitLogic + Copy + Default + Identity<Additive>`). A consumer
chooses
the word width its node count needs: `Bits<64, Hot, Unsigned>` for up to
64 nodes, `Bits<128>` / `Bits<256>` for wider, any width the substrate's
container projection supports (native up to 128, wide bucket 129 to 256
via WideBits). The node ceiling is the chosen word's width, not a fixed
64; the algorithm bodies are the same across widths. The container-width
projection itself (how wide `Bits<N>` can go) is a separate arvo-storage
axis.

The capacity is a TYPE: `C: Capacity` (arvo-tensor's `Capacity`) in
place of the prior `const N: Cap`. Array storage is the associated
type `C::Array<X>`, so no `cap_size` expression sits in type position;
the algorithm bodies that need the count as a value read
`cap_size(C::CAP)` (a value-position const-fn call). Weight inputs and
array returns in the signatures below are `&C::Array<W>` and
`C::Array<X>`; the prior form spelled these `&[W; N]` and `[X; N]`
with an implied `where [(); cap_size(N)]:` bound that is now gone.

Generic over numeric trait bounds for weight types. Does not import
UFixed or IFixed directly. Consumer instantiates with concrete arvo
types; this crate is library code.

## Weight type contract

```rust
fn upward_rank<C: Capacity, W, B>(
 dag: &BitMatrix<B, C>,
 weights: &C::Array<W>,
) -> C::Array<W>
where
 W: Add<Output = W> + TotalOrd + Copy + FromConstant
```

The algorithm needs addition (accumulate path weights), ordering
(find maximum), copy (store in arrays), and a zero value (initialise).
It does not need multiplication, division, or square root.

If W is `UFixed<{IBits(16)}, {FBits(0)}, Hot>`, rank accumulation
wraps on overflow. If the same type with `Precise`, it saturates.
The algorithm is identical. The consumer chooses the safety level by
choosing W.

## Topological sort

Kahn's algorithm on BitMatrix adjacency:

```rust
fn topo_sort<C: Capacity, B>(
 dag: &BitMatrix<B, C>,
) -> (USize, C::Array<NodeId>) // (valid_count, topo_order)
```

Fixed `C::Array<NodeId>` queue + `C::Array<USize>` in-degree array. Zero heap.
Returns topo-ordered node IDs and the count of successfully sorted
nodes. Cycle detection built-in: `valid_count < node_count` means a cycle
was detected. `valid_count` tells you exactly how many nodes were
sorted before the cycle was hit.

## Node renumbering

```rust
fn renumber<C: Capacity>(
 topo_order: &C::Array<NodeId>,
) -> C::Array<NodeId>
```

After topo sort, renumber all node IDs so they match reverse
topological order. Upward rank traversal then accesses the rank
array sequentially, the hardware prefetcher sees a sequential
scan. Same principle as column co-location: make access patterns
sequential for the prefetcher.

## Rank computation

```rust
fn upward_rank<C: Capacity, W, B>(
 dag: &BitMatrix<B, C>,
 weights: &C::Array<W>,
) -> C::Array<W>
where
 W: Add<Output = W> + TotalOrd + Copy + FromConstant

fn downward_rank<C: Capacity, W, B>(
 dag: &BitMatrix<B, C>,
 weights: &C::Array<W>,
) -> C::Array<W>
where
 W: Add<Output = W> + TotalOrd + Copy + FromConstant
```

`rank(u) = cost(u) + max(rank(successors(u)))`. Bottom-up in reverse
topo order. Cost per node is a generic weight type W satisfying the
trait bounds above. Identifies the critical path: the node with the
highest rank is the trunk root.

Upward rank: longest path from any node to any leaf.
Downward rank: longest path from any root to any node.
Both computed in one pass each over the topo-ordered nodes.

## Connected components

```rust
fn components<C: Capacity, B>(
 dag: &BitMatrix<B, C>,
) -> C::Array<USize>
```

DFS on BitMatrix adjacency using a `Mask` as the visited set. Stack
is a fixed `C::Array<NodeId>`. Returns component ID (as USize) per
node. Two nodes are in the same component if their access masks
intersect (directly or transitively).

Common application: feeding phase identification by pairing
component membership with block-diagonal detection results.

## Longest/shortest weighted path

```rust
fn longest_path<C: Capacity, W, B>(
 dag: &BitMatrix<B, C>,
 weights: &C::Array<W>,
 topo_order: &C::Array<NodeId>,
) -> (W, Mask<B>, C::Array<NodeId>) // (path_weight, has_predecessor, predecessors)
where
 W: Add<Output = W> + TotalOrd + Copy + FromConstant
```

Weighted path computation on DAG (no cycles). Uses topo order for
single-pass O(V+E). Returns the path weight, a validity Mask, and
the predecessor array. Roots have their bit unset in the Mask. Only
read `predecessors[i]` when the Mask bit is set.

## Critical path analysis

The critical path is the longest weighted path from any root to any
leaf. Computed via upward rank, the path following the highest-ranked
successor at each step. Identifies the serial bottleneck in a DAG.

The weight type is consumer-chosen; a common pattern is summing
`size_of` of the data each node touches, which approximates
per-element compute cost in a pipeline setting.

## Waist detection

```rust
fn waist_detect<C: Capacity, B>(
 dag: &BitMatrix<B, C>,
 topo_order: &C::Array<NodeId>,
) -> Mask<B>
```

Walk topo order. At each level (set of nodes at the same topo depth),
count how many independent paths are alive. Where the count drops to
a local minimum = waist = phase boundary. Returns a Mask with bits
set at waist positions in the topo order.

Different from connected components: connected components find fully
independent sub-problems. Waist detection finds narrow bottleneck
points WITHIN a connected DAG where all paths converge through a few
nodes before fanning out again.

Common application: phase decomposition, the waist points become
natural phase boundaries in a staged pipeline.

### waist_detect_const, the compile-time analog

```rust
pub const fn waist_detect_const<C, W>(
 succ_rows: &C::Array<W>,        // succ_rows[i] = successor word of node i (bit j set = edge i -> j)
 topo_order: &C::Array<NodeId>,
) -> C::Array<Bool>              // slot k = topo position k sits at a waist depth
where
 C: [const] ConstCapacity,
 W: [const] BitAccess;
```

The const version of `waist_detect`, for consumers that need waist boundaries
at compile time (the canonical phase axis is waist-bounded, so a const dispatch
plan computes phases from the access graph at const time). Same algorithm: topo
depth pass, level widths, strict local minima among occupied depths, flags at
the topo positions of waist-depth nodes.

The runtime `waist_detect` is not const: it builds arrays through
`Capacity::filled` + `AsRef`/`AsMut` and iterates predecessors via
`Mask::iter_set_bits`, none const-callable. `waist_detect_const` works over the
`ConstCapacity` contract (const `filled`/`get`/`set`) and inlines the
predecessor test with the const `BitAccess::bit` contract, so it touches no
non-const `BitMatrix`/`Mask` method. Its input is the raw successor words (the
`BitMatrix.rows[i].word` analog) and its output is a `C::Array<Bool>` flag per
topo position, which agrees with the runtime `Mask<B>` position-for-position
(flag `k` true iff bit `k` set). The runtime `waist_detect` is unchanged.

## Spanning tree decomposition

```rust
pub struct SpanningTree<C: Capacity, B> {
 pub on_trunk: Mask<B>, // which nodes are on the trunk
 pub trunk_next: C::Array<NodeId>, // next node on trunk (valid where on_trunk is set)
 pub branch_roots: Mask<B>, // nodes that start branches
 pub bridges: Mask<B>, // fan-in nodes (mandatory fiber breaks)
}

fn spanning_tree<C: Capacity, W, B>(
 dag: &BitMatrix<B, C>,
 ranks: &C::Array<W>,
) -> SpanningTree<C, B>
where
 W: TotalOrd + Copy
```

Decompose a DAG into a spanning tree with trunk (critical path) and
branches (side paths joining at fan-in points).

1. Trunk = path following highest-ranked successor from root to leaf
2. At fan-out: trunk follows heaviest child, others become branches
3. At fan-in: record bridge (node reading from multiple trunks)
4. Recurse: each branch is a sub-DAG

Natural barriers (fan-in points) are mandatory grouping-break points
for any consumer that batches along trunks.
