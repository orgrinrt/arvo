# arvo-bits-contracts. Design

The bit-level trait declarations. Every trait here is `pub const trait`.
Default-method bodies reference `Bits<N, S, Sign>` and the bare
primitive containers; consumer call sites pull this crate to bind to
the trait surface, then reach the concrete impls in `arvo-bits` via
blanket dispatch. `#![no_std]`, no alloc.

The Sign axis on `Bits<N, S, Sign>` is invisible
at the trait surface; bit-level operations act on raw bit patterns
which are sign-agnostic by construction. Default `Sign = Unsigned` at
the Bits surface keeps existing call sites unchanged.

Depends on `notko`, `arvo-transparent`, `arvo-strategy`, `arvo-storage`.

## HasBitWidth

```rust
pub const trait HasBitWidth {
 const WIDTH: USize;
}
```

How many logical bits a type occupies. Renamed from `BitWidth` per
to free that name for the `Width` newtype in
`arvo-storage`. Const trait so `T::WIDTH` works in const fn bodies
under generic-T.

## BitAccess

```rust
pub const trait BitAccess: HasBitWidth + Copy {
 fn bit(self, idx: USize) -> Bool;
 fn with_bit_set(self, idx: USize) -> Self;
 fn with_bit_cleared(self, idx: USize) -> Self;
 fn with_bit_toggled(self, idx: USize) -> Self;
}
```

Individual bit manipulation. Functional style, no mutation. `idx` is
from LSB.

## BitSequence

```rust
pub const trait BitSequence: HasBitWidth + Copy {
 fn trailing_zeros(self) -> USize;
 fn leading_zeros(self) -> USize;
 fn count_ones(self) -> USize;
 fn count_zeros(self) -> USize;
 fn is_zero(self) -> Bool;
}
```

Scanning and counting. Maps to hardware intrinsics (`cttz`, `ctlz`,
`popcnt`). The primitives that mask iteration uses internally.

## BitLogic

```rust
pub const trait BitLogic: HasBitWidth + Copy {
 fn bitor(self, other: Self) -> Self;
 fn bitand(self, other: Self) -> Self;
 fn bitnot(self) -> Self;
 fn bitxor(self, other: Self) -> Self;
 fn shl(self, n: USize) -> Self;
 fn shr(self, n: USize) -> Self;
 fn clear_lowest_set_bit(self) -> Self
 where
 Self: BitAccess + BitSequence;
}
```

Whole-word bitwise logic. Single-instruction on the backing
primitive. Hot-only surface (other strategies' wider containers make
whole-word ops meaningless at the logical-width level).

`clear_lowest_set_bit` has a default body via `BitSequence` +
`BitAccess`; concrete types override with the BLSR-equivalent fast
path.

### Sign-axis generalisation

The blanket impls of `BitAccess`, `BitSequence`, `BitLogic`, and
`HasBitWidth` on `Bits<N, S, Sign>` generalise from `Sign = Unsigned`
(default) to `Sign: Signedness`. Before the
round, `Bits<N, S, Signed>` (which is what `IFixed<I, F, S>` wraps)
exposed no const-callable bit-op surface: half of arvo's
domain primitives could not call any bit method in const fn bodies.

The new blanket signature (post Width lift):

```rust
impl<const N: u16, S: Strategy, Sign: Signedness>
const HasBitWidth for Bits<N, S, Sign>
where
 S: [const] BitsContainerFor<N, Sign>,
 <S as BitsContainerFor<N, Sign>>::T: [const] BitsBitPrim<Sign>,
{ /*... */ }
```

`BitsBitPrim<Sign>` is a sealed bridge trait introduced in this round
to single-predicate the BitPrim-or-IBitPrim selection. Two impls
(one for `Sign = Unsigned` projecting to `BitPrim`; one for
`Sign = Signed` projecting to `IBitPrim`) plus a `type T` associated
type that names the underlying primitive bridge. The single-
predicate-per-impl-block shape avoids the `generic_const_exprs` cycle
that two parallel predicates (`<S as...>::T: [const] BitPrim` AND
`<S as...>::T: [const] IBitPrim`) would trigger.

Once the blanket generalises, every const-callable bit op on
`Bits<N, S, Sign>` routes through the appropriate primitive bridge.
`IFixed<I, F, S>` consumers gain the same const-callable bit-op
surface as `UFixed<I, F, S>` consumers.

This lifts the const-generic `N` from `u16` to `Width`
to match `arvo-storage::Bits<const N: u16,...>` after Round 2's
Width lift cascaded through the projection layer.

## BitPrim family

```rust
pub const trait BitPrim: Copy + ConstParamTy_ +... {
 const WIDTH: USize;

 fn count_ones(self) -> USize;
 fn trailing_zeros(self) -> USize;
 fn leading_zeros(self) -> USize;
 fn get_bit(self, idx: USize) -> Bool;
 fn with_bit_set(self, idx: USize) -> Self;
 fn with_bit_cleared(self, idx: USize) -> Self;
 fn with_bit_toggled(self, idx: USize) -> Self;
 fn bitor(self, other: Self) -> Self;
 fn bitand(self, other: Self) -> Self;
 fn bitnot(self) -> Self;
 fn bitxor(self, other: Self) -> Self;
 fn clear_lowest_set_bit(self) -> Self;
 fn is_zero(self) -> Bool;

 // helper consumed by mask /
 // hash / bitfield call sites that build a low-N-bits mask.
 // Default body composes through the additive and multiplicative
 // identities, Bounded::MAX, and the const-stable shift bridge.
 // now consumed by the `bitfield!` macro
 // emission in the arvo facade for slot-mask construction
 // (replaces the hardcoded `(1u64 << N) - 1` pattern with
 // strategy-aware routing).
 fn mask_low(n: USize) -> Self;
}

pub const trait IBitPrim: Copy + ConstParamTy_ +... {
 // signed counterpart with full method parity vs BitPrim
 // (closes the parity gap;
 // adds the mask_low method)
 fn mask_low(n: USize) -> Self;
}

pub const trait UBitContainer<const N: u16> {
 type Container: [const] BitPrim;
}

pub const trait IBitContainer<const N: u16> {
 type Container: [const] IBitPrim;
}
```

The primitive-bridge family. `BitPrim` is the sealed surface that
`u8`, `u16`, `u32`, `u64`, `u128` implement (the five native bucket
projections from `BitsContainerFor<N, Unsigned>` for N ≤ 128) plus
`WideBits<const BYTES: usize>` for the byte-sequence storage shape at
N > 128 (Warm/Cold/Precise) and `AlignedWideBits16<const BYTES: usize>`
for the SIMD-aligned shape at N > 128 (Hot). The `MultiContainer<HiT,
LoT>` impl shipped briefly is deleted entirely
in alongside the type itself; per
`no-legacy-shims-pre-1.0.md`, no deprecation alias.

`IBitPrim` mirrors the same surface for signed primitives `i8`..`i128`.
The signed wide-width path uses the same `WideBits` /
`AlignedWideBits16` storage with sign-aware op composition (the byte
storage is sign-erased; the BitPrim impl interprets bytes per the
caller's Bits<N, S, Signed> wrapping).

This lifted `BitPrim::WIDTH` from `u16` to `USize`.
Cascading lifts: `count_ones`, `trailing_zeros`, `leading_zeros`
return `USize` (was `u32`); `get_bit`, `with_bit_*` accept `idx: USize`
(was `u32`).

This lifts the `N` const-generic on `UBitContainer` /
`IBitContainer` from `u16` to `Width`, matching the arvo-storage
`Bits<const N: u16,...>` shape and the unified
`BitsContainerFor<const N: u16, Sign>` projection in arvo-strategy.

Used by blanket impls in `arvo-bits` to delegate from
`Bits<N, S, Sign>::to_raw()` to the primitive's bit method, then
`Bits::from_raw(...)` wraps the result. Const trait throughout.

### BitPrim impls on WideBits / AlignedWideBits16

This ships the BitPrim impl on the byte-sequence
storage shapes. The previous BitPrim impl on `MultiContainer<HiT,
LoT>` (which composed half-by-half across two native primitives) is
replaced by byte-by-byte composition over `[u8; BYTES]`.

```rust
impl<const BYTES: usize> const BitPrim for WideBits<BYTES> {
 const WIDTH: USize = USize::new(BYTES * 8);

 fn count_ones(self) -> USize { /* sum of bytes[i].count_ones() */ }
 fn count_zeros(self) -> USize { /* WIDTH - count_ones() */ }
 fn trailing_zeros(self) -> USize { /* walk from byte 0 LSB upward */ }
 fn leading_zeros(self) -> USize { /* walk from byte BYTES-1 MSB downward */ }
 fn get_bit(self, idx: USize) -> Bool { /* (bytes[idx/8] >> (idx % 8)) & 1 */ }
 fn with_bit_set(self, idx: USize) -> Self { /* byte-indexed mask set */ }
 fn with_bit_cleared(self, idx: USize) -> Self { /* byte-indexed mask clear */ }
 fn with_bit_toggled(self, idx: USize) -> Self { /* byte-indexed mask xor */ }
 fn bitor(self, other: Self) -> Self { /* byte-wise */ }
 fn bitand(self, other: Self) -> Self { /* byte-wise */ }
 fn bitnot(self) -> Self { /* byte-wise */ }
 fn bitxor(self, other: Self) -> Self { /* byte-wise */ }
 fn clear_lowest_set_bit(self) -> Self { /* locate byte, apply b & (b-1) */ }
 fn is_zero(self) -> Bool { /* all bytes zero */ }
}

// AlignedWideBits16 has identical surface; only storage layout differs.
impl<const BYTES: usize> const BitPrim for AlignedWideBits16<BYTES> { /* same body */ }
```

The byte-ordering convention (locked at the doc-CL level per audit
C1): bit 0 is the LSB of byte 0; `trailing_zeros` walks from byte 0
upward; `leading_zeros` walks from byte BYTES-1 downward. This
matches `u128::trailing_zeros` / `u128::leading_zeros` semantics
viewed as bit-significance order.

Sketch 02 in
`mock/research/sketches/202605031400_hlist_heterogeneous_container/02_widebits_basic.rs`
verified the byte-by-byte composition across BYTES values 17, 25, 32,
64, 128, 512: count_ones + bitwise ops produce correct results
across all test patterns.

Sketch 04 verified the cfg(target_arch) intrinsic surface compiles
cleanly on x86_64 (SSE2 + popcnt) and aarch64 (NEON vcntq_u8 + horizontal
sum). Three implementation paths (scalar, chunked-u64, intrinsic-load)
produce identical results across test patterns. The intrinsic-driven
fast paths land in #320 with bench evidence; the scalar baseline above
ships in #316 with the deletion of MultiContainer.

## Narrow

```rust
pub const trait Narrow<T> {
 fn narrow_to<const N: u16>(self) -> T
 where
 Self: Sized;

 fn narrow_to_unmasked<const N: u16>(self) -> T
 where
 Self: Sized;
}

pub type Narrowed<const N: u16, T> = T;
```

The unified mask-and-cast bridge for cross-primitive narrowing.
`narrow_to::<N>` composes `BitPrim::mask_low(N)` (from this crate)
with `BitLogic::and` then the `as` operator to cast to the target
primitive type, sound under the mask precondition. Routing through
`BitPrim` keeps the narrow path inside the bare-primitive layer
where the cast actually happens; the prior reference to
`Mask<W>::mask_for_width(N)` from `arvo-mask-contracts` predated the
trait reshape and is no longer the
primitive that drives narrowing.

`narrow_to_unmasked::<N>` skips the mask op for the hot case where
the high bits are already zero (chained narrow, bitfield extraction
that just-shifted-down, value carried through a Bits<M,...>
projection of equal-or-narrower width). The precondition is the
consumer's responsibility; calling with non-zero high bits produces
silent garbage in the unmasked path.

Moved here from the previously-separate `arvo-narrow-contracts`
crate. The merge is justified because
every consumer of `Narrow` already depends on `BitLogic` for the
default-body composition; the single-trait crate split was ceremony
without transitive-footprint benefit. Concrete impls live in
`arvo-bits-contracts` itself (cross-primitive + cross-Bits forwarder)
and are re-exported via `arvo-refit` (combined narrow + widen
gateway crate, renamed from `arvo-narrow`).

`Narrowed<const N: u16, T>` is a cosmetic alias for the result of
`narrow_to::<N>` so consumer signatures read `fn foo() -> Narrowed<13, u16>`
instead of bare `u16`. The const-generic `N` is documentation only at
the type level (the value has been narrowed to `N` bits but the
carrier is still `T`).

The const-generic param widened from `u8` to `u16` in Pass F of round
202604281000, matching the `Bits<const N: u16>` widening at the same
pass. The widening accommodates reachable widths up to 65535; concrete
narrow impls cover 1..=256.

The cross-primitive impl matrix is closed under same-container
narrowing: `u8: Narrow<u8>`, `u16:
Narrow<u16>`,..., `i128: Narrow<i128>`. The macro body's `>= BITS`
short-circuit handles the same-width case as a no-op (mask of full
width zero-extends, cast is identity). Same-container Narrow
unblocks cross-Bits narrowing within one container range
(`Bits<32, Hot>` → `Bits<28, Hot>` both u32-backed; `Bits<28, Hot>`
→ `Bits<24, Hot>` both u32-backed). Without the same-container
impls the cross-Bits forwarder's `<S as BitsContainerFor<M>>::T:
Narrow<<S as BitsContainerFor<N>>::T>` where-clause cannot be
satisfied when M and N project to the same carrier.

## Widen

```rust
pub const trait Widen<T> {
 fn widen_to(self) -> T
 where
 Self: Sized;

 fn widen_to_unmasked(self) -> T
 where
 Self: Sized;
}

pub type Widened<T> = T;
```

The dual to `Narrow<T>`. `widen_to` promotes a value into a wider
bit-width carrier. For primitive sources (full-carrier-width values),
unsigned widening zero-extends and signed widening sign-extends
through Rust's `as` cast.

For sub-carrier-width `Bits<M, S, Sign>` the contract is
**bit-pattern-preserving**, not logical-value-preserving, on both
`Narrow` and `Widen`. The cross-Bits forwarder calls the carrier-
side primitive trait method without any explicit M-bit sign-extension
machinery: bits above M in the source carrier are forwarded to the
destination carrier as-is. For values constructed via `Narrow` (which
zero-pads above the logical width via `(source as unsigned) & ((1 <<
N) - 1)`), this produces zeros above the logical width in the widened
result regardless of the source's logical signedness.

Consumers needing logical-value-preserving signed conversion (sign-
extension at bit M-1 on cross-Bits widen) compose `Narrow`, explicit
sign-extension, and `Widen` at the application layer. The
refit family stays bit-pattern-preserving by contract; the
`IFixed<I, F, S>` numeric type holds carrier bits matching its
declared logical width via construction, and its consumers do not
typically refit through the bit-pattern path.

`widen_to_unmasked` is the source-side-mask-free variant for hot
paths where bits above the source's logical width are already zero
(well-formed `Bits<M,...>` constructed via `Narrow`); `widen_to`
calls the same carrier-side widen body without an extra source mask
because the carrier-side `as` cast preserves bit pattern unconditionally.

### Asymmetry with `Narrow`

`Widen<T>` does not carry the const-N parameter `Narrow<T>` does.
Narrow's const-N is the *destination* logical width and is load-
bearing for the mask: `wide_u32.narrow_to::<13>()` masks to 13 bits
out of 32, the same wide_u32 narrows to any logical width in `0..32`
under one impl. Widen does not have an analogous degree of freedom.
Each `Widen<T>` impl widens from a fixed source type to a fixed
target type; the source bit-width is determined by the impl context
(carrier `BITS` for primitives, `M` for `Bits<M, S, Sign>`). A const
parameter on `widen_to` would be informational (consumer-side
declaration of source width) at best and misleading (callers might
expect it to drive sign-extension behaviour, but the impl context
already determines that) at worst.

The asymmetry is deliberate. Documented topic
file decision A. Consumers reaching for symmetry between the two
traits land on `Narrow::narrow_to::<N>()` and `Widen::widen_to()` as
parallel call shapes; the const param appears only where it
materially drives behaviour.

### Cross-primitive Widen impls

Macro-generated symmetric to the cross-primitive Narrow tables:
unsigned `u8 → {u16, u32, u64, u128}`, `u16 → {u32, u64, u128}`,
`u32 → {u64, u128}`, `u64 → u128`; signed counterparts using sign-
extending `as`. Same orphan-rule reasoning as `Narrow`: the impls
live here because both trait and primitive types are foreign to
`arvo-refit`.

### Cross-Bits Widen impl

Forwards through the underlying primitive `Widen<T_N>` impl on the
source's container type, parallel to the cross-Bits Narrow forwarder:

```rust
impl<const M: u16, const N: u16, S: Strategy, Sign: Signedness>
 const Widen<Bits<N, S, Sign>> for Bits<M, S, Sign>
where
 S: BitsContainerFor<M, Sign>,
 S: BitsContainerFor<N, Sign>,
 <S as BitsContainerFor<M, Sign>>::T:
 ~const Widen<<S as BitsContainerFor<N, Sign>>::T>,
{
 fn widen_to(self) -> Bits<N, S, Sign> {... }
}
```

Where M < N is not enforced at the type level (parallel to Narrow's
M > N non-enforcement); consumers supplying M >= N still get a valid
result, but the widening is a no-op for cells where the source width
already matches the destination.

## NarrowFromU64<N, S, Sign>

Bounded-generic narrowing of a `u64` to the dispatched container for `(N, S, Sign)`. Used by `ConstHash` (arvo-hash) to produce typed `Bits<N, S, Sign>` from a u64 algorithm state, and available to any other consumer that needs to project a u64 into a strategy-aware container.

```rust
use arvo_strategy::{Strategy, Signedness};

pub const trait NarrowFromU64<const N: u16, S: Strategy, Sign: Signedness>: Sized {
 fn narrow_u64(raw: u64) -> Self;
}
```

Per-(S, Sign) blanket impls on every native primitive that can be a dispatched container under the matching `BitsContainerFor<N, Sign>` cell:

| Strategy | Sign | Native primitives covered |
|---|---|---|
| Hot, Cold | Unsigned | u8, u16, u32, u64, u128 |
| Hot, Cold | Signed | i8, i16, i32, i64, i128 |
| Warm, Precise | Unsigned | u16, u32, u64, u128 (no u8; 2x-logical ladder) |
| Warm, Precise | Signed | i16, i32, i64, i128 |

The `(S, Sign)` partitioning means no two impls overlap on the same `Self` primitive type; sketch 01 validates rustc accepts all 36 native blanket impls without E0119 conflicts.

Wide-bucket impl: `impl<const N: u16, S: Strategy, Sign: Signedness, const BYTES: usize, A: Align> const NarrowFromU64<N, S, Sign> for WideBits<BYTES, A>`. The narrowing places the masked u64 in the low 8 bytes of the byte sequence.

Internally uses `mask_low_bits` (declared in `arvo-strategy/src/width.rs`) to centralise the `if N >= 64 { u64::MAX } else { (1u64 << N) - 1 }` pattern that previously inlined four times in the hash-algorithm macros.

Round 4 (#314) introduces this trait alongside `ConstHash<N, S, Sign>` in arvo-hash. The pair collapses 128 hand-written `Hasher<N>` impl bodies (per-N macro paste across two algorithms) into 2 bounded-generic impl blocks. The trait declaration lives in arvo-bits-contracts per the bridge-home rule: this is the lowest layer reachable from arvo-hash where the `BitsContainerFor` projection and the `WideBits<BYTES, A>` wide-bucket type are both visible.

## Cross-domain primitive↔Bits direct impls

Symmetric `Pri: Narrow<Bits<N, S, Sign>>` and `Bits<N, S, Sign>:
Widen<Pri>` impls let consumers refit a primitive directly into a
typed `Bits`, or refit a typed `Bits` directly into a primitive
carrier, without an intermediate `Bits::from_raw` wrap. Macro-
generated over the strategy-and-sign matrix the existing tables
cover. The cross-domain impls underlie the `Bits::from_narrowed<Src>`
and `Bits::from_widened<Src>` ergonomic constructors (see
`arvo-storage/DESIGN.md`).
