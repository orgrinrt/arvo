# arvo-storage. Design

The minimal bare-primitive layer of arvo. Sits at the bottom of every
dependency chain in the substrate. Hosts the only fielded primitive
types whose existence requires wrapping bare Rust primitives directly,
the strategy markers used by every numeric type, and the typed
meta-bit newtypes that carry bit-count meta values through const
generic positions. `#![no_std]`, no alloc.

Depends on `arvo-transparent` (for the `Transparent` const unsafe
trait that every `repr(transparent)` type implements) and
`arvo-strategy` (for the strategy markers, the unified
`BitsContainerFor<N, Sign>` projection trait, and the `Width`
newtype). No other workspace dependencies.

This crate is small on purpose. Everything else in the arvo stack
(bit-level contracts, mask types, narrowing, fixed-point arithmetic,
algorithms) lives upstream and consumes these primitives via trait
bounds. New types here are added only when the type genuinely cannot
be expressed without wrapping a bare primitive.

## Bits

`Bits<const N: Width, S: Strategy = Hot, Sign: Signedness = Unsigned>` is
the N-bit storage primitive. A `#[repr(transparent)]` newtype over
`<S as BitsContainerFor<N, Sign>>::T`. The container projection picks
either a native primitive (N ≤ 128) or a byte-sequence storage
(`WideBits<bytes_for(N), A>` for N > 128, see below) per the
strategy axis. `Bits<8, Hot>` lowers to `u8`, `Bits<7, Hot>` lowers
to `u8` (with the high bit unused under Hot), `Bits<32, Warm>` lowers
to `u32`, `Bits<64, Hot>` to `u64`, `Bits<96, Hot>` to `u128`,
`Bits<200, Hot>` to `WideBits<25, A16>` (byte-sequence at align(16)),
`Bits<200, Warm>` to `WideBits<25, A1>` (byte-sequence at align-1),
and so on per the strategy bands.

The const-generic param is `Width` (the typed newtype around `u16`),
relocated from this crate to `arvo-strategy` in round 202605031400.
`arvo-storage` re-exports it via `pub use arvo_strategy::Width;` for
source-compatibility within the workspace facade. The parameter
space accommodates 1..=65535 logical bits.

Default `Sign = Unsigned` keeps every existing `Bits<N, S>` call site
unchanged. Domain code that wants signed bit patterns writes
`Bits<N, S, Signed>` directly; in practice the consumer reaches for
`IFixed<I, F, S>` instead, which is itself `repr(transparent)` over
`Bits<{1+I+F}, S, Signed>` (the symmetric counterpart of UFixed's
wrap of `Bits<{I+F}, S, Unsigned>`).

The public surface is partitioned and minimal:

```rust
impl<const N: Width, S: Strategy, Sign: Signedness> Bits<N, S, Sign>
where S: BitsContainerFor<N, Sign>,
{
    pub const fn from_raw(raw: <S as BitsContainerFor<N, Sign>>::T) -> Self;
    pub const fn to_raw(self) -> <S as BitsContainerFor<N, Sign>>::T;

    pub const fn from_narrowed<Src>(src: Src) -> Self
    where Src: ~const Narrow<<S as BitsContainerFor<N, Sign>>::T>;

    pub const fn from_widened<Src>(src: Src) -> Self
    where Src: ~const Widen<<S as BitsContainerFor<N, Sign>>::T>;
}
```

Plus `Deref<Target = ::T>`, `AsRef<::T>`, and `impl const Transparent`.

Per round 202604271346 D-7, every per-size helper is gone. No
`from_raw_uN` / `to_raw_uN` family. No `From<uN>` per N. No
`Bits::new(u64)` / `Bits::bits()` deprecated front-doors. The
`impl_bits_uN` macro family is removed in its entirety.

Consumers that need to take a wider raw value and narrow it to fit
`Bits<N, S, Sign>` go through the refit family from
`arvo-bits-contracts` (post-merge of arvo-narrow-contracts during
round 202604280034, post-Widen-addition during round 202604300826):
`Narrow<T>::narrow_to::<N>` for shrinks, `Widen<T>::widen_to` for
promotions. The trait surface and impl tables are re-exported
through the `arvo-refit` crate. The pipeline is explicit at the call
site instead of hidden inside per-size helpers.

### Ergonomic constructors `from_narrowed` and `from_widened`

The inherent `Bits<N, S, Sign>` impl ships two refit-aware
constructors that route through the `Narrow` and `Widen` traits:

```rust
let bits28 = Bits::<{width(28)}, Hot>::from_narrowed(wide_u64);   // narrow_to::<28>() inside
let bits64 = Bits::<{width(64)}, Hot>::from_widened(bits28);       // widen_to() inside
let raw28 = Bits::<{width(28)}, Hot>::from_raw(carrier_u32);       // unchecked entry point
```

The source type `Src` is inferred from the value at the call site;
no turbofish needed. The constructors' bodies route through the
trait's method (`src.narrow_to::<N>()` for `from_narrowed` where N
is `Self`'s outer const-generic; `src.widen_to()` for `from_widened`
where the source's bit-width derives from the impl context). Cross-
domain primitive↔Bits direct impls (round 202604300826) provide
the trait coverage so these constructors work with primitive sources
as well as `Bits<M, ...>` sources.

`from_raw` remains the unchecked entry point; `from_narrowed` and
`from_widened` are the recommended path when the source type does
not exactly match the carrier projection.

The `repr(transparent)` of `Bits<N, S, Sign>` over its projection
target is compile-time-asserted at boundary cells in
`arvo-storage/src/layout_assertions.rs`. The boundary set covers
each of the five native buckets (1, 8, 9, 16, 17, 32, 33, 64, 65,
128) plus representative wide widths (129, 200, 256, 4096) for both
the `WideBits<BYTES, A1>` (Warm/Cold/Precise) and
`WideBits<BYTES, A16>` (Hot) projections. If a future round changes
the container projection at
any boundary cell, the build breaks.

The boundary set is the default. A `cfg(arvo_full_layout_audit)` gate
opens the full (Strategy, N, Sign) tuple expansion, asserting every
cell across the projection space. Periodic CI nightly builds run the
full audit; default builds keep the bounded set to hold compile time
in check.

## Strategy markers (re-exported)

`Hot`, `Warm`, `Cold`, `Precise` are zero-sized types declared in
`arvo-strategy`. arvo-storage re-exports them via `pub use
arvo_strategy::{Hot, Warm, Cold, Precise};` so consumers reaching
for the storage primitive at `arvo_storage::Bits<...>` can name the
strategy without importing two crates.

Strategy semantics across the substrate (full detail in
`arvo-strategy/DESIGN.md.tmpl`):

- `Hot` picks the narrowest container per bit width. 1..=8 → `u8`,
  9..=16 → `u16`, ..., 65..=128 → `u128`. Above 128 →
  `WideBits<bytes_for(N), A16>` (align(16) byte sequence).
- `Warm` mirrors Hot's container shape below 128. Above 128 →
  `WideBits<bytes_for(N), A1>` (align-1 byte sequence). The previous
  "2x logical width" Warm contract collapsed once the substrate
  passed single native primitives in width.
- `Cold` mirrors Warm's per-value container shape. Bitpacking happens
  at the column-store layer above the per-Bits container, not at the
  per-value container shape.
- `Precise` mirrors Warm's container shape; saturating arithmetic
  distinguishes the strategy at the op layer.

The unified `BitsContainerFor<const N: Width, Sign: Signedness>`
projection trait lives in `arvo-strategy` (not here). Round 202605031400
deletes the previous `UContainerFor` / `IContainerFor` split and the
`MultiContainer<HiT, LoT>` family entirely.

## Signedness markers

`Unsigned` and `Signed` are zero-sized markers. Each implements the
sealed `Signedness` marker trait and derives `ConstParamTy` so it
appears as a const-generic argument on `Bits<N, S, Sign>`.

```rust
pub const trait Signedness: sealed::Sealed + Copy + Clone + Default + 'static {}

#[derive(ConstParamTy, PartialEq, Eq, Copy, Clone, Debug, Default)]
pub struct Unsigned;

#[derive(ConstParamTy, PartialEq, Eq, Copy, Clone, Debug, Default)]
pub struct Signed;

impl const Signedness for Unsigned {}
impl const Signedness for Signed {}
```

The Sign axis on `Bits` was introduced in round 202604280500 to close
the symmetry gap between UFixed and IFixed. Default `Sign = Unsigned`
on `Bits` keeps existing call sites unchanged; IFixed's
`repr(transparent)` wrap of `Bits<{1+I+F}, S, Signed>` reaches for the
non-default value.

## WideBits

`pub struct WideBits<const BYTES: usize, A: Align = A1>` is the
byte-sequence storage primitive used at logical bit widths above
128 (where no native primitive exists). Round 202605031400 introduces
this type as the replacement for the deleted `MultiContainer<HiT, LoT>`
family.

```rust
pub trait Align: Copy { const VALUE: usize; }

#[repr(C, align(1))]   pub struct A1;
#[repr(C, align(16))]  pub struct A16;
#[repr(C, align(32))]  pub struct A32;
#[repr(C, align(64))]  pub struct A64;

#[repr(C)]
pub struct WideBits<const BYTES: usize, A: Align = A1> {
    _align: [A; 0],
    pub bytes: [u8; BYTES],
}
```

`#[repr(C)]` with a zero-sized alignment marker `[A; 0]` plus a single
`[u8; BYTES]` field. Layout is exactly BYTES bytes; alignment is
`A::VALUE`. Sketch 02 verified the layout across widths 1, 25, 32,
64, 128, 512: size matches BYTES exactly, alignment matches the marker.
No internal padding.

The `Align` axis lets one type cover every SIMD tier from a single
declaration. `WideBits<BYTES, A1>` is the align-1 baseline (Warm /
Cold / Precise above 128); `WideBits<BYTES, A16>` is the SSE2 + NEON
SIMD-friendly default (Hot above 128). `A32` and `A64` (AVX-2 and
AVX-512) plug in by adding markers, not container types, behind cfg
gates per #320.

### Byte-ordering convention

The byte-ordering convention for `WideBits<BYTES, A>` matches
`u128::trailing_zeros` / `u128::leading_zeros` semantics
viewed as bit-significance order:

- Bit index 0 is the LSB of byte 0.
- `count_ones`: order-independent, sum of `bytes[i].count_ones()`.
- `count_zeros`: `BYTES * 8 - count_ones()`.
- `trailing_zeros`: walks from byte 0 LSB upward. If `bytes[0] == 0`,
  accumulate 8 and advance; otherwise return accumulated +
  `bytes[0].trailing_zeros()`.
- `leading_zeros`: walks from byte BYTES-1 MSB downward symmetrically.
- `get_bit(idx: USize)`: `(bytes[idx/8] >> (idx % 8)) & 1`.
- Bitwise ops (`bitand` / `bitor` / `bitxor` / `bitnot`): byte-wise.
- `is_zero`: all bytes zero.
- `clear_lowest_set_bit`: locate first non-zero byte, apply
  `b & (b-1)` semantics.

This mirrors the existing `MultiContainer` lo-first cascade
(MultiContainer's `trailing_zeros` consulted `lo` first, `leading_zeros`
consulted `hi` first; with byte-sequence storage, `lo` is byte 0 and
`hi` is byte BYTES-1). The convention preserves observable behaviour
for every consumer transitioning across the 128-bit boundary. Per
audit C1, this is locked at the doc-CL level so the src CL does not
silently flip the convention.

### Size envelope

BYTES ranges from 1 to 8191 (Width=u16 → max 65535 logical bits → max
8192 physical bytes; one byte slack accounts for the type system's
unsigned-arithmetic bookkeeping in the projection const fns). For
N=129 (smallest wide width above the native ladder), BYTES = 17. For
N=4096 (RSA-4096 modulus), BYTES = 512. For SHA3-512 digest (N=512),
BYTES = 64.

### BitPrim impl (in arvo-bits-contracts)

The `BitPrim` impl lives in `arvo-bits-contracts/src/widebits.rs`
because `arvo-storage` cannot depend on `arvo-bits-contracts` (the
direction is the other way). Methods compose byte-by-byte per the
byte-ordering convention; full surface documented in
`arvo-bits-contracts/DESIGN.md.tmpl`.

## Wider alignment tiers via `Align` markers

The `Align` trait + ZST markers `A1` / `A16` / `A32` / `A64` cover
SSE2 / NEON / AVX-2 / AVX-512 from a single `WideBits<BYTES, A>`
declaration. Sketch 03 verified the layout across BYTES values 17,
25, 32, 33, 64, 512 with each marker: size = `round_up(BYTES, A::VALUE)`
when A > 1, alignment = `A::VALUE`. Trailing pad bytes from the
alignment requirement are not initialized by the standard
constructors; reading the full struct as bytes via transmute or
raw-pointer cast is **undefined behaviour**. Only
`as_bytes() -> &[u8; BYTES]` returns a safe view of the initialized
portion.

`A1` and `A16` are the actively-used markers today. `A32` and `A64`
are declared for future SIMD use behind cfg gates per #320. Per
audit H1, the cfg-driven internal alignment originally proposed in
round 202605031400's first topic was rejected as a
`arvo-toolbox-not-policer` violation: it silently imposed up to 4×
storage overhead on the consumer with no visibility. The marker-based
form makes the alignment choice explicit at the dispatch site.

## Bool

`pub struct Bool(pub bool)`. The newtype that carries Rust's `bool`
through the substrate's "every public type is an arvo wrapper" rule.
Used by predicates (`is_zero`, `bit`, `Predicate` family) and in
control flow that returns to consumer code.

`Bool` implements `Try` with `Residual = Infallible` so the `?`
operator extracts the inner `bool` for use in `if` expressions. The
extraction has zero runtime cost (the Continue path is the only
inhabited path).

`Bool` implements `notko::ConstTry` and
`notko::ConstFromResidual<core::convert::Infallible>` so the existing
non-const `core::ops::Try` / `FromResidual` impls have const-callable
counterparts. This is a substrate-internal const-branch surface
reached via explicit `match b.const_branch() { ... }`; the `?` syntax
itself stays non-const because rustc desugars `?` directly to
`core::ops::Try::branch`, which is not `pub const trait` as of
2026-05.

`Bool` implements the const unsafe `Transparent` trait so the inner
`bool` is reachable in const context via `arvo::raw(b)`.

### Const-trait surfaces (round 202605021800)

Round 202605021800 lifts the `AsBool` trait to `pub const trait` and
adds substrate-bridge `ConstEq` and `ConstDefault` impls on `Bool`.

```rust
pub const trait AsBool {
    fn as_bool(&self) -> bool;
}

impl const AsBool for Bool {
    fn as_bool(&self) -> bool { self.0 }
}

impl const ConstEq for Bool {
    fn const_eq(&self, other: &Self) -> Bool {
        Bool(self.0 == other.0)
    }
}

impl const ConstDefault for Bool {
    fn const_default() -> Self { Bool(false) }
}
```

`ConstOrd` is skipped for `Bool` (only two values; lattice ordering
is trivial and not consumer-needed). `Bool` is not a candidate for
`Bounded` / `Identity`: it is not a numeric primitive.

Stdlib `From<bool> for Bool` and `From<Bool> for bool` impls remain
non-const for boundary coverage. The parallel `ConstFrom` impls land
in Round 4 (#314) once the `ConstFrom` substrate bridge ships.

## USize

`pub struct USize(pub usize)`. The newtype for platform-pointer-width
unsigned integers. Used as the universal index/length type across the
substrate: `Cap` wraps it, `HasBitWidth::WIDTH` returns it, every
arvo-tensor offset is a `USize`.

This round preserves `USize`'s field shape (still `usize`). Future
rounds may migrate the inner field to `Bits<{cfg-platform-width},
Hot>` for a unified bit-storage view; the prior round explored that
direction and parked it.

`USize` implements the const unsafe `Transparent` trait.

### Const-trait surface (round 202605021200, refined round 202605021800)

`USize` impls `core::ops::*` const traits: `Add`, `Sub`, `Mul`,
`Div`, `Rem`, `Shl<USize>`, `Shr<USize>`, `BitAnd`, `BitOr`,
`BitXor`, `Not`. Comparison via `PartialOrd<USize>` and `Ord`. Each
op is `impl const Trait<USize> for USize`. Two crate-level features
are required at any crate that authors or consumes the const-trait
surface: `feature(const_trait_impl)` (already shipped via
`arvo-transparent`, set on `arvo-storage`'s crate root) and
`feature(const_ops)` (new in round 202605021200).

Round 202605021800 makes the canonical-const surface trait-only:
`USize` impls `Bounded`, `Identity`, `ConstEq`, `ConstOrd`, and
`ConstDefault` (all from `arvo-strategy`). Bodies route to the inner
`usize`'s primitive operators. The bare-primitive `usize::MAX`
literal appears only at the bottom-out point inside `impl const
Bounded for USize`'s body, per `no-bare-primitives.md` definition-
site exception 3 (platform-binding wrappers).

Consumer code reaches for `<USize as Identity>::ZERO` /
`<USize as Identity>::ONE` / `<USize as Bounded>::MAX` directly, or
`use arvo_strategy::{Identity, Bounded};` and writes
`USize::ZERO` / `USize::ONE` / `USize::MAX` resolved through the
trait associated constants. The trait is the canonical surface;
inherent re-definitions are not maintained.

Mixed-arity ops (`USize + bare-usize`) deliberately do not compile.
Consumer call sites that need a literal use `<USize as Identity>::ONE`
/ `<USize as Identity>::ZERO` for the common cases or `USize(N)` for
arbitrary literals.

Overflow semantics match `usize`'s primitive contract: panic on
debug-assertion builds, wrap on release.

## Cap

`pub struct Cap(pub USize)`. Const-generic capacity newtype, used
wherever a const generic sizes an array. The wrapping prevents
mixing capacities with unrelated indices. The const parameter name
carries the semantic distinction (`N`, `ROWS`, `NNZ`).

Cap impls `Bounded`, `Identity`, `ConstEq`, `ConstOrd`, and
`ConstDefault` (round 202605021800). Bodies delegate through the
inner USize's trait projections; no raw `usize` arithmetic in Cap's
body. Consumer code reaches for `<Cap as Identity>::ZERO` /
`<Cap as Identity>::ONE` / `<Cap as Bounded>::MAX`.

Const-trait ops on Cap operating against Cap: `Add`, `Sub`, `Mul`,
`Div`, `Rem`. Bodies delegate through USize's const-trait surface
(`Cap(self.0.add(rhs.0))`); no raw `usize` arithmetic in Cap's
body. The semantic distinction holds at the type level: `Cap +
USize` does not compile.

Cap implements `Transparent` over USize.

## NUSize

`pub struct NUSize(Slot<NonZeroUSize>)`. The newtype that carries
"absent or present USize" without paying a discriminant byte.
`#[repr(transparent)]` over `Slot<NonZeroUSize>`, which is itself
`#[repr(transparent)]` over `Maybe<NonZeroUSize>`. Layout is
identical to `usize` (8 bytes on 64-bit) via niche optimisation
through `core::num::NonZero<usize>`: `Maybe::Isnt` lives in the zero
slot that `NonZero` excludes.

```rust
impl NUSize {
    pub const NONE: Self;
    pub const fn some(logical: USize) -> Self;
    pub const fn into_maybe(self) -> Maybe<USize>;
    pub const fn unwrap_or(self, default: USize) -> USize;
    pub const fn is_some(&self) -> Bool;
    pub const fn is_none(&self) -> Bool;
}
```

The "+1 shift on construction, -1 on extraction" is the wrapper's
only contract beyond `Slot`. Consumers see logical 0-indexed values
throughout: `NUSize::some(USize(0))` is a valid present value
referring to logical bin / index / slot 0; `NUSize::NONE` is the
absent marker. The internal `NonZeroUSize` representation
(`NonZero::new(logical + 1)`) is not visible to the caller.

`into_maybe` is the consuming form. There is no in-memory
`Maybe<USize>` for the wrapper to borrow into (the -1 shift
synthesises a fresh value), so the borrow form `as_maybe` is not
provided. The notko convention names the consuming form `into_*`,
the borrow form `as_*`. NUSize ships `into_maybe` only.

`some` cannot fail in practice. The single overflow case is
`NUSize::some(USize(usize::MAX))`, which folds into `NUSize::NONE`
because the +1 shift would wrap. Practical workloads never hit
this because `Cap<N>` is bounded well below `usize::MAX`.

`Slot<T: NonZeroable>` lives in notko as the generic transparent
niche-Maybe wrapper. `NUSize` is the USize-shaped specialisation that
adds the +1/-1 shift for ergonomic 0-indexed semantics. The split
keeps notko arithmetic-free; the shift logic lives where USize is
known.

Replaces the `USize(0)` overloaded sentinel idiom previously used in
`arvo-comb/src/binpack.rs` (Expert A audit Finding 14, round
202605040602). Use NUSize whenever the substrate needs "an optional
USize without paying discriminant overhead."

NU8 / NU16 / NU32 / NU64 are not shipped this round; the N-prefix
naming convention is established for future per-width extensions when
a consumer demands them. See BACKLOG.

## MetaCarrier

`pub struct MetaCarrier(pub u16)`. A `#[repr(transparent)]` companion
to `Bits<{width(9)}, Hot, Unsigned>` used as the meta-newtype carrier
(`IBits`, `FBits`).

`MetaCarrier` is layout-equivalent to `Bits<{width(9)}, Hot, Unsigned>`:
both are `repr(transparent)` over u16 (the underlying primitive
`<Hot as BitsContainerFor<{width(9)}, Unsigned>>::T` projects to). The
`MetaCarrier::as_bits()` const-fn exposes the Bits-typed view at zero
cost via a layout-equivalence transmute.

This companion exists to bypass a rustc trait-solver cycle that
arises when the meta-newtype field literally writes the generic
`Bits<{width(9)}, Hot>` projection. Using a concrete
`repr(transparent)` companion at the field type sidesteps the
projection chain at well-formedness time while preserving the
9-bit native range, the `Hot` strategy, and the `Unsigned` sign of
the conceptual carrier.

`MetaCarrier` derives `ConstParamTy` (via `feature(const_param_ty_trait)`
plus the standard structural-eq derive set), so the meta-newtypes
themselves remain const-generic-position-usable.

The layout-equivalence invariant against `Bits<{width(9)}, Hot, Unsigned>`
is compile-time-asserted in `arvo-storage/src/layout_assertions.rs`.
Any divergence between `MetaCarrier`'s hardcoded u16 and the projection's
choice for `<Hot as BitsContainerFor<{width(9)}, Unsigned>>::T` breaks
the build at compile time, surfacing the drift before any runtime
soundness violation could occur via the `as_bits()` transmute.

## Typed meta-bit newtypes

Two `#[repr(transparent)]` newtypes over `MetaCarrier`. Each derives
`ConstParamTy`:

```rust
#[derive(ConstParamTy, ...)]
#[repr(transparent)]
pub struct IBits(pub MetaCarrier);

#[derive(ConstParamTy, ...)]
#[repr(transparent)]
pub struct FBits(pub MetaCarrier);
```

`IBits` carries the integer-bit count of a fixed-point type. `FBits`
carries the fractional-bit count.

`Width` previously lived here as a third meta-newtype; round
202605031400 relocates it to `arvo-strategy::width` per the
`arvo-bridge-home-rule` workspace rule (Width's primary use is as a
const-generic parameter of the projection traits in arvo-strategy;
the type belongs in the lowest crate where its position is reachable).
arvo-storage re-exports it via `pub use arvo_strategy::Width;` in
`lib.rs` so consumer imports through `arvo_storage::Width` keep
working.

`MetaCarrier`, `IBits`, `FBits`, and `Width` (re-exported) all satisfy
`StructuralEq + Copy + Eq + ConstParamTy`. The trait obligations are
compile-time-asserted alongside the layout assertions in
`arvo-storage/src/layout_assertions.rs`.

`MetaCarrier::as_bits()` and `IBits::as_bits()` / `FBits::as_bits()` /
`Width::as_bits()` give the `Bits<{width(9)}, Hot, Unsigned>`-typed
view without going through the field-level projection. Consumers
reaching for the Bits-typed view get it at zero cost.

## Architectural pivot record (round 202605031400)

The previous wide-storage primitive `MultiContainer<HiT, LoT>` is
deleted entirely in round 202605031400. Sketch 01 verified that
`MultiContainer<u64, u128>` was always 32 bytes physical (the
alignment-of-largest-prim padding rule in `repr(C)` forces the total
to round up to a multiple of 16, the alignment of u128). The "u64+u128
saves bytes" rationale documented in prior rounds was incorrect:
sketch 01 measured the existing substrate's physical layout and
confirmed the supposed savings did not exist.

The replacement is the parametric `WideBits<BYTES, A: Align = A1>`:
align-1 (`A1`) for Warm / Cold / Precise, align(16) (`A16`) for Hot.
The `Align` axis is parametric on a ZST marker family
(`A1` / `A16` / `A32` / `A64`) so a single type covers every SIMD
tier; the typedef-per-tier shape from earlier sketches
(`AlignedWideBits16` etc.) was rejected as fragile. Same physical
size as the previous MultiContainer for the canonical pairs; honest
about what the substrate stores; substrate-implementor cost of the
byte-by-byte BitPrim impl is offset by no per-pair combinatorics in
the projection table.

Per `no-legacy-shims-pre-1.0.md`, no deprecation alias for
MultiContainer. Workspace consumers were grep'd 2026-05-03T14:30Z;
zero references in any consumer repo (hilavitkutin, viola, vehje,
notko, viola-grammar-ts, viola-script-lints, mockspace,
mockspace-hilavitkutin-stack-lints). Deletion is mechanical.
