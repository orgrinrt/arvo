# arvo-strategy. Design

The strategy-marker and container-projection layer. Defines what
"strategy" means in arvo: a compile-time tag that picks the
underlying primitive container for a given bit width. No fielded
types beyond the four ZST markers. `#![no_std]`, no alloc.

Depends on `notko` and `arvo-transparent`. Does NOT depend on
`arvo-storage`. The trait declarations are type-only and the
projection bodies name only bare primitives (`u8`..`u128`, `i8`..`i128`)
plus the `WideBits<BYTES, A>` storage shape whose declaration
lives in `arvo-storage` and re-exports back through
`arvo-storage`'s public surface. The `arvo-strategy` to
`arvo-storage` direction is acyclic by topology.

## Strategy markers

```rust
#[derive(ConstParamTy,...)]
pub struct Hot;

#[derive(ConstParamTy,...)]
pub struct Warm;

#[derive(ConstParamTy,...)]
pub struct Cold;

#[derive(ConstParamTy,...)]
pub struct Precise;
```

Four zero-sized types. Each derives `ConstParamTy` so it works as a
const generic argument. Each implements the sealed `Strategy` marker
trait declared here.

`Hot` selects the narrowest container per bit width. 1..=8 bits use
`u8`, 9..=16 use `u16`, 17..=32 use `u32`, 33..=64 use `u64`,
65..=128 use `u128` (single-primitive). Above 128, Hot uses
`WideBits<{bytes_for(N)}, A16>` (align(16) byte-sequence baseline,
SSE2 + NEON aligned-load compatible). Picked when consumers want
minimum storage and SIMD-friendly alignment for the SSE2/NEON floor.

`Warm` selects a containers matching Hot's footprint up to native
primitives. The earlier "2x-logical safety" Warm cap collapsed to
"same projection as Hot" once arvo's bit-width range exceeded
single native primitives. Above 128 bits, Warm uses
`WideBits<{bytes_for(N)}>` (align-1 byte-exact). Picked for
development ergonomics; full precision; no SIMD assumption.

`Cold` mirrors Warm's container shape; bitpacking is an access-path
concern at the column-store layer above the per-Bits container, not
a per-value container shape. Below 128 bits, native primitive picks
its own alignment. Above 128, Cold uses `WideBits<{bytes_for(N)}>`
(align-1).

`Precise` mirrors Warm's container shape; saturating arithmetic
distinguishes the strategy at the op layer. Below 128, native
primitive. Above 128, `WideBits<{bytes_for(N)}>` (align-1).

The 128-bit boundary captures the rustc primitive ladder: u8/u16/u32/
u64/u128 each have stable Rust support with stdlib ops that lower as
well as the toolchain currently does for that width. Above 128 we
accept that no native primitive exists and route to byte-sequence
storage with custom ops. The boundary is not a hardware-instruction
claim; it is a rustc-primitive-ladder claim.

Hot's wider SIMD alignment tiers (align(32) for AVX-2, align(64) for
AVX-512) are not currently exposed. Bench evidence in #320 will
determine whether they ship as opt-in `HotAvx2` / `HotAvx512`
consumer-visible variants. The cfg-driven internal alignment with
no consumer visibility was rejected per the audit's H1 finding (it
violates `arvo-toolbox-not-policer` by silently policing a 4x
storage overhead the consumer can't see).

## Strategy axis decomposition

Round C decomposes the bundled `Strategy` axis
into three orthogonal sub-axes, each its own sealed marker trait. Round
202605021800 lifts every axis trait to `pub const trait` so `[const]`
propagation reaches every `Self: HasAxes` projection through arvo.

```rust
pub const trait OverflowPolicy { /* Wrapping / Saturating */ }
pub const trait ContainerWidth { /* Min / DoubleLogical */ }
pub const trait StorageLayout { /* Dense / Bitpacked */ }
```

Each axis has two ZST markers (`Wrapping` / `Saturating`, `Min` /
`DoubleLogical`, `Dense` / `Bitpacked`). The four existing strategy
markers implement specific axis combinations:

| Marker | OverflowPolicy | ContainerWidth | StorageLayout |
|---------|----------------|----------------|---------------|
| Hot | Wrapping | Min | Dense |
| Warm | Wrapping | Min | Dense |
| Cold | Wrapping | Min | Bitpacked |
| Precise | Saturating | Min | Dense |

The public surface (the four markers) is unchanged. The axis traits
are the dispatch backbone: `arvo`'s arithmetic / widen / narrow
impls (`UArith`, `IArith`, `UWidenFrom`, `UNarrowFrom`) project
through `HasAxes` to pick the codegen path per axis combination.
A consumer composing `Hot + Saturating` (Hot's container width
with saturating overflow) reaches a different codegen path than
`Hot + Wrapping` does, without breaking the public marker surface.

This collapses all four strategies to `Min` container
width: with the 128-bit native boundary, the previous "2x logical"
distinction at the storage layer disappears. The `DoubleLogical`
marker remains in the axis enum for forward-compatibility with future
strategy additions; today no strategy uses it.

Each axis surface carries a `const DISCRIMINANT: u8` projection.
`HasAxes::Container::DISCRIMINANT` is asserted at compile time to
match `<S as ContainerWidth>::Output::DISCRIMINANT` for every
strategy. The cross-check pins the documentation table above to
behaviour: a future round changing a strategy's axis impl without
updating `HasAxes` breaks the build, not silent runtime divergence.

`HasAxes` itself is `pub const trait`. The four
strategy `impl const HasAxes for Hot/Warm/Cold/Precise` blocks are
`impl const`. Every consumer-side `where T: HasAxes` bound becomes
`where T: [const] HasAxes` for const-context callers.

Per the `arvo-toolbox-not-policer` workspace rule, the axis
decomposition exists so arvo can grow its strategy lattice
without forking the marker namespace each time. Consumer-facing
expansion (new public markers) requires an explicit design round.

## Sealed marker traits and `pub const trait` discipline

Workspace-wide pattern: sealed marker traits
carrying associated types or const discriminants but no method bodies
(or trivially-pure bodies) lift to `pub const trait` so `[const]`
propagation reaches every where-clause that bounds on them. The
following traits across the foundation crates are covered.

- `Strategy` (sealed marker; `pub const trait`).
- `OverflowPolicy`, `ContainerWidth`, `StorageLayout`, `HasAxes`
 (axis decomposition above).
- `BitsContainerFor<N, Sign>` (unified projection trait below;
 unifies what was previously U/IContainerFor).
- `Project<TAG, Sign, BYTES, S>` (helper trait for the Pattern C
 const-tag dispatch; ).
- `CrossStrategyOp<S1, S2>` (cross-strategy diagnostic marker; sibling
 of the already-const `Resolve`).
- `Signedness` (in `arvo-storage`; sealed `Unsigned` / `Signed` marker
 trait carried as a const-generic bound on `Bits<N, S, Sign>`).
- `Ieee` and `FromU8Ieee` (this crate; supertrait-bound on `Identity`).
- `IntegerLike`, `FractionLike`, `BitPresentation`, `FloatLike`,
 `BoolLike` (in `arvo`; consumer-facing markers).
- `AsBool` (in `arvo-storage`; `Bool::as_bool` projection).

Every existing `impl X for Y` block for these traits lifts to
`impl const X for Y` in the same round.

This deletes `MultiContainerHalf` along with the
`MultiContainer<HiT, LoT>` family. The container projection above
128 bits goes through byte-sequence storage; no half-marker is
required.

## Const-trait bridges (`ConstEq`, `ConstOrd`, `ConstDefault`)

This introduces three const-trait bridges in arvo.
They replace stdlib non-const trait usage in const fn bodies
where the foundation composes generically.

```rust
pub const trait ConstEq {
 fn const_eq(&self, other: &Self) -> Bool;
 fn const_ne(&self, other: &Self) -> Bool {
 Bool(!self.const_eq(other).0)
 }
}

pub const trait ConstOrd: ConstEq {
 fn const_cmp(&self, other: &Self) -> Ordering;
 fn const_lt(&self, other: &Self) -> Bool;
 fn const_le(&self, other: &Self) -> Bool;
 fn const_gt(&self, other: &Self) -> Bool;
 fn const_ge(&self, other: &Self) -> Bool;
}

pub const trait ConstDefault {
 fn const_default() -> Self;
}
```

`Ordering` reuses `core::cmp::Ordering` if const-constructible on
rustc 1.96.0-nightly; otherwise arvo ships `pub enum
ConstOrdering { Less, Equal, Greater }`. The decision is recorded at
round close.

Coverage: every primitive-wrapper type (`USize`, `Cap`,
`Bool`, `Bits<N, S, Sign>`, `UFixed<I, F, S>`, `IFixed<I, F, S>`,
`FastFloat<F>`, `StrictFloat<F>`, `Mask<W>`, `BitMatrix<W, const N: Cap>`,
`NodeId`, `MetaCarrier`, `IBits`, `FBits`, `Width`) gains `impl const ConstEq`
and `impl const ConstDefault`. `ConstOrd` lands for the totally-ordered
subset (skip `Mask` lattice; skip floats due to NaN).

Stdlib `Default`, `PartialEq`, `Eq`, `PartialOrd`, `Ord` impls remain
alongside (boundary coverage). The bridges are additive, not
replacements.

Bridge cross-references and shipping status:

- `ConstDeref` / `ConstAsRef<T>` bridges (placed in `arvo-transparent`). Ships (#314). See `arvo-transparent/DESIGN.md`.
- `ConstHash<N, S, Sign>` (placed in `arvo-hash`) plus `NarrowFromU64<N, S, Sign>` (placed in `arvo-bits-contracts`). Ships (#314). See `arvo-hash/DESIGN.md` and `arvo-bits-contracts/DESIGN.md`.

## ConstFrom and ConstTryFrom bridges

Const traits mirroring `core::convert::From` and `core::convert::TryFrom`, callable from `const` context.

```rust
pub const trait ConstFrom<T>: Sized {
 fn const_from(value: T) -> Self;
}

pub const trait ConstTryFrom<T>: Sized {
 type Error;
 fn const_try_from(value: T) -> Outcome<Self, Self::Error>;
}
```

`Outcome<T, E>` is `notko::Outcome`. The trait declarations live in `arvo-strategy` per the bridge-home rule: `notko` (which hosts `Outcome`) is reachable from `arvo-strategy`, and the bridges return `Self` and `Outcome<Self,...>` respectively. Per-type impls live in the type-declaring crate (forward composition through the bridge).

## Canonical typed-const surfaces: `Bounded`, `Identity`, `SignedIdentity`

`Bounded` (MIN / MAX) and `Identity` (ZERO / ONE) are the canonical
const-trait surfaces for typed-min, typed-max, typed-zero, typed-one
across arvo. Every primitive-wrapper impls them. The trait
**is** the canonical surface: consumer code reaches for
`<T as Bounded>::MAX` / `<T as Identity>::ZERO`, or imports the
trait (`use arvo_strategy::{Bounded, Identity};`) and writes
`T::MAX` / `T::ZERO` resolved through trait associated-const
lookup.

Inherent re-definitions of the form `impl T { pub const ZERO: T =
<T as Identity>::ZERO; }` are deliberately NOT maintained. They
duplicate trait constants, promise an API consistency arvo
would have to remember to maintain across every wrapper, and rot the
moment a trait gains a constant. The trait impls ship as the
canonical surface; consumer ergonomics is satisfied by `use`-importing
the trait.

This adds `SignedIdentity` for the signed `-1`:

```rust
pub const trait SignedIdentity: Identity {
 const NEG_ONE: Self;
}
```

Per-signed-primitive `impl const SignedIdentity` for `i8`..=`i128`
and `isize`. Body wraps the underlying `-1` of the typed primitive.

Deletion of `UPrimConst` and `IPrimConst` (which previously duplicated
`Bounded` + `Identity`) landed. The two-trait-
for-one-axis pattern is rejected per `arvo-toolbox-not-policer`.

## Width newtype

`Width` is a newtype around `u16` (max 65535 logical bits). Round 2
(#312) introduced it in `arvo-storage::meta_bits`. The pivot
relocates it to `arvo-strategy::width`.

```rust
pub struct Width(pub u16);
```

Per `arvo-bridge-home-rule.md`, a foundation type lives in the lowest
crate where its position-as-const-generic-param is reachable. `Width`
appears as the const-generic parameter of the projection traits
(`BitsContainerFor<const N: u16, Sign>`), which live here in
`arvo-strategy`. The previous home in `arvo-storage` left the type
declaration above its principal use site, requiring arvo-strategy to
either downcast Width to u16 (wasting the typed-position lift Round 2
already did) or violating the layering rule (arvo-strategy depending
on arvo-storage). Relocation to `arvo-strategy::width` resolves both.

`arvo-storage` adds `pub use arvo_strategy::Width;` for
source-compatibility within the workspace facade. The `MetaCarrier`
companion stays in `arvo-storage` (it carries Width but doesn't
define it; the `ConstParamTy_` carrier shape belongs alongside the
storage primitives that use it).

## Storage primitives (cross-references)

The container projection bottoms out at concrete storage types
declared in `arvo-storage`:

- `Bits<const N: u16, S: Strategy, Sign: Signedness>`, the
 user-facing typed-width bit container. Resolves its physical
 storage via `<S as BitsContainerFor<N, Sign>>::T`.
- `WideBits<const BYTES: usize>`, byte-sequence storage at
 align-1, used by Warm/Cold/Precise for N > 128.
- `WideBits<const BYTES: usize, A: Align = A1>` covers all wide
 storage. The `Align` trait + ZST markers `A1` / `A16` / `A32` /
 `A64` parameterise alignment. Hot at N > 128 uses
 `WideBits<BYTES, A16>` (SSE2 + NEON SIMD-friendly baseline); wider
 alignment tiers (`A32` AVX-2, `A64` AVX-512) land behind cfg gates
 per #320 with bench evidence.

The byte-ordering convention for both wide containers: bit 0 is the
LSB of byte 0; `trailing_zeros` walks from byte 0 upward; `leading_zeros`
walks from the highest-index byte downward. This mirrors the existing
`u128::trailing_zeros` / `u128::leading_zeros` semantics and preserves
observable behaviour for every consumer transitioning from native
primitive at N ≤ 128 to WideBits at N > 128.

## BitsContainerFor: unified container projection

```rust
pub const trait BitsContainerFor<const N: u16, Sign: Signedness>: Strategy {
 type T: Copy + ConstParamTy_ +...;
}
```

Single projection trait covering both Sign axes. Replaces the previous three-trait family (`UContainerFor<N>` + `IContainerFor<N>` + a Sign-axis bridge `BitsContainerFor`) with one trait that takes the Sign axis directly. Currently, deletes the old shapes entirely; per `no-legacy-shims-pre-1.0.md`, no deprecation aliases.

UFixed where-clauses migrate from `S: UContainerFor<N>` to `S: BitsContainerFor<N, Unsigned>`; IFixed similarly to `S: BitsContainerFor<N, Signed>`. The user-facing `UFixed<I, F, S>` and `IFixed<I, F, S>` types stay unchanged at the public surface.

The const-generic position is `const N: u16` directly. The `Width` newtype lives in `arvo-strategy::width` and is used for typed-const operations elsewhere; it does not appear in `BitsContainerFor`'s position because `feature(adt_const_params)` cycles around newtype-as-const-param plus `feature(generic_const_exprs)` evaluation under the const-trait-solver are unreliable on current nightly. Bare `const N: u16` resolves cleanly.

### Pattern C: const-tag dispatch through Project

The internal mechanism for the projection. Replaces 256 per-N entries × 2 Sign × 4 Strategy = 2048+ projection-table cells with 48 impls total (~98% reduction). Currently, macro-deduplicates the 40 native + 8 wide impls into 4 invocations of `macro_rules! impl_native_bucket` (one per Strategy) plus 4 wide-bucket impls; total impl count is unchanged but source-line count drops by ~70%.

```rust
pub const fn bytes_for_u16(n: u16) -> usize {
 (n as usize).div_ceil(8)
}

pub const fn tag_hot_cold(n: u16) -> usize {
 let n = n as usize;
 if n <= 8 { 0 }
 else if n <= 16 { 1 }
 else if n <= 32 { 2 }
 else if n <= 64 { 3 }
 else if n <= 128 { 4 }
 else { 5 }
}

pub const fn tag_warm_precise(n: u16) -> usize {
 let n = n as usize;
 if n <= 8 { 0 }
 else if n <= 16 { 1 }
 else if n <= 32 { 2 }
 else if n <= 64 { 3 }
 else { 5 }
}

pub trait Project<const TAG: usize, Sign: Signedness, const BYTES: usize, S: Strategy>: sealed::Sealed {
 type T: Copy + ConstParamTy_ +...;
}

pub struct Picker;
impl sealed::Sealed for Picker {}
```

`Project` is sealed via the `sealed::Sealed` supertrait bound. Downstream consumers cannot add `impl Project<6,..., Picker>` etc. `Picker` itself stays `pub` because it appears in the public associated-type body of every `BitsContainerFor` impl (`type T = <Picker as Project<...>>::T`). The actual gate against downstream impls is the seal on `Project`, not the visibility of `Picker`. Sketch 02 Finding 2 records this: a `pub(crate) Picker` triggers `E0446: private type Picker in public interface`; sealing the trait is the right shape.

Per-`(TAG, Sign, S)` impls of `Project` are distinct because TAG is a const-generic value distinct per impl. Rustc accepts the impls with no E0119 conflict.

Native bucket impls (40 total, Strategy-aware):
- Hot, Cold: 5 buckets × 2 sign axes × 2 strategies = 20 impls. Native primitives u8..u128 (Hot/Cold use min-aligned native ladder).
- Warm, Precise: 4 buckets × 2 sign axes × 2 strategies = 16 impls. Native primitives u16..u128 (Warm/Precise use 2x-logical native ladder; no bucket 4 because there is no native u256).
- 4 invocations of `impl_native_bucket!(Strategy, [unsigned-list], [signed-list])` produce all 40 from Strategy-keyed templates.

Wide bucket impls (4 total, Sign-erased):
- `impl<Sign, const BYTES: usize> Project<5, Sign, BYTES, Hot> for Picker { type T = WideBits<BYTES, A16>; }`
- `impl<Sign, const BYTES: usize> Project<5, Sign, BYTES, {Cold, Warm, Precise}> for Picker { type T = WideBits<BYTES, A1>; }`

The `Sign` parameter is a generic placeholder because the WideBits storage shape is sign-erased (bytes are bytes); the BitPrim impl on WideBits carries the sign-axis interpretation through the consumer's own type (`Bits<N, S, Sign>`).

User-facing `BitsContainerFor` impls (4 total, one per Strategy):

```rust
impl<const N: u16, Sign: Signedness> const BitsContainerFor<N, Sign> for Hot
where
 Picker: Project<{ tag_hot_cold(N) }, Sign, { bytes_for_u16(N) }, Hot>,
{
 type T = <Picker as Project<{ tag_hot_cold(N) }, Sign, { bytes_for_u16(N) }, Hot>>::T;
}
```

Hot and Cold use `tag_hot_cold`; Warm and Precise use `tag_warm_precise`. Per apply-time finding 1, redundant `[(); tag(N)]:, [(); bytes_for(N)]:` const-witness clauses are not needed: the const-expressions in the trait-arg position of `Picker: Project<{...},...>` already carry the WF requirement, and adding the bare `[();...]: ` lines triggers E0275 trait-solver overflow.

## mask_low_bits helper

```rust
#[inline(always)]
pub const fn mask_low_bits(n: u16) -> u64 {
 if n >= 64 { u64::MAX } else { (1u64 << n) - 1 }
}
```

Centralises the bit-mask pattern previously inlined in the `impl_fnv1a!` and `impl_xxhash3!` macro pastes in arvo-hash, plus used by `NarrowFromU64` impls in arvo-bits-contracts. Saturates at `u64::MAX` for `n >= 64` to avoid the `1u64 << 64` undefined-behaviour shift. Lives in `arvo-strategy/src/width.rs` next to `bytes_for_u16` and the `tag_*` const fns.

Round 4 (#314) replaces four hand-inlined copies of this pattern (Fnv1a's `update`, Fnv1a's `hash_const`, XxHash3's `update`, XxHash3's `hash_const`) with one helper. The bounded-generic `Hasher` impl in arvo-hash and the `NarrowFromU64` impls in arvo-bits-contracts both reach for it.
