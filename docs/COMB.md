# arvo-comb. Design

Combinatorial optimisation algorithms on const-generic fixed-size
structures. `#![no_std]`, no alloc. Constraint representations use
arvo-bitmask; value storage uses arvo-tensor.

The crate depends on
`arvo-storage`, `arvo-bits-contracts`, `arvo-numeric-contracts`,
`arvo-tensor`, `arvo-bitmask`. The prior `arvo-bits` direct dep is
replaced by `arvo-bits-contracts`.

Generic over numeric trait bounds for cost and weight types. Does not
import UFixed or IFixed directly. Consumer instantiates with concrete
arvo types; this crate is library code.

`N` / `M` / `B` are `Capacity` type parameters (arvo-tensor's
`Capacity`) in place of the prior `const N: Cap` / `const M: Cap` /
`const B: Cap`. Value storage flows through `arvo_tensor::Array<T, N>`
and `arvo_tensor::Matrix<W, N>`, whose backing is the
`Capacity::Array` associated type, so no `cap_size` sits in type
position. The wrappers hide indexing inside their `get` / `set`
methods; where a body needs the count as a value it reads
`cap_size(N::CAP)`. `cap_size` is re-exported from arvo-tensor
(canonical home).

## Range

```rust
pub struct Range {
 pub start: USize,
 pub end: USize,
}
```

A half-open interval `[start, end)` over indices. Used by
`greedy_group` as the output element. `#[repr(transparent)]` is not
used (two fields); `Copy + Eq + Default + Debug` derived.

## Cost type contract

```rust
fn matrix_chain_dp<N: Capacity, W>(
 cost: impl Fn(USize, USize) -> W,
 feasible: impl Pred2<USize, USize>,
) -> (W, Array<USize, N>)
where
 W: Add<Output = W> + TotalOrd + Copy + FromConstant
```

Same bounds as arvo-graph rank computation. Addition, ordering, copy,
zero. The consumer's cost function returns a type satisfying these
bounds; the DP accumulates and compares via trait bounds. Internal DP
tables: `Matrix<W, N>` for costs, `Matrix<Bool, N>` for feasibility /
reachability, `Matrix<USize, N>` for split points. All stack-allocated.

## Greedy interval grouping

Fully generic. No numeric traits needed, the feasibility predicate
and merge function are closures:

```rust
fn greedy_group<N: Capacity, M: Capacity, A, T>(
 items: &Array<T, N>,
 feasible: impl Pred2<A, T>,
 merge: impl Fn(A, &T) -> A,
 init: impl Fn() -> A,
) -> (USize, Array<Range, M>)
```

Sequential grouping under a feasibility predicate. Walk items in
order; accumulate into current group while feasible; break when
infeasible and start new group. Returns `(group_count, groups)`. Only the first `group_count` entries of `groups` are meaningful.

`M` is the caller-supplied upper bound on the number of groups. It
must be ≥ ceil(N / min_group_size); the algorithm asserts this at
compile time by bounding `M >= 1` and at runtime by returning early
if the group array fills.

Typical application: walk nodes in an RCM-reordered topo order,
accumulate access sets, break when a feasibility predicate fails or
a mandatory boundary (fan-in) occurs. Default algorithm for small
problem sizes or as a fallback for DP-based variants.

## Matrix chain ordering DP

Optimal grouping of sequential items into intervals, minimising total
cost under feasibility constraints. Generic over:

- Cost function: `cost(i, j) -> W` where W satisfies trait bounds
- Feasibility predicate: `feasible(i, j) -> bool`

DP recurrence: `dp[i][j] = min over valid split points k: dp[i][k] + dp[k+1][j]`

Returns `(optimal_cost, split_points)` where `split_points` is the
recorded split for each interval length. Stack table `Matrix<W, N>`.

Typical pipeline-grouping application:
- Cost: `element_count × sum of size_of::<T_k>()` for union data
 of ops `i..j` (memory bandwidth of one walk over the group's arena).
- Feasibility: a whole-pipeline resource check (register file, L1 write
 budget, L1+L2 total, no fan-in, no pipeline breaker).

Researched threshold: use DP when problem size exceeds 10 units;
fall back to greedy's left-to-right sequential join below that.

## Bin-packing

Two-level greedy bin-packing. Pack items into fixed-capacity bins,
minimising bin count.

```rust
fn bin_pack<N: Capacity, B: Capacity, T, W>(
 items: &Array<T, N>,
 capacity: W,
 weight_of: impl Fn(&T) -> W,
 affinity: impl Fn(&T, &T) -> W,
) -> (USize, Array<NUSize, N>)
where
 W: Add<Output = W> + TotalOrd + Copy + FromConstant
```

Returns `(bin_count, bin_id_per_item)`. The first element is the
opened-bin count. The second element holds, per input item, either
`NUSize::some(USize(b))` for placement in bin `b` (0-indexed) or
`NUSize::NONE` for items that did not fit. Niche-packed: per-slot
layout is one usize, same as raw `USize`, so the array footprint is
unchanged from the prior raw-USize representation.

`B` is the upper bound on the number of bins (used for internal
stack-allocated per-bin accumulator arrays). `W` is the weight /
affinity numeric type; must be addable, ordered, copyable, and have a
zero via `FromConstant`.

This replaced the prior `Array<USize, N>` return with
`Array<NUSize, N>`. The previous shape used `USize(0)` as both "first
valid bin" and "did not fit", an overloaded sentinel that surfaced as
Expert A audit Finding 14. The NUSize form distinguishes the cases at
the type level without paying a discriminant byte.

Common application: bit assignment for co-firing flags. Items that
co-fire pack into the same byte / word and enable hierarchical skip
(u64 == 0 → skip 64 bits). Affinity-ordered: high-co-fire pairs
placed adjacent.
