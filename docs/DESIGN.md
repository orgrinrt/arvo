# arvo. Architecture Design

> Numeric primitives + analysis algorithms with Hot / Warm / Cold /
> Precise strategy markers. `#![no_std]`, no alloc. Zero dependency
> on platform. Designed so every downstream consumer shares one
> numeric layer.

## Principles

1. **Strategy-parameterised primitives.** Numeric containers declared
   at type level as `Hot` / `Warm` / `Cold` / `Precise`, driving
   storage width and codegen choices without runtime dispatch.
2. **no_std, no alloc.** Every crate is const-sized.
   Consumers pre-allocate; arvo never calls into an allocator.
3. **Trait contracts, not concrete types.** Sub-crates generic over
   trait bounds so downstream code picks its own concrete
   instantiations. Trait declarations live in dedicated contract
   crates (small transitive dependency footprint per consumer).
4. **Monomorphisation is the dispatch.** No `dyn`, no `TypeId`. The
   monomorphised function IS the type identity.
5. **Const-trait-driven.** Every trait whose methods are sensibly
   callable in const context is `pub const trait` (RFC 3762 line).
   Trait projections work in const fn bodies; default bodies stay
   reachable from const generic positions.

## Crate topology

Three crates, and the dependency direction is what enforces the design rather
than a rule asking for it. `arvo-format` cannot name a carrier because it does
not depend on the crate that has one, which is how "every operation is a
function of the declared width and never of the machine carrier" stays true
under later edits.

| Crate | What it ships | Depends on |
|---|---|---|
| `arvo-format` | The declared signature. The representable set as one affine predicate over a phase, a quantum law and a slot range, of which integers, fixed point, scaled integers and floats are points. The six rounding modes, the overflow policies, the adaptation as the pair of those two, and the map that applies one. Introduces the numeric category, so `Width` and `Bool` are defined here. | `notko` |
| `arvo-placement` | The placement derivation, keyed on occupancy. One output at sole occupancy, the carrier; three at shared, the carrier and the access width and the stride. No declared operation reads any of them. | `arvo-format` |
| `arvo-strategy` | The binding from a name to a placement objective and an adaptation selection. Four presets ship as instances of an open concept rather than as members of an enumeration. | `arvo-format`, `arvo-placement` |

The set is open at both ends it can be. A new numeral joins by implementing
`Format`, a new overflow policy by implementing `Overflow`, and a new strategy by
implementing `Strategy`, none of which edits anything that already exists. The
rounding vocabulary is the one closed enumeration, fixed at six names, so a
const predicate over it is exhaustive and a seventh mode is a different design
rather than a new row.

## Contracts and their instances

Every crate here is a small set of contracts plus the instances that ship with
them. `Format`, `Ambient`, `Quantum`, `Slots`, `Rounding`, `Overflow`,
`Adaptation`, `DeclaredSignature` and `Operation` are contracts; `Integer`,
`UFixed`, `Biased`, `Floating`, the six modes and the three policies are
instances of them.

The reason the split falls this way is what a consumer has to depend on to say
one thing. Stating what values exist needs `arvo-format` and nothing else.
Stating where they sit needs `arvo-placement` on top of it. Choosing between
placements needs `arvo-strategy` on top of both. Saying the same thing in an
industrial convention's own words is still stating what values exist, so it needs
`arvo-format` and nothing else, and the conventions ship there beside the
parameterisation points. A consumer that only declares formats never compiles a
carrier ladder.

## Dependency direction

Strictly upward, and it carries a design constraint rather than a convention.
`arvo-format` has no workspace dependency, so nothing in it can mention a
carrier; `arvo-placement` depends on it and derives one; `arvo-strategy` depends
on both and binds a name to a choice between them. There is no facade today, and
a crate that re-exported the three would sit below all of them rather than
above.

## Consumers

arvo is a library rather than a program, so how it gets used is not fully known
here. What it is built for is the algorithm crates every downstream repository
uses, and the contracts for things that compose into units bigger than numerals
alone. The numeral base has to work first, which is what the three crates above
are.
