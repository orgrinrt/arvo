# `arvo-digest`: a digest of explicit bytes at a named width

Canon this design declares: `obligation::a_content_hash`, a hash of content stable across sessions
and machines whose width the consumer names rather than inherits. No ruling places a digest crate in
arvo, names it or picks its algorithms.

## What this crate is

A digest here is a function of a byte string and a width, and of nothing else. The same bytes give the
same digest in every session, on every machine, at every pointer width and in const context as at run
time. That stability is the whole of what `obligation::a_content_hash` asks for besides the width, and
it is why the crate takes bytes and never a value of some other type: a value's bytes are its
consumer's to decide, and a digest that decided them would be choosing a layout on the consumer's
behalf.

Nothing here is cryptographic. FNV-1a and XXH3 mix well and are fast, and an adversary who chooses the
input can make either collide. A consumer that needs resistance to that takes a different crate.

## The result: `Digest<BITS>`

`Digest<const BITS: u16>` holds a digest at its algorithm's output width. The widths are the ones the
marker `Width<BITS>` implements the sealed trait `Carrier` for, 32, 64 and 128, and `Carrier` names the
container each is held in: `arvo_bits::Bits<32>`, `Bits<64>`, and `[Bits<64>; 2]` at 128, low half first,
since a `Bits` stops at sixty-four. Any other width does not exist
as a type, so asking for one is a compile error and never a check at run time.

`raw()` returns that container, and a consumer that needs the host's integer takes it from `Bits::raw`,
so the digest names no host integer itself. A digest compares for equality and copies; it has no ordering, because the order of two digests means nothing.

`bits::<N>()` on `Digest<32>` and `Digest<64>` is the obligation's named width: a masked cast into
`arvo_bits::Bits<N>`, keeping the low `N` bits. Both algorithms spread their output across every bit,
so the low bits are as good as any others, and the cast is `Bits::cast`, the masking `arvo-bits` already owns rather
than a second one here. `N` wider than the digest is refused when the function is instantiated.

## The input

Every entry point takes `arvo_bits::Bytes`, a borrowed run of the host's bytes. The host's byte image
enters the stack at that type's door in `arvo-bits`, the introducing crate that owns the container a
byte is read into, and nowhere in this crate: not in its surface and not in its internals. FNV-1a walks
the run with `Bytes::split_first`, and the call into xxhash-rust takes `Bytes::host` and hands its
result to `Bits::masked`, or at 128 bits to `Bits::halves`.

The crate neither implements nor accepts `core::hash::Hash`. That trait feeds a slice's length as a
`usize`, so the same value hashes differently on a 32 bit and a 64 bit target, which is the
instability this crate exists to rule out.

## `Fnv1a<BITS>`

`Fnv1a<32>::of` is a `const fn` over the reference offset basis `0x811c9dc5` and prime `0x01000193`.
Each byte is xored in and the state multiplied by the prime, wrapping. This is the digest a consumer
names when the values it has already persisted are FNV-1a.

Neither step is written here. The state is an `arvo_numeral::Uint<32, Adapt<TowardZero, Wrap>, Quiet>`,
whose `Num::mul` is the product reduced modulo two to the thirty-second, the wrap being the declared
overflow policy and `Quiet` saying that the wrap is what the product means. The xor is `Bits::xor`, the
byte cast up to thirty-two bits. The state crosses between the two through `Num::index` and
`Num::from_index`, with the host integer between them inferred from `Bits::masked` and `Bits::raw`
rather than named, so the walk spells no host type.

`Fnv1a<64>` is the same walk at 64 bits, at the offset basis `0xcbf29ce484222325` and prime
`0x00000100000001b3`, and it is not in the crate yet: `arvo-format` does not yet admit the wrapping
product over the unsigned 64-bit range, so `Uint<64>`'s `mul` is refused at build.

## `Xxh3<BITS>`

`Xxh3<64>` and `Xxh3<128>` run XXH3 through xxhash-rust, with its default secret and no seed. Each has
two entry points, because one function cannot be both. `of` takes the runtime path, whose SIMD width is
chosen by `cfg(target_feature)` when the crate is compiled, so the dispatch is monomorphised and there
is no detection at run time. `of_const` takes the `const fn` path. They return the same value for the
same bytes, and a test asserts it over every length class the algorithm has.

## The switched digest

<!-- FIXME(arvo_format_admits_the_wrapping_product_over_the_unsigned_64): the switched digest, its length predicate and its crossover bench join with the 64-bit FNV-1a. -->
This section describes a digest that waits on the 64-bit FNV-1a and is not in the crate yet. The
64-bit switched digest's `of` and `of_const` are the stack's digest when no existing format has to
be matched. Input shorter than the crossover is digested with FNV-1a and the rest with XXH3, by the
same rule on both paths, so a digest computed at compile time equals the one computed at run time.

Because the rule depends on the length, the crossover is part of what the digest is. Moving it changes
the digest of every input between the old and the new value, which is a format change for anyone who
stored one, so tests pin a length on each side of it to its algorithm.

The crossover is measured. The `digest-crossover` bench in `mock/benches/` times FNV-1a, XXH3's runtime
path and XXH3's const path over a sweep of lengths, and the crossover is the shortest length from which
the runtime XXH3 path is faster than FNV-1a at every measured length, each with a confidence interval
that excludes zero. Its CSV and findings are committed beside the bench, and the decision note is in
`mock/research/`. The measurement is from one host, and the note says which.

There is no switched digest at 128 bits. FNV-1a at that width multiplies a 128 bit state per byte, and
nothing asks for it.

## What this crate does not do

No seed and no custom secret, since nothing asks for either and a seeded digest is a different
function. No streaming state: the input is one slice. No edits to consumers; the FNV-1a they spell for
themselves moves here when each of them takes the switch.

## Tests

The FNV-1a suite checks the reference values for the empty string, `"a"` and `"foobar"` at 32 bits.
The XXH3 suite checks xxHash's own sanity vectors, over its generated test buffer, at a length
from each of the algorithm's length classes, at 64 and at 128 bits. Each suite carries one planted
wrong vector that is shown failing. The const and runtime paths are compared over the same lengths, and
the switched digest, when it joins, is checked against the 64-bit FNV-1a one byte below the crossover
and against `Xxh3<64>` at it. The carriers are checked at the width each names, `halves` included.
